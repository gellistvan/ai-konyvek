33.2 Kernelimplementáció

A Követelmények és architektúra egységben rögzített záróprojekt-követelményeket a kernelimplementáció szintjére fordítjuk le: ahelyett, hogy egyetlen monolitikus kernelt írnánk, a feladatot egy fő kernelre és több, jól körülhatárolt segédkernelre bontjuk. Az alábbiakban egy 2D hővezetési egyenletet megoldó explicit Euler-rendszert használunk példaként, amely a korábbi fejezetekben már bevezetett stencil- és tilingfogalmakra épít, de nem ismétli meg azokat. A hangsúly a kernelimplementáció szerkezetén, a memória- és szinkronizációs döntéseken, valamint a hibakezelésen van.

33.2.1 A fő kernel és a segédkernelek szerepe

Egy GPGPU-alkalmazás ritkán áll egyetlen kernelből. A záróprojektben a következő logikai feladatokat érdemes elkülöníteni:

  • Fő kernel: a számítási mag, amely a legtöbb időt fogyasztja. Itt ez az időlépés-stencil, amely a hőmérsékletmezőt a következő időszintre lépteti.
  • Segédkernelek: inicializálás, peremfeltétel-beállítás, hibaszámítás és kiértékelés. Ezek futásideje gyakran elhanyagolható, de a helyes működéshez nélkülözhetetlenek.

A szétválasztás előnye, hogy a segédkernelek egyszerű, könnyen ellenőrizhető egységek, míg a fő kernel optimalizálását önállóan, a teljes rendszer újrafordítása nélkül végezhetjük. A következő egységben (Optimalizálás és mérés) a fő kernel teljesítményét fogjuk tovább javítani, ezért itt a hangsúly a helyes, mérhető alapimplementáción van.

33.2.2 A példa: 2D hővezetési egyenlet

A Követelmények és architektúra követelményei alapján a feladat a

∂u∂t=α(∂2u∂x2+∂2u∂y2) \frac{\partial u}{\partial t} = \alpha \left( \frac{\partial^2 u}{\partial x^2} + \frac{\partial^2 u}{\partial y^2} \right)

megoldása Dirichlet-peremfeltétellel. Az explicit Euler-diszkretizáció egyenlete:

ui,jn+1=ui,jn+αΔt(ui−1,jn−2ui,jn+ui+1,jnΔx2+ui,j−1n−2ui,jn+ui,j+1nΔy2) u^{n+1}_{i,j} = u^n_{i,j} + \alpha \Delta t \left( \frac{u^n_{i-1,j} - 2u^n_{i,j} + u^n_{i+1,j}}{\Delta x^2} + \frac{u^n_{i,j-1} - 2u^n_{i,j} + u^n_{i,j+1}}{\Delta y^2} \right)

ahol i=1,…,nx−2i=1,\dots,n_x-2, j=1,…,ny−2j=1,\dots,n_y-2, a perempontok pedig rögzítettek. A stabilitási feltétel 2D-ben αΔt≤14min(Δx2,Δy2)\alpha \Delta t \leq \frac{1}{4} \min(\Delta x^2, \Delta y^2). A laborban ezt a feltételt teljesítő paramétereket használunk.

33.2.3 A fő kernel implementációja: naiv verzió

A naiv kernel egyetlen szálat rendel minden belső rácsponthoz, és minden iterációban a globális memóriából olvassa a szomszédos értékeket. Ez a legegyszerűbb implementáció, és remek kiindulópont a helyesség ellenőrzéséhez.

// CUDA C++ (C++17), nvcc 12.8, Linux x86_64
// Blokk: 16x16, grid: ceil((nx-2)/16) x ceil((ny-2)/16)
__global__ void heat_step_naive(const float* __restrict__ u_old,
                                float* __restrict__ u_new,
                                int nx, int ny,
                                float alpha, float dt,
                                float dx, float dy) {
    int i = blockIdx.x * blockDim.x + threadIdx.x;
    int j = blockIdx.y * blockDim.y + threadIdx.y;

    // Csak belső pontokat számolunk, a peremeket a segédkernel kezeli.
    if (i >= 1 && i < nx - 1 && j >= 1 && j < ny - 1) {
        float u_center = u_old[j * nx + i];
        float u_left   = u_old[j * nx + (i - 1)];
        float u_right  = u_old[j * nx + (i + 1)];
        float u_down   = u_old[(j - 1) * nx + i];
        float u_up     = u_old[(j + 1) * nx + i];

        float d2x = (u_left - 2.0f * u_center + u_right) / (dx * dx);
        float d2y = (u_down - 2.0f * u_center + u_up) / (dy * dy);

        u_new[j * nx + i] = u_center + alpha * dt * (d2x + d2y);
    }
}

A naiv kernel minden időlépésben öt globális memóriaolvasást és egy írást végez belső pontonként. A memória-hozzáférés nem koaleszkált optimálisan, mert a szomszédos sorok olvasása nagy stride-ot okoz, és a cache kihasználtsága alacsony. A teljesítményt az Optimalizálás és mérés alfejezetben részletesen elemezzük; itt a kernel a helyesség referenciájaként szolgál.

33.2.4 A fő kernel implementációja: tiled verzió

A naiv kernel memóriaforgalmának csökkentésére a shared memory tiling technikát alkalmazzuk. A blokk egy 16×1616\times16 belső pontból álló csempét számol, de a stencilhez szükséges halo (szegély) elemekkel együtt egy 18×1818\times18 méretű shared memory tömböt töltünk fel. A halo elemeket a szomszédos csempékből vagy a peremfeltételekből olvassuk be egyszer, így minden belső pont számításakor a szomszédok már a shared memoryban vannak.

// CUDA C++ (C++17), nvcc 12.8, Linux x86_64
// Blokk: 16x16, grid: ceil((nx-2)/16) x ceil((ny-2)/16)
constexpr int TILE_X = 16;
constexpr int TILE_Y = 16;

__global__ void heat_step_tiled(const float* __restrict__ u_old,
                                float* __restrict__ u_new,
                                int nx, int ny,
                                float alpha, float dt,
                                float dx, float dy) {
    // Shared memory csempe: belső pontok + 1 halo mindkét irányban
    __shared__ float tile[TILE_Y + 2][TILE_X + 2];

    int i = blockIdx.x * blockDim.x + threadIdx.x;
    int j = blockIdx.y * blockDim.y + threadIdx.y;
    int tx = threadIdx.x;
    int ty = threadIdx.y;

    // Belső pont betöltése
    if (i >= 1 && i < nx - 1 && j >= 1 && j < ny - 1) {
        tile[ty + 1][tx + 1] = u_old[j * nx + i];
    }

    // Halo elemek betöltése
    // Bal halo
    if (tx == 0 && i >= 1 && i < nx - 1 && j >= 1 && j < ny - 1) {
        tile[ty + 1][0] = u_old[j * nx + (i - 1)];
    }
    // Jobb halo
    if (tx == TILE_X - 1 && i >= 1 && i < nx - 1 && j >= 1 && j < ny - 1) {
        tile[ty + 1][TILE_X + 1] = u_old[j * nx + (i + 1)];
    }
    // Alsó halo
    if (ty == 0 && i >= 1 && i < nx - 1 && j >= 1 && j < ny - 1) {
        tile[0][tx + 1] = u_old[(j - 1) * nx + i];
    }
    // Felső halo
    if (ty == TILE_Y - 1 && i >= 1 && i < nx - 1 && j >= 1 && j < ny - 1) {
        tile[TILE_Y + 1][tx + 1] = u_old[(j + 1) * nx + i];
    }

    // Minden szál befejezte a betöltést, mielőtt bármelyik olvasná a csempét
    __syncthreads();

    // Számítás a belső pontokra
    if (i >= 1 && i < nx - 1 && j >= 1 && j < ny - 1) {
        float u_center = tile[ty + 1][tx + 1];
        float u_left   = tile[ty + 1][tx];
        float u_right  = tile[ty + 1][tx + 2];
        float u_down   = tile[ty][tx + 1];
        float u_up     = tile[ty + 2][tx + 1];

        float d2x = (u_left - 2.0f * u_center + u_right) / (dx * dx);
        float d2y = (u_down - 2.0f * u_center + u_up) / (dy * dy);

        u_new[j * nx + i] = u_center + alpha * dt * (d2x + d2y);
    }
}

A shared memory tömb mérete 18×1818\times18 elem, FP32 esetén 18⋅18⋅4=129618\cdot18\cdot4 = 1296 bájt, ami messze a limit alatt van. A __syncthreads() kulcsfontosságú: biztosítja, hogy a csempe minden eleme látható legyen a blokk minden szála számára, mielőtt a számítás elkezdődik. Enélkül versenyhelyzet alakulna ki: egyes szálak olvashatnák a még nem inicializált halo elemeket.

33.2.5 Segédkernelek implementációja

33.2.6 Inicializálás

Az inicializáló kernel egy kezdeti hőmérsékleti eloszlást állít elő. A példában egy Gauss-csomagot helyezünk a tartomány közepére.

// CUDA C++ (C++17), nvcc 12.8, Linux x86_64
// Blokk: 16x16, grid: ceil(nx/16) x ceil(ny/16)
__global__ void init_field(float* __restrict__ u,
                           int nx, int ny,
                           float dx, float dy) {
    int i = blockIdx.x * blockDim.x + threadIdx.x;
    int j = blockIdx.y * blockDim.y + threadIdx.y;
    if (i < nx && j < ny) {
        float x = i * dx;
        float y = j * dy;
        float cx = nx * dx * 0.5f;
        float cy = ny * dy * 0.5f;
        float r2 = (x - cx) * (x - cx) + (y - cy) * (y - cy);
        u[j * nx + i] = expf(-r2 / (2.0f * 0.1f * 0.1f));
    }
}

33.2.7 Peremfeltétel

A Dirichlet-peremfeltétel rögzített értéket ír a mező széleire. A kernel az alsó/felső sort és a bal/jobb oszlopot kezeli.

// CUDA C++ (C++17), nvcc 12.8, Linux x86_64
// Blokk: 256 szál, grid: ceil(max(nx,ny)/256)
__global__ void apply_boundary(float* __restrict__ u,
                               int nx, int ny,
                               float bc_value) {
    int idx = blockIdx.x * blockDim.x + threadIdx.x;
    if (idx < nx) {
        u[idx] = bc_value;                  // alsó sor (j=0)
        u[(ny - 1) * nx + idx] = bc_value;  // felső sor (j=ny-1)
    }
    if (idx < ny) {
        u[idx * nx] = bc_value;             // bal oszlop (i=0)
        u[idx * nx + nx - 1] = bc_value;    // jobb oszlop (i=nx-1)
    }
}

A sarokpontokat mindkét ág felülírja, de ugyanazzal az értékkel, ezért nincs versenyhelyzet, ha a kernel egyetlen streamen fut.

33.2.8 Hibaszámítás

A validációhoz szükség van a numerikus megoldás és egy referencia közötti eltérés normájára. A redukciót shared memoryban végezzük blokkszinten, majd a parciális összegeket a host számolja össze. Ez a segédkernel is a fő kernel helyességét ellenőrzi.

// CUDA C++ (C++17), nvcc 12.8, Linux x86_64
// Blokk: 256 szál, grid: ceil(n/256)
__global__ void compute_l2_diff(const float* __restrict__ u,
                                const float* __restrict__ u_ref,
                                int n,
                                float* __restrict__ partial) {
    extern __shared__ float sdata[];
    int tid = threadIdx.x;
    int idx = blockIdx.x * blockDim.x + tid;

    float diff = 0.0f;
    if (idx < n) {
        float d = u[idx] - u_ref[idx];
        diff = d * d;
    }

    sdata[tid] = diff;
    __syncthreads();

    for (unsigned int s = blockDim.x / 2; s > 0; s >>= 1) {
        if (tid < s) {
            sdata[tid] += sdata[tid + s];
        }
        __syncthreads();
    }

    if (tid == 0) {
        partial[blockIdx.x] = sdata[0];
    }
}

A host oldalon a parciális összegeket összeadjuk és gyököt vonunk, így megkapjuk a két mező közötti L2L^2-hibát.

33.2.9 Memória és szinkronizáció a kernelben

A fő kernel implementációjának központi kérdése a memóriaterek helyes megválasztása és a szinkronizáció.

  • Global memory: a hőmérsékletmezők (u_old, u_new) nagy méretűek, ezért csak global memoryban tárolhatók. A naiv kernel minden pontnál öt globális olvasást és egy írást végez, ami nagy memóriaforgalmat generál.
  • Shared memory: a tiled kernel a csempéhez szükséges pontokat egyszer tölti be shared memoryba, majd a számítás során onnan olvassa őket. A shared memory sávszélessége nagyságrendekkel nagyobb, mint a global memoryé, ezért a memóriaforgalom csökken.
  • Regiszterek: a belső számítások során a skalár értékeket (u_center, u_left, stb.) a fordító regiszterekben tartja, ami a leggyorsabb memóriatér.
  • Szinkronizáció: a __syncthreads() blokkszintű barrier, amely garantálja, hogy a shared memoryba írt összes érték láthatóvá válik a blokk minden szála számára, mielőtt a számítás elkezdődik. A hiánya versenyhelyzetet okoz, ami nemdeterminisztikus eredményekhez vezethet.

Fontos megjegyezni, hogy a __syncthreads() csak a blokkon belüli szálakat szinkronizálja. A blokkok közötti szinkronizációt a kernelhatárok oldják meg: minden időlépés külön kernelindítás, így a következő időlépés csak akkor kezdődik, ha az előző befejeződött (stream-szintű sorosítás esetén). A grid-szintű szinkronizációra itt nincs szükség.

33.2.10 Hibakezelés a kernelimplementációban

A CUDA-alkalmazásokban a hibakezelés nem opcionális. A kernelindítás aszinkron, ezért a hibák gyakran csak a cudaDeviceSynchronize() vagy a következő API-hívás során derülnek ki. A laborban kötelezően használt hibamakró a következő:

// CUDA C++ (C++17), nvcc 12.8, Linux x86_64
#include <cstdio>
#include <cstdlib>
#include <cuda_runtime.h>

#define CUDA_CHECK(call) do {                                       \
    cudaError_t err = (call);                                       \
    if (err != cudaSuccess) {                                       \
        fprintf(stderr, "CUDA hiba: %s:%d: %s\n",                   \
                __FILE__, __LINE__, cudaGetErrorString(err));       \
        exit(EXIT_FAILURE);                                         \
    }                                                               \
} while (0)

// Kernel indítás után közvetlenül:
// CUDA_CHECK(cudaGetLastError());
// A szinkronizáció után:
// CUDA_CHECK(cudaDeviceSynchronize());

A cudaGetLastError() a kernelindítási hibákat (pl. érvénytelen launch konfiguráció, nem létező függvény) fogja el, míg a cudaDeviceSynchronize() a kernel végrehajtása közben fellépő aszinkron hibákat (pl. illegális memória-hozzáférés) jelenti. A hibamakró használata kötelező minden CUDA API-hívás körül.

A fejlesztés során a compute-sanitizer --tool memcheck futtatása feltárja az out-of-bounds hozzáféréseket és a versenyhelyzeteket. A laborban ezt is futtatjuk, és az eredményt rögzítjük.

  • Warm-up: 5 iteráció
  • Mérés: 10 ismétlés, átlag és szórás számítása
  • Időmérés: CUDA events, a teljes időlépés-sorozatra
  • Effektív sávszélesség számítása a tényleges adatmozgatás alapján:

33.2.17 Mért és várt eredmények

A validációhoz a CPU referencia implementáció (FP64, azonos paraméterek) által számított hőmérsékletmező L2L^2-normája 100 lépés után: 0.0123456 (várt). A GPU FP32 megoldások normája:

Az eltérés a lebegőpontos kerekítésből adódik, és a megengedett hibakorláton belül van. A futásidőre vonatkozó várt arány a roofline-modell alapján kb. 2.5×, a mért arány 2.33×, ami a modell pontosságán belül van.

33.2.19 Összegzés

Ebben az egységben a záróprojekt kernelimplementációját építettük fel: a fő stencil-kernelt naiv és tiled változatban, valamint az inicializáló, peremfeltételt beállító és hibaszámító segédkerneleket. A memória- és szinkronizációs döntések középpontjában a shared memory tiling és a blokkszintű barrier állt. A hibakezelést kötelező makróval és compute-sanitizer-rel biztosítottuk. A labor mérési naplója megmutatta, hogy a tiled kernel kb. 2.3× gyorsabb a naivnál, miközben a numerikus hiba a megengedett tartományon belül marad. A következő egység (Optimalizálás és mérés) ezt az alapot használja további optimalizálásra: occupancy-növelés, vectorizált betöltés, double buffering és részletes Nsight-elemzés következik.
