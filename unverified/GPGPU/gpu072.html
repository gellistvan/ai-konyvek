19.3 SpMV és sparse optimalizálás

A sparse mátrix-vektor szorzás (SpMV) a ritka lineáris algebra sarokköve: iteratív megoldók, PageRank, spektrális klaszterezés, végeselem-módszerek és számos tudományos kód minden iterációja legalább egy SpMV-t végez. A dense GEMM-mel ellentétben az SpMV memória-kötött, szabálytalan hozzáférési mintájú, és a teljesítménye erősen függ a mátrix nemnulla szerkezetétől. Ebben az alfejezetben a CSR-reprezentáció feletti alapvető kernelektől a terheléskiegyensúlyozatlanság kezelésén át a cuSPARSE könyvtári megoldásig jutunk el, és egy teljes mérési labort építünk fel.

19.3.1 Az SpMV definíciója és költségmodellje

Az SpMV az y=Axy = A x műveletet számítja, ahol A∈ℝn×nA \in \mathbb{R}^{n \times n} ritka, x,y∈ℝnx,y \in \mathbb{R}^n. A ritkaságot a nemnulla elemek számával, nnz\mathrm{nnz}-vel jellemezzük. A művelet aritmetikai költsége 2nnz2\, \mathrm{nnz} lebegőpontos művelet (FLOP), de a tényleges futásidőt a memóriaforgalom dominálja: minden nemnulla elemhez be kell olvasni az értékét és az oszlopindexét, minden sorhoz a sorhatárokat, valamint az xx vektorból a megfelelő elemeket, és ki kell írni az yy vektort. A memóriaforgalom tipikusan 8nnz+4nnz+4(n+1)+8n+8n8\,\mathrm{nnz} + 4\,\mathrm{nnz} + 4(n+1) + 8n + 8n bájt double precízió esetén, ami általában egy nagyságrenddel nagyobb, mint a hasznos aritmetika – ezért az SpMV a memória-sávszélesség-korlátos tartományban van.

A Sparse mátrixreprezentációk alfejezetben bevezetett CSR-formátum a legelterjedtebb reprezentáció. Itt a row_ptr tömb hossza n+1n+1, a col_idx és values tömbök hossza nnz\mathrm{nnz}. A soronkénti feldolgozás természetes párhuzamosságot ad, de a sorhosszak szóródása – a ritka mátrixok jellegzetessége – egyenetlen munkamennyiséget okoz a szálak között.

19.3.2 A naiv scalar kernel

A legegyszerűbb CUDA-megvalósítás minden sorhoz egy szálat rendel. A kernel a globális indexszámítást követően a row_ptr határokon belül iterál, és felhalmozza a részletösszeget:

// CUDA C++ (C++17)
__global__ void spmv_csr_scalar(const int* row_ptr,
                                 const int* col_idx,
                                 const double* values,
                                 const double* x,
                                 double* y,
                                 int n)
{
    int row = blockIdx.x * blockDim.x + threadIdx.x;
    if (row < n) {
        double sum = 0.0;
        int start = row_ptr[row];
        int end   = row_ptr[row + 1];
        for (int j = start; j < end; ++j) {
            sum += values[j] * x[col_idx[j]];
        }
        y[row] = sum;
    }
}

A launch konfiguráció: dim3 block(256); dim3 grid((n + block.x - 1) / block.x);, a kernel indítása pedig spmv_csr_scalar<<<grid, block>>>(...). Minden szál pontosan egy sort dolgoz fel, így nincs versenyhelyzet az y írásakor. A memória-hozzáférés a col_idx[j] indirekción keresztül történik, ami az xx vektor véletlenszerű, nem koaleszkált olvasását eredményezi. A values[j] és col_idx[j] tömbök viszont soron belül folytonosak, tehát a globális memória-hozzáférés ezekre a tömbökre koaleszkált, amennyiben a szomszédos szálak hasonló ütemben haladnak – ez azonban ritkán teljesül.

A kernel fő problémája a terheléskiegyensúlyozatlanság (load imbalance). Ha a sorhosszak eloszlása széles – például egy skálafüggetlen gráf mátrixában néhány sor több ezer nemnulla elemet tartalmaz, míg a legtöbb sor csak néhányat –, akkor a hosszú sorokat feldolgozó szálak sokáig dolgoznak, míg a rövid sorokhoz rendelt szálak befejezik a munkájukat és várakoznak. A GPU ütemezője a warpokat csak akkor vonja ki, ha a warp mind a 32 szála befejezte a kernelét, ezért a leghosszabb sor hossza határozza meg a teljes warp futásidejét. A divergencia mellett a kihasználatlan szálak csökkentik az effektív sávszélességet.

A scalar kernel előnye az egyszerűsége és az alacsony regiszterigénye, ami magas occupancy-t tesz lehetővé. Rövid, egyenletes sorhosszúságú mátrixokon – például sávos mátrixokon, ahol minden sorban 5–7 nemnulla elem van – a kernel elfogadhatóan teljesít, mert a warp minden szála közel azonos munkát végez, és a koaleszkált hozzáférés megmarad.

19.3.3 A warp-per-row kernel

A hosszú sorok hatékony feldolgozásához egy sort több szálra kell bontani. A warp-per-row stratégia minden sorhoz egy 32 szálból álló warp-ot rendel, a sor nemnulla elemeit pedig a warp szálai ciklikusan osztják el. A részletösszegeket ezután egy warp-szintű redukcióval kombináljuk:

// CUDA C++ (C++17)
__global__ void spmv_csr_warp(const int* row_ptr,
                               const int* col_idx,
                               const double* values,
                               const double* x,
                               double* y,
                               int n)
{
    int warps_per_block = blockDim.x / warpSize;   // warpSize == 32
    int row = blockIdx.x * warps_per_block + (threadIdx.x / warpSize);
    if (row >= n) return;

    int lane = threadIdx.x % warpSize;
    int start = row_ptr[row];
    int end   = row_ptr[row + 1];

    double sum = 0.0;
    for (int j = start + lane; j < end; j += warpSize) {
        sum += values[j] * x[col_idx[j]];
    }

    // Warp-szintű redukció shuffle-lel
    for (int offset = warpSize / 2; offset > 0; offset >>= 1) {
        sum += __shfl_down_sync(0xffffffffu, sum, offset);
    }

    if (lane == 0) {
        y[row] = sum;
    }
}

A launch konfiguráció: dim3 block(256); int rows_per_block = block.x / warpSize; dim3 grid((n + rows_per_block - 1) / rows_per_block);. A kernelben a __shfl_down_sync a warp szálai közötti adatcserét valósítja meg regisztereken keresztül, ami elkerüli a shared memory használatát és a barrier szinkronizációt. A redukció után csak a 0. lane írja az y[row] értéket, így nincs versenyhelyzet.

A warp-per-row kernel lényegesen jobb a hosszú sorokra, mert a nemnulla elemek feldolgozását 32 szál párhuzamosítja, és a values/col_idx tömbök olvasása szintén koaleszkált marad. A shuffle-redukció logaritmikus költsége elhanyagolható a soron belüli iterációhoz képest. A kernel hátránya, hogy rövid sorok esetén a warp nagy része tétlen: ha egy sorban csak 3 nemnulla elem van, a 32 szálból 29 nem végez hasznos munkát a ciklusban, és a redukció is pazarló. Ezért a warp-per-row kernel a hosszú sorok dominálta mátrixoknál előnyös, míg a scalar kernel a rövid soroknál.

19.3.4 Load imbalance és irregularitás

A ritka mátrixok sorhossz-eloszlása gyakran erősen ferde. A valós alkalmazásokban – például szociális hálózatok, webgráfok, vagy adaptív végeselem-hálók – előfordul, hogy a sorok 90%-a kevesebb mint 10 nemnulla elemet tartalmaz, míg a maradék 10% több száz vagy több ezer elemet. A naiv scalar kernel ilyenkor a leghosszabb sor hosszával arányos időt tölt, miközben a legtöbb szál már régen végzett. A warp-per-row kernel ezt részben orvosolja, de a rövid soroknál a warp pazarlása miatt a teljesítmény még mindig messze van a memória-sávszélesség-korláttól.

A terheléskiegyensúlyozatlanság mérésére a sorhossz-szóródás (coefficient of variation) használható: σ/μ\sigma / \mu, ahol μ\mu az átlagos sorhossz, σ\sigma pedig a szórása. Ha ez az érték nagy, akkor a soronkénti párhuzamosítás rosszul teljesít. A megoldás az, hogy a hosszú sorokat több szálra bontjuk, a rövid sorokat pedig több soronként egy szálra csoportosítjuk. Ezt a hibrid megközelítést a következőképpen valósíthatjuk meg:

// CUDA C++ (C++17)
// Hibrid kernel: rövid sorokhoz scalar, hosszú sorokhoz warp-per-row.
// A row_ptr alapján előre besoroljuk a sorokat.
__global__ void spmv_csr_hybrid(const int* row_ptr,
                                 const int* col_idx,
                                 const double* values,
                                 const double* x,
                                 double* y,
                                 int n,
                                 int threshold)
{
    int tid = blockIdx.x * blockDim.x + threadIdx.x;
    int total_threads = gridDim.x * blockDim.x;

    // Minden szál egy vagy több rövid sort dolgoz fel scalar módban,
    // a hosszú sorokat pedig a warpok közösen.
    for (int row = tid; row < n; row += total_threads) {
        int start = row_ptr[row];
        int end   = row_ptr[row + 1];
        int nnz_row = end - start;
        if (nnz_row <= threshold) {
            double sum = 0.0;
            for (int j = start; j < end; ++j) {
                sum += values[j] * x[col_idx[j]];
            }
            y[row] = sum;
        }
    }
    // A hosszú sorokhoz külön kernel vagy szakasz tartozik;
    // itt a teljesség kedvéért a warp-per-row logikát alkalmazzuk.
    // A gyakorlatban ezt külön kernelbe érdemes szervezni.
    __syncthreads(); // blokk-szintű szinkronizáció a közös munkához
    int warps_per_block = blockDim.x / warpSize;
    int warp_id = blockIdx.x * warps_per_block + (threadIdx.x / warpSize);
    int lane = threadIdx.x % warpSize;
    // A hosszú sorok listáját egy előfeldolgozott tömbből kapjuk,
    // vagy egyszerűen újraindítjuk a gridet a hosszú sorokra.
}

A fenti vázlatban a hibrid kernel két fázisra bomlik, de a tényleges implementációban a hosszú sorokat érdemes külön kernelben vagy a __syncthreads() utáni szakaszban kezelni, ahol a warpok a hosszú sorok listáját kapják. A döntési küszöb (threshold) tipikusan 16–32 nemnulla elem, mivel efölött a warp-per-row előnye meghaladja a pazarlást.

A SELL-C-σ formátum egy másik megoldás: a mátrixot sorblokkokra osztja, és minden blokkban a sorokat a blokk maximális sorhosszára egészíti ki üres helyekkel, majd a blokk sorait oszlopfolytonosan tárolja. Ez a formátum a koaleszkált hozzáférést és a terheléskiegyensúlyozást egyszerre javítja, de a feltöltés miatt extra memóriát igényel. A gyakorlatban a SELL-C-σ a rövid sorok dominálta mátrixokon igen hatékony, míg a CSR a hosszú sorokra jobb.

19.3.5 A cuSPARSE könyvtár SpMV API-ja

A CUDA ökoszisztéma a ritka mátrixműveletekhez a cuSPARSE könyvtárat biztosítja. A cuSPARSE a CUDA 11-től kezdve egy generikus API-t kínál, amely a mátrix- és vektorleírók segítségével egységes felületet ad a különböző formátumokhoz. Az SpMV-hez a cusparseSpMV függvény tartozik, amely puffert igényel az előfeldolgozási adatokhoz. Az API használata:

// CUDA C++ (C++17) – cuSPARSE generikus API (CUDA 11+)
#include <cusparse.h>

void cusparse_spmv_example(int n, int nnz,
                           int* d_row_ptr, int* d_col_idx, double* d_values,
                           double* d_x, double* d_y)
{
    cusparseHandle_t handle;
    cusparseCreate(&handle);

    cusparseSpMatDescr_t matA;
    cusparseDnVecDescr_t vecX, vecY;

    // Mátrixleíró: CSR formátum, 32 bites indexek, 0 bázisú indexelés, double
    cusparseCreateCsr(&matA, n, n, nnz,
                      d_row_ptr, d_col_idx, d_values,
                      CUSPARSE_INDEX_32I, CUSPARSE_INDEX_32I,
                      CUSPARSE_INDEX_BASE_ZERO, CUDA_R_64F);

    // Vektorleírók
    cusparseCreateDnVec(&vecX, n, d_x, CUDA_R_64F);
    cusparseCreateDnVec(&vecY, n, d_y, CUDA_R_64F);

    double alpha = 1.0, beta = 0.0;
    size_t bufferSize = 0;
    void* d_buffer = nullptr;

    // Pufferméret lekérdezése
    cusparseSpMV_bufferSize(handle, CUSPARSE_OPERATION_NON_TRANSPOSE,
                            &alpha, matA, vecX, &beta, vecY,
                            CUDA_R_64F, CUSPARSE_SPMV_ALG_DEFAULT,
                            &bufferSize);
    CHECK_CUDA(cudaMalloc(&d_buffer, bufferSize));

    // SpMV végrehajtása: y = alpha * A * x + beta * y
    cusparseSpMV(handle, CUSPARSE_OPERATION_NON_TRANSPOSE,
                 &alpha, matA, vecX, &beta, vecY,
                 CUDA_R_64F, CUSPARSE_SPMV_ALG_DEFAULT,
                 d_buffer);

    // Takarítás
    cusparseDestroySpMat(matA);
    cusparseDestroyDnVec(vecX);
    cusparseDestroyDnVec(vecY);
    cusparseDestroy(handle);
    cudaFree(d_buffer);
}

A cusparseSpMV_bufferSize hívás nélkülözhetetlen: a cuSPARSE a megadott algoritmushoz szükséges ideiglenes puffert itt méretezi, és a cusparseSpMV ennek a puffernek a tartalmát használja. A CUSPARSE_SPMV_ALG_DEFAULT az alapértelmezett algoritmus, de létezik CUSPARSE_SPMV_ALG_MERGE_PATH is, amely nagyobb párhuzamosságot biztosít a hosszú sorokra. A mátrixleírót a formátumnak megfelelően kell létrehozni; CSR-hez a cusparseCreateCsr, COO-hoz a cusparseCreateCoo, BSR-hez a cusparseCreateBsr szolgál. A vektorleírók a sűrű vektorokat reprezentálják.

A cuSPARSE belsőleg több optimalizálást alkalmaz, beleértve a soronkénti feldolgozás adaptív kiválasztását, a memória-hozzáférési minták javítását és a hosszú sorok párhuzamosítását. A gyakorlatban a cuSPARSE SpMV-ja általában jelentősen gyorsabb, mint a naiv kernel, de a teljesítménye erősen függ a mátrix szerkezetétől és a választott formátumtól. A cusparseSpMV a CUSPARSE_MV_ALG_DEFAULT mellett lehetővé teszi az elemzési fázis különválasztását is (cusparseSpMV_analysis), ami ismételt SpMV-knél hasznos.

Fontos verziómegjegyzés: A cuSPARSE API a CUDA 10.x előtt más szignatúrával rendelkezett (cusparseDcsrmv). A fenti példa a CUDA 11+ generikus API-t használja, amely a jelenlegi (CUDA 12.x) verziókban az ajánlott. A pontos függvényszignatúrák és konstansok a cuSPARSE dokumentációban ellenőrizendők, mivel azok verzióról verzióra változhatnak.

// --- Kernelek a korábbi definíciókból ---
__global__ void spmv_csr_scalar(const int* row_ptr, const int* col_idx,
                                 const double* values, const double* x,
                                 double* y, int n)
{
    int row = blockIdx.x * blockDim.x + threadIdx.x;
    if (row < n) {
        double sum = 0.0;
        int start = row_ptr[row];
        int end   = row_ptr[row + 1];
        for (int j = start; j < end; ++j) {
            sum += values[j] * x[col_idx[j]];
        }
        y[row] = sum;
    }
}

__global__ void spmv_csr_warp(const int* row_ptr, const int* col_idx,
                               const double* values, const double* x,
                               double* y, int n)
{
    int warps_per_block = blockDim.x / warpSize;
    int row = blockIdx.x * warps_per_block + (threadIdx.x / warpSize);
    if (row >= n) return;
    int lane = threadIdx.x % warpSize;
    int start = row_ptr[row];
    int end   = row_ptr[row + 1];
    double sum = 0.0;
    for (int j = start + lane; j < end; j += warpSize) {
        sum += values[j] * x[col_idx[j]];
    }
    for (int offset = warpSize / 2; offset > 0; offset >>= 1) {
        sum += __shfl_down_sync(0xffffffffu, sum, offset);
    }
    if (lane == 0) y[row] = sum;
}

// --- CPU referencia ---
void spmv_cpu(const int* row_ptr, const int* col_idx, const double* values,
              const double* x, double* y, int n)
{
    for (int i = 0; i < n; ++i) {
        double sum = 0.0;
        for (int j = row_ptr[i]; j < row_ptr[i + 1]; ++j) {
            sum += values[j] * x[col_idx[j]];
        }
        y[i] = sum;
    }
}

// --- Mátrixgenerátor: minden sorban véletlen számú nemnulla elem,
//     log-normális eloszlású sorhosszakkal a terheléskiegyensúlyozatlanság modellezésére ---
void generate_sparse_matrix(int n, int target_nnz_per_row, double imbalance,
                            std::vector<int>& row_ptr, std::vector<int>& col_idx,
                            std::vector<double>& values, int& nnz)
{
    row_ptr.resize(n + 1);
    std::mt19937 rng(42);
    std::lognormal_distribution<double> dist(0.0, imbalance);
    row_ptr[0] = 0;
    for (int i = 0; i < n; ++i) {
        int len = std::max(1, (int)std::round(dist(rng) * target_nnz_per_row));
        row_ptr[i + 1] = row_ptr[i] + len;
    }
    nnz = row_ptr[n];
    col_idx.resize(nnz);
    values.resize(nnz);
    std::uniform_int_distribution<int> col_dist(0, n - 1);
    std::uniform_real_distribution<double> val_dist(-1.0, 1.0);
    for (int i = 0; i < n; ++i) {
        for (int j = row_ptr[i]; j < row_ptr[i + 1]; ++j) {
            col_idx[j] = col_dist(rng);
            values[j] = val_dist(rng);
        }
    }
}

// --- Mérési segédfüggvény ---
double measure_time(void (*launch)(const int*, const int*, const double*,
                                   const double*, double*, int, int, int),
                    const int* d_row_ptr, const int* d_col_idx,
                    const double* d_values, const double* d_x, double* d_y,
                    int n, int nnz, int block_size, int grid_size,
                    int warmup, int iters)
{
    // Warm-up
    for (int i = 0; i < warmup; ++i) {
        launch(d_row_ptr, d_col_idx, d_values, d_x, d_y, n, nnz, block_size, grid_size);
        CHECK_CUDA(cudaDeviceSynchronize());
    }
    cudaEvent_t start, stop;
    cudaEventCreate(&start);
    cudaEventCreate(&stop);
    cudaEventRecord(start);
    for (int i = 0; i < iters; ++i) {
        launch(d_row_ptr, d_col_idx, d_values, d_x, d_y, n, nnz, block_size, grid_size);
    }
    cudaEventRecord(stop);
    cudaEventSynchronize(stop);
    float ms = 0.0f;
    cudaEventElapsedTime(&ms, start, stop);
    cudaEventDestroy(start);
    cudaEventDestroy(stop);
    return ms / iters;
}

    spmv_csr_warp<<<grid_size, block_size>>>(d_row_ptr, d_col_idx, d_values, d_x, d_y, n);
}

// cuSPARSE launch wrapper
void launch_cusparse(const int* d_row_ptr, const int* d_col_idx,
                     const double* d_values, const double* d_x, double* d_y,
                     int n, int nnz, int block_size, int grid_size,
                     cusparseHandle_t handle)
{
    cusparseSpMatDescr_t matA;
    cusparseDnVecDescr_t vecX, vecY;
    CHECK_CUSPARSE(cusparseCreateCsr(&matA, n, n, nnz,
                                     const_cast<int*>(d_row_ptr),
                                     const_cast<int*>(d_col_idx),
                                     const_cast<double*>(d_values),
                                     CUSPARSE_INDEX_32I, CUSPARSE_INDEX_32I,
                                     CUSPARSE_INDEX_BASE_ZERO, CUDA_R_64F));
    CHECK_CUSPARSE(cusparseCreateDnVec(&vecX, n, const_cast<double*>(d_x), CUDA_R_64F));
    CHECK_CUSPARSE(cusparseCreateDnVec(&vecY, n, d_y, CUDA_R_64F));

    double alpha = 1.0, beta = 0.0;
    size_t bufferSize = 0;
    void* d_buffer = nullptr;
    CHECK_CUSPARSE(cusparseSpMV_bufferSize(handle, CUSPARSE_OPERATION_NON_TRANSPOSE,
                                           &alpha, matA, vecX, &beta, vecY,
                                           CUDA_R_64F, CUSPARSE_SPMV_ALG_DEFAULT,
                                           &bufferSize));
    CHECK_CUDA(cudaMalloc(&d_buffer, bufferSize));
    CHECK_CUSPARSE(cusparseSpMV(handle, CUSPARSE_OPERATION_NON_TRANSPOSE,
                                &alpha, matA, vecX, &beta, vecY,
                                CUDA_R_64F, CUSPARSE_SPMV_ALG_DEFAULT, d_buffer));
    CHECK_CUDA(cudaFree(d_buffer));
    CHECK_CUSPARSE(cusparseDestroySpMat(matA));
    CHECK_CUSPARSE(cusparseDestroyDnVec(vecX));
    CHECK_CUSPARSE(cusparseDestroyDnVec(vecY));
}

int main()
{
    // Paraméterek
    const int n = 1'000'000;
    const int target_nnz_per_row = 10;
    const double imbalance = 1.5;  // log-normális szórás
    const int block_size = 256;
    const int warmup = 5;
    const int iters = 20;

    // Mátrix generálása CPU-n
    std::vector<int> h_row_ptr, h_col_idx;
    std::vector<double> h_values;
    int nnz;
    generate_sparse_matrix(n, target_nnz_per_row, imbalance, h_row_ptr, h_col_idx, h_values, nnz);
    printf("n = %d, nnz = %d, avg row length = %.1f\n", n, nnz, (double)nnz / n);

    // CPU referencia
    std::vector<double> h_x(n), h_y_ref(n), h_y_test(n);
    std::mt19937 rng(123);
    std::uniform_real_distribution<double> dist(-1.0, 1.0);
    for (auto& v : h_x) v = dist(rng);
    spmv_cpu(h_row_ptr.data(), h_col_idx.data(), h_values.data(), h_x.data(), h_y_ref.data(), n);

    // GPU allokáció és feltöltés
    int *d_row_ptr, *d_col_idx;
    double *d_values, *d_x, *d_y;
    CHECK_CUDA(cudaMalloc(&d_row_ptr, (n + 1) * sizeof(int)));
    CHECK_CUDA(cudaMalloc(&d_col_idx, nnz * sizeof(int)));
    CHECK_CUDA(cudaMalloc(&d_values, nnz * sizeof(double)));
    CHECK_CUDA(cudaMalloc(&d_x, n * sizeof(double)));
    CHECK_CUDA(cudaMalloc(&d_y, n * sizeof(double)));
    CHECK_CUDA(cudaMemcpy(d_row_ptr, h_row_ptr.data(), (n + 1) * sizeof(int), cudaMemcpyHostToDevice));
    CHECK_CUDA(cudaMemcpy(d_col_idx, h_col_idx.data(), nnz * sizeof(int), cudaMemcpyHostToDevice));
    CHECK_CUDA(cudaMemcpy(d_values, h_values.data(), nnz * sizeof(double), cudaMemcpyHostToDevice));
    CHECK_CUDA(cudaMemcpy(d_x, h_x.data(), n * sizeof(double), cudaMemcpyHostToDevice));

    // Mérések
    int grid_scalar = (n + block_size - 1) / block_size;
    double t_scalar = measure_time(launch_scalar, d_row_ptr, d_col_idx, d_values, d_x, d_y,
                                   n, nnz, block_size, grid_scalar, warmup, iters);

    int warps_per_block = block_size / 32;
    int grid_warp = (n + warps_per_block - 1) / warps_per_block;
    double t_warp = measure_time(launch_warp, d_row_ptr, d_col_idx, d_values, d_x, d_y,
                                 n, nnz, block_size, grid_warp, warmup, iters);

    // cuSPARSE mérés
    cusparseHandle_t handle;
    CHECK_CUSPARSE(cusparseCreate(&handle));
    cudaEvent_t start, stop;
    cudaEventCreate(&start);
    cudaEventCreate(&stop);
    for (int i = 0; i < warmup; ++i) {
        launch_cusparse(d_row_ptr, d_col_idx, d_values, d_x, d_y, n, nnz, block_size, 0, handle);
        CHECK_CUDA(cudaDeviceSynchronize());
    }
    cudaEventRecord(start);
    for (int i = 0; i < iters; ++i) {
        launch_cusparse(d_row_ptr, d_col_idx, d_values, d_x, d_y, n, nnz, block_size, 0, handle);
    }
    cudaEventRecord(stop);
    cudaEventSynchronize(stop);
    float ms_cusparse = 0.0f;
    cudaEventElapsedTime(&ms_cusparse, start, stop);
    cudaEventDestroy(start);
    cudaEventDestroy(stop);
    double t_cusparse = ms_cusparse / iters;
    CHECK_CUSPARSE(cusparseDestroy(handle));

    // Ellenőrzés: a cuSPARSE eredményt használjuk (utolsó futtatásból)
    CHECK_CUDA(cudaMemcpy(h_y_test.data(), d_y, n * sizeof(double), cudaMemcpyDeviceToHost));
    double max_abs_err = 0.0;
    for (int i = 0; i < n; ++i) {
        double err = std::abs(h_y_test[i] - h_y_ref[i]);
        if (err > max_abs_err) max_abs_err = err;
    }
    printf("Max abs error vs CPU: %.3e\n", max_abs_err);

    // Sávszélesség számítása
    size_t mem_bytes = nnz * (sizeof(double) + sizeof(int)) + (n + 1) * sizeof(int) + 2 * n * sizeof(double);
    double bw_scalar = mem_bytes / (t_scalar * 1e-3) / 1e9;
    double bw_warp   = mem_bytes / (t_warp * 1e-3) / 1e9;
    double bw_cusparse = mem_bytes / (t_cusparse * 1e-3) / 1e9;

    printf("\n=== Mérési eredmények ===\n");
    printf("Kernel        Idő (ms)   Sávszélesség (GB/s)\n");
    printf("scalar        %8.4f   %8.2f\n", t_scalar, bw_scalar);
    printf("warp          %8.4f   %8.2f\n", t_warp, bw_warp);
    printf("cusparse      %8.4f   %8.2f\n", t_cusparse, bw_cusparse);

    // Takarítás
    CHECK_CUDA(cudaFree(d_row_ptr));
    CHECK_CUDA(cudaFree(d_col_idx));
    CHECK_CUDA(cudaFree(d_values));
    CHECK_CUDA(cudaFree(d_x));
    CHECK_CUDA(cudaFree(d_y));
    return 0;
}

Megjegyzés a kódhoz: A launch_cusparse a leírókat minden hívásnál létrehozza és megsemmisíti, ami a mérés során overheadet visz be. A tényleges teljesítményméréshez a leírókat és a puffert érdemes a mérési cikluson kívül létrehozni, és csak a cusparseSpMV hívást ismételni. A laborban a hallgatónak ezt az optimalizálást el kell végeznie, és a mérési naplóban jeleznie kell. A fenti kód a didaktikai egyszerűség kedvéért mutatja a teljes életciklust, de a mérési eredmények így konzervatívabbak (a cuSPARSE valós teljesítménye jobb lehet).

A labor során a következő táblázatot kell kitölteni. A várt eredmény oszlopban a tendencia szerepel – ezt a mérés előtt kell megadni, a mért oszlopot pedig a futtatás után.

A laborjelentésnek tartalmaznia kell a teljes környezetet (GPU modell, driver, CUDA verzió, órajel, power limit, ECC állapot) és a mérés statisztikáját (átlag, szórás, ismétlésszám). A mérési naplóban a tényleges és a várt eredményeket egyértelműen el kell különíteni, és ha eltérés van, azt elemezni kell.

A sávszélesség számításánál a tényleges adatforgalmat kell használni: bytes=nnz⋅(8+4)+(n+1)⋅4+2n⋅8\mathrm{bytes} = \mathrm{nnz} \cdot (8 + 4) + (n+1) \cdot 4 + 2 n \cdot 8 double precízió esetén. A névleges GPU sávszélesség (pl. A100: 1555 GB/s HBM2e) csak felső korlát; a tényleges SpMV ennek általában 10–30%-át éri el a ritka hozzáférés miatt.

19.3.11 Gyakori hibák és megelőzésük

  1. Out-of-bounds indexelés a CSR tömbökben. Ha a row_ptr[n] nem egyezik a values hosszával, vagy a col_idx elemei kívül esnek a [0,n−1][0, n-1] tartományon, a kernel nem definiált viselkedést okoz. Megelőzés: a mátrixgenerátor után ellenőrizni kell a tömbök konzisztenciáját, és a kernelben a col_idx[j] értékét a beolvasás előtt validálni (debug módban).

  2. Versenyhelyzet az y írásakor. Ha a grid konfiguráció nem fedi le pontosan a sorokat, vagy a hibrid kernelben több szál ugyanazt a sort kezeli, az y[row] írása versenyhelyzethez vezet. A scalar és warp kernelekben a sor-szál hozzárendelés egyértelmű, de a hibrid megoldásoknál atomi művelet vagy gondos indexelés szükséges. Megelőzés: a kernelben minden sort pontosan egyszer dolgozzunk fel, és ezt a hozzárendelést a launch konfigurációval biztosítsuk.

  3. A warp-redukció utáni szinkronizáció elhagyása. A __shfl_down_sync után a warp szálai közötti láthatóság nem garantált a __syncwarp() vagy a shuffle szinkronizációs maszkja nélkül. A fenti kódban a shuffle hívás magában foglalja a szinkronizációt a megadott maszkkal, de ha más warp-szintű műveleteket használunk, explicit __syncwarp() kell. Megelőzés: mindig használjuk a _sync utótagú intrinsics-eket.

  4. A cuSPARSE puffer elhagyása vagy helytelen méretezése. A cusparseSpMV a bufferSize által meghatározott puffert igényli; ha a puffer túl kicsi, a hívás hibát ad vagy nem definiált viselkedést okoz. Megelőzés: mindig hívjuk meg a cusparseSpMV_bufferSize-t, és ellenőrizzük a visszatérési értékeket.

  5. A mérési idő nem tartalmazza a teljes adatmozgatást. Ha a mérés csak a kernel futásidejét rögzíti, de a mátrix feltöltését nem, akkor a valós alkalmazás teljesítménye rosszabb lesz. Megelőzés: a mérés során a teljes adatutat mérjük, vagy legalább külön jelöljük a kernel- és a transzferidőt.

  6. A numerikus pontosság elhanyagolása. Az SpMV-nál a felhalmozás sorrendje befolyásolja a kerekítési hibát, különösen ha a mátrix értékei nagy dinamikatartományúak. A warp-per-row kernel redukciós sorrendje eltér a CPU-tól, ami kis eltéréseket okozhat. Megelőzés: a hibahatárt a feladat numerikus igényeihez kell igazítani, és a mérési naplóban rögzíteni kell a használt precíziót (FP64/FP32).

19.3.12 Összefoglalás

Az SpMV a GPU-számítás egyik legnehezebb memória-kötött feladata. A naiv scalar kernel egyszerű, de a terheléskiegyensúlyozatlanság miatt a valós mátrixokon gyakran nagyon lassú. A warp-per-row kernel a hosszú sorokat párhuzamosítja, de a rövid soroknál pazarló. A hatékony megoldás a sorhossz-eloszláshoz igazodó hibrid stratégia vagy a SELL-C-σ formátum. A cuSPARSE generikus API-ja kényelmes és erősen optimalizált SpMV-t kínál, de a teljesítmény még így is a mátrix szerkezetétől függ. A labor során a hallgató a három megközelítést méri össze, és a mért eredményeket a várt tendenciákkal veti össze.
