16.4 CUB és Thrust használata

A redukció, a prefix összeg (scan) és a rendezés a párhuzamos algoritmusok leggyakrabban használt építőkövei. Az előző alfejezetekben saját CUDA kernelekkel valósítottuk meg őket, hogy megértsük a működésüket. A termelési kódban azonban ritkán írunk kézzel redukciót vagy scan-t: a gyártó és a közösség által karbantartott könyvtárak több éves optimalizálást, hardverspecifikus hangolást és alapos tesztelést foglalnak magukba. Ez az alfejezet a CUDA ökoszisztéma két alapvető eszközét, a CUB-ot és a Thrust-ot mutatja be, a redukció, a scan és a rendezés használatára összpontosítva.

16.4.1 A CUB és a Thrust szerepe

A CUB (CUDA UnBound) egy alacsony szintű, header-only párhuzamos primitív könyvtár. A CUDA Toolkit részeként érkezik, és olyan eszközöket biztosít, mint a DeviceReduce, DeviceScan, DeviceSort, DeviceSelect, DeviceSegmentedReduce és társaik. A CUB közvetlenül a CUDA C++ execution modelre épül, ezért a hívásai gyakran tömbmutatókat, méreteket és opcionálisan CUDA streamet várnak. A Thrust ezzel szemben egy magasabb szintű, STL-szerű sablonkönyvtár, amely konténereket (thrust::device_vector), iterátorokat és általános algoritmusokat (thrust::reduce, thrust::transform_reduce, thrust::sort) kínál. A Thrust számos műveletét a CUB primitívekre építi, így a kettő jól kiegészíti egymást: a Thrust kényelmes, gyors fejlesztést tesz lehetővé, míg a CUB finomabb kontrollt ad, és a teljesítmény szempontjából kritikus kódrészekhez alkalmas.

A gyakorlatban a következő döntési szempontokat érdemes követni:

  • Ha egy összeget, minimumot, maximumot vagy prefix összeget kell számítani egyetlen nyers device-tömbön, a CUB DeviceReduce és DeviceScan közvetlen, minimális overheaddel járó megoldást ad.
  • Ha a műveleteket transzformációval kombináljuk, például norma számítása vagy feltételes kiválasztás, a Thrust transform_reduce és transform_scan kényelmesebb.
  • Ha a kódban már thrust::device_vector-ok vannak, akkor a Thrust algoritmusai természetesen illeszkednek; ha nyers pointerekkel dolgozunk, a CUB és a Thrust egyaránt használható, utóbbi esetben pointer-konverzióval.

16.4.2 A CUB programozási modellje

A CUB eszközfüggvényei kétfázisú hívást alkalmaznak. Először lekérdezzük a szükséges ideiglenes tárterület méretét egy nullptr mint ideiglenes puffer átadásával. A CUB ilyenkor nem hajt végre számítást, csak kitölti a méretet tartalmazó változót. Ezután a hívó fél allokálja a megfelelő méretű puffert, és egy második hívással ténylegesen futtatja a műveletet. Ez a minta lehetővé teszi a memória újrafelhasználását több hívás között, és elkerüli a belső allokációkat.

Példa a DeviceReduce::Sum hívására:

// CUDA C++ (C++17), nvcc 12.1, sm_80
// Hibakezelő makró
#define CHECK_CUDA(call) do {                                     \
    cudaError_t err = call;                                       \
    if (err != cudaSuccess) {                                     \
        fprintf(stderr, "CUDA error at %s:%d: %s\n",              \
                __FILE__, __LINE__, cudaGetErrorString(err));      \
        exit(EXIT_FAILURE);                                       \
    }                                                             \
} while (0)

// Feltételezzük, hogy d_in és d_out érvényes device-mutatók, n > 0
void* d_temp_storage = nullptr;
size_t temp_storage_bytes = 0;

// 1. fázis: a szükséges ideiglenes tárterület méretének lekérdezése
CHECK_CUDA(cub::DeviceReduce::Sum(
    nullptr, temp_storage_bytes, d_in, d_out, n));

// 2. fázis: allokálás és tényleges végrehajtás
CHECK_CUDA(cudaMalloc(&d_temp_storage, temp_storage_bytes));
CHECK_CUDA(cub::DeviceReduce::Sum(
    d_temp_storage, temp_storage_bytes, d_in, d_out, n));

// Opcionális: stream megadása
// CHECK_CUDA(cub::DeviceReduce::Sum(
//     d_temp_storage, temp_storage_bytes, d_in, d_out, n, stream));

A legtöbb CUB hívás visszatérési értéke cudaError_t, így a hibakezelő makrónkkal közvetlenül ellenőrizhető. A hívás után a szokásos cudaDeviceSynchronize is szükséges lehet, ha a host oldalon azonnal fel akarjuk használni az eredményt vagy mérni akarjuk a futásidőt.

16.4.3 DeviceReduce: könyvtári redukció

A cub::DeviceReduce sablonosztály a leggyakoribb redukciós műveleteket kínálja:

  • cub::DeviceReduce::Sum – összegzés,
  • cub::DeviceReduce::Min / Max – minimum és maximum,
  • cub::DeviceReduce::ArgMin / ArgMax – a szélsőérték indexe,
  • cub::DeviceReduce::Reduce – tetszőleges, saját bináris művelet.

A beépített műveleteknél a hívás szignatúrája egyszerű:

cudaError_t cub::DeviceReduce::Sum(
    void* d_temp_storage,
    size_t& temp_storage_bytes,
    const T* d_in,
    T* d_out,
    int num_items,
    cudaStream_t stream = 0);

A d_in mutató a bemeneti tömb device-memóriájára mutat, a d_out pedig egyetlen elemet fog tartalmazni. A num_items a redukálandó elemek száma. A d_temp_storage az előzőleg lekérdezett méretű puffer; nullptr esetén csak a méretet kapjuk meg.

A CUB redukciója a háttérben többszintű, regiszterekben és shared memory-ban végzett részösszegzést hajt végre, majd a blokkok közötti összegzést az ideiglenes tárterületen keresztül oldja meg. A bemeneti tömböt általában coalescing-barát módon olvassa, a memória-sávszélesség nagy részét kihasználva. A futásidő jellemzően a bemeneti adat méretétől és a memória-sávszélességtől függ, nem pedig a számítási teljesítménytől.

Fontos, hogy a d_out pointernek is device-memóriára kell mutatnia. Az eredmény hostra másolásához használjunk cudaMemcpy-t. A következő példa egy 1 Mi elemből álló float tömb összegét számítja ki, és ellenőrzi az eredményt:

// CUDA C++ (C++17), nvcc 12.1, sm_80
#include <cub/cub.cuh>
#include <cstdio>
#include <cstdlib>

#define CHECK_CUDA(call) /* lásd fent */

int main() {
    const int n = 1 << 20; // 1 048 576
    size_t bytes = n * sizeof(float);

    // Host bemenet: x[i] = 1.0f
    float* h_in = static_cast<float*>(malloc(bytes));
    for (int i = 0; i < n; ++i) h_in[i] = 1.0f;

    // Device memória
    float *d_in = nullptr, *d_out = nullptr;
    CHECK_CUDA(cudaMalloc(&d_in, bytes));
    CHECK_CUDA(cudaMalloc(&d_out, sizeof(float)));
    CHECK_CUDA(cudaMemcpy(d_in, h_in, bytes, cudaMemcpyHostToDevice));

    // Ideiglenes tárterület méretének lekérdezése
    void* d_temp_storage = nullptr;
    size_t temp_storage_bytes = 0;
    CHECK_CUDA(cub::DeviceReduce::Sum(
        nullptr, temp_storage_bytes, d_in, d_out, n));

    // Allokálás és futtatás
    CHECK_CUDA(cudaMalloc(&d_temp_storage, temp_storage_bytes));
    CHECK_CUDA(cub::DeviceReduce::Sum(
        d_temp_storage, temp_storage_bytes, d_in, d_out, n));
    CHECK_CUDA(cudaDeviceSynchronize());

    // Eredmény visszamásolása
    float h_out = 0.0f;
    CHECK_CUDA(cudaMemcpy(&h_out, d_out, sizeof(float), cudaMemcpyDeviceToHost));

    printf("Sum: %f (expected %f)\n", h_out, static_cast<float>(n));

    // Takarítás
    CHECK_CUDA(cudaFree(d_temp_storage));
    CHECK_CUDA(cudaFree(d_in));
    CHECK_CUDA(cudaFree(d_out));
    free(h_in);
    return 0;
}

Mivel a bemeneti értékek mindegyike 1.0f, a várt összeg 1048576.0f. Ez a szám a float típus pontossági tartományán belül van, így bitpontos egyezést várunk. Ha a bemenet véletlenszerű lebegőpontos érték lenne, akkor a GPU és a CPU redukciója közötti eltérést a lebegőpontos összegzés sorrendjének különbsége okozná; ilyenkor tűréssel kell összehasonlítani, amit a numerikus pontosságról szóló fejezet tárgyal.

16.4.4 DeviceScan: könyvtári scan

A cub::DeviceScan a prefix összeg (scan) számítását végzi. Két alapvető változata van:

  • cub::DeviceScan::InclusiveSum – a kimenet ii-edik eleme tartalmazza az input 00-tól ii-ig terjedő elemeinek összegét: yi=∑j=0ixjy_i = \sum_{j=0}^{i} x_j.
  • cub::DeviceScan::ExclusiveSum – a kimenet ii-edik eleme az input 00-tól i−1i-1-ig terjedő elemeinek összegét adja, azaz yi=∑j=0i−1xjy_i = \sum_{j=0}^{i-1} x_j, ahol y0=0y_0 = 0.

Az exclusive scan különösen hasznos olyan feladatoknál, ahol a kimenetet egy későbbi lépésben címzésre használjuk, például kompaktálásnál vagy szegmentált feldolgozásnál. A CUB más típusú scan műveleteket is támogat (Min, Max, ByKey, BySegment), de most a két összegző változatra koncentrálunk.

A hívás alakja hasonló a redukcióhoz:

cudaError_t cub::DeviceScan::InclusiveSum(
    void* d_temp_storage,
    size_t& temp_storage_bytes,
    const T* d_in,
    T* d_out,
    int num_items,
    cudaStream_t stream = 0);

A kimeneti tömb num_items elemet tartalmaz, nem num_items + 1-et, még az exclusive scan esetén sem. A kimenet első eleme exclusive scan-nél mindig nulla (feltéve, hogy nincs explicit kezdőérték paraméter).

A következő kód egy float tömb inkluzív prefix összegét számítja ki:

// CUDA C++ (C++17), nvcc 12.1, sm_80
// Feltételezzük: n = 1 << 20, d_in és d_scan_out érvényes device-tömbök
void* d_temp_storage = nullptr;
size_t temp_storage_bytes = 0;

CHECK_CUDA(cub::DeviceScan::InclusiveSum(
    nullptr, temp_storage_bytes, d_in, d_scan_out, n));

CHECK_CUDA(cudaMalloc(&d_temp_storage, temp_storage_bytes));
CHECK_CUDA(cub::DeviceScan::InclusiveSum(
    d_temp_storage, temp_storage_bytes, d_in, d_scan_out, n));
CHECK_CUDA(cudaDeviceSynchronize());

Ha a bemenet minden eleme 1.0f, akkor a várt kimenet: yi=i+1y_i = i + 1, azaz 1, 2, 3, ..., 1 048 576. Ezt CPU-n könnyű ellenőrizni egy egyszerű ciklussal.

A CUB scan implementációja work-efficient algoritmust használ (gyakran Blelloch vagy hasonló), amely csökkenti a felesleges műveletek számát. A teljesítményt elsősorban a bemeneti és kimeneti adatok mozgatása határozza meg, mert a scan olvassa és írja is a teljes tömböt.

16.4.5 DeviceSort: könyvtári rendezés

A CUB DeviceSort osztálya kulcs szerinti rendezést valósít meg radix sort alapú algoritmussal. A radix sort nem összehasonlítás alapú, ezért jól illeszkedik a GPU párhuzamos architektúrájához. A CUB a következő főbb változatokat kínálja:

  • cub::DeviceSort::SortKeys – kulcsok rendezése in-place,
  • cub::DeviceSort::SortKeysCopy – kulcsok rendezése külön be- és kimeneti tömbbel,
  • cub::DeviceSort::SortPairs – kulcsok és hozzájuk tartozó értékek rendezése,
  • cub::DeviceSort::SortPairsCopy – mint előbb, de külön kimenettel.

A SortPairs akkor fontos, ha a rendezett sorrendhez adatok is tartoznak, például indexek vagy pontszámok. A kulcsok típusa lehet int, float, unsigned int, long long stb., de a radix sort bitműveletek alapján dolgozik, ezért a lebegőpontos típusoknál a belső bitreprezentációt használja. A helyes sorrend eléréséhez a CUB a lebegőpontos számok IEEE 754 bitképét alakítja át, így a rendezés eredménye a várt numerikus sorrend lesz.

Az alapvető in-place kulcsrendezés kódja:

// CUDA C++ (C++17), nvcc 12.1, sm_80
// d_keys: n méretű int device-tömb, rendezendő
void* d_temp_storage = nullptr;
size_t temp_storage_bytes = 0;

CHECK_CUDA(cub::DeviceSort::SortKeys(
    nullptr, temp_storage_bytes, d_keys, n));

CHECK_CUDA(cudaMalloc(&d_temp_storage, temp_storage_bytes));
CHECK_CUDA(cub::DeviceSort::SortKeys(
    d_temp_storage, temp_storage_bytes, d_keys, n));
CHECK_CUDA(cudaDeviceSynchronize());

A SortKeys a kulcsokat növekvő sorrendbe rendezi. Ha csökkenő sorrendet szeretnénk, a kulcsokat negálhatjuk, vagy a SortKeysDescending változatot használhatjuk (bizonyos CUB verziókban elérhető). A radix sort az adott típus összes bitjét feldolgozza; ez alapértelmezésben a típus teljes bitszélessége, például sizeof(int) * 8 az int esetén. A CUB lehetőséget ad a feldolgozott bitek számának korlátozására is, ami akkor hasznos, ha a kulcsok értékkészlete kisebb.

A CUB DeviceSort futásideje általában O(n)O(n) a radix sort miatt, ellentétben az összehasonlítás alapú rendezések O(nlogn)O(n \log n) elméleti korlátjával. A gyakorlatban a teljesítményt a memória-hozzáférés és a radix lépések száma határozza meg. A következő alfejezet (Radix sort) a radix sort belső működését tárgyalja, ezért itt csak a használatra összpontosítunk.

16.4.6 Thrust: magasabb szintű absztrakció

A Thrust a CUDA számára készült párhuzamos algoritmusgyűjtemény, amelynek felülete az STL-re hasonlít. A legfontosabb konténerei a thrust::host_vector<T> és a thrust::device_vector<T>. Az algoritmusok iterátorokon dolgoznak, így ugyanaz a kód használható host- és device-konténerekkel egyaránt. A Thrust header-only, a CUDA Toolkit tartalmazza.

16.4.7 transform_reduce és reduce

A thrust::reduce egy tartomány elemeit redukálja egyetlen értékké. Alapértelmezés szerint összeadást végez, de tetszőleges bináris műveletet adhatunk meg. A thrust::transform_reduce először egy unáris transzformációt alkalmaz minden elemre, majd a transzformált értékeket redukálja. Ez a kombináció rendkívül gyakori: például vektor normájának számításakor először négyzetre emelünk, majd összegzünk.

A következő példa egy float vektor euklideszi normájának négyzetét számítja ki:

// CUDA C++ (C++17), nvcc 12.1, sm_80
#include <thrust/device_vector.h>
#include <thrust/transform_reduce.h>
#include <thrust/functional.h>
#include <thrust/sequence.h>
#include <cstdio>

// Unáris funktor: négyzetre emelés
struct square_functor {
    __host__ __device__
    float operator()(float x) const { return x * x; }
};

int main() {
    const int n = 1 << 20;
    thrust::device_vector<float> d_vec(n);

    // Feltöltés 1.0f értékekkel
    thrust::fill(d_vec.begin(), d_vec.end(), 1.0f);

    // A négyzetösszeg kiszámítása: sum(x_i^2)
    float sum_sq = thrust::transform_reduce(
        d_vec.begin(), d_vec.end(),
        square_functor(),
        0.0f,
        thrust::plus<float>());

    printf("Sum of squares: %f (expected %f)\n", sum_sq, static_cast<float>(n));
    return 0;
}

A thrust::transform_reduce szignatúrája a következő:

template<typename InputIterator, typename UnaryFunction, typename T, typename BinaryFunction>
T thrust::transform_reduce(
    InputIterator first, InputIterator last,
    UnaryFunction unary_op,
    T init,
    BinaryFunction binary_op);

A binary_op általában thrust::plus<T>(), de használhatunk szorzást, maximumot, minimumot vagy saját funktort. A thrust::reduce hasonló, de unáris transzformáció nélkül:

float total = thrust::reduce(d_vec.begin(), d_vec.end(), 0.0f, thrust::plus<float>());

A thrust::sort szintén in-place rendezést végez, hasonlóan a CUB SortKeys-hez:

// CUDA C++ (C++17), nvcc 12.1, sm_80
#include <thrust/sort.h>
#include <thrust/device_vector.h>

thrust::device_vector<int> d_keys(n);
// ... feltöltés ...
thrust::sort(d_keys.begin(), d_keys.end());

A Thrust rendezése alapértelmezésben növekvő sorrendet ad, és beépítetten támogatja az összehasonlító funktorokat is.

16.4.8 Mutató konverziók Thrust és nyers CUDA pointerek között

A Thrust konténerei jól integrálhatók a CUB-bal és a kézzel írt kernelekkel. A thrust::device_ptr<T> egy vékony burkoló a nyers T* pointer körül, amely lehetővé teszi a Thrust algoritmusok közvetlen használatát anélkül, hogy device_vector-t kellene létrehozni. A thrust::device_pointer_cast egy nyers mutatót device_ptr-re alakít, míg a thrust::raw_pointer_cast az ellenkező irányt végzi el.

Példa nyers mutatóval:

// CUDA C++ (C++17), nvcc 12.1, sm_80
float* d_in = nullptr;
cudaMalloc(&d_in, n * sizeof(float));
// ... feltöltés ...

float sum = thrust::reduce(
    thrust::device_pointer_cast(d_in),
    thrust::device_pointer_cast(d_in) + n,
    0.0f,
    thrust::plus<float>());

Ha egy thrust::device_vector-ból nyers pointert szeretnénk átadni egy CUB vagy saját kernel hívásnak, a thrust::raw_pointer_cast használatos:

thrust::device_vector<float> d_vec(n);
float* raw_ptr = thrust::raw_pointer_cast(d_vec.data());

Ez a konverzió okos, mert nem jár adatmásolással, csupán típusmódosítással. Fontos azonban, hogy a device_vector memóriája a vektor élettartamához kötött; ha a vektor destruálódik, a nyers pointer érvénytelenné válik.

A Thrust műveletek alapértelmezésben a default stream-en futnak, és a hívó blokkolódik, amíg a művelet be nem fejeződik. Ez leegyszerűsíti a hibakeresést és a kezdeti fejlesztést, de akadályozhatja az aszinkron végrehajtást. A későbbi, streamekről szóló fejezet (Streamek és események) megmutatja, hogyan lehet a Thrust hívásait explicit streamhez kötni.

16.4.9 Saját vs. könyvtári megoldás

A saját kernel írásának oktatási értéke vitathatatlan: elmélyíti a memória-hozzáférés, a szinkronizáció és az algoritmusok megértését. A termelési kódban azonban a könyvtárak használata a következő előnyökkel jár:

  • Teljesítmény: A CUB és a Thrust implementációit a hardvergyártó mérnökei optimalizálták az adott GPU-generációkra. A naiv saját kernel gyakran messze elmarad a memória-sávszélesség kihasználásában, míg a CUB redukciója jellemzően a sávszélesség 80–90%-át eléri.
  • Megbízhatóság: A könyvtárak kezelik a szélsőséges méreteket, a nem pontosan osztható elemszámokat, a nagy tömböket és a konkurens hívásokat. A saját kódban ezek a sarok esetek gyakran hibákhoz vezetnek.
  • Karbantarthatóság: A könyvtári hívás tömör, deklaratív, és a mögöttes optimalizációk a jövőbeni hardverfrissítésekkel együtt fejlődhetnek, anélkül hogy a felhasználói kódot módosítani kellene.
  • Fejlesztési idő: A two-phase CUB hívás vagy egy thrust::reduce néhány sor, míg egy robosztus saját redukció több száz sor tesztelt kódot igényel.

Ugyanakkor a könyvtárak használatának is vannak korlátai. A CUB DeviceReduce::Sum nem tud egyszerűen egy transzformációt beolvasztani; ha például a bemeneti értékeket egy kernelben számítjuk ki, és azonnal redukálni szeretnénk őket anélkül, hogy a teljes tömböt kiírnánk a globális memóriába, akkor a CUB külön lépést igényel a generálásra és a redukcióra. Hasonlóképpen a Thrust transform_reduce kényelmes, de a funktorok és a köztes tárolók bevezetése néha kevésbé hatékony, mint egy kézzel írt, fúzionált kernel. Az ilyen esetekben a saját kernel indokolt lehet.

A gyakorlatban a legjobb stratégia a rétegződés: használjuk a Thrust-ot a magas szintű vezérlésre, a CUB-ot az alacsony szintű primitívekre, és saját kernelt csak ott írjunk, ahol a fúzió vagy a speciális adatelrendezés valódi előnyt ad. Ez a szemlélet a későbbi fejezetekben is visszaköszön, például a cuBLAS és a CUTLASS kapcsán.

16.4.10 Gyakori hibák és elkerülésük

A könyvtári hívások használata során a következő tipikus hibákkal találkozhatunk:

  1. Az ideiglenes tárterület méretének lekérdezése elmarad vagy helytelen.
    A CUB hívások kétfázisúak; ha közvetlenül egy érvénytelen d_temp_storage pointerrel hívjuk őket, a program lefagyhat vagy hibát ad. Mindig először nullptr-rel kérdezzük le a méretet, majd allokálunk, majd hívunk.

  2. A temp_storage_bytes változót nem frissítjük a második hívás előtt.
    A második hívás ugyanazt a méretet várja, amit az első hívás adott. Ha a változó értéke megváltozik, a CUB hibásan működhet. A legjobb, ha a méretet egy külön size_t változóban tároljuk, és nem módosítjuk a két hívás között.

  3. A bemeneti vagy kimeneti pointer host-memóriára mutat.
    A CUB és a Thrust device-oldali algoritmusai device-memóriát várnak. Host-memória átadása esetén a CUDA hibát ad, vagy a program leáll. Ellenőrizzük, hogy minden pointer cudaMalloc-kal vagy thrust::device_vector-ral jött létre.

  4. A kimeneti tömb mérete rossz a scan esetén.
    Az InclusiveSum és ExclusiveSum kimenete num_items elemű, nem num_items + 1. Ha a kimeneti puffert túl kicsire méretezzük, memóriahiba lép fel. Az exclusive scan első eleme nulla, ezért nem kell külön hely a kezdőértéknek.

  5. A DeviceSort kulcs–érték pároknál a tömbméretek eltérnek.
    A SortPairs feltételezi, hogy a kulcsok és értékek tömbje azonos elemszámú. Ha az egyik rövidebb, a CUB hibát jelez vagy nem definiált viselkedést mutat.

  6. A Thrust iterátorok és a nyers pointerek keverése hibás konverzióval.
    A thrust::device_pointer_cast és a thrust::raw_pointer_cast megfelelő használata elengedhetetlen. A device_vector::data() önmagában nem device_ptr, ezért Thrust algoritmusokhoz nem használható közvetlenül; vagy használjuk a begin()-t, vagy alakítsuk át.

  7. A hibakezelés hiánya.
    A CUB hívások után ellenőrizni kell a visszatérési értéket és a cudaGetLastError kimenetét. A hibaüzenetek gyakran azonnal rámutatnak a hibás paraméterre.

  8. A szinkronizálás elhagyása mérésnél vagy host-oldali felhasználásnál.
    A CUB és a Thrust hívásai aszinkronok lehetnek. Ha az eredményt közvetlenül a hívás után olvassuk host-oldalon, előbb cudaDeviceSynchronize-t kell hívni. A méréseknél is szinkronizálni kell az eseményeket.

  9. A DeviceScan-nél az input és output átfedése.
    A CUB általában támogatja az in-place scan-t (azaz d_in == d_out), de a biztonságos megoldás a külön kimeneti tömb használata, hacsak a dokumentáció egyértelműen nem engedi az átfedést. Ha a két pointer azonos, győződjünk meg a változat dokumentációjából, hogy ez megengedett.

  10. A thrust::device_vector másolása implicit módon host-vektorba.
    A thrust::device_vector-ból thrust::host_vector-ba való másolás szinkronizál, de ha a kód nem szándékoltan teszi, teljesítményproblémát okozhat. A nagy tömböknél ez a rejtett adatmozgás jelentős lehet.

A fenti hibák elkerülése érdekében a kódban mindig a CHECK_CUDA makrót használjuk, a CUB hívásokat kétfázisúan hajtjuk végre, és a tömbméreteket egységesen kezeljük.

16.4.13 Kód

A következő CUDA C++ program elvégzi a kért műveleteket, ellenőrzi az eredményt, és méri a futásidőt CUDA eventek segítségével.

// CUDA C++ (C++17), nvcc 12.1, sm_80
#include <cub/cub.cuh>
#include <cstdio>
#include <cstdlib>
#include <cmath>

#define CHECK_CUDA(call) do {                                     \
    cudaError_t err = call;                                       \
    if (err != cudaSuccess) {                                     \
        fprintf(stderr, "CUDA error at %s:%d: %s\n",              \
                __FILE__, __LINE__, cudaGetErrorString(err));      \
        exit(EXIT_FAILURE);                                       \
    }                                                             \
} while (0)

int main() {
    const int n = 1 << 20; // 1 048 576
    const size_t bytes = n * sizeof(float);

    // Host bemenet feltöltése: x[i] = 1.0f
    float* h_in = static_cast<float*>(malloc(bytes));
    for (int i = 0; i < n; ++i) h_in[i] = 1.0f;

    // Device memória
    float *d_in = nullptr, *d_reduce_out = nullptr, *d_scan_out = nullptr;
    CHECK_CUDA(cudaMalloc(&d_in, bytes));
    CHECK_CUDA(cudaMalloc(&d_reduce_out, sizeof(float)));
    CHECK_CUDA(cudaMalloc(&d_scan_out, bytes));
    CHECK_CUDA(cudaMemcpy(d_in, h_in, bytes, cudaMemcpyHostToDevice));

    // Ideiglenes pufferek mérete és allokálása
    void* d_temp_reduce = nullptr;
    size_t temp_reduce_bytes = 0;
    CHECK_CUDA(cub::DeviceReduce::Sum(
        nullptr, temp_reduce_bytes, d_in, d_reduce_out, n));

    void* d_temp_scan = nullptr;
    size_t temp_scan_bytes = 0;
    CHECK_CUDA(cub::DeviceScan::InclusiveSum(
        nullptr, temp_scan_bytes, d_in, d_scan_out, n));

    CHECK_CUDA(cudaMalloc(&d_temp_reduce, temp_reduce_bytes));
    CHECK_CUDA(cudaMalloc(&d_temp_scan, temp_scan_bytes));

    // Mérési események
    cudaEvent_t start, stop;
    CHECK_CUDA(cudaEventCreate(&start));
    CHECK_CUDA(cudaEventCreate(&stop));

    const int warmup = 10;
    const int iters = 50;

    // Warm-up (nem mérjük)
    for (int i = 0; i < warmup; ++i) {
        CHECK_CUDA(cub::DeviceReduce::Sum(
            d_temp_reduce, temp_reduce_bytes, d_in, d_reduce_out, n));
        CHECK_CUDA(cub::DeviceScan::InclusiveSum(
            d_temp_scan, temp_scan_bytes, d_in, d_scan_out, n));
    }
    CHECK_CUDA(cudaDeviceSynchronize());

    // DeviceReduce mérése
    CHECK_CUDA(cudaEventRecord(start));
    for (int i = 0; i < iters; ++i) {
        CHECK_CUDA(cub::DeviceReduce::Sum(
            d_temp_reduce, temp_reduce_bytes, d_in, d_reduce_out, n));
    }
    CHECK_CUDA(cudaEventRecord(stop));
    CHECK_CUDA(cudaEventSynchronize(stop));
    float reduce_ms = 0.0f;
    CHECK_CUDA(cudaEventElapsedTime(&reduce_ms, start, stop));
    reduce_ms /= iters;

    // DeviceScan mérése
    CHECK_CUDA(cudaEventRecord(start));
    for (int i = 0; i < iters; ++i) {
        CHECK_CUDA(cub::DeviceScan::InclusiveSum(
            d_temp_scan, temp_scan_bytes, d_in, d_scan_out, n));
    }
    CHECK_CUDA(cudaEventRecord(stop));
    CHECK_CUDA(cudaEventSynchronize(stop));
    float scan_ms = 0.0f;
    CHECK_CUDA(cudaEventElapsedTime(&scan_ms, start, stop));
    scan_ms /= iters;

    // Eredmények visszamásolása és ellenőrzése
    float h_reduce = 0.0f;
    float* h_scan = static_cast<float*>(malloc(bytes));
    CHECK_CUDA(cudaMemcpy(&h_reduce, d_reduce_out, sizeof(float), cudaMemcpyDeviceToHost));
    CHECK_CUDA(cudaMemcpy(h_scan, d_scan_out, bytes, cudaMemcpyDeviceToHost));

    // Várt eredmények
    float expected_reduce = static_cast<float>(n);
    float max_scan_error = 0.0f;
    for (int i = 0; i < n; ++i) {
        float expected_scan = static_cast<float>(i + 1);
        float err = fabsf(h_scan[i] - expected_scan);
        if (err > max_scan_error) max_scan_error = err;
    }

    printf("=== CUB DeviceReduce::Sum ===\n");
    printf("  mért:    %.1f\n", h_reduce);
    printf("  várt:    %.1f\n", expected_reduce);
    printf("  eltérés: %.6e\n", fabsf(h_reduce - expected_reduce));
    printf("  átlagos futásidő: %.4f ms\n", reduce_ms);

    printf("=== CUB DeviceScan::InclusiveSum ===\n");
    printf("  maximális abszolút hiba a scan kimenetben: %.6e\n", max_scan_error);
    printf("  átlagos futásidő: %.4f ms\n", scan_ms);

    // Sávszélesség becslés
    // Reduce: beolvasás n*sizeof(float), kiírás sizeof(float) -> kb. n*4 byte mozog
    double reduce_gb = (n * sizeof(float) + sizeof(float)) / 1e9;
    printf("  effektív reduce sávszélesség: %.2f GB/s\n",
           reduce_gb / (reduce_ms / 1000.0));
    // Scan: beolvasás n*sizeof(float), kiírás n*sizeof(float) -> 2*n*4 byte
    double scan_gb = (2.0 * n * sizeof(float)) / 1e9;
    printf("  effektív scan sávszélesség: %.2f GB/s\n",
           scan_gb / (scan_ms / 1000.0));

    // Takarítás
    CHECK_CUDA(cudaFree(d_temp_reduce));
    CHECK_CUDA(cudaFree(d_temp_scan));
    CHECK_CUDA(cudaFree(d_in));
    CHECK_CUDA(cudaFree(d_reduce_out));
    CHECK_CUDA(cudaFree(d_scan_out));
    free(h_in);
    free(h_scan);
    CHECK_CUDA(cudaEventDestroy(start));
    CHECK_CUDA(cudaEventDestroy(stop));
    return 0;
}

16.4.17 Önellenőrző kérdések

  1. Miért kétfázisú a CUB DeviceReduce és DeviceScan hívása?
    Az első hívás nullptr ideiglenes pufferrel lekérdezi a szükséges tárterület méretét, hogy a felhasználó egyszer allokálhasson, és a puffert több hívás között újrahasznosíthassa. A második hívás ténylegesen végrehajtja a műveletet. Ez elkerüli a belső allokációkat és a felesleges memóriaműveleteket.

  2. Miben különbözik a cub::DeviceScan::InclusiveSum és a cub::DeviceScan::ExclusiveSum?
    Az inclusive scan a kimenet ii-edik elemébe az input 00-tól ii-ig terjedő elemeinek összegét írja (yi=∑j=0ixjy_i = \sum_{j=0}^{i} x_j). Az exclusive scan az input 00-tól i−1i-1-ig terjedő elemeinek összegét adja (yi=∑j=0i−1xjy_i = \sum_{j=0}^{i-1} x_j), ezért y0=0y_0 = 0. A kimeneti tömb mérete mindkét esetben nn.

  3. Mikor érdemes saját redukciós kernelt írni a CUB vagy a Thrust helyett?
    Olyan esetekben, amikor a redukciót egy másik kernel fúziójával akarjuk összevonni, például a bemeneti értékeket egy kernelben számítjuk ki, és nem akarjuk a teljes tömböt a globális memóriába kiírni. Szintén szükség lehet saját kernelre, ha a CUB vagy a Thrust nem támogatja a kívánt típust vagy műveletet. Az oktatási cél is indokolhatja, de a termelési kódban a könyvtárak a megbízhatóság és a teljesítmény miatt általában előnyösebbek.

Ebben az alfejezetben bemutattuk a CUB és a Thrust könyvtárak használatát a redukció, a scan és a rendezés műveleteire. A CUB alacsony szintű, kétfázisú hívásokkal közvetlen irányítást ad a device-memórián, míg a Thrust magas szintű, STL-szerű felülettel kényelmes transzformációkat és redukciókat tesz lehetővé. Megvizsgáltuk a saját kernel és a könyvtári megoldás közötti kompromisszumokat, és felsoroltuk a leggyakoribb hibákat azok elkerülési módjaival. A következő alfejezet a radix sort belső működésére és a CUB DeviceSort implementációjának részleteire épít, így az itt bevezetett könyvtári hívások ismerete közvetlen előfeltétel.
