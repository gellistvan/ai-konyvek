16.2 Scan (prefix sum)

A scan (prefix sum) az egyik leggyakrabban használt párhuzamos primitív. Egy x[0..n-1] bemeneti sorozathoz az inclusive scan az y[i] = x[0] + x[1] + ... + x[i] kimenetet adja, az exclusive scan pedig az y[0] = 0, y[i] = x[0] + ... + x[i-1] értékeket. A kettő közötti kapcsolat egyszerű: ha az exclusive scan eredményéhez hozzáadjuk az aktuális x[i] elemet, inclusive scan-t kapunk; ha az inclusive scan-ből kivonjuk x[i]-t, exclusive scan-t kapunk. Ez a látszólag apró eltérés a gyakorlatban döntő, mert a legtöbb algoritmus – például a stream compaction, a radix sort, a sparse mátrix-vektor szorzás vagy a párhuzamos memóriacímzés – kifejezetten exclusive scan-t igényel.

A scan látszólag soros rekurziónak tűnik, hiszen minden kimenet az összes megelőző bemenettől függ. A GPU-n mégis hatékonyan párhuzamosítható, mert az asszociatív összegzési művelet lehetővé teszi a részösszegek fa-szerű kombinálását. Ebben a fejezetben a Blelloch-féle úgynevezett work-efficient scan-t építjük fel: ez a redukcióhoz hasonló up-sweep fázisból, majd egy down-sweep fázisból áll, és a munkaigénye O(n), a mélysége pedig O(log n). A fejezet előfeltételezi a redukciók ismeretét (Redukciók), ezért az up-sweep fázist nem magyarázzuk újra teljes részletességgel, csak a scan-specifikus részekre összpontosítunk.

16.2.1 1. Inclusive és exclusive scan definíció szerint

Legyen ⊕ egy asszociatív bináris művelet, például összeadás, szorzás vagy maximumképzés. A továbbiakban az olvashatóság kedvéért összeadást írunk, de minden képlet érvényes tetszőleges asszociatív műveletre, ha a neutrális elemet is definiáljuk. Az inclusive scan:

yincl[i]=⨁j=0ix[j], y_{\text{incl}}[i] = \bigoplus_{j=0}^{i} x[j],

míg az exclusive scan:

yexcl[0]=0,yexcl[i]=⨁j=0i−1x[j],i>0. y_{\text{excl}}[0] = 0, \quad y_{\text{excl}}[i] = \bigoplus_{j=0}^{i-1} x[j], \quad i > 0.

A 0 itt az összeadás neutrális eleme; általános műveletnél a neutrális elemet kell használni. A két definíció közötti átjárás egyetlen elemenkénti művelettel megvalósítható:

yincl[i]=yexcl[i]⊕x[i],yexcl[i]=yincl[i]⊕x[i]−1, y_{\text{incl}}[i] = y_{\text{excl}}[i] \oplus x[i], \qquad y_{\text{excl}}[i] = y_{\text{incl}}[i] \oplus x[i]^{-1},

ahol x[i]^{-1} az inverz elem, ha létezik (összeadásnál a negatív). Ha nincs inverz, az exclusive scan-t közvetlenül kell előállítani, vagy egy eltolt másolatot kell alkalmazni.

A gyakorlati alkalmazások szempontjából az exclusive scan azért fontos, mert megadja, hogy egy adott elem elé hány elem kerül a kimeneti tömbben. Például stream compaction esetén bemenetként egy predikátumtömböt kapunk, ahol a teljesülő elemeket 1-gyel, a többit 0-val jelöljük. Az exclusive scan megadja a célindexet: ha a predikátum az i-edik helyen igaz, akkor az elem a scan_excl[i] indexre kerül. Ez a minta a párhuzamos programozás egyik alapeleme.

16.2.2 2. Naiv párhuzamos megközelítés és a work-efficient scan

A legegyszerűbb párhuzamos scan a Hillis–Steele-féle algoritmus. Minden iterációban minden szál hozzáadja a tőle 2^{d-1} távolságra lévő elem értékét a saját értékéhez:

for d = 1 to log2(n):
    for k in parallel:
        if k >= 2^(d-1):
            x[k] += x[k - 2^(d-1)]

Ez a forma inclusive scan-t ad. A munkaigénye O(n log n), mert az összes elemet log2(n)-szer módosítja. A GPU-n ez a felesleges munka gyakran elfogadható kis tömbök esetén, de nagy adathalmazoknál pazarló.

A Blelloch-scan ezzel szemben O(n) munkát végez, és a mélysége is O(log n). Két fázisból áll:

  1. Up-sweep (reduce): a redukcióhoz hasonlóan páronként összegzünk egy felfelé haladó fában, de az eredményeket a fában tároljuk, nem csak a gyökeret. A gyökérben a teljes összeg jelenik meg.
  2. Down-sweep: a fa gyökerét nullára állítjuk, majd lefelé haladva minden csomópontnál az aktuális (bal oldali) prefix értéket átmásoljuk a bal gyermekbe, a jobb gyermekbe pedig a bal gyermek régi értékét és az aktuális értéket összegezve írjuk. A levél elemekben az exclusive scan értéke jelenik meg.

A Blelloch-scan tehát közvetlenül exclusive scan-t produkál. Inclusive scan-t úgy kapunk, ha az algoritmus után hozzáadjuk az eredeti bemeneti elemet, vagy ha a down-sweep során a neutrális elem helyett az utolsó levelet x[n-1]-gyel inicializáljuk, de a részletek implementációfüggők.

A gyakorlatban a Blelloch-scan a legszélesebb körben használt blokk-szintű scan, mert a shared memory-ban tárolt adatokkal jól illeszkedik a GPU-szálak indexeléséhez, és a __syncthreads() hívásokkal a fázisok közötti konzisztencia garantálható.

16.2.3 3. Blokk-szintű Blelloch-scan CUDA-ban

A blokk-szintű megvalósítás feltételezi, hogy a bemenet hossza megegyezik a blokkmérettel, vagy legalábbis annál nem nagyobb. A szokásos gyakorlat szerint n a blokkméret, és a bemenet a shared memory-ba kerül. Az alábbi kód egy teljes, fordítható CUDA kernelt mutat be. A kód a fejezet laborjaként is szolgál, ezért a hibakezelést a könyv szabályai szerint beépítettük.

// nyelv: CUDA C++17
// fordítás: nvcc -O3 -arch=sm_80 blelloch_scan.cu -o blelloch_scan

#include <cuda_runtime.h>
#include <cstdio>
#include <cstdlib>
#include <cassert>

#define CUDA_CHECK(call)                                                \
    do {                                                                \
        cudaError_t err = (call);                                       \
        if (err != cudaSuccess) {                                       \
            fprintf(stderr, "CUDA error %s:%d: %s\n", __FILE__, __LINE__, \
                    cudaGetErrorString(err));                           \
            exit(EXIT_FAILURE);                                         \
        }                                                               \
    } while (0)

// Blokkszintű Blelloch exclusive scan.
// Feltételek:
//  - n == blockDim.x
//  - n hatványa kettő (power of two)
//  - a bemenet és kimenet külön global memory területen van,
//    de a kernel shared memory-ban dolgozik.
template <int BLOCK_SIZE>
__global__ void blelloch_scan_kernel(const float* __restrict__ input,
                                      float* __restrict__ output) {
    __shared__ float temp[BLOCK_SIZE];
    int tid = threadIdx.x;

    // Bemenet betöltése shared memory-ba.
    temp[tid] = input[tid];
    __syncthreads();

    // Up-sweep: redukció a fán felfelé.
    for (unsigned int stride = 1; stride < BLOCK_SIZE; stride <<= 1) {
        unsigned int idx = (tid + 1) * (stride << 1) - 1;
        if (idx < BLOCK_SIZE) {
            temp[idx] += temp[idx - stride];
        }
        __syncthreads();
    }

    // Down-sweep: az exclusive scan értékek előállítása.
    if (tid == 0) {
        temp[BLOCK_SIZE - 1] = 0.0f;   // a gyökér neutrális elemre állítása
    }
    __syncthreads();

    for (unsigned int stride = BLOCK_SIZE >> 1; stride > 0; stride >>= 1) {
        unsigned int idx = (tid + 1) * (stride << 1) - 1;
        if (idx < BLOCK_SIZE) {
            float left_value = temp[idx - stride];
            temp[idx - stride] = temp[idx];
            temp[idx] += left_value;
        }
        __syncthreads();
    }
    __syncthreads();

    // Kimenet írása global memory-ba.
    output[tid] = temp[tid];
}

A kernel működésének megértéséhez kövessük végig egy BLOCK_SIZE = 8 példán. Az up-sweep a következő elemeket módosítja:

  • stride = 1: a páros indexű elemek (1, 3, 5, 7) hozzáadják a tőlük eggyel kisebb indexű elem értékét.
  • stride = 2: a 3 és 7 indexű elemek hozzáadják az 1 és 5 indexű elemek értékét.
  • stride = 4: a 7 indexű elem hozzáadja a 3 indexű elem értékét.

Eredmény: temp[7] a teljes összeg, a többi elem a részfa-összegeket tartalmazza. A down-sweep során a gyökérbe 0 kerül, majd a fa mentén lefelé haladva a bal gyermek kapja a szülő aktuális értékét, a jobb gyermek pedig a bal gyermek régi értékét és a szülő aktuális értékét összegezve. A levelekben az exclusive scan jelenik meg.

Fontos részlet: a __syncthreads() hívás a hurkokon belül minden iteráció után kötelező. Ha kihagyjuk, a szálak nem garantáltan látják a korábbi iterációban módosított értékeket, és a kimenet versenyhelyzet miatt nem determinisztikus lesz. A cudaDeviceSynchronize() a kernel után, valamint a cudaGetLastError() a launch hibák ellenőrzésére szolgál.

A fenti kód csak akkor helyes, ha n hatványa kettő. A gyakorlatban a bemenet hossza ritkán ilyen; ilyenkor a leggyakoribb megoldás a bemenet kiegészítése a következő kettőhatványra, ahol a fiktív elemek értéke a neutrális elem (összeadásnál 0). A kiegészítés a kernelben a feltételes betöltéssel kezelhető: az if (tid < n) feltételt kell alkalmazni a betöltésnél és a kiírásnál, míg a shared memory többi elemét nullával kell inicializálni. A laborban ezt a kiterjesztést is érdemes megvalósítani.

16.2.4 4. Grid-szintű scan: több blokk együttműködése

Egyetlen blokk csak korlátozott számú elemet tud kezelni, hiszen a blokkméret jellemzően legfeljebb 1024 szál. Nagy bemenetek esetén a scan-t több blokkra kell bontani. A standard megközelítés három lépésből áll:

  1. Blokkszintű scan: minden blokk a saját szegmensén végrehajtja a Blelloch-scan-t (vagy bármely blokk-szintű scan-t). A blokk az exclusive scan eredményét írja a kimeneti tömb saját szegmensébe, és a szegmens teljes összegét egy külön block_sums tömbbe menti.
  2. Részösszegek scan-je: a block_sums tömbön lefuttatunk egy exclusive scan-t. Ez lehet egyetlen blokk által végzett scan, ha a blokkok száma kicsi, vagy rekurzívan ismételhető a fenti lépés.
  3. Offset hozzáadása: minden blokk a saját block_sums-beli exclusive scan értékét hozzáadja a saját szegmensének minden eleméhez.

Ez a módszer három kernelindítást igényel, és a köztes tárolók mérete O(num_blocks). A módszer jól párhuzamosítható, de a második lépésben a blokkok közötti szinkronizációt kernelhatárokkal valósítja meg. A modern CUDA-ban a decoupled look-back technika ezt a szinkronizációt egyetlen kernelben, az utolsó blokk által publikált összegek dinamikus olvasásával oldja meg; ezt a CUB DeviceScan algoritmusa használja.

A grid-szintű scan másik fontos szempontja a streaming vagy perzisztens megközelítés: a grid-stride loop segítségével egy kernel több szegmenst is feldolgozhat, így a blokkok száma és a feldolgozási sorrend tervezhető. Ennek részletei a Grid-stride loop és perzisztens kernelek alfejezetben bemutatott grid-stride loopra épülnek.

Egy egyszerű, de működő grid-szintű exclusive scan vázlata:

__global__ void scan_block_kernel(const float* input, float* output,
                                  float* block_sums, int n) {
    // 1. blokkszintű Blelloch exclusive scan a saját szegmensen
    // 2. block_sums[blockIdx.x] = a szegmens teljes összege
}

__global__ void add_offset_kernel(float* output, const float* block_offsets,
                                  int n) {
    // minden elemhez hozzáadja a blokkjának offsetjét
}

// Host oldalon:
// 1. scan_block_kernel<<<num_blocks, block_size, shmem, stream>>>
// 2. egy kisebb exclusive scan a block_sums-on
// 3. add_offset_kernel<<<num_blocks, block_size, 0, stream>>>

A fenti vázlatban a második lépés egyetlen blokkal is elvégezhető, ha a blokkok száma legfeljebb BLOCK_SIZE. Ha a blokkok száma ennél nagyobb, a rekurzív bővítés ugyanezt a mintát követi.

A grid-szintű scan gyakorlati megvalósítása során kritikus a hibakezelés: a block_sums tömböt minden kernelindítás után ellenőrizni kell, és a végén a kimenetet CPU-n össze kell hasonlítani egy szekvenciális referenciával. A laborban egy ilyen ellenőrző függvényt is be kell mutatni.

16.2.5 5. Gyakori hibák és megelőzésük

A scan implementálásakor a leggyakoribb hibák a következők:

  1. Hiányzó __syncthreads() a scan hurkokban. A Blelloch-scan minden iterációja után szükséges, mert a szálak a shared memory-ban más szálak által írt értékeket olvasnak. Ha a szinkronizáció elmarad, a kimenet nem determinisztikus, és a compute-sanitizer racecheck eszköz (Compute-sanitizer: memcheck és racecheck) jelzi a versenyhelyzetet.

  2. Nem hatványa kettő hosszúság. A fenti kernel feltételezi, hogy BLOCK_SIZE pontosan a blokkméret, és a bemeneti hossz ennyi. Ha a bemenet rövidebb, a feltétel nélküli hozzáférés shared memory túlindexeléshez vezet. A megoldás a kiegészítés neutrális elemekkel, vagy egy általánosabb, bármilyen hosszúságot kezelő kernel írása.

  3. Az exclusive és inclusive összekeverése. A Blelloch-scan exclusive eredményt ad. Ha a felhasználó inclusive scan-t vár, a kimenethez hozzá kell adni az eredeti bemenetet. Ez a hiba a tesztelés során azonnal kiderül, ha a referenciával összehasonlítjuk. A laborban ezt a lépést expliciten kell dokumentálni.

  4. Shared memory bank conflict. A temp tömb hozzáférése a fenti indexeléssel (idx = (tid+1)*2*stride - 1) általában nem okoz bank conflictet, mert a szálak azonos bankokhoz különböző időpontokban férnek hozzá, de ha a tömb méretét nem megfelelően választjuk meg, vagy ha a kiegészítés miatt a tényleges használt méret eltér, a bankkonfliktusok ronthatják a teljesítményt. A __shared__ float temp[BLOCK_SIZE] esetén a bankok száma 32, és a float méret miatt a szomszédos elemek különböző bankokban vannak. A probléma jellemzően akkor jelentkezik, ha a hozzáférési mintázat stride 32 többszöröse, ami itt nem áll fenn.

  5. Global memory hozzáférési minta nem coalescing. A bemenet és kimenet írása a fenti példában szomszédos szálak szomszédos memóriacímekre írnak, ami coalescing. Ez a szabály a grid-szintű scan offset-hozzáadásánál is fontos, ahol a blokkon belüli szálak a saját tid indexükkel férnek hozzá a kimenethez.

  6. A neutrális elem hibás definiálása. A Blelloch-scan a gyökérben a neutrális elemet használja. Összeadásnál ez 0, szorzásnál 1, maximumképzésnél a típus legkisebb eleme. Ha a műveletet általánosítjuk, a neutrális elemet paraméterként kell átadni, és a laborban ezt dokumentálni kell.

16.2.6 6. Labor: Blelloch-scan implementálása

A labor célja egy teljes, hibakezeléssel ellátott CUDA C++ program elkészítése, amely a fenti blelloch_scan_kernel segítségével exclusive scan-t számít egy véletlenszerű float tömbre, és az eredményt CPU-referenciával hasonlítja össze. A laborhoz tartozó kód, buildparancs, futtatási parancs és mérési napló az alábbiakban látható.

16.2.7 6.1. A teljes CUDA program

// nyelv: CUDA C++17
// fordítás: nvcc -O3 -arch=sm_80 blelloch_scan_lab.cu -o blelloch_scan_lab

#include <cuda_runtime.h>
#include <cstdio>
#include <cstdlib>
#include <cassert>
#include <cmath>
#include <vector>

#define CUDA_CHECK(call)                                                \
    do {                                                                \
        cudaError_t err = (call);                                       \
        if (err != cudaSuccess) {                                       \
            fprintf(stderr, "CUDA error %s:%d: %s\n", __FILE__, __LINE__, \
                    cudaGetErrorString(err));                           \
            exit(EXIT_FAILURE);                                         \
        }                                                               \
    } while (0)

template <int BLOCK_SIZE>
__global__ void blelloch_scan_kernel(const float* __restrict__ input,
                                      float* __restrict__ output) {
    __shared__ float temp[BLOCK_SIZE];
    int tid = threadIdx.x;

    temp[tid] = input[tid];
    __syncthreads();

    // Up-sweep
    for (unsigned int stride = 1; stride < BLOCK_SIZE; stride <<= 1) {
        unsigned int idx = (tid + 1) * (stride << 1) - 1;
        if (idx < BLOCK_SIZE) {
            temp[idx] += temp[idx - stride];
        }
        __syncthreads();
    }

    // Down-sweep
    if (tid == 0) {
        temp[BLOCK_SIZE - 1] = 0.0f;
    }
    __syncthreads();

    for (unsigned int stride = BLOCK_SIZE >> 1; stride > 0; stride >>= 1) {
        unsigned int idx = (tid + 1) * (stride << 1) - 1;
        if (idx < BLOCK_SIZE) {
            float left_value = temp[idx - stride];
            temp[idx - stride] = temp[idx];
            temp[idx] += left_value;
        }
        __syncthreads();
    }
    __syncthreads();

    output[tid] = temp[tid];
}

// CPU referencia: exclusive scan
void cpu_exclusive_scan(const std::vector<float>& input,
                        std::vector<float>& output) {
    int n = input.size();
    output.resize(n);
    if (n == 0) return;
    output[0] = 0.0f;
    for (int i = 1; i < n; ++i) {
        output[i] = output[i-1] + input[i-1];
    }
}

int main() {
    constexpr int BLOCK_SIZE = 256;   // hatvány kettő
    constexpr int N = BLOCK_SIZE;     // labor: egyetlen blokk

    // Host bemenet
    std::vector<float> h_input(N);
    for (int i = 0; i < N; ++i) {
        h_input[i] = static_cast<float>(i % 7) * 0.25f - 1.0f;
    }

    // Device memória
    float *d_input = nullptr, *d_output = nullptr;
    CUDA_CHECK(cudaMalloc(&d_input, N * sizeof(float)));
    CUDA_CHECK(cudaMalloc(&d_output, N * sizeof(float)));
    CUDA_CHECK(cudaMemcpy(d_input, h_input.data(), N * sizeof(float),
                          cudaMemcpyHostToDevice));

    // Kernel launch: grid=1, block=BLOCK_SIZE, shared=0, stream=0
    blelloch_scan_kernel<BLOCK_SIZE><<<1, BLOCK_SIZE, 0, 0>>>(d_input, d_output);
    CUDA_CHECK(cudaGetLastError());
    CUDA_CHECK(cudaDeviceSynchronize());

    // Kimenet visszamásolása
    std::vector<float> h_output(N);
    CUDA_CHECK(cudaMemcpy(h_output.data(), d_output, N * sizeof(float),
                          cudaMemcpyDeviceToHost));

    // CPU referencia
    std::vector<float> h_reference;
    cpu_exclusive_scan(h_input, h_reference);

    // Ellenőrzés
    float max_error = 0.0f;
    for (int i = 0; i < N; ++i) {
        max_error = std::max(max_error, std::abs(h_output[i] - h_reference[i]));
    }
    printf("Max abszolút hiba: %e\n", max_error);
    assert(max_error < 1e-5f);

    // Takarítás
    CUDA_CHECK(cudaFree(d_input));
    CUDA_CHECK(cudaFree(d_output));

    return 0;
}

A program egyetlen blokkot indít BLOCK_SIZE = 256 szállal, és a bemenet hossza is ennyi. A cudaGetLastError() ellenőrzi a kernel indításának hibáját, a cudaDeviceSynchronize() pedig bevárja a végét. A kimenetet CPU-n ellenőrizzük a referenciával; az eltérés float pontosság mellett kisebb kell legyen, mint 1e-5.

16.2.10 7. Összefoglalás és továbblépés

A scan a párhuzamos algoritmusok egyik leggyakrabban használt építőköve. A Blelloch-scan O(n) munkával és O(log n) mélységgel állítja elő az exclusive scan-t, és a GPU-blokkokon belül a shared memory és a __syncthreads() segítségével hatékonyan implementálható. Az inclusive és exclusive közötti átváltás egyetlen elemenkénti művelet, de a legtöbb downstream algoritmus az exclusive formát igényli.

A következő fejezet (Histogram) a histogramra épít, amely gyakran a scan segítségével valósítja meg a tömörítést vagy a címzést. A jelen fejezetben bemutatott blokk-szintű scan közvetlenül újrafelhasználható ott is.
