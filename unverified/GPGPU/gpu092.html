24.3 Attention kernelek

A scaled dot-product attention a transformer modellek központi építőköve: a bemeneti szekvencia minden tokenjéhez kiszámítja, hogy a többi token mennyire releváns a reprezentációjában. GPU-n a művelet három nagy mátrixszorzásra és egy softmaxra bontható, ezért elsőre egyszerűnek tűnik, de a gyakorlatban a memóriaelérési minta és a softmax numerikus stabilitása határozza meg a teljesítményt. Ebben az alfejezetben a scaled dot-product attention CUDA C++ implementációját építjük fel a naiv kerneltől a tiled, online softmaxot használó változatig, és bemutatjuk a FlashAttention alapelvét.

24.3.1 A scaled dot-product attention matematikai alakja

Adott egy Q∈ℝN×dQ \in \mathbb{R}^{N \times d} query, egy K∈ℝN×dK \in \mathbb{R}^{N \times d} key és egy V∈ℝN×dV \in \mathbb{R}^{N \times d} value mátrix, ahol NN a szekvencia hossza, dd a fej dimenziója. Az attention kimenet:

O=softmax(QKTd)V O = \text{softmax}\left(\frac{QK^T}{\sqrt{d}}\right)V

A softmax soronként normalizál:

pij=esij−mi∑k=1Nesik−mi,sij=(QKT)ijd,mi=maxjsij p_{ij} = \frac{e^{s_{ij} - m_i}}{\sum_{k=1}^{N} e^{s_{ik} - m_i}}, \quad s_{ij} = \frac{(QK^T)_{ij}}{\sqrt{d}}, \quad m_i = \max_j s_{ij}

A mim_i kivonása numerikusan stabilizálja a kitevőt: a legnagyobb logit nulla lesz, így a kitevő értéke nem csordul túl FP32 esetén sem. A 1/d1/\sqrt{d} skálázás a nagy dd esetén fellépő variancia-növekedést kompenzálja.

A kimenet O∈ℝN×dO \in \mathbb{R}^{N \times d}, minden sora a value vektorok súlyozott összege:

Oi=∑j=1NpijVj O_i = \sum_{j=1}^{N} p_{ij} V_j

A művelet számítási komplexitása O(N2d)O(N^2 d), a memóriaigénye a naiv implementációban O(N2)O(N^2), mert a köztes S=QKT/dS = QK^T/\sqrt{d} mátrixot ki kell számítani és eltárolni. A FlashAttention ezt a memóriaigényt csökkenti tiling és online softmax alkalmazásával.

24.3.2 Naiv CUDA implementáció

Az első implementációban minden kimeneti sorhoz egy CUDA thread tartozik. A thread kiszámolja a query sor és az összes key sor skaláris szorzatát, elvégzi a softmaxot, majd a value sorok súlyozott összegét írja az outputba. A kernel a következő:

// attention_naive.cu
#include <cuda_runtime.h>
#include <cstdio>
#include <cstdlib>
#include <cmath>

#define CHECK_CUDA(call) do {                                  \
    cudaError_t err = call;                                    \
    if (err != cudaSuccess) {                                  \
        std::fprintf(stderr, "CUDA error at %s:%d: %s\n",      \
                     __FILE__, __LINE__, cudaGetErrorString(err)); \
        std::exit(1);                                          \
    }                                                          \
} while (0)

__global__ void attention_naive_kernel(const float* __restrict__ Q,
                                       const float* __restrict__ K,
                                       const float* __restrict__ V,
                                       float* __restrict__ O,
                                       int N, int D) {
    int row = blockIdx.x * blockDim.x + threadIdx.x;
    if (row >= N) return;

    const float inv_sqrt_d = 1.0f / sqrtf((float)D);
    float max_s = -INFINITY;
    // Először a maximumot keressük a stabil softmaxhoz.
    for (int j = 0; j < N; ++j) {
        float dot = 0.0f;
        for (int d = 0; d < D; ++d) {
            dot += Q[row * D + d] * K[j * D + d];
        }
        float s = dot * inv_sqrt_d;
        max_s = fmaxf(max_s, s);
    }

    float sum = 0.0f;
    for (int j = 0; j < N; ++j) {
        float dot = 0.0f;
        for (int d = 0; d < D; ++d) {
            dot += Q[row * D + d] * K[j * D + d];
        }
        float s = dot * inv_sqrt_d;
        float p = expf(s - max_s);
        sum += p;
    }

    float* O_row = O + row * D;
    for (int d = 0; d < D; ++d) {
        O_row[d] = 0.0f;
    }

    for (int j = 0; j < N; ++j) {
        float dot = 0.0f;
        for (int d = 0; d < D; ++d) {
            dot += Q[row * D + d] * K[j * D + d];
        }
        float s = dot * inv_sqrt_d;
        float p = expf(s - max_s) / sum;
        for (int d = 0; d < D; ++d) {
            O_row[d] += p * V[j * D + d];
        }
    }
}

int main() {
    int N = 1024;
    int D = 64;
    size_t bytes = N * D * sizeof(float);
    float *h_Q, *h_K, *h_V, *h_O;
    float *d_Q, *d_K, *d_V, *d_O;
    // Host allokáció és inicializálás (véletlen értékekkel).
    h_Q = (float*)malloc(bytes);
    h_K = (float*)malloc(bytes);
    h_V = (float*)malloc(bytes);
    h_O = (float*)malloc(bytes);
    for (int i = 0; i < N * D; ++i) {
        h_Q[i] = (float)(rand()) / RAND_MAX;
        h_K[i] = (float)(rand()) / RAND_MAX;
        h_V[i] = (float)(rand()) / RAND_MAX;
    }

    CHECK_CUDA(cudaMalloc(&d_Q, bytes));
    CHECK_CUDA(cudaMalloc(&d_K, bytes));
    CHECK_CUDA(cudaMalloc(&d_V, bytes));
    CHECK_CUDA(cudaMalloc(&d_O, bytes));
    CHECK_CUDA(cudaMemcpy(d_Q, h_Q, bytes, cudaMemcpyHostToDevice));
    CHECK_CUDA(cudaMemcpy(d_K, h_K, bytes, cudaMemcpyHostToDevice));
    CHECK_CUDA(cudaMemcpy(d_V, h_V, bytes, cudaMemcpyHostToDevice));

    int block = 256;
    int grid = (N + block - 1) / block;
    attention_naive_kernel<<<grid, block>>>(d_Q, d_K, d_V, d_O, N, D);
    CHECK_CUDA(cudaGetLastError());
    CHECK_CUDA(cudaDeviceSynchronize());

    CHECK_CUDA(cudaMemcpy(h_O, d_O, bytes, cudaMemcpyDeviceToHost));
    // Ellenőrzés: az első sor összege 1 körül kell legyen.
    float sum_row0 = 0.0f;
    for (int d = 0; d < D; ++d) sum_row0 += h_O[d];
    std::printf("Naiv kernel: az első sor összege = %.6f\n", sum_row0);
    // Az eredménynek 1.0 körül kell lennie, mert a value vektorok
    // normalizált súlyozott összege, de itt a value nem normalizált.
    // Ezért a softmax súlyok összege 1, de a value elemek összege nem.
    // Helyes ellenőrzés: egy külön kernelben a softmax súlyokat számoljuk.
    // A laborban ezt a CPU referencia implementációval hasonlítjuk össze.

    free(h_Q); free(h_K); free(h_V); free(h_O);
    CHECK_CUDA(cudaFree(d_Q)); CHECK_CUDA(cudaFree(d_K));
    CHECK_CUDA(cudaFree(d_V)); CHECK_CUDA(cudaFree(d_O));
    return 0;
}

A naiv kernel háromszor járja be a KK mátrixot: egyszer a maximumhoz, egyszer az összeghez, egyszer a súlyozott összeghez. A QQ sor minden iterációban a globális memóriából olvasódik, a KK és VV mátrixok pedig N×DN \times D elemenként újra és újra beolvasásra kerülnek. A kernel regiszterhasználata alacsony, de a memóriaforgalom nagy: minden thread O(Nd)O(Nd) lebegőpontos olvasást végez, összesen O(N2d)O(N^2 d) globális memória tranzakciót. A kernel ráadásul a softmax köztes ss értékeit nem tárolja, ezért háromszor számolja ki a QKTQK^T szorzatot. Ez a redundancia a teljesítmény fő korlátja.

24.3.3 Softmax és tiling

A naiv kernel a softmaxot a teljes sorra számítja ki, amihez ismerni kell az összes sijs_{ij} értéket. Ha a KK és VV mátrixokat blokkokra osztjuk, a softmaxot inkrementálisan is kiszámíthatjuk. Az online softmax algoritmus a következő állapotot tartja karban:

  • mm: az eddig látott maximális logit,
  • ℓ\ell: az eddig látott exponenciális összeg,
  • OO: az eddigi súlyozott value összeg.

Amikor egy új sjs_j logit érkezik, a frissítés:

mnew=max(m,sj) m_{\text{new}} = \max(m, s_j) ℓnew=ℓ⋅em−mnew+esj−mnew \ell_{\text{new}} = \ell \cdot e^{m - m_{\text{new}}} + e^{s_j - m_{\text{new}}} Onew=O⋅em−mnew+Vj⋅esj−mnew O_{\text{new}} = O \cdot e^{m - m_{\text{new}}} + V_j \cdot e^{s_j - m_{\text{new}}}

Az algoritmus lényege, hogy a korábbi exponenciális összeget és a korábbi kimenetet átskálázzuk, amikor új maximumot találunk. Így soha nem kell az összes sijs_{ij} értéket egyszerre tárolni, és a kimenet a blokkok feldolgozása közben folyamatosan frissül.

A tiling lényege, hogy a KK és VV mátrixokat BcB_c méretű blokkokra osztjuk, a QQ mátrixot BrB_r méretű blokkokra. Egy CUDA blokk egy QQ-blokkhoz tartozó kimeneti blokkot számol ki, és a K,VK,V-blokkokat shared memoryba tölti be. A kernel pszeudokódja:

for each Q block (B_r x d) in Q:
    load Q block into shared memory
    initialize m, l, acc to 0
    for each K,V block (B_c x d) in K,V:
        load K block and V block into shared memory
        compute S block = Q_block * K_block^T / sqrt(d)
        for each row i in Q block:
            for each column j in K block:
                s = S[i][j]
                m_new = max(m[i], s)
                l_new = l[i] * exp(m[i] - m_new) + exp(s - m_new)
                acc[i] = acc[i] * exp(m[i] - m_new) + V_block[j] * exp(s - m_new)
                m[i] = m_new
                l[i] = l_new
    write O block = acc[i] / l[i]

A tiled kernel a következő CUDA C++ implementációban valósul meg. A kernel egy Br×dB_r \times d méretű QQ-blokkot tölt be a shared memoryba, majd a K,VK,V-blokkokat iterálja. A blokk dimenziója BrB_r, minden thread egy sort dolgoz fel. A DD dimenzió ciklusban van, de a shared memory miatt a K,VK,V elemek gyorsan elérhetők.

// attention_tiled.cu
#include <cuda_runtime.h>
#include <cstdio>
#include <cstdlib>
#include <cmath>

#define CHECK_CUDA(call) do {                                  \
    cudaError_t err = call;                                    \
    if (err != cudaSuccess) {                                  \
        std::fprintf(stderr, "CUDA error at %s:%d: %s\n",      \
                     __FILE__, __LINE__, cudaGetErrorString(err)); \
        std::exit(1);                                          \
    }                                                          \
} while (0)

#define BLOCK_M 128
#define BLOCK_N 64
#define D 64

__global__ void attention_tiled_kernel(const float* __restrict__ Q,
                                       const float* __restrict__ K,
                                       const float* __restrict__ V,
                                       float* __restrict__ O,
                                       int N) {
    extern __shared__ float smem[];
    float* Q_shared = smem;                     // BLOCK_M * D
    float* K_shared = smem + BLOCK_M * D;       // BLOCK_N * D
    float* V_shared = K_shared + BLOCK_N * D;   // BLOCK_N * D

    int row = blockIdx.x * BLOCK_M + threadIdx.x;
    int local_row = threadIdx.x;                // 0 .. BLOCK_M-1
    float inv_sqrt_d = 1.0f / sqrtf((float)D);

    // Q blokk betöltése shared memoryba.
    for (int idx = threadIdx.x; idx < BLOCK_M * D; idx += blockDim.x) {
        int r = idx / D;
        int c = idx % D;
        int global_r = blockIdx.x * BLOCK_M + r;
        Q_shared[idx] = (global_r < N) ? Q[global_r * D + c] : 0.0f;
    }
    __syncthreads();

    // Online softmax állapot regiszterekben.
    float m_i = -INFINITY;
    float l_i = 0.0f;
    float acc[D];
    for (int d = 0; d < D; ++d) acc[d] = 0.0f;

    // K,V blokkok iterálása.
    for (int block_start = 0; block_start < N; block_start += BLOCK_N) {
        // K blokk betöltése.
        for (int idx = threadIdx.x; idx < BLOCK_N * D; idx += blockDim.x) {
            int r = idx / D;
            int c = idx % D;
            int global_r = block_start + r;
            K_shared[idx] = (global_r < N) ? K[global_r * D + c] : 0.0f;
        }
        // V blokk betöltése.
        for (int idx = threadIdx.x; idx < BLOCK_N * D; idx += blockDim.x) {
            int r = idx / D;
            int c = idx % D;
            int global_r = block_start + r;
            V_shared[idx] = (global_r < N) ? V[global_r * D + c] : 0.0f;
        }
        __syncthreads();

        // Skaláris szorzat és online softmax frissítés.
        if (row < N) {
            for (int j = 0; j < BLOCK_N; ++j) {
                int global_j = block_start + j;
                if (global_j >= N) break;
                float dot = 0.0f;
                for (int d = 0; d < D; ++d) {
                    dot += Q_shared[local_row * D + d] * K_shared[j * D + d];
                }
                float s = dot * inv_sqrt_d;

                float m_new = fmaxf(m_i, s);
                float exp_m_old = expf(m_i - m_new);
                float exp_s = expf(s - m_new);
                l_i = l_i * exp_m_old + exp_s;
                for (int d = 0; d < D; ++d) {
                    acc[d] = acc[d] * exp_m_old + V_shared[j * D + d] * exp_s;
                }
                m_i = m_new;
            }
        }
        __syncthreads();
    }

    // Kimenet írása.
    if (row < N) {
        for (int d = 0; d < D; ++d) {
            O[row * D + d] = acc[d] / l_i;
        }
    }
}

int main() {
    int N = 1024;
    size_t bytes = N * D * sizeof(float);
    float *h_Q, *h_K, *h_V, *h_O;
    float *d_Q, *d_K, *d_V, *d_O;
    h_Q = (float*)malloc(bytes);
    h_K = (float*)malloc(bytes);
    h_V = (float*)malloc(bytes);
    h_O = (float*)malloc(bytes);
    for (int i = 0; i < N * D; ++i) {
        h_Q[i] = (float)(rand()) / RAND_MAX;
        h_K[i] = (float)(rand()) / RAND_MAX;
        h_V[i] = (float)(rand()) / RAND_MAX;
    }

    CHECK_CUDA(cudaMalloc(&d_Q, bytes));
    CHECK_CUDA(cudaMalloc(&d_K, bytes));
    CHECK_CUDA(cudaMalloc(&d_V, bytes));
    CHECK_CUDA(cudaMalloc(&d_O, bytes));
    CHECK_CUDA(cudaMemcpy(d_Q, h_Q, bytes, cudaMemcpyHostToDevice));
    CHECK_CUDA(cudaMemcpy(d_K, h_K, bytes, cudaMemcpyHostToDevice));
    CHECK_CUDA(cudaMemcpy(d_V, h_V, bytes, cudaMemcpyHostToDevice));

    int block = BLOCK_M;
    int grid = (N + BLOCK_M - 1) / BLOCK_M;
    size_t shared_bytes = (BLOCK_M + 2 * BLOCK_N) * D * sizeof(float);
    attention_tiled_kernel<<<grid, block, shared_bytes>>>(d_Q, d_K, d_V, d_O, N);
    CHECK_CUDA(cudaGetLastError());
    CHECK_CUDA(cudaDeviceSynchronize());

    CHECK_CUDA(cudaMemcpy(h_O, d_O, bytes, cudaMemcpyDeviceToHost));
    // Ellenőrzés: a kimeneti sorok értékeinek nagyságrendje.
    float max_val = 0.0f;
    for (int i = 0; i < N * D; ++i) max_val = fmaxf(max_val, h_O[i]);
    std::printf("Tiled kernel: maximális kimeneti érték = %.6f\n", max_val);

    free(h_Q); free(h_K); free(h_V); free(h_O);
    CHECK_CUDA(cudaFree(d_Q)); CHECK_CUDA(cudaFree(d_K));
    CHECK_CUDA(cudaFree(d_V)); CHECK_CUDA(cudaFree(d_O));
    return 0;
}

A tiled kernel shared memory igénye (128+2⋅64)⋅64⋅4=65536(128 + 2 \cdot 64) \cdot 64 \cdot 4 = 65536 bájt, ami 64 KiB. Ez belefér az A100 vagy RTX 3090 shared memory kapacitásába, de az occupancyt korlátozza: egy SM-en legfeljebb 1-2 blokk fér el, ha a shared memory limit 100-164 KiB. A kernelben a DD dimenzió ciklusban van, ezért a számítási intenzitás alacsony, de a cél a memóriaforgalom csökkentése.

A naiv kernelhez képest a tiled kernel a KK és VV mátrixokat blokkonként csak egyszer olvassa be a globális memóriából, utána a shared memoryból dolgozik. A QQ blokk is csak egyszer kerül beolvasásra. A softmax online frissítése pedig elkerüli, hogy a teljes SS sort tárolni kelljen. Ez a két tulajdonság a FlashAttention alapelve.

24.3.4 FlashAttention elve

A FlashAttention (Dao et al., 2022) a fenti tiling és online softmax ötletét viszi tovább. A naiv attention implementáció a teljes S=QKT/dS = QK^T/\sqrt{d} mátrixot kiírja a globális memóriába, majd beolvassa a softmaxhoz, és végül a VV-vel való szorzáshoz. Ez O(N2)O(N^2) memóriaforgalmat jelent, ami nagy NN esetén a HBM sávszélességét telíti, és a számítási egységek kihasználatlanok maradnak. A FlashAttention ezt a SS mátrixot soha nem materializálja a globális memóriában; helyette a K,VK,V blokkokat tölti be, az online softmaxot a regiszterekben és a shared memoryban végzi, és a kimenetet folyamatosan frissíti.

A FlashAttention főbb technikai elemei:

  1. Tiling: a Q,K,VQ,K,V mátrixokat olyan blokkokra osztja, amelyek beférnek a shared memoryba. A QQ blokk Br×dB_r \times d, a K,VK,V blokk Bc×dB_c \times d méretű. A kernel egy QQ-blokkhoz tartozó kimeneti blokkot számol ki, és a K,VK,V-blokkokat sorban tölti be.

  2. Online softmax: a softmax normalizáló összeget és a kimeneti accumulatorokat inkrementálisan frissíti a fent bemutatott képletekkel. Így nincs szükség arra, hogy a teljes SS sort egyszerre lássa.

  3. Regiszteres tiling: a QQ blokk egyes sorait a regiszterekben tartja, a K,VK,V blokkokat a shared memoryban. A DD dimenziót is blokkolja, hogy a mátrixszorzás a lehető legtöbb adatot regiszterből érje el.

  4. Pontos hibakezelés: az online softmax miatt a numerikus hiba kicsi marad, mert minden lépésben a maximális logit kivonásra kerül. A FlashAttention FP16/BF16 esetén is stabil, ha a skálázást és a kitevőt megfelelően kezelik.

A FlashAttention gyakorlati előnye, hogy a memóriaforgalom O(N2d)O(N^2 d)-ről O(Nd⋅(Br+Bc))O(N d \cdot (B_r + B_c)) körülire csökken, és a kernel a HBM sávszélesség helyett a számítási egységek kihasználtságát növeli. A CUDA implementációban a shared memory és a regiszterek közötti adatáramlás optimalizálása a fő feladat.

A fenti tiled kernel a FlashAttention egy leegyszerűsített változata: a DD dimenziót nem tili, a QQ blokk sorait a shared memoryban tárolja, és a K,VK,V blokkokat is a shared memoryból olvassa. A valódi FlashAttention a DD dimenziót is blokkolja, és a mátrixszorzást warp-szintű primitívekkel, például a mma utasításokkal gyorsítja. A laborban az egyszerűsített változatot mérjük, hogy az alapelvek érthetők legyenek.

A naiv kernel lassabb, mert a KK és VV mátrixokat háromszor olvassa be, és a softmax köztes értékeket nem tárolja, ezért a QKTQK^T szorzatot háromszor számítja. A tiled kernel a shared memory miatt csökkenti a globális memóriaforgalmat, de az alacsonyabb occupancy miatt a számítási egységek kihasználtsága nem optimális. A valódi FlashAttention további gyorsulást hoz a DD dimenzió tilingjével és a regiszteres adattartással.

24.3.8 Ellenőrzés

Az implementáció helyességét CPU referencia implementációval kell összehasonlítani. A CPU referencia a naiv matematikai definíciót számítja ki FP32-ben, és a kimeneti mátrix elemeit összehasonlítja a GPU eredménnyel. A hiba FP32 esetén 10−410^{-4} alatt kell legyen, mert mindkét implementáció ugyanazt a műveleti sorrendet követi. A laborban a CPU referencia implementációt külön kell megírni, vagy a JAX jax.nn.softmax függvényével ellenőrizni.

JAX ellenőrző példa (csak dokumentáció, nem futtatott):

import jax.numpy as jnp
from jax.nn import softmax

def attention(q, k, v):
    d = q.shape[-1]
    scores = jnp.einsum("qhd,khd->hqk", q, k) / jnp.sqrt(d)
    weights = softmax(scores, axis=-1)
    return jnp.einsum("hqk,khd->qhd", weights, v)

# Helyőrző adatok, nem valós mérés.
q = jnp.ones((1024, 8, 64), dtype=jnp.float32)
k = jnp.ones((1024, 8, 64), dtype=jnp.float32)
v = jnp.ones((1024, 8, 64), dtype=jnp.float32)
out = attention(q, k, v)
print(out.shape)

A JAX példa a TPU-n való futtatásra is alkalmas, de a laborban csak a CPU/GPU ellenőrzéshez használjuk.

24.3.9 Gyakori hibák és megoldások

  1. Softmax túlcsordulás: ha a sijs_{ij} értékek nagyok, a expf túlcsordulhat, és inf értéket ad. A megoldás a maximum kivonása minden sorban. A naiv kernel ezt a max_s kiszámításával, a tiled kernel az online softmax frissítéssel oldja meg.

  2. Skálázás elfelejtése: a 1/d1/\sqrt{d} tényező kihagyása nagy dd esetén a softmax bemenet varianciáját növeli, ami numerikus instabilitáshoz és rossz tanulási dinamikához vezet. A kernelben mindig alkalmazni kell az inv_sqrt_d szorzót.

  3. Race condition az output írásakor: ha több thread írja ugyanazt a kimeneti elemet, atomi művelet vagy redukció szükséges. A naiv kernelben minden thread egy sort ír, ezért nincs ütközés. A tiled kernelben a kimeneti sorokat a blokk threadjei írják, de minden thread egy sort, így szintén nincs ütközés. Ha a DD dimenziót párhuzamosítanánk, akkor atomi add vagy külön redukciós lépés kellene.

  4. Túl nagy shared memory foglalás: ha a BLOCK_M és BLOCK_N értékeket nagyra választjuk, a shared memory igény túl nagy lesz, és az occupancy drasztikusan csökken. A laborban a BLOCK_M=128, BLOCK_N=64 választás 64 KiB shared memóriát igényel, ami RTX 3090-en még elfogadható, de a BLOCK_M=256 már 128 KiB-ot igényelne, ami már korlátozza a párhuzamosságot.

  5. A naiv kernel regiszter spill: ha a naiv kernelben a teljes SS sort lokális tömbben tároljuk, a regiszterekből a lokális memóriába kerül, ami lassú. A tiled kernel ezt elkerüli, mert nem tárolja a teljes sort.

  6. Nem megfelelő blokkméret: a naiv kernel blokkmérete 256, ami jó occupancyt ad. A tiled kernel blokkmérete BLOCK_M=128, ami alacsonyabb, de a shared memory igény miatt elfogadható. A blokkméretet a kernel erőforrás-igényéhez kell igazítani.

24.3.10 Önellenőrző kérdés

Miért kerüli el a FlashAttention a teljes S=QKT/dS = QK^T/\sqrt{d} mátrix globális memóriába írását, és hogyan befolyásolja ez a teljesítményt?

Válasz: A teljes SS mátrix mérete N×NN \times N, ami nagy NN esetén hatalmas memóriaforgalmat jelent. A FlashAttention a K,VK,V blokkokat tölti be, az online softmaxot a regiszterekben és a shared memoryban végzi, és a kimenetet folyamatosan frissíti. Ezáltal a globális memóriaforgalom O(N2)O(N^2)-ről O(Nd)O(N d)-re csökken, és a kernel a számítási egységek kihasználtságát növeli. A teljesítményt a HBM sávszélesség helyett a számítási átbocsátóképesség határozza meg.
