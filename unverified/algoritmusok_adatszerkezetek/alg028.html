8.3 AVL- és piros-fekete fák

A bináris keresőfák (BST) műveleteinek hatékonyságát a fa magassága határozza meg. Ha a beszúrások sorozata rendezett vagy közel rendezett, a BST lánccá degenerálódik, és a keresés, beszúrás, törlés mind lineáris idejűvé válik. A kiegyensúlyozott keresőfák ezt a problémát úgy oldják meg, hogy minden művelet után fenntartanak egy szerkezeti korlátot a fa magasságára, ami garantálja a logaritmikus műveleti időt. Ebben az alfejezetben két klasszikus megoldást vizsgálunk: az AVL-fát és a piros-fekete fát. Mindkettő forgatásokkal és szükség esetén átszínezéssel (piros-fekete fánál) állítja helyre az egyensúlyt, miközben megőrzi a BST tulajdonságot.

8.3.1 Miért van szükség kiegyensúlyozásra?

Egy n csúcsú bináris keresőfa magassága legrosszabb esetben n-1, ha minden belső csúcsnak legfeljebb egy gyermeke van. Ilyenkor a keresés, a minimum/maximum megkeresése, a beszúrás és a törlés mind Θ(n) időt igényel, hiszen gyakorlatilag egy láncon kell végigmenni. A kiegyensúlyozott keresőfák olyan további invariánsokat írnak elő, amelyek a fa magasságát O(log n)-ben tartják. Ezáltal minden alapművelet (keresés, beszúrás, törlés, minimum, maximum, előd, rákövetkező) O(log n) időben fut, függetlenül az input sorrendjétől.

A magasságkorlát biztosításához a fák módosítás után helyi átalakításokat, úgynevezett forgatásokat hajtanak végre. A forgatás egy állandó számú mutató átkötését jelenti, tehát O(1) időben elvégezhető, és megőrzi a BST inorder sorrendjét.

8.3.2 AVL-fák

Az AVL-fa (Adelson-Velszkij és Landisz nevéből) a legrégebbi kiegyensúlyozott keresőfa. Minden csúcshoz egy egyensúlyi tényezőt rendelünk, amely a bal és jobb részfa magasságának különbsége:

balance(v) = height(left(v)) - height(right(v))

Egy csúcs AVL-tulajdonságú, ha balance(v) ∈ {-1, 0, 1}. A fa AVL-fa, ha minden csúcsa AVL-tulajdonságú. Ez a feltétel garantálja, hogy a fa magassága legfeljebb 1,44 log_2 (n+1) (pontosabban legfeljebb log_φ(n+1), ahol φ az aranymetszés aránya). A bizonyítás a Fibonacci-számokkal analóg minimális csúcsszámú AVL-fák vizsgálatán alapul: legyen N_h a minimális csúcsszám egy h magasságú AVL-fában. Ekkor N_h = N_{h-1} + N_{h-2} + 1, és N_0 = 1, N_1 = 2. Ez a rekurzió exponenciálisan nő, ezért a magasság logaritmikus a csúcsszámhoz képest.

8.3.3 Forgatások

A forgatás egy lokális átalakítás, amely a fa BST-tulajdonságát megtartja, de megváltoztatja a részfák magasságát. Két alapforgatás van: jobb forgatás (right rotation) és bal forgatás (left rotation). Ezek egymás inverzei.

Legyen x egy csúcs, y pedig x bal gyermeke (jobb forgatás esetén). A jobb forgatás során y-t tesszük meg az x helyére, x lesz y jobb gyermeke, és y jobb oldali részfája x bal oldali részfája lesz. A bal forgatás ennek tükörképe. Pszeudokódban (a mutatókat left és right mezők jelölik, parent opcionális):

function right_rotate(x):
    // Előfeltétel: x létezik, és x.left != NIL.
    y = x.left
    x.left = y.right
    if y.right != NIL:
        y.right.parent = x
    y.parent = x.parent
    if x.parent == NIL:
        root = y
    else if x == x.parent.left:
        x.parent.left = y
    else:
        x.parent.right = y
    y.right = x
    x.parent = y
    // Frissítjük a magasságokat, ha tároljuk.
    update_height(x)
    update_height(y)
    // Kimenet: y az új gyökere a részfának.

A bal forgatás szimmetrikus:

function left_rotate(x):
    // Előfeltétel: x létezik, és x.right != NIL.
    y = x.right
    x.right = y.left
    if y.left != NIL:
        y.left.parent = x
    y.parent = x.parent
    if x.parent == NIL:
        root = y
    else if x == x.parent.left:
        x.parent.left = y
    else:
        x.parent.right = y
    y.left = x
    x.parent = y
    update_height(x)
    update_height(y)

A forgatások O(1) időt és O(1) memóriát igényelnek, feltéve, hogy a magasságokat minden csúcsnál tároljuk.

8.3.4 Beszúrás AVL-fába

A beszúrás két fázisból áll: először a szokásos BST-beszúrást hajtjuk végre, majd a bejárt úton visszafelé haladva ellenőrizzük és szükség esetén forgatásokkal állítjuk helyre az AVL-tulajdonságot. A pszeudokód:

function avl_insert(root, key, value):
    // Bemenet: root az AVL-fa gyökere, key a kulcs, value az érték.
    // Előfeltétel: a fa érvényes AVL-fa.
    // Kimenet: az új gyökér, az AVL-tulajdonság helyreállítva.
    // 1. Normál BST-beszúrás.
    new_node = BST_insert(root, key, value)   // O(log n)
    // 2. Visszafelé haladás a gyökérig.
    node = new_node.parent
    while node != NIL:
        update_height(node)
        balance = height(node.left) - height(node.right)
        // Bal oldal túl magas.
        if balance > 1:
            if key < node.left.key:        // jobbra forgatás
                node = right_rotate(node)
            else:                          // bal-jobb forgatás
                node.left = left_rotate(node.left)
                node = right_rotate(node)
        // Jobb oldal túl magas.
        else if balance < -1:
            if key > node.right.key:       // balra forgatás
                node = left_rotate(node)
            else:                          // jobb-bal forgatás
                node.right = right_rotate(node.right)
                node = left_rotate(node)
        node = node.parent
    return root

A beszúrás során legfeljebb egy (egyszeres vagy dupla) forgatás szükséges az egyensúly helyreállításához, mert a beszúrás egyetlen csúcsot ad hozzá, és a magasságkülönbség csak azon az úton romolhat el, ahol a csúcs beillesztésre került. A forgatás után a részfa magassága visszaáll a beszúrás előtti értékre, így a felette lévő csúcsok egyensúlya már nem sérül.

Komplexitás: A BST-beszúrás O(log n) idő, a visszafelé haladás O(log n) csúcsot érint, minden csúcsnál O(1) művelet, a forgatások O(1) idő. A teljes beszúrás tehát O(log n) idő és O(1) extra memória (a rekurziós verem vagy explicit stack O(log n)-ig terjedhet, de ha iteratív módon tároljuk az utat, az O(log n) memória).

Törlés: A törlés hasonló, de bonyolultabb. A BST-ből való törlés után (amely lehet levél törlése, egyetlen gyermekkel rendelkező csúcs törlése, vagy két gyermek esetén a rákövetkezővel való csere) a visszafelé haladás során az egyensúlyi tényezők ellenőrzése és a forgatások addig folytatódnak, amíg a gyökérig nem érünk. A törlésnél előfordulhat, hogy többszörös forgatásra van szükség, mert a részfa magassága csökkenhet, és ez felfelé terjedő egyensúlyromlást okozhat. A törlés időigénye is O(log n).

8.3.5 Példa AVL-beszúrásra

Beszúrjuk a következő kulcsokat üres fába: 10, 20, 30, 15, 25.

  1. 10 beszúrása: a fa gyökere 10, egyensúly 0.
  2. 20 beszúrása: 10 jobb gyermeke 20. 10 egyensúlya -1, 20 egyensúlya 0. OK.
  3. 30 beszúrása: 20 jobb gyermeke 30. Most 20 egyensúlya -1, 10 egyensúlya -2 (jobb részfa magasabb). A 10 jobb gyermeke (20) jobb gyermeke (30) a magasabb, ezért bal forgatást hajtunk végre 10-en. Eredmény: 20 a gyökér, bal gyermeke 10, jobb gyermeke 30. Minden egyensúly 0.
  4. 15 beszúrása: 20 bal gyermeke 10, 10 jobb gyermeke 15. 10 egyensúlya -1, 20 egyensúlya 1, 15 egyensúlya 0. OK.
  5. 25 beszúrása: 30 bal gyermeke 25. 30 egyensúlya 1, 20 egyensúlya 0. OK.

A fa magassága 2, és tökéletesen kiegyensúlyozott.

8.3.6 Tipikus hibák AVL-fáknál

  • Elfelejtett magasságfrissítés: ha a forgatás után nem frissítjük a magasságokat, a későbbi egyensúlyi tényezők rosszak lesznek. A magasságot mindig alulról felfelé kell frissíteni, miután a gyermekek magassága már végleges.
  • Rossz forgatási irány: az egyensúlyi tényező előjele és a gyermek egyensúlyi tényezője együttesen határozza meg a szükséges forgatást. Például ha balance(node) > 1 és balance(node.left) < 0, akkor dupla forgatás kell (először balra a bal gyermeken, majd jobbra a csúcson).
  • A szülő mutatók nem megfelelő átállítása: ha a forgatás során nem frissítjük a szülőkre mutató pointereket, a fa invariánsa sérül, és későbbi műveletek hibát okoznak.
  • Nem ellenőrzik a forgatás utáni hatást a felette lévő csúcsokra: beszúrásnál elég egy forgatás, de törlésnél a magasságcsökkenés továbbterjedhet, ezért a visszafelé haladást a gyökérig folytatni kell.

8.3.7 Piros-fekete fák

A piros-fekete fa (Red-Black Tree) egy másik kiegyensúlyozott keresőfa, amely minden csúcshoz egy színt (piros vagy fekete) rendel. A fa az alábbi öt piros-fekete tulajdonságot teljesíti:

  1. Minden csúcs színe piros vagy fekete.
  2. A gyökér fekete.
  3. Minden levél (NIL) fekete. (A leveleket gyakran üres, színezett NIL-csúcsokként ábrázoljuk; ezek nem tárolnak adatot.)
  4. Ha egy csúcs piros, akkor mindkét gyermeke fekete. (Nincs két piros szomszédos csúcs az úton.)
  5. Minden csúcsból a leszármazott levelekig vezető összes úton ugyanannyi fekete csúcs található. (A csúcsot nem számítva; a fekete magasság definíciója.)

Az 5. tulajdonság miatt a fa lényegében kiegyensúlyozott: egy csúcs fekete magassága (black-height) a belőle a levélig vezető utakon lévő fekete csúcsok száma. A fa minden levelére ugyanaz a fekete magasság; jelölje ezt bh(root). A 4. tulajdonság miatt a leghosszabb gyökér-levél út legfeljebb kétszer olyan hosszú, mint a legrövidebb, mert piros csúcs csak fekete után következhet. Ebből következik, hogy a fa magassága legfeljebb 2 * bh(root), és mivel egy bh fekete magasságú részfának legalább 2^{bh} - 1 belső csúcsa van, a teljes fa magassága O(log n). Pontosabban a magasság legfeljebb 2 log_2 (n+1).

8.3.8 Műveletek piros-fekete fán

A keresés ugyanaz, mint a BST-ben, O(log n) időben. A beszúrás és törlés viszont a színezési szabályok megsértését okozhatja, ezért forgatások és átszínezések szükségesek.

8.3.8.1 Beszúrás piros-fekete fába

A beszúrás alapelve: az új csúcsot pirosra színezzük, majd a szabályok helyreállítására egy ciklust futtatunk felfelé a fán. A piros szín választása azért előnyös, mert az 5. tulajdonság (fekete magasság) nem sérül, csak a 4. tulajdonság sérülhet, ha a szülő is piros. A javítás során három fő esetet különböztetünk meg attól függően, hogy a nagybácsi (a szülő testvére) milyen színű.

Pszeudokód a beszúráshoz (a parent, left, right, color mezők használatával; a NIL fekete színű):

function rb_insert(root, key, value):
    // Bemenet: root az RB-fa gyökere, key a kulcs, value az érték.
    // Előfeltétel: a fa érvényes piros-fekete fa.
    // Kimenet: az új gyökér, az RB-tulajdonságok helyreállítva.
    z = new_node(key, value)
    BST_insert(root, z)   // z-t piros színnel szúrjuk be
    z.color = RED
    while z != root and z.parent.color == RED:
        if z.parent == z.parent.parent.left:
            y = z.parent.parent.right   // nagybácsi
            if y.color == RED:
                // 1. eset: a nagybácsi is piros.
                z.parent.color = BLACK
                y.color = BLACK
                z.parent.parent.color = RED
                z = z.parent.parent
            else:
                if z == z.parent.right:
                    // 2. eset: z jobb gyermek -> bal forgatás a szülőn.
                    z = z.parent
                    left_rotate(z)
                // 3. eset: a szülő piros, a nagybácsi fekete, z bal gyermek.
                z.parent.color = BLACK
                z.parent.parent.color = RED
                right_rotate(z.parent.parent)
        else:
            // Szimmetrikus eset: a szülő jobb gyermek.
            y = z.parent.parent.left   // nagybácsi
            if y.color == RED:
                z.parent.color = BLACK
                y.color = BLACK
                z.parent.parent.color = RED
                z = z.parent.parent
            else:
                if z == z.parent.left:
                    z = z.parent
                    right_rotate(z)
                z.parent.color = BLACK
                z.parent.parent.color = RED
                left_rotate(z.parent.parent)
    root.color = BLACK
    return root

A ciklus leállási feltétele: z.parent nem piros, vagy z a gyökér. Minden iterációban z legfeljebb két szinttel feljebb kerül, ezért a ciklus O(log n)-szer fut le. Minden lépés O(1) idő, tehát a beszúrás O(log n) időt és O(1) extra memóriát igényel (ha iteratív módon tároljuk az utat, akkor O(log n) memória a bejárt útvonalhoz).

A beszúrás során a forgatások száma korlátos: az 1. eset csak átszínez, a 2. és 3. eset egy-egy forgatást tartalmaz, és utána a ciklus megszakad, mert a szülő fekete lesz. Így beszúrásonként legfeljebb két forgatás történik.

8.3.8.2 Törlés piros-fekete fából

A törlés bonyolultabb. A BST-ből való törlés után, ha a törölt csúcs fekete volt, az 5. tulajdonság sérül (a fekete magasság csökken az adott úton). Ilyenkor egy „dupla fekete” fogalmat vezetünk be, és egy sor átszínezéssel és forgatással helyreállítjuk az egyensúlyt. A részletes esettanulmányt itt nem ismertetjük teljes mélységben, de a fő elv: a dupla fekete csúcsot addig toljuk felfelé vagy átalakítjuk, amíg a szabályok helyre nem állnak. A törlés időigénye O(log n), legfeljebb O(log n) forgatással.

8.3.9 Összehasonlítás AVL és piros-fekete fák között

  • Egyensúly szorossága: Az AVL-fa szigorúbban kiegyensúlyozott, ezért a magassága általában kisebb, és a keresés gyorsabb. A piros-fekete fa lazább egyensúlyt tart, ezért a magassága akár kétszerese is lehet a minimálisnak, de a konstans szorzó alacsony.
  • Beszúrás/törlés költsége: A piros-fekete fán a beszúrás és törlés gyakran kevesebb forgatást igényel (beszúrásnál max. 2, törlésnél max. 3 forgatás a gyakorlatban), míg az AVL-fán a törlés több forgatást okozhat. Ezért írásintenzív alkalmazásokban a piros-fekete fa előnyösebb.
  • Implementációs bonyolultság: Az AVL-fa egyszerűbb, mert csak magasságokat kell tárolni és egy egyensúlyi tényezőt ellenőrizni. A piros-fekete fa több esetet és színezési szabályt tartalmaz, ezért bonyolultabb.
  • Gyakorlati használat: A legtöbb standard könyvtár (pl. C++ std::map, Java TreeMap) piros-fekete fát használ, mert a beszúrás/törlés átlagos költsége kedvező, és garantált O(log n) műveleteket ad.

8.3.10 Közös invariánsok és bizonyítási vázlat

Mindkét fa esetében a következő invariánsoknak kell teljesülniük minden művelet után:

  • BST-tulajdonság: minden csúcsra a bal részfa kulcsai kisebbek, a jobb részfa kulcsai nagyobbak, mint a csúcs kulcsa.
  • Kiegyensúlyozási tulajdonság: AVL-nél az egyensúlyi tényező abszolút értéke ≤ 1; piros-feketénél az öt színre és fekete magasságra vonatkozó szabály.
  • Magassági korlát: a fa magassága O(log n).

A forgatások megőrzik a BST-tulajdonságot, mert az inorder bejárás sorrendje változatlan. A magasságkorlátot a fent vázolt érvekkel lehet bizonyítani. A beszúrás és törlés során a bejárt úton végrehajtott helyi javítások visszaállítják a kiegyensúlyozási tulajdonságot, és mivel a javítások csak O(log n) csúcsot érintenek, a műveletek logaritmikusak.

8.3.11 Gyakorlati példa: kis ellenőrzött beszúrások piros-fekete fába

Beszúrjuk a 10, 20, 30 kulcsokat üres piros-fekete fába.

  1. 10 beszúrása: a gyökér piros, de a 2. szabály miatt feketére színezzük. A fa: fekete 10.
  2. 20 beszúrása: 20-at pirosra színezve a 10 jobb gyermekeként szúrjuk be. A szülő fekete, tehát nincs szabálysértés. A fa: fekete 10, piros 20.
  3. 30 beszúrása: 30-at pirosra színezve a 20 jobb gyermekeként szúrjuk be. Most a 30 szülője (20) piros, és a nagybátyja (10 bal gyermeke? valójában a 20 szülője 10, a 10 bal gyermeke NIL, ami fekete) fekete. A 30 jobb gyermeke a szülőjének, tehát a 2. eset: először bal forgatás a szülőn (20), így 30 lesz a gyökér, bal gyermeke 20, jobb gyermeke NIL. Ezután a 3. eset szerint a szülőt (most 20) feketére, a nagyszülőt (30) pirosra színezzük, és jobbra forgatunk a nagyszülőn (30). A végeredmény: 20 fekete, bal gyermeke 10 piros, jobb gyermeke 30 piros. A gyökér fekete, minden szabály teljesül.

Ez a kis példa jól mutatja az esetek működését.

8.3.12 Tipikus hibák piros-fekete fáknál

  • A gyökér piros marad: a beszúrás végén a gyökeret mindig feketére kell állítani, különben a 2. szabály sérül.
  • A NIL csúcsok színének elfelejtése: a NIL-eket feketeként kell kezelni, mert az 5. szabály a NIL-ekig vezető úton számolja a fekete csúcsokat.
  • Az esetek helytelen felismerése: ha a nagybácsi piros, csak átszínezés kell; ha fekete, akkor forgatás is. A szimmetrikus esetek (jobb/bal) tükrözése gyakran hibát okoz.
  • Nem frissítik a mutatókat a forgatás után: hasonlóan az AVL-hez, a szülő- és gyermekpointerek inkonzisztenciája súlyos hibákhoz vezet.

8.3.13 Laborfeladat: AVL-forgatások és piros-fekete szabályok követése

A labor célja, hogy a hallgató implementáljon egy AVL-fát és egy piros-fekete fát, tesztelje azokat, és mérje a műveletek tényleges viselkedését. Az átadandó egy reprodukálható kódprojekt vagy jegyzetfüzet, amely tartalmazza a következőket:

  1. Implementáció: AVL-fa és piros-fekete fa osztályok (vagy függvénykönyvtár) a következő műveletekkel: insert(key, value), delete(key), search(key), minimum(), maximum(), successor(key), predecessor(key), és a fa ellenőrzése (invariánsok validálása).
  2. Tesztcsomag: Rögzített inputokkal (pl. [10, 20, 30, 15, 25], [5, 3, 8, 1, 4, 7, 9, 2, 6], valamint véletlen sorozatok) ellenőrizze a szerkezeti invariánsokat minden beszúrás és törlés után. Az invariáns-ellenőrző függvénynek ellenőriznie kell a BST-tulajdonságot, az AVL egyensúlyi tényezőket, illetve a piros-fekete öt szabályt.
  3. Mérési napló: Mérje meg a beszúrás és keresés idejét különböző méretű inputokra (pl. 10^3, 10^4, 10^5, 10^6 véletlen kulcs). Ismételje a méréseket legalább 5-ször, és számoljon átlagot és szórást. Hasonlítsa össze az AVL-fa és a piros-fekete fa teljesítményét, valamint egy egyszerű (kiegyensúlyozatlan) BST-vel.
  4. Napló és értékelés: Dokumentálja a tapasztalatokat, külön kiemelve a tipikus hibákat, amelyekbe belefutott, és azok javítását.

A mérési körülményeket rögzíteni kell: nyelv, fordító, optimalizációs szint, hardver (CPU, memória), operációs rendszer. Az eredményeket táblázatban vagy diagramon kell bemutatni.

Példa ellenőrző kérdések:

  • Hogyan bizonyítanád, hogy egy AVL-fa magassága O(log n)?
  • Mi a különbség az AVL-fa és a piros-fekete fa közötti egyensúlyi feltételben?
  • Miért fontos a piros-fekete fánál a gyökér fekete színe?
  • Milyen esetekben van szükség dupla forgatásra AVL-fánál?
  • Hogyan lehet ellenőrizni, hogy egy piros-fekete fa valóban teljesíti-e az öt szabályt?

A labor elvégzése után a hallgató képes lesz önállóan megvalósítani és diagnosztizálni a kiegyensúlyozott keresőfákat, ami a következő alfejezet (B-fák, B+-fák) alapjául szolgál.
