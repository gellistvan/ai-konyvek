10.2 Szomszédsági mátrix, lista és él lista

Ugyanazt a gráfot többféleképpen is el lehet helyezni a memóriában. Ez az alfejezet a három legismertebb alapreprezentációt, a szomszédsági mátrixot, a szomszédsági listát és az él listát járja körül. A választás nem pusztán ízlés kérdése: ugyanaz az algoritmus nagyságrendileg eltérő sebességgel és memóriaigénnyel futhat attól függően, hogyan tároljuk az éleket. A következő alfejezetben tárgyalt BFS és DFS is szorosan kötődik ehhez a döntéshez, ezért az itteni fogalmakat annak megértéséhez is alkalmazni kell.

A fejezet célja, hogy

  • megmagyarázza a gráfok tárolási módjait és azok költségeit,
  • segítsen egy kis, ellenőrizhető példán alkalmazni a három reprezentációt,
  • felismerje a tipikus hibákat, és meg tudja indokolni a helyes megoldást.

Az absztrakt gráfot G=(V,E)G=(V,E) jelöli, ahol VV a csúcsok, EE az élek halmaza. Legyen n=|V|n=|V| a csúcsok száma, m=|E|m=|E| az élek száma. Irányítatlan gráfban az él rendezetlen pár, irányítottban rendezett pár. Súlyozott gráfban minden élhez egy ww súly tartozik. A reprezentációnak általában a következő kérdésekre kell gyors választ adnia:

  • Létezik-e él két adott csúcs között?
  • Melyek egy adott csúcs szomszédai?
  • Mi egy adott él súlya?
  • Hogyan lehet egy élt beszúrni vagy törölni?
  • Mekkora memóriát foglal az adatstruktúra?

A három alapforma éppen ezekben a kérdésekben talál eltérő kompromisszumot.

10.2.1 1. Szomszédsági mátrix

A szomszédsági mátrix egy n×nn \times n-es táblázat. Az A[u][v]A[u][v] cella 11-et tárol, ha létezik él uu-ból vv-be, egyébként 00-t. Súlyozott gráfnál a cella az él súlyát tartalmazza, és a hiányzó élt valamilyen ∞\infty vagy egy külön érvénytelen érték jelöli. Irányítatlan gráfnál a mátrix szimmetrikus: A[u][v]=A[v][u]A[u][v]=A[v][u] minden csúcsra.

A felépítés pszeudokódja 1-től indexelt tömbökkel:

// Pszeudokód: az A mátrix sorait és oszlopait 1-től indexeljük.
SzomszédságiMátrix(n, E):
  A[1..n][1..n] <- 0
  ciklus minden (u, v, w) élre E-ben:
    A[u][v] <- w          // súlyozatlan esetben w = 1
    ha a gráf irányítatlan:
      A[v][u] <- w
  vissza A

Pythonban a nyelv konvenciója szerint 0-tól indexelünk:

# Python 3; a listák 0-tól indexeltek.
class AdjacencyMatrix:
    def __init__(self, n: int):
        self.n = n
        # Kezdetben nincs él. Súlyozatlan esetben 0 a hiányzó érték.
        self.a = [[0] * n for _ in range(n)]

    def add_edge(self, u: int, v: int, w: int = 1, undirected: bool = True):
        self.a[u][v] = w
        if undirected:
            self.a[v][u] = w

    def has_edge(self, u: int, v: int) -> bool:
        return self.a[u][v] != 0

    def neighbors(self, u: int):
        for v in range(self.n):
            if self.a[u][v] != 0:
                yield v

A mátrix előnye az él teszt Θ(1)\Theta(1) ideje: az has_edge közvetlenül olvassa a cellát. Az él beszúrása és törlése is Θ(1)\Theta(1). A szomszédok felsorolása azonban minden esetben Θ(n)\Theta(n), mert a teljes sort végig kell vizsgálni, akkor is, ha a csúcsnak kevés szomszédja van.

Memóriaigénye Θ(n2)\Theta(n^2). Ez teljes gráf esetén, ahol m=Θ(n2)m=\Theta(n^2), arányos az élek számával, így elfogadható. Ritka gráf esetén viszont a mátrix legnagyobb része üres, a tárolás pedig akkor is Θ(n2)\Theta(n^2) cellát foglal. A súlyozott mátrixnál még nagyobb a konstans: minden cella nem bit, hanem egész vagy lebegőpontos érték.

Irányítatlan gráfnál a mátrix feleslegesen tárolja mindkét irányt. A memória csökkenthető, ha csak a felső háromszöget tároljuk, de ez bonyolítja az indexelést, és a gyakorlatban ritkán éri meg.

Súlyozott gráfnál a 00 érték félrevezető lehet, mert egy él súlya lehet 00. Ezért helyesebb egy külön INF vagy None értéket használni a hiányzó élekre. Például:

# Python; hiányzó él jelölése None, így a 0 súly is érvényes lehet.
INF = float("inf")
class WeightedAdjacencyMatrix:
    def __init__(self, n: int):
        self.n = n
        self.a = [[INF] * n for _ in range(n)]

10.2.2 2. Szomszédsági lista

A szomszédsági lista minden csúcshoz egy külön listát rendel. A vv csúcs listája azokat a csúcsokat tartalmazza, amelyekbe vv-ből él vezet. Súlyozott gráfnál a lista elemei (cél, súly) párok. Irányítatlan gráfban minden élt kétszer tárolunk: egyszer uu-nál vv-t, egyszer vv-nél uu-t. Így a tárolt listaelemek száma irányítatlan esetben 2m2m, irányítottban mm.

A felépítés Pythonban:

# Python 3; 0-tól indexelt listák.
class AdjacencyList:
    def __init__(self, n: int):
        self.n = n
        self.adj = [[] for _ in range(n)]

    def add_edge(self, u: int, v: int, w: int = 1, undirected: bool = True):
        self.adj[u].append((v, w))
        if undirected:
            self.adj[v].append((u, w))

    def neighbors(self, u: int):
        return self.adj[u]

A lista memóriaigénye Θ(n+m)\Theta(n+m). Ritka gráfnál, ahol m=O(n)m=O(n), ez lineáris méretű, szemben a mátrix Θ(n2)\Theta(n^2) igényével. Sűrű gráfban m=Θ(n2)m=\Theta(n^2), így a lista is Θ(n2)\Theta(n^2) elemet tárol, ilyenkor a mátrix versenyképesebb lehet.

A műveleti költségek attól függnek, hogyan van megvalósítva a belső lista, és hogy rendezett-e.

  • Szomszédok iterálása: Θ(deg(v))\Theta(\deg(v)), ahol deg(v)\deg(v) a vv csúcs kifoka. Ez lényegesen jobb a mátrix Θ(n)\Theta(n) költségénél, ha a csúcs foka kicsi.
  • Él teszt: rendezetlen listán Θ(deg(v))\Theta(\deg(v)), mert a szomszédok között lineárisan kell keresni. Rendezett listán bináris kereséssel Θ(logdeg(v))\Theta(\log \deg(v)) is lehet, de ekkor a beszúrás drágul, mert a rendezettséget fenn kell tartani.
  • Él beszúrása: láncolt listánál Θ(1)\Theta(1), ha az adott csúcs listájának elejére szúrunk be. Dinamikus tömbnél, például Python listánál az append amortizáltan Θ(1)\Theta(1). Ha a listát rendezetten akarjuk tartani, a beszúrás Θ(deg(v))\Theta(\deg(v)).
  • Él törlése: rendezetlen listán meg kell keresni az élt, így Θ(deg(v))\Theta(\deg(v)). Irányítatlan gráfnál mindkét irányt törölni kell.

Párhuzamos élek, azaz multi-gráf estén a lista természetesen kezeli a többszörös éleket: ugyanaz a szomszéd többször is szerepelhet. A mátrixnál ehhez vagy számlálót kellene tárolni minden cellában, vagy elveszik a multiplicitás.

A szomszédsági lista sorrendje befolyásolhatja a későbbi algoritmusok kimenetét. Például a BFS sorrendje függ attól, milyen sorrendben járja be a szomszédokat. A determinisztikus működéshez érdemes a listát rendezni, vagy a beolvasási sorrendet rögzíteni.

10.2.3 3. Él lista

Az él lista a gráfot az élek sorozataként tárolja. Minden él egy (u, v) vagy (u, v, w) rekord. Nincs külön mutató a csúcsok szomszédaira. A memóriaigény irányítatlan esetben Θ(m)\Theta(m), irányítottban szintén Θ(m)\Theta(m), mert minden élt pontosan egyszer tárolunk.

# Python 3; az élek 0-tól indexelt csúcsokat tartalmaznak.
class EdgeList:
    def __init__(self):
        self.edges = []

    def add_edge(self, u: int, v: int, w: int = 1):
        self.edges.append((u, v, w))

A műveleti költségek:

  • Összes él felsorolása: Θ(m)\Theta(m), gyakran ez a leghatékonyabb forma.
  • Él beszúrása: Θ(1)\Theta(1) amortizáltan, ha a lista végére írunk.
  • Él törlése: Θ(m)\Theta(m), mert meg kell keresni a törlendő élt.
  • Szomszédok lekérdezése: Θ(m)\Theta(m), mert az összes élt át kell nézni, hogy kiszűrjük az adott csúcsra illeszkedőket.
  • Él teszt: Θ(m)\Theta(m).

Az él lista olyan algoritmusoknál előnyös, amelyek az éleket egyszer, globálisan dolgozzák fel. Ilyen például a Bellman–Ford algoritmus, amely minden iterációban az összes élt újra bejárja, vagy a Kruskal-féle minimális feszítőfa-algoritmus, amely az éleket súly szerint rendezve vizsgálja. Ilyenkor a lista természetes, mert nincs szükség gyakori szomszédság-lekérdezésre.

Gyakori megoldás az él lista és egy külön szomszédsági index kombinálása. Az él listát megtartjuk az élalapú feldolgozáshoz, de emellett minden csúcshoz tároljuk a hozzá tartozó élek azonosítóit vagy mutatóit. Ez a hibrid forma Θ(n+m)\Theta(n+m) memóriát foglal, és mindkét műveletcsoportot gyorsítja.

10.2.4 4. Sűrű és ritka gráfok

A reprezentáció kiválasztásánál a legfontosabb szempont a gráf sűrűsége.

  • Ritka gráf: m=O(n)m = O(n). Ilyen például egy fa, egy út, egy síkbarajzolható gráf vagy egy olyan hálózat, ahol minden csúcs foka kicsi. A szomszédsági lista itt egyértelműen előnyös: a memória lineáris, a szomszédok bejárása pedig a fokszámmal arányos.
  • Sűrű gráf: m=Θ(n2)m = \Theta(n^2). Ilyen a teljes gráf vagy egy olyan gráf, ahol a csúcsok nagy része össze van kötve. A mátrix itt nem pazarol, mert a cellák nagy része értékes. Ráadásul az él teszt Θ(1)\Theta(1) ideje kihasználható.
  • Közepes sűrűség: m=Θ(nlogn)m = \Theta(n \log n) vagy m=Θ(n1,5)m = \Theta(n^{1{,}5}) esetén általában a szomszédsági lista a jobb választás, de ha az algoritmus nagyon gyakran kérdez él létezését, érdemes lehet mátrixot vagy hibrid struktúrát használni.

Nincs merev szabály, de hasznos hüvelykujj: ha az algoritmus főként szomszédokat jár be, akkor listát; ha főként éleket tesztel, akkor mátrixot; ha pedig főként az élek mint sorozat felett iterál, akkor él listát válasszunk. A következő táblázat összefoglalja a tipikus költségeket.

10.2.6 6. Reprezentációk közötti átjárás

A három forma egymásba alakítható, de az átalakítás költsége eltérő.

  • Él lista → szomszédsági lista: létrehozzuk az nn üres listát, majd minden élt feldolgozunk. Irányítatlan gráfnál mindkét végpont listájához hozzáadjuk a másikat. Idő: Θ(n+m)\Theta(n+m), memória: Θ(n+m)\Theta(n+m).
  • Szomszédsági lista → él lista: bejárjuk minden csúcs szomszédait. Ha a gráf irányítatlan, minden élt kétszer látunk, ezért vagy elfogadjuk a duplikátumot, vagy szűrjük. Idő: Θ(n+m)\Theta(n+m).
  • Mátrix → szomszédsági lista: a mátrix minden celláját meg kell vizsgálni, így az idő Θ(n2)\Theta(n^2), akkor is, ha ritka a gráf.
  • Szomszédsági lista → mátrix: először fel kell tölteni a mátrixot nullákkal, ez Θ(n2)\Theta(n^2), majd minden élt be kell írni. Az idő Θ(n2+m)\Theta(n^2 + m), tehát sűrű gráfban Θ(n2)\Theta(n^2), ritkában is Θ(n2)\Theta(n^2) a mátrix miatt.

Az átjárásnál ügyelni kell arra, hogy az indexelés konzisztens maradjon. Ha a gráf csúcsait 11-től indexeljük a matematikai modellben, de a kód 00-tól indexeli a tömböket, akkor az átjárásnál explicit konverziót kell végezni.

10.2.7 7. Korrektségi szerződés és invariáns

A reprezentációkat létrehozó eljárásokra is fel lehet írni a korrektségi szerződést. Tekintsük az él listából szomszédsági listát építő eljárást.

  • Bemenet: n∈ℤ≥0n\in\mathbb{Z}_{\ge 0}; EE élek listája, ahol minden él (u,v,w)(u,v,w) alakú, 1≤u,v≤n1\le u,v\le n.
  • Kimenet: adj szomszédsági lista, ahol adj[u] az uu-ból kiinduló élek (v,w) párjait tartalmazza.
  • Előfeltétel: a csúcsazonosítók érvényesek; irányítatlan gráf esetén az élek rendezetlen párokat jelentenek.
  • Utófeltétel: minden (u,v,w)∈E(u,v,w)\in E esetén (v,w) szerepel adj[u]-ban, irányítatlan gráfban pedig (u,w) is szerepel adj[v]-ben.
  • Leállási feltétel: az élek száma véges, a ciklus minden él után csökkenti a hátralévő élek számát, ezért az eljárás biztosan leáll.

A felépítés ciklusinvariánsa: a kk-adik él feldolgozása után a szomszédsági lista pontosan az első kk él által meghatározott éleket tartalmazza. Kezdetben k=0k=0, a lista üres, így az invariáns teljesül. Egy él feldolgozása során hozzáadjuk az új szomszédsági elemeket, tehát az invariáns megmarad. A ciklus végén k=mk=m, így az utófeltétel is teljesül.

Ugyanez a gondolatmenet a mátrix és az él lista felépítésénél is alkalmazható. Az invariáns azért fontos, mert a látszólag egyszerű felépítésnél könnyen elfelejthető egy irány vagy egy súly.

10.2.8 8. Tipikus hibák

A reprezentációk használata során a leggyakoribb hibák a következők.

Irányítatlan gráf éle csak egy irányban. Ha az add_edge csak adj[u].append(v) hívást végez, akkor a vv csúcs szomszédai közül hiányzik uu. A BFS és DFS ilyenkor tévesen nem látja az élt a másik irányból. Helyes megoldás: irányítatlan gráfban mindkét irányt hozzá kell adni.

A súlyozott gráfban a 0 hiányzó él jelölése. Ha a hiányzó élt 00 jelöli, akkor egy valódi 00 súlyú él nem különböztethető meg a nem létező éltől. Helyes megoldás: ∞\infty vagy None használata hiányzó élre.

Az indexelés keverése. A pszeudokód 11-től indexel, a legtöbb programozási nyelv 00-tól. Ha a gráf csúcsait 11-től számozzuk, a kódban vagy át kell konvertálni, vagy a 00-ás csúcsot nem használjuk. Következetlenség esetén könnyen túlindexelés vagy érvényes él elvesztése lép fel.

Párhuzamos élek figyelmen kívül hagyása. A mátrix egy cellában csak egy értéket tárol, ezért a párhuzamos élek közül az egyik elveszhet. A szomszédsági lista és az él lista természetesen tárolja a multiplicitást. Ha a gráf multi-gráf, a mátrix helyett listát érdemes használni, vagy a mátrixcellában tároljunk számlálót.

Hurok élek kezelése. Irányítatlan hurok esetén a matematikai modellben a fokszám általában kettővel nő, de a gyakorlatban a hurok egyszeri vagy kétszeri tárolása következetlen lehet. A reprezentációnak rögzítenie kell, hogy a hurok hogyan számít a memóriában és a fokszámban.

Él lista minden lekérdezéshez. Ha az él listát szomszédság vizsgálatra használjuk, akkor minden lekérdezés Θ(m)\Theta(m) idejű. A gyakori lekérdezésre szomszédsági listát vagy mátrixot kell választani.

Rendezetlen szomszédok. Ha a szomszédsági lista sorrendje a beolvasási sorrendtől függ, ugyanaz a gráf eltérő bejárási sorrendet eredményezhet. A reprodukálhatósághoz rendezzük a szomszédokat, vagy a tesztkörnyezetben rögzítsük a sorrendet.

10.2.9 9. Tesztelési stratégia

A reprezentációk tesztelésénél a kontextusban rögzített esetosztályokat kell lefedni: üres, egyelemű, duplikált, rendezett, fordított és véletlen inputokat, valamint szélső értékeket.

Gráfokra ez így konkretizálható:

  • Üres gráf: n=0n=0 vagy n>0n>0, de m=0m=0. Minden reprezentációnak tükröznie kell, hogy nincs él.
  • Egyelemű gráf: n=1n=1. A mátrix 1×11\times 1-es, a lista egy üres lista, az él lista üres.
  • Hurok él: (u,u)(u,u) él. Ellenőrizzük, hogy a kiválasztott reprezentáció helyesen tárolja-e, és a fokszám-definícióval összhangban van-e.
  • Párhuzamos élek: ugyanazon csúcsok között több él. Szomszédsági lista és él lista esetén a multiplicitás megmarad, mátrixnál dokumentálni kell az elvesztést vagy a számlálót.
  • Irányítatlan gráf szimmetriája: a mátrix legyen szimmetrikus, a lista mindkét irányt tartalmazza, az él lista minden élt egyszer.
  • Súlyok és negatív súlyok: a hiányzó él jelölése ne legyen azonos egy érvényes súllyal.
  • Teljes gráf: minden lehetséges él jelen van. Ekkor a mátrix minden diagonálison kívüli cellája kitöltött, a lista minden szomszédja a többi n−1n-1 csúcs.
  • Véletlen gráf: rögzített magú véletlengenerátorral állítsunk elő G(n,p)G(n,p) gráfot, majd mindhárom reprezentációból nyerjük ki az éleket, rendezzük őket, és hasonlítsuk össze. Ez a konzisztencia-teszt a hibák nagy részét feltárja.

A kódblokkban egy konzisztencia-teszt vázlata:

# Python 3; 0-tól indexelt.
def edges_from_adjacency_matrix(a):
    n = len(a)
    edges = set()
    for u in range(n):
        for v in range(n):
            if a[u][v] != 0:
                edges.add((u, v, a[u][v]))
    return edges

def edges_from_adjacency_list(adj):
    edges = set()
    for u, nbrs in enumerate(adj):
        for v, w in nbrs:
            edges.add((u, v, w))
    return edges

def edges_from_edge_list(edges):
    return set(edges)

10.2.10 10. Laborfeladat: ugyanazon gráf három reprezentációja

A laborfeladat célja, hogy a fejezet tanulási céljait egy reprodukálható projektben alkalmazzuk.

Input. Válasszon egy rögzített, 6 csúcsú, irányítatlan, súlyozott gráfot. Például a csúcsok 0,…,50,\dots,5, az élek pedig:

(0, 1, 4), (0, 2, 2), (1, 2, 1), (1, 3, 5),
(2, 3, 8), (2, 4, 10), (3, 4, 2), (3, 5, 6),
(4, 5, 3)

Feladatok.

  1. Implementáljon három osztályt: AdjacencyMatrix, AdjacencyList, EdgeList. Mindegyik tudja az éleket beszúrni és a belső állapotát visszaadni.
  2. Töltse fel mindhárom struktúrát ugyanazzal az élhalmazzal.
  3. Írjon konzisztencia-teszteket: mindegyikből nyerje ki az élhalmazt, alakítsa rendezett listává, és hasonlítsa össze. Ellenőrizze továbbá, hogy az él teszt mindhárom esetben ugyanazt adja, és hogy irányítatlan gráfban a szomszédság szimmetrikus.
  4. Mérje meg a memóriaigényt és a futási időt különböző nn és mm értékekre. Használjon ritka gráfot, például m=5nm=5n élt, és sűrű gráfot, például m=0,8(n2)m=0{,}8\,\binom{n}{2} élt.
  5. Rögzítse a mérési naplót: nyelv, fordító vagy interpreter, optimalizációs szint, hardver, inputméret, ismétlésszám. Az eredményeket átlaggal és szórással közölje. A mért értékeket különítse el a várt elméleti komplexitástól.
  6. Értékelje röviden, hogy a mért futási időmenet összhangban van-e az elméleti táblázattal. Ha eltérés van, keresse a cache-viselkedés, a konstans tényező vagy az implementáció okát.

A labor eredménye egy jegyzetfüzet vagy kódprojekt, amely a fenti pontokat tartalmazza. A teszteknek meg kell felelniük a korrektségi szerződésnek, és a mérésnek reprodukálhatónak kell lennie.

10.2.12 12. Kapcsolódás a következő alfejezethez

A következő egység a gráfok bejárását, a BFS-t, a DFS-t és a topológiai rendezést tárgyalja. Az ott leírt algoritmusok szomszédsági listán természetesen Θ(n+m)\Theta(n+m) időben futnak, mátrixon viszont Θ(n2)\Theta(n^2) időben. Az itt bevezetett három reprezentáció így nem csupán tárolási technika, hanem a bejárási algoritmusok hatékonyságának alapja.

A gráf tárolási módja tehát mérnöki döntés: a választott struktúra egyensúlyt teremt a memória, a kifejezőerő és a műveleti költségek között. A szomszédsági mátrix a sűrű gráfok és az él tesztelés eszköze, a szomszédsági lista a ritka gráfok és a bejárások természetes formája, az él lista pedig az élalapú algoritmusoké.
