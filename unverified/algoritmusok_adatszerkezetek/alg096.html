25.3 Dinic és push-relabel

A maximális áramlás problémáját az Áramlási hálózatok és maradék gráf–Ford-Fulkerson és Edmonds-Karp egységekben bevezettük, és az Edmonds–Karp-algoritmussal egy olyan, mindig termináló megoldást kaptunk, amelynek időbonyolultsága O(VE2)O(V E^2). Ez sok hálózaton elegendő, ám nagy, sűrű vagy speciális szerkezetű gráfokon a gyakorlatban is jelentős lassulást okozhat. Ebben az alfejezetben két, a versenyprogramozásban és az ipari implementációkban is elterjedt, hatékonyabb algoritmust vizsgálunk: a Dinic-féle szintgráf-alapú blokkoló áramlást, valamint a Goldberg–Tarjan-féle push-relabel (más néven preflow-push) módszert. Mindkettő az áramlási hálózat lokális szerkezetét használja ki, és aszimptotikusan is jobb, illetve a gyakorlatban gyakran nagyságrendekkel gyorsabb az Edmonds–Karpnál.

A tárgyalás során feltételezzük, hogy az olvasó ismeri a maradék gráf, a növelő út és a max-flow min-cut tétel fogalmait (lásd Ford-Fulkerson és Edmonds-Karp). A kapacitások nemnegatívak, a gráf irányított, és a forrásból a nyelőbe vezető utakat keressük.

25.3.1 1. Dinic algoritmusa: szintgráf és blokkoló áramlás

25.3.2 1.1 Alapgondolat

A Dinic-algoritmus úgy gyorsítja a növelőutas módszert, hogy egy fázisban több növelő utat is keres, mégpedig olyan utakat, amelyek mind az aktuális maradék gráf egy legrövidebb utakból álló részgráfjában, a szintgráfban haladnak. Ahelyett, hogy minden egyes növelő út után újra BFS-t futtatnánk, egy fázisban addig keresünk utakat a rögzített szintgráfban, amíg az adott szintgráfban már nincs több növelő út. Az így kapott áramlást blokkoló áramlásnak nevezzük. A fázis végén újra BFS-t futtatunk; a maradék gráfban a forrásból a nyelőbe vezető legrövidebb út hossza szigorúan nő, így legfeljebb V−1V-1 fázisra van szükség.

25.3.3 1.2 Definíciók

Legyen G=(V,E)G=(V,E) áramlási hálózat, ss forrás, tt nyelő, és cfc_f az aktuális maradék kapacitás.

  • Szintgráf: Futtassunk BFS-t az ss-ből a maradék gráfon. Minden vv csúcsra kapjuk a szint(v)\operatorname{szint}(v) értéket, az ss-ből vv-be vezető legrövidebb út élszámát. A szintgráf azokat az (u,v)(u,v) maradék éleket tartalmazza, amelyekre szint(v)=szint(u)+1\operatorname{szint}(v) = \operatorname{szint}(u) + 1. Ez tehát egy aciklikus, rétegzett irányított gráf.
  • Blokkoló áramlás: Olyan ff áramlás a szintgráfban, amelyre igaz, hogy a szintgráfban nincs olyan s→ts \to t irányított út, amelynek minden élén pozitív maradék kapacitás van. Másképpen: a szintgráfban minden s→ts \to t úton legalább egy él telítetté válik.
  • A blokkoló áramlás nem feltétlenül maximális az egész hálózatban, de a fázis után a maradék gráfban a legrövidebb s→ts \to t út hossza nő.

25.3.4 1.3 Az algoritmus

A Dinic-algoritmus fő ciklusa:

  1. Inicializálás: f=0f = 0, cf=cc_f = c.
  2. Amíg tt elérhető ss-ből a maradék gráfban:
    • Futtassunk BFS-t, építsük fel a szintgráfot.
    • Ha szint(t)\operatorname{szint}(t) nem létezik, álljunk meg: ff maximális.
    • Keressünk blokkoló áramlást a szintgráfban.
    • Adjuk hozzá a blokkoló áramlást ff-hez, és frissítsük a maradék kapacitásokat.
  3. Eredmény: az ff értéke.

A blokkoló áramlás keresése tipikusan mohó DFS-sel történik, amely a szintgráf élein halad. Minden csúcshoz egy current mutatót tartunk, amely azt az élt jelöli, amelytől a következő DFS-hívásnak folytatnia kell a keresést. Ez a current-arc optimalizáció biztosítja, hogy egy fázison belül minden élt legfeljebb egyszer vizsgálunk meg.

25.3.5 1.4 Pszeudokód

Az alábbi pszeudokód nem fordítási célú, hanem az algoritmus lényegét mutatja. A tömböket 1-től indexeljük, a nyelvi sajátosságokat a kódblokk elején jelezzük.

// Dinic maximális áramlás – pszeudokód (1-től indexelt tömbök)
Bemenet: G=(V,E) irányított gráf, c(u,v) >= 0 kapacitások, s forrás, t nyelő
Kimenet: a maximális folyam értéke
Előfeltétel: s != t, nincs negatív kapacitás
Utófeltétel: a maradék gráfban nincs s -> t irányított út

DinicMaxFlow(G, s, t):
    folyam <- 0
    c_f <- c                              // maradék kapacitások másolata

    while BFS_szintek(c_f, s, t) igaz:
        // BFS_szintek feltölti a szint[] tömböt, és visszaadja, hogy t elérhető-e
        cur <- [1..1] minden csúcsra      // current-arc mutatók

        while igaz:
            pushed <- DFS(s, VEGTELEN)
            if pushed = 0:
                break
            folyam <- folyam + pushed

    return folyam

DFS(u, limit):
    ha u = t:
        return limit

    for i <- cur[u] to szomszedok_szama(u):
        cur[u] <- i                       // jegyzet: az aktuális élt elmentjük
        v <- szomszed(u, i)
        if c_f[u][v] > 0 es szint[v] = szint[u] + 1:
            pushed <- DFS(v, min(limit, c_f[u][v]))
            if pushed > 0:
                c_f[u][v] <- c_f[u][v] - pushed
                c_f[v][u] <- c_f[v][u] + pushed
                return pushed

    return 0

Megjegyzés a pszeudokódhoz: A cur[u] mutatót akkor léptetjük, ha az adott élen a DFS 0-val tér vissza; ha a DFS sikeres, a mutató ugyanazon az élen marad, hiszen lehet még további kapacitás. A gyakorlati implementációkban a cur tömböt a szintgráf felépítése után nullázzák, és az éllistákon 0-tól indexelnek.

25.3.6 1.5 Korrektség vázlat

A Dinic-algoritmus helyességének két fő állítása:

  1. A blokkoló áramlás után a szintgráfban nincs növelő út. Ez a blokkoló áramlás definíciójából következik: ha lenne olyan s→ts \to t út, amelyen minden él maradék kapacitása pozitív, akkor a szintgráfban növelő út lenne, és a blokkoló áramlás keresése még nem állhatott volna le.
  2. Minden fázis után a maradék gráfban a legrövidebb s→ts \to t út hossza nő. Tegyük fel, hogy a fázis előtt a legrövidebb út hossza LL volt. A blokkoló áramlás után bármely új s→ts \to t út a maradék gráfban nem lehet rövidebb LL-nél, mert a szintgráf minden LL hosszúságú útját blokkolta. Ha lenne LL hosszúságú út, akkor az a szintgráfban is út volna, ami ellentmondás. Így a távolság legalább L+1L+1. Mivel a távolság legfeljebb V−1V-1, legfeljebb V−1V-1 fázis van.

A terminálás: a fázisok száma korlátos, és minden fázis véges sok DFS-hívást végez. Az utófeltétel teljesül, mert amikor a BFS már nem talál tt-t, a maradék gráfban nincs növelő út, tehát a folyam maximális (a max-flow min-cut tétel alapján).

25.3.7 1.6 Komplexitás

Egy fázisban a BFS O(E)O(E) időt vesz igénybe. A blokkoló áramlás keresése a current-arc optimalizációval O(VE)O(VE) műveletet igényel fázisonként, mert minden él legfeljebb egyszer telítődik vagy kerül elutasításra, és minden DFS-hívás O(V)O(V) lépést tesz. Így a teljes futási idő O(V⋅(VE))=O(V2E)O(V \cdot (VE)) = O(V^2 E).

Speciális hálózatokban ennél lényegesen jobb korlát is elérhető. Például egységkapacitású hálózatokban (minden él kapacitása 1) a Dinic-algoritmus futásideje O(EV)O(E \sqrt{V}), illetve általánosabban, ha minden él kapacitása egész és legfeljebb 11 vagy a forrásból/nyelőbe vezető élek speciális korlátokat teljesítenek, további gyorsítás érhető el. A pontos aszimptotikus állítások a standard forrásokban (például CLRS 4. kiadás, 24. fejezet; Erickson jegyzet) ellenőrizhetők.

25.3.8 1.7 Lépésenkénti példa

Tekintsük a következő kis hálózatot: csúcsok s,a,b,ts, a, b, t, élek és kapacitások:

  • s→as \to a: 10
  • s→bs \to b: 10
  • a→ba \to b: 2
  • a→ta \to t: 5
  • b→tb \to t: 10

A keresett maximális áramlás értéke 15, mert az s→a→ts \to a \to t út 5 egységet, az s→b→ts \to b \to t út 10 egységet tud átvinni, és az a→ba \to b élen csak 2 egység haladhat, de az nem növeli a nyelőbe jutó összmennyiséget, mert a b→tb \to t kapacitás 10, az s→bs \to b szintén 10, így a teljes átvitel 5 + 10 = 15.

1. fázis – BFS: A maradék gráfban (még az eredeti kapacitások) a szintek:

  • szint(s)=0\operatorname{szint}(s) = 0
  • szint(a)=1\operatorname{szint}(a) = 1 (az s→as \to a élen)
  • szint(b)=1\operatorname{szint}(b) = 1 (az s→bs \to b élen)
  • szint(t)=2\operatorname{szint}(t) = 2 (az a→ta \to t és b→tb \to t éleken)

A szintgráf élei: s→as \to a, s→bs \to b, a→ta \to t, b→tb \to t. Az a→ba \to b él nem kerül be, mert szint(b)≠szint(a)+1\operatorname{szint}(b) \ne \operatorname{szint}(a)+1.

Blokkoló áramlás keresése:

  1. DFS(s, ∞) az s→as \to a élen indul: DFS(a, 10). Az a→ta \to t élen DFS(t, 5) 5-öt ad vissza. Frissítjük: cf(s,a)=5c_f(s,a) = 5, cf(a,s)=5c_f(a,s) = 5, cf(a,t)=0c_f(a,t) = 0, cf(t,a)=5c_f(t,a) = 5. A folyam értéke 5.
  2. A DFS az ss-nél folytatja, mert az s→as \to a ágon az aa csúcsból nincs több szintgráf-él (az a→ta \to t telített, az a→ba \to b nem szintgráf él). Az s→as \to a él nem telített, de az aa ágon nem tudunk tovább haladni, ezért a DFS 0-t ad, és az ss cur mutatója az s→bs \to b élre lép.
  3. DFS(s, ∞) az s→bs \to b élen: DFS(b, 10). A b→tb \to t élen DFS(t, 10) 10-et ad vissza. Frissítjük: cf(s,b)=0c_f(s,b) = 0, cf(b,s)=10c_f(b,s) = 10, cf(b,t)=0c_f(b,t) = 0, cf(t,b)=10c_f(t,b) = 10. A folyam értéke 15.
  4. Újabb DFS nem talál utat, mert az s→as \to a él maradék kapacitása 5, de az aa csúcsból nincs olyan szintgráf él, amelyen tovább lehetne haladni. A blokkoló áramlás összesen 15.

2. fázis – BFS: A frissített maradék gráfban s→as \to a maradék 5, a→ba \to b maradék 2, de a→ta \to t maradék 0 és b→tb \to t maradék 0. A b→sb \to s él maradék 10, de az nem visz közelebb tt-hez. Az ss-ből induló BFS eléri aa-t, majd aa-ból bb-t (mert a→ba \to b maradék 2), de bb-ből a b→tb \to t él telített, a b→sb \to s él pedig visszavezet ss-be, így tt nem érhető el. A BFS nem találja tt-t, az algoritmus leáll. A maximális folyam értéke 15.

25.3.9 2. A push-relabel algoritmus

25.3.10 2.1 Motiváció és alapfogalmak

A push-relabel algoritmus eltér a növelőutas szemlélettől. Nem utakat keres, hanem preflow-t tart fenn, amely lokális szabályok szerint mozog a csúcsok között. A módszer előnye, hogy nem függ a növelő utak hosszától, és sűrű gráfokon gyakran jobb a gyakorlati teljesítménye.

  • Preflow: Olyan ff függvény, amelyre teljesülnek a kapacitás-korlátok: 0≤f(u,v)≤c(u,v)0 \le f(u,v) \le c(u,v) minden (u,v)(u,v) élre, és f(u,v)=−f(v,u)f(u,v) = -f(v,u). A folyam-megmaradást azonban csak a belső csúcsokra lazítjuk: minden u∈V\{s,t}u \in V \setminus \{s,t\} csúcsra a bejövő áramlás összege legalább akkora, mint a kimenő áramlás összege, tehát a csúcsban túlcsordulás (excess) halmozódhat fel.
  • Túlcsordulás: Az uu csúcs túlcsordulása
    e(u)=∑v∈Vf(v,u)−∑v∈Vf(u,v).e(u) = \sum_{v \in V} f(v,u) - \sum_{v \in V} f(u,v).
    A forrásra e(s)e(s) negatív is lehet (hiszen a forrásból több áramlik ki, mint be), a nyelőre pedig e(t)e(t) pozitív. A többi csúcsra e(u)≥0e(u) \ge 0 a preflow definíciója szerint. Azokat a u≠s,tu \ne s,t csúcsokat, ahol e(u)>0e(u) > 0, aktív csúcsoknak nevezzük.
  • Magasságcímke: Minden vv csúcshoz egy h(v)∈ℕh(v) \in \mathbb{N} magasságot rendelünk. A címkézésre az az invariáns érvényes: ha a maradék gráfban van (u,v)(u,v) él, akkor
    h(u)≤h(v)+1.h(u) \le h(v) + 1.
    Ez a feltétel azt fejezi ki, hogy a maradék élen a magasság legfeljebb eggyel csökkenhet. Ha h(u)=h(v)+1h(u) = h(v) + 1, akkor az (u,v)(u,v) élt megengedett élnek nevezzük; csak ilyen élen hajthatunk végre push műveletet. A forrás magasságát VV-re, a nyelőét 0-ra állítjuk, a többi csúcs magassága kezdetben 0.

25.3.11 2.2 Műveletek: push és relabel

A preflow-push algoritmus két alapműveletet használ:

  • Push(u, v): Ha uu aktív, és (u,v)(u,v) megengedett él, akkor a uu túlcsordulásából δ=min(e(u),cf(u,v))\delta = \min(e(u), c_f(u,v)) egységet áttolunk vv-be. A maradék kapacitásokat frissítjük: cf(u,v)−=δc_f(u,v) \mathrel{-}= \delta, cf(v,u)+=δc_f(v,u) \mathrel{+}= \delta. A túlcsordulások: e(u)−=δe(u) \mathrel{-}= \delta, e(v)+=δe(v) \mathrel{+}= \delta.
  • Relabel(u): Ha uu aktív, de nincs megengedett él (u,v)(u,v), akkor növeljük uu magasságát a lehető legkisebb olyan értékre, amely mellett valamelyik kimenő maradék él megengedetté válik:
    h(u)←1+min{h(v):cf(u,v)>0}.h(u) \leftarrow 1 + \min\{ h(v) : c_f(u,v) > 0 \}.
    Ha nincs kimenő maradék él, akkor h(u)h(u)-t valamilyen nagy értékre, például V+1V+1-re állítjuk, ami jelzi, hogy uu már nem tud hozzájárulni a nyelő eléréséhez.

A relabel művelet növeli a magasságot, így a magasságok felülről korlátosak, ami biztosítja a terminálást.

25.3.12 2.3 Inicializálás

A push-relabel algoritmus inicializálása a következő:

  1. Minden u≠su \ne s csúcsra h(u)=0h(u) = 0, és e(u)=0e(u) = 0. A forrásra h(s)=Vh(s) = V.
  2. Minden élre f(u,v)=0f(u,v) = 0, és a maradék kapacitás cf(u,v)=c(u,v)c_f(u,v) = c(u,v).
  3. A forrásból kiinduló minden (s,v)(s,v) élt telítünk: f(s,v)=c(s,v)f(s,v) = c(s,v), f(v,s)=−c(s,v)f(v,s) = -c(s,v). Ennek hatására e(v)=c(s,v)e(v) = c(s,v) lesz minden ss-szomszédra, és e(s)=−∑vc(s,v)e(s) = -\sum_{v} c(s,v).

Ezzel a forrásból kiinduló összes áramlás azonnal a hálózatba kerül, és a szomszédos csúcsok aktívvá válnak. A forrásnak VV magassága van, ami megakadályozza, hogy a túlcsordulás közvetlenül visszafolyjon a forrásba, hiszen a forrás magasabban van, mint a többiek, és a megengedett élekhez a magasságnak pontosan eggyel kell csökkennie.

25.3.13 2.4 Az algoritmus pszeudokódja

// Push-relabel maximális áramlás – pszeudokód (1-től indexelt tömbök)
Bemenet: G=(V,E), c(u,v) >= 0, s forrás, t nyelő
Kimenet: a maximális folyam értéke
Előfeltétel: s != t, nincs negatív kapacitás
Utófeltétel: a maradék gráfban nincs s -> t út

PushRelabelMaxFlow(G, s, t):
    for minden u csúcsra:
        h[u] <- 0
        e[u] <- 0
    h[s] <- |V|

    // Inicializálás: telítjük a forrásból kimenő éleket
    for minden (s,v) élre:
        f[s][v] <- c(s,v)
        f[v][s] <- -c(s,v)
        c_f[s][v] <- 0
        c_f[v][s] <- c(v,s) + c(s,v)   // mert c(v,s) = 0, így c_f[v][s] = c(s,v)
        e[v] <- e[v] + c(s,v)
        e[s] <- e[s] - c(s,v)

    // Amíg van aktív csúcs (u != s,t, e[u] > 0):
    while létezik aktív u:
        ha van megengedett él (u,v):
            push(u, v)
        különben:
            relabel(u)

    return e[t]   // a nyelő túlcsordulása egyenlő a maximális folyam értékével

push(u, v):
    delta <- min(e[u], c_f[u][v])
    c_f[u][v] <- c_f[u][v] - delta
    c_f[v][u] <- c_f[v][u] + delta
    e[u] <- e[u] - delta
    e[v] <- e[v] + delta

relabel(u):
    if nincs olyan v, hogy c_f[u][v] > 0:
        h[u] <- |V| + 1
    különben:
        h[u] <- 1 + min{ h[v] : c_f[u][v] > 0 }

Megjegyzés a pszeudokódhoz: A c_f kezelése itt a maradék kapacitások explicit frissítését jelenti. A push művelet feltétele, hogy e[u]>0e[u] > 0, cf[u][v]>0c_f[u][v] > 0, és h[u]=h[v]+1h[u] = h[v] + 1. A relabel után a magasság nő, így a while ciklus nem végtelen. A return e[t] akkor helyes, ha a preflow termináláskor áramlássá válik, azaz nincs aktív csúcs.

25.3.14 2.5 Korrektség vázlat

A push-relabel algoritmus korrektségét három részre bontjuk:

  1. A preflow invariánsai fennmaradnak. A push csak a maradék kapacitás erejéig mozgat áramlást, tehát a kapacitás-korlátok nem sérülnek; a túlcsordulások frissítése pedig megőrzi a preflow tulajdonságot (a belső csúcsokra e(u)≥0e(u) \ge 0). A relabel nem változtatja az áramlást, csak a magasságcímkét. A magassági invariáns (h(u)≤h(v)+1h(u) \le h(v)+1 minden maradék élre) a relabel után is igaz, mert a magasságot éppen a minimum fölé állítjuk, és a push nem sérti az invariánst, mert csak megengedett élen történik.
  2. A termináláskor a preflow áramlás. Ha nincs aktív csúcs (e(u)=0e(u)=0 minden u≠s,tu \ne s,t esetén), akkor a belső csúcsokra a bejövő és kimenő áramlás megegyezik, tehát a folyam-megmaradás teljesül. A kapacitás-korlátok és az antiszimmetria is érvényben van, így a preflow valódi áramlás.
  3. A termináláskor az áramlás maximális. Ha a preflow már áramlás, és a maradék gráfban nincs s→ts \to t út, akkor a max-flow min-cut tétel garantálja a maximálisságot. A push-relabel algoritmus akkor áll le, amikor nincs aktív csúcs. Ekkor a forrásból a nyelőbe vezető maradék út sem létezhet, mert ha létezne, akkor az út mentén az aktív csúcsok túlcsordulásai nem lehetnének mind nullák.

A leállás belátásához: a relabel műveletek száma korlátos, mert minden csúcs magassága legfeljebb 2V−12V-1 (vagy 2V2V, ha a forrás magassága VV, és a nyelőé 0). A pushok száma is korlátos, mert minden telítő push egy élt telít, és minden nem telítő push egy aktív csúcs túlcsordulását csökkenti nullára; a kétféle push együttes száma O(VE)O(VE). Így a ciklus véges.

25.3.15 2.6 Komplexitás

A push-relabel algoritmus általános megvalósítása O(V2E)O(V^2 E) időt igényel. Ez a következőképpen jön ki: a relabel műveletek száma O(V2)O(V^2), a pushok száma O(VE)O(VE), ha minden aktív csúcsot egyszerűen tárolunk és feldolgozunk. Fontos megjegyezni, hogy a legmagasabb aktív csúcs kiválasztásával (highest-label push-relabel) a futásidő aszimptotikusan javítható; bizonyos implementációk O(V2E)O(V^2 \sqrt{E}) vagy O(V3)O(V^3) korlátot érnek el, de a pontos érték a heurisztikáktól és a gráf szerkezetétől függ. A gyakorlatban a push-relabel sűrű gráfokon gyakran gyorsabb, mint a Dinic, míg a Dinic ritka gráfokon és egységkapacitású hálózatokon rendszerint jobb.

25.3.16 2.7 Gap heurisztika és további optimalizációk

A relabel műveletek hatékonyságát jelentősen növeli a gap heurisztika. Ha egy adott kk magassági szinten nincs csúcs, akkor minden olyan uu csúcsot, amelynek h(u)>kh(u) > k, azonnal nagy magasságra, például V+1V+1-re állíthatunk, mert ezek a csúcsok már biztosan nem érhetik el a nyelőt. Ez gyakorlatban drasztikusan csökkenti a felesleges relabel és push műveletek számát.

További optimalizáció a current-arc mutató a push művelethez: minden csúcshoz nyilvántartjuk, hogy melyik élét vizsgáltuk utoljára, így a relabel után nem kell újra az összes kimenő élt végignézni.

25.3.18 3. Gyakorlati megfontolások és tipikus hibák

25.3.19 3.1 Mikor melyiket válasszuk?

  • Dinic általában egyszerűbb helyesen implementálni, és ritka, valamint egységkapacitású hálózatokon kiváló teljesítményt nyújt. Gyakran ez az első választás versenyfeladatokban.
  • Push-relabel sűrű gráfokon és olyan hálózatokon lehet gyorsabb, ahol a növelő utak hossza nagy, vagy ahol az Edmonds–Karp sok BFS-t igényelne. A jól hangolt push-relabel (például legmagasabb aktív csúcs + gap heurisztika) gyakorlatban nagyon gyors.
  • Mindkét algoritmus O(V2E)O(V^2 E) általános korláttal rendelkezik, de a konstansok és a gyakorlati viselkedés jelentősen eltérhet.

25.3.20 3.2 Tipikus hibák

  • Dinicnél gyakori hiba a szintgráf éleinek helytelen kiválasztása. Csak azok az élek tartoznak a szintgráfhoz, ahol a maradék kapacitás pozitív és a célszint pontosan eggyel nagyobb. Az a→ba \to b típusú, azonos szintre mutató éleket ki kell hagyni.
  • A current-arc mutató rossz kezelése: ha a DFS 0-val tér vissza, a mutatót léptetni kell; ha sikeres, nem szabad léptetni, mert lehet még kapacitás. Ennek elmulasztása exponenciális lassulást okozhat.
  • A visszafelé élek elhagyása a maradék gráf frissítésekor szintén helytelen eredményt ad.
  • Push-relabelnél a magassági invariáns megsértése a leggyakoribb hiba. A push csak megengedett élen hajtható végre; a relabel után azonnal ellenőrizni kell, hogy a magasság nőtt-e.
  • A forrás magasságát nem szabad csökkenteni, mert az lehetővé tenné, hogy a túlcsordulás közvetlenül visszafolyjon a forrásba a nyelő elérése nélkül.
  • A gap heurisztika helytelen alkalmazása (például a magasságok túl alacsonyra állítása) megsértheti a terminálási garanciát.

25.3.23 4.2 Példa kódvázlat (Python, tájékoztató jelleggel)

Az alábbi vázlat nem teljes, csak a Dinic blokkolóáramlás-keresésének szerkezetét mutatja; a push-relabel hasonló részletességgel kidolgozandó.

# Python 3 – Dinic blokkoló áramlás vázlat
# A lista 0-tól indexelt, ezért az éleket 0-tól tároljuk.

class Dinic:
    def __init__(self, n, s, t):
        self.n = n
        self.s = s
        self.t = t
        self.graph = [[] for _ in range(n)]
        self.edge = []          # minden él [to, cap, rev_index]

    def add_edge(self, u, v, cap):
        self.graph[u].append([v, cap, len(self.graph[v])])
        self.graph[v].append([u, 0, len(self.graph[u]) - 1])

    def bfs_szintek(self):
        self.level = [-1] * self.n
        q = [self.s]
        self.level[self.s] = 0
        for u in q:
            for v, cap, _ in self.graph[u]:
                if cap > 0 and self.level[v] < 0:
                    self.level[v] = self.level[u] + 1
                    q.append(v)
        return self.level[self.t] >= 0

    def dfs(self, u, limit):
        if u == self.t:
            return limit
        for i in range(self.it[u], len(self.graph[u])):
            self.it[u] = i
            v, cap, rev = self.graph[u][i]
            if cap > 0 and self.level[v] == self.level[u] + 1:
                pushed = self.dfs(v, min(limit, cap))
                if pushed > 0:
                    self.graph[u][i][1] -= pushed
                    self.graph[v][rev][1] += pushed
                    return pushed
            # ha sikertelen, a következő iterációban léptetjük az it[u]-t
        return 0

    def max_flow(self):
        flow = 0
        INF = 10**18
        while self.bfs_szintek():
            self.it = [0] * self.n
            while True:
                pushed = self.dfs(self.s, INF)
                if pushed == 0:
                    break
                flow += pushed
        return flow

A fenti vázlatban a dfs a self.it[u] mutatót minden él vizsgálatakor beállítja, de csak akkor lép tovább, ha a rekurzív hívás 0-t ad; ez a gyakorlatban helyesen működik, mert a ciklus a következő iterációban folytatja. A teljes laborhoz hasonló szerkezetű push-relabel implementációt kell készíteni, explicit height és excess tömbökkel, valamint a forrás inicializálásával.
