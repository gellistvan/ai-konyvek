20.2 N-királynő és Hamilton-kör

A visszalépéses keresés és a pruning alfejezetben bevezetett visszalépéses keresés két klasszikus alkalmazása az N-királynő és a Hamilton-kör feladat. Mindkettő jól mutatja, hogyan lehet egy nagy állapotteret bejárni úgy, hogy a részleges megoldás ütközésvizsgálatával és a belőle következő kényszerekkel a holtágakat minél hamarabb levágjuk. Ebben az alfejezetben a két problémát a korrektségi szerződés, a pszeudokód, egy bejárási példa, a szimmetriákból adódó optimalizálás és a mérési szempontok mentén tárgyaljuk.

20.2.1 Az N-királynő probléma

Az N-királynő feladatban egy n×nn \times n-es sakktáblára kell nn királynőt elhelyezni úgy, hogy semelyik kettő ne üsse egymást. A sakkban a királynő üti az azonos sorban, azonos oszlopban és azonos átlóban álló bábukat.

Bemenet: nn pozitív egész szám.
Kimenet: az összes megoldás listája; minden megoldás egy nn hosszú sorozat, amelyben az ii-edik elem az ii-edik sorban elhelyezett királynő oszlopát adja meg.
Előfeltétel: n≥1n \ge 1.
Utófeltétel: minden megoldásban minden sorban pontosan egy királynő áll, minden oszlopban legfeljebb egy, és minden átlón legfeljebb egy királynő helyezkedik el.
Leállási feltétel: a rekurzió mélysége legfeljebb n+1n+1, és minden rekurzív hívás véges sok jelöltet vizsgál.

20.2.2 Állapotábrázolás és ütközésvizsgálat

Mivel egy sorban két királynő nem állhat, minden sorba pontosan egy királynőt kell tenni. Ezért a megoldást soronkénti oszlopindexekkel ábrázolhatjuk: a részleges állapot az első r−1r-1 sorban lerakott királynők oszlopait tartalmazza.

Két királynő, (r1,c1)(r_1, c_1) és (r2,c2)(r_2, c_2), akkor üti egymást, ha:

  1. azonos sorban vannak: r1=r2r_1 = r_2 — ezt a reprezentáció kizárja;
  2. azonos oszlopban vannak: c1=c2c_1 = c_2;
  3. azonos főátlón vannak: r1−c1=r2−c2r_1 - c_1 = r_2 - c_2;
  4. azonos mellékátlón vannak: r1+c1=r2+c2r_1 + c_1 = r_2 + c_2.

A naiv ütközésvizsgálat minden új királynőt az összes már lerakottal összehasonlít. Ez lépésenként O(r)O(r) időt igényel. Hatékonyabb, ha három foglaltsági halmazt tartunk karban:

  • col[1..n]: foglalt oszlopok;
  • diag1[1..2n-1]: foglalt főátlók, ahol a főátló azonosítója r−c+nr - c + n;
  • diag2[1..2n-1]: foglalt mellékátlók, ahol a mellékátló azonosítója r+c−1r + c - 1.

Ekkor annak eldöntése, hogy a (r,c)(r, c) mező szabad-e, három logikai érték ellenőrzését jelenti, tehát O(1)O(1) idejű. A kényszerterjesztés itt abban áll, hogy a rekurzió csak azokat az oszlopokat próbálja ki, amelyek mindhárom halmaz szerint szabadok.

Az alábbi pszeudokód 1-től indexeli a tömböket:

N-Queens-All(n):
    col[1..n] ← hamis
    diag1[1..2n-1] ← hamis     // főátló: r - c + n
    diag2[1..2n-1] ← hamis     // mellékátló: r + c - 1
    queen[1..n] ← 0
    megoldások ← []

    Backtrack(r):
        ha r > n:
            megoldások.hozzáad(queen másolata)
            visszatér
        minden c ∈ 1..n:
            d1 ← r - c + n
            d2 ← r + c - 1
            ha col[c] hamis és diag1[d1] hamis és diag2[d2] hamis:
                queen[r] ← c
                col[c] ← diag1[d1] ← diag2[d2] ← igaz
                Backtrack(r + 1)
                col[c] ← diag1[d1] ← diag2[d2] ← hamis

    Backtrack(1)
    return megoldások

A Python-változat 0-tól indexel, ezért az átlóazonosítók eltolása eltér:

def n_queens_all(n: int) -> list[list[int]]:
    col = [False] * n
    diag1 = [False] * (2 * n - 1)   # r - c + n - 1
    diag2 = [False] * (2 * n - 1)   # r + c
    queen = []
    solutions = []

    def backtrack(r: int) -> None:
        if r == n:
            solutions.append(queen.copy())
            return
        for c in range(n):
            d1 = r - c + n - 1
            d2 = r + c
            if not col[c] and not diag1[d1] and not diag2[d2]:
                queen.append(c)
                col[c] = diag1[d1] = diag2[d2] = True
                backtrack(r + 1)
                col[c] = diag1[d1] = diag2[d2] = False
                queen.pop()

    backtrack(0)
    return solutions

A queen.pop() visszaállítása szorosan összetartozik a foglaltsági tömbök visszaállításával. Ha bármelyik visszaállítás elmarad, a párhuzamos rekurzív ágak hamis foglaltságokat örökölnek, és megoldások vesznek el.

20.2.3 Korrektségi vázlat

Rekurzív invariáns: amikor Backtrack(r) fut, az első r−1r-1 sorban elhelyezett királynők kölcsönösen nem ütik egymást, és a foglaltsági tömbök pontosan az általuk támadott oszlopokat és átlókat jelzik.

Bázis: r=1r = 1 esetén még nincs lerakott királynő, a tömbök üresek.

Lépés: a jelöltet csak akkor fogadjuk el, ha a három foglaltsági halmaz szerint szabad. Az elhelyezés után a tömbök frissülnek, így az invariáns r+1r+1-re is teljesül. A sikertelen vagy befejezett ág visszalépése után a tömbök visszaállítása helyreállítja a hívás előtti állapotot.

Teljes megoldás: ha r>nr > n, akkor minden sorban pontosan egy királynő áll, és az invariáns miatt nincs ütközés, tehát a queen sorozat megoldás.

Teljesség: egy megoldás egyértelműen megadható a soronkénti oszlopindexekkel. A rekurzió minden olyan oszlopot kipróbál, amely az addigi lerakásokkal nem ütközik, ezért a keresési fa minden megoldást tartalmaz.

Leállás: a rekurziós mélység minden hívásnál eggyel nő, és legfeljebb n+1n+1 lehet; a bejárás véges.

20.2.4 Példa: négy királynő

A 4×44 \times 4-es táblán két megoldás létezik. 1-től indexelt soronkénti oszlopokkal:

(2,4,1,3)és(3,1,4,2).(2, 4, 1, 3) \quad \text{és} \quad (3, 1, 4, 2).

A pszeudokód először az (1,1)(1,1) kezdést vizsgálja. A második sorban c=1c=1 oszlopütközés, c=2c=2 főátlóütközés, ezért először c=3c=3 jön szóba. A (2,3)(2,3) lerakása után a harmadik sorban egyetlen oszlop sem szabad, ezért az ág visszalép. A második sorban c=4c=4 következik, a harmadikban c=2c=2, de a negyedik sorban nem marad szabad mező, így ismét visszalépés. Az (1,1)(1,1) kezdés tehát nem vezet megoldáshoz.

Ezután az első sorban c=2c=2 következik. A rekurzió a (2,4)(2,4), (3,1)(3,1), (4,3)(4,3) lerakásokat találja meg, ami az első megoldást adja. A másik megoldást az első sor c=3c=3 kezdése hozza létre.

A példa jól mutatja a kényszerterjesztést: amikor a harmadik sorban az összes jelölt ütközik, az ágat azonnal lezárjuk, nem várjuk meg a negyedik sor kipróbálását.

20.2.5 Szimmetria és optimalizálás

A sakktábla tükrözései és forgatásai megoldásból megoldást képeznek. A legegyszerűbb szimmetria a függőleges tükrözés: ha az oszlopindexeket 1-től indexeljük, a tükrözés egy cc oszlopot n+1−cn + 1 - c-re képez. A 4×44 \times 4-es táblán például a (2,4,1,3)(2,4,1,3) megoldás tükrözése éppen a (3,1,4,2)(3,1,4,2) megoldás.

Ha csak egyetlen megoldást keresünk, elegendő az első sorban a tábla középvonaláig terjedő oszlopokat kipróbálni. A jobb oldali kezdések tükörképe bal oldali kezdésből megkapható, ezért az állapottér nagyjából felére csökken. Ha az összes megoldást kell visszaadni, a szimmetriát deduplikációra vagy utólagos generálásra használhatjuk.

Az n=8n=8 táblán az összes megoldások száma 92; a forgatás és tükrözés szerinti alapmegoldások száma 12. A mérési naplóban ezért rögzíteni kell, hogy az algoritmus symetria szerint deduplikál-e vagy sem.

További optimalizálás a bitmaszkos ábrázolás: a foglaltsági halmazokat egy-egy gépi szó bitjei tárolják, így a szabad oszlopok listája bitműveletekkel állítható elő. Ez a bemutatott logikai tömbös változatnál gyorsabb, de kevésbé áttekinthető, ezért a laborban a logikai tömbökkel kezdjük.

20.2.6 A Hamilton-kör probléma

Legyen G=(V,E)G = (V, E) irányítatlan egyszerű gráf, amelyben n=|V|n = |V| csúcs van. Hamilton-körnek nevezzük a csúcsok olyan körbe rendezését, amely minden csúcsot pontosan egyszer érint. Formálisan egy

(v0,v1,…,vn−1)(v_0, v_1, \ldots, v_{n-1})

csúcssorozat Hamilton-kör, ha a sorozat a csúcsok permutációja, minden ii-re {vi,vi+1}∈E\{v_i, v_{i+1}\} \in E, és {vn−1,v0}∈E\{v_{n-1}, v_0\} \in E.

Bemenet: az nn csúcsú gráf szomszédsági listája; a csúcsok azonosítói 0,1,…,n−10, 1, \ldots, n-1.
Kimenet: egy Hamilton-kör csúcssorrendje, vagy HIÁNY, ha nem létezik.
Előfeltétel: n≥1n \ge 1; a gráf irányítatlan és egyszerű, azaz nincs önhurok és nincs párhuzamos él.
Utófeltétel: a kimenet hossza nn, minden csúcs pontosan egyszer szerepel benne, a szomszédos elemek és a záró pár között él van.
Leállási feltétel: a rekurzió mélysége legfeljebb n+1n+1, és minden csúcsnak véges sok szomszédja van.

A Hamilton-kör létezésének eldöntése NP-teljes probléma, ezért nem ismert polinomiális algoritmusa. A visszalépéses keresés legrosszabb esetben a csúcsok permutációit járhatja be; a gyakorlati hatékonyságot a vágások és a heurisztikák adják.

20.2.7 Alap backtracking

A kör eltolási szimmetriáját kihasználva a 0. csúcsot rögzíthetjük a kör első helyére. A path lista az aktuális részleges kört tárolja. Amikor a path hossza eléri nn-et, már csak a záró élet kell ellenőrizni.

Hamilton-kor(adj[0..n-1]):
    // adj rendezett szomszédsági listák listája
    visited[0..n-1] ← hamis
    path ← [0]
    visited[0] ← igaz

    Keres(u, mélység):
        ha mélység == n:
            ha 0 ∈ adj[u]:
                return path másolata
            return HIÁNY
        minden v ∈ adj[u]:
            ha visited[v] hamis:
                path.hozzáad(v)
                visited[v] ← igaz
                eredmény ← Keres(v, mélység + 1)
                ha eredmény != HIÁNY:
                    return eredmény
                visited[v] ← hamis
                path.töröl_utolsó()
        return HIÁNY

    return Keres(0, 1)

A Python-megfelelő:

def hamilton_cycle(adj: list[list[int]]) -> list[int] | None:
    n = len(adj)
    # Determinizmusért rendezzük a szomszédlistákat.
    adj = [sorted(neighbors) for neighbors in adj]
    visited = [False] * n
    path = [0]
    visited[0] = True

    def backtrack(u: int, depth: int) -> bool:
        if depth == n:
            return 0 in adj[u]
        for v in adj[u]:
            if not visited[v]:
                visited[v] = True
                path.append(v)
                if backtrack(v, depth + 1):
                    return True
                path.pop()
                visited[v] = False
        return False

    if backtrack(0, 1):
        return path.copy()
    return None

A 0 in adj[u] ellenőrzés lineáris időt is igényelhet; érdemes a záró szomszédságot külön logikai értékként vagy halmazmetszetként tárolni, de ez a bemutatott kódban az áttekinthetőséget szolgálja.

20.2.8 Korrektségi vázlat

Invariáns: a Keres(u, depth) hívás előtt a path hossza depth, a benne lévő csúcsok páronként különbözők, minden szomszédos pár éllel van összekötve, és a visited tömb pontosan a path elemeit tartalmazza.

Bázis: a kezdő path = [0], depth = 1, visited[0] = True.

Lépés: ha v nem látogatott szomszéd, a hozzáfűzés után az invariáns depth + 1-re is teljesül. A sikertelen ág visszalépéskor eltávolítja v-t és visszaállítja a látogatottságot, így a többi ág tiszta állapotot lát.

Teljes megoldás: ha depth == n, akkor minden csúcs a path-ban van. Ha a 0 csúcs szomszédja az aktuális utolsó csúcsnak, akkor a záró él is létezik, tehát a path Hamilton-kört alkot.

Teljesség: minden Hamilton-kör ábrázolható úgy, hogy a 0. csúcs a kör első eleme. A rekurzió a 0-ból indulva minden szomszédot megvizsgál, ezért a kört megtalálja.

Leállás: a mélység minden hívásnál nő, és legfeljebb nn; a bejárás véges.

20.2.9 Kényszerterjesztés és vágások

Az alap backtracking csak a látogatottságot ellenőrzi. A kényszerterjesztés azt jelenti, hogy a részleges út és a maradék gráf szerkezetéből következő kényszereket is használjuk a holtágak levágására.

A legegyszerűbb előszűrés: ha bármely csúcs foka kisebb, mint 2, akkor nem létezhet Hamilton-kör, hiszen a körön minden csúcsnak legalább két szomszédja kell legyen.

A rekurzió közben a nem látogatott csúcsok RR halmazára további fokszám-szabályokat alkalmazhatunk. Ha egy w∈Rw \in R csúcsnak RR-ben nincs szomszédja, akkor ww a hátralévő körben legfeljebb a jelenlegi út végéhez vagy a kezdőcsúcshoz kapcsolódhatna. Ha egyikhez sem kapcsolódik, az ág halott. Ha ww-nek RR-ben pontosan egy szomszédja van, és sem az aktuális útvég, sem a kezdőcsúcs nem jelent megfelelő második kapcsolatot, akkor az ág szintén lezárható.

Egy erősebb, de költségesebb vágás a maradék gráf összefüggőségének ellenőrzése. Ha a nem látogatott csúcsokra megszorított gráf nem összefüggő, akkor a kör hátralévő része nem járhatja be az összes komponenst, tehát az ág halott. Ez a vizsgálat O(n+m)O(n+m) időt igényel minden rekurzív hívásban, ezért kis gráfokon hasznos, nagyobbakon a mérési naplóban érdemes megfigyelni, hogy a vágás mennyi hívást takarít meg.

Heurisztikaként a szomszédok fokszám szerinti rendezése is gyorsíthat: a kisebb fokú csúcsokat előbb próbálva a kényszerek hamarabb zárják le a holtágakat.

20.2.10 Példa kis gráfon

Legyen a gráf csúcshalmaza V={0,1,2,3,4}V = \{0,1,2,3,4\}, és az élek:

{0,1},{0,2},{0,4},{1,2},{1,3},{2,3},{2,4},{3,4}.\{0,1\}, \{0,2\}, \{0,4\}, \{1,2\}, \{1,3\}, \{2,3\}, \{2,4\}, \{3,4\}.

Ebben a gráfban van Hamilton-kör, például:

0−1−3−4−2−0.0 - 1 - 3 - 4 - 2 - 0.

A rendezett szomszédsági listák:

0: [1, 2, 4]
1: [0, 2, 3]
2: [0, 1, 3, 4]
3: [1, 2, 4]
4: [0, 2, 3]

A backtracking a path = [0] állapotból indul. Az első lehetséges szomszéd 11, így path = [0, 1]. A következő nem látogatott szomszéd 22, majd 33, majd 44. Amikor a path hossza eléri az 5-öt, a záró él 4−04 - 0 létezik, ezért az algoritmus a [0, 1, 2, 3, 4] kört adja vissza. Más élrendezés esetén a keresés további ágakat is bejárna, mielőtt a megoldást megtalálja.

Ellenpéldaként vegyünk egy csillaggráfot, amelyben a 0. csúcs a középpont, és a többi csúcs csak a középponthoz kapcsolódik. Nincs Hamilton-kör, mert a középpontot elhagyva mindig vissza kell térni, és a levelek között nincs él. Az algoritmus a lehetséges ágak bejárása után HIÁNY értéket ad.

20.2.11 Szimmetria és optimalizálás Hamilton-körnél

A kör eltolási szimmetriája miatt a kezdőcsúcs rögzítése nn-szeresére csökkenti a keresési teret. Az irány szimmetria miatt azonban ugyanaz a kör két irányban is előállhat:

(0,a,…,b,0)és(0,b,…,a,0).(0, a, \ldots, b, 0) \quad \text{és} \quad (0, b, \ldots, a, 0).

Ha az összes Hamilton-kört listázni szeretnénk, ezt a duplikációt a záró ellenőrzésnél szűrhetjük: csak akkor adjuk ki a kört, ha

𝚙𝚊𝚝𝚑[𝟷]<𝚙𝚊𝚝𝚑[𝚗-𝟷].\texttt{path[1]} < \texttt{path[n-1]}.

Így minden kör pontosan egyszer jelenik meg, mert a két lehetséges irány közül pontosan az egyiknél teljesül az egyenlőtlenség. Ez a szűrés a kimenetet deduplikálja, de a mélyebb keresési ágakban nem feltétlenül csökkenti a munkát. A laborban mérhető, hogy a szimmetriavágás mennyi rekurzív hívást és futásidőt takarít meg.

20.2.12 Komplexitás

N-királynő. A teljes állapottér nnn^n lenne, ha minden sorba tetszőleges oszlopot választhatnánk. A foglaltsági halmazokkal végzett ütközésvizsgálat és az azonnali vágás ezt jelentősen csökkenti. A bejárt rekurzív csúcsok számát nehéz zárt alakban megadni, mert az ütközések eloszlása függ az nn-től. A pszeudokód minden csúcsban nn jelöltet tekint, és a vizsgálat O(1)O(1), ezért ha a bejárt csúcsok száma SS, az idő O(nS)O(nS). A memória O(n)O(n) a rekurzió és a segédtömbök miatt.

A megoldások száma nem monoton növekszik: n=4n=4-re 2, n=8n=8-ra 92, n=9n=9-re 352, n=10n=10-re 724. A szimmetria szerinti alapmegoldások ennél lényegesen kevesebben vannak.

Hamilton-kör. Az alap visszalépés legrosszabb esete O(n!)O(n!), mert a csúcsok permutációit járhatja be. A fokszám- és összefüggőségi vágások a gyakorlati esetet javítják, de a legrosszabb korlátot nem változtatják meg. A memóriaigény O(n+m)O(n + m) a szomszédsági listáknak, és O(n)O(n) a rekurziós veremnek és a path tárolásának.

    • nem összefüggő gráf: nincs kör;
    • rögzített seeddel generált véletlen gráf: a kimenetet érvényesség szempontjából ellenőrizd, ne konkrét kört várj.
  3. A Hamilton-kör érvényességét független ellenőrző függvénnyel validáld: ellenőrizze, hogy a lista valóban permutáció, és minden szomszédos pár, valamint a záró pár éllel van összekötve.
  4. Mérd a rekurzív hívások számát és a futásidőt a fenti gráfokon, valamint egy n=8n=8 csúcsú, p=0.5p=0.5 élvalószínűségű véletlen gráfon.

A mérési naplóban tüntesd fel a rekurzív hívások számát, az esetleges vágott ágak számát és a futásidőt. A mért és várt eredményeket táblázatban különítsd el; ha egy mérést nem futtattál, ne mutasd be ellenőrzött eredményként.

20.2.14 Tipikus hibák

  1. A visszaállítás hiánya N-királynőben. Ha a foglaltsági tömbökben igaz érték marad, a párhuzamos ágak hamis ütközéseket látnak, és megoldások vesznek el.
  2. Az átlóindex rossz eltolása. 0-tól indexelt kódban a r - c + n - 1 és r + c tartománya 0…2n−20 \ldots 2n-2; 1-től indexelve r - c + n és r + c - 1 használandó.
  3. Csak az oszlopütközés ellenőrzése. Az átlóütközés elhagyása hamis megoldásokat eredményez.
  4. A kezdőcsúcs rögzítésének elfelejtése Hamilton-körnél. Ugyanaz a kör nn eltolt alakban jelenik meg.
  5. A záró él ellenőrzésének hiánya. Az algoritmus Hamilton-utat talál kör helyett.
  6. A visited tömb visszaállításának elmulasztása. A sikertelen ág után a többi ág nem tudja meglátogatni az adott csúcsot.
  7. Rendezetlen szomszédlista. Irányítatlan gráfokban a determinisztikus kimenet érdekében a szomszédlistákat rendezni kell, vagy a tesztekben a kimenetet normalizálni.
  8. Önhurok és párhuzamos él kezelése. A Hamilton-kör definíciója egyszerű gráfra vonatkozik; az inputot validálni kell vagy a gráf reprezentációban kizárni.
