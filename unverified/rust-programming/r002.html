2.2 Eszközlánc: rustup, cargo, rustfmt, clippy, dokumentáció

Egy C++-projektben a buildrendszer, a függőségkezelés, a formázás és a statikus elemzés általában külön eszközökből áll össze: CMake vagy Make, vcpkg vagy Conan, clang-format, clang-tidy vagy cppcheck, és gyakran még egy CI-szkript, amely ezeket összefogja. A Rust ezt a négy területet egyetlen eszközláncba, a Cargo köré szervezi: a rustup a fordítót és a kiegészítőket telepíti, a cargo buildel, tesztel, függőséget tölt le és dokumentációt generál, a rustfmt formáz, a clippy pedig a nyelv saját statikus elemzője. Ez a fejezet ezt a munkafolyamatot alapozza meg; a későbbi rkv-laborok mind ezekre a parancsokra épülnek.

2.2.1 Fogalmak és szabályok

Definíció. A rustup a Rust toolchaineket kezelő eszköz. Egy toolchain a Rust fordítóból (rustc), a csomagkezelőből (cargo), a standard könyvtárból és választható komponensekből áll. A három fő csatorna:

  • stable: a stabil kiadás, éles kódhoz ez az ajánlott;
  • beta: a következő stable előzetese;
  • nightly: a legfrissebb, de instabil funkciókat is tartalmazó build, kísérletezéshez.

Szabály. A könyv projektjei a stable toolchaint használják; nightly-only funkciót csak akkor említünk, ha azt külön jelöljük, és soha nem építünk rá éles kódot.

A rustup komponenseket is kezel: rustfmt (formázó), clippy (linter), rust-docs (helyi dokumentáció), rust-analyzer (nyelvi szerver). A rustup component add <név> paranccsal telepíthetők.

Definíció. A Cargo a Rust buildrendszere és csomagkezelője. Egy Cargo-projekt lelkét a Cargo.toml manifest adja, amely a csomag nevét, verzióját, editionjét és függőségeit tartalmazza. A Cargo.lock a feloldott függőségi gráf pontos verzióit rögzíti; könyvtár (library) crate esetén általában nem commitoljuk, bináris alkalmazásnál viszont igen, mert reprodukálható buildet ad.

A Cargo alapvető parancsai:

  • cargo new <név> – új projekt létrehozása;
  • cargo build – debug profilú fordítás, alapértelmezés szerint a target/debug/ könyvtárba;
  • cargo build --release – optimalizált release fordítás a target/release/ könyvtárba;
  • cargo run – build, majd futtatás;
  • cargo test – tesztfordítás és tesztek futtatása;
  • cargo check – csak típusellenőrzés, kódgenerálás nélkül; gyorsabb, mint a teljes build;
  • cargo fmt – a rustfmt futtatása a projektre;
  • cargo clippy – a clippy linter futtatása;
  • cargo doc --open – dokumentáció generálása és megnyitása böngészőben.

Szabály. A target/ könyvtár mindig generált, nem kerül verziókezelésbe. A cargo clean törli, a cargo build újra létrehozza.

A debug profil gyors fordításra optimalizál, cserébe lassabb futást ad; a release profil lassabb fordításért cserébe agresszív optimalizációt (opt-level = 3) és kevesebb futásidejű ellenőrzést kapcsol be. A profilok a Cargo.toml [profile.*] szekcióiban hangolhatók, de az alapértelmezések a legtöbb projekthez megfelelők.

2.2.2 C++ ↔︎ Rust összevetés

A C++-világban a buildrendszer és a csomagkezelő szét van választva; a Rustban a Cargo mindkettőt egyszerre végzi. Tekintsünk egy minimális C++ programot és annak CMake-buildjét, majd a Rust-megfelelőt.

// main.cpp
#include <iostream>
int main() {
    std::cout << "Hello, C++!\n";
}

// CMakeLists.txt
cmake_minimum_required(VERSION 3.16)
project(hello_cpp)
add_executable(hello_cpp main.cpp)
// src/main.rs
fn main() {
    println!("Hello, Rust!");
}
# Cargo.toml
[package]
name = "hello_rust"
version = "0.1.0"
edition = "2024"

[dependencies]

A különbség nem csak szintaktikai. A CMake egy általános célú buildgenerátor, amely mögött Make, Ninja vagy Visual Studio áll; a Cargo közvetlenül hívja a rustc-t, és maga gondoskodik a függőségek letöltéséről, verziózásáról és a fordítási sorrendről. A vcpkg/Conan rendszerekben a függőségek gyakran rendszerszintű vagy félglobális könyvtárakba kerülnek; a Cargo a függőségeket a ~/.cargo/registry/ gyorsítótárba tölti, és projektenként, a Cargo.lock alapján reprodukálhatóan építi be őket.

A minőségi eszközök is szorosabban integráltak. A C++-ban a clang-format és a clang-tidy külön parancsok, gyakran egyedi konfigurációval; a Rustban a cargo fmt és a cargo clippy a manifestben vagy külön konfigurációs fájlokban állítható, de működésük alapértelmezésben is konzisztens. A rustdoc a Doxygenhez hasonló szerepet tölt be, de a dokumentációs kommentek (///) a nyelv szintjén kapcsolódnak a kódhoz, és a generált HTML-be a dokumentációs tesztpéldák is bekerülnek.

2.2.3 Kidolgozott labor: a teljes eszközlánc működés közben

Munkakönyvtár: ~/rust-labor/r002/

A labor célja: telepíteni a stable toolchaint, létrehozni egy Cargo-projektet, lefuttatni a buildet, a teszteket, a formázót és a lintert, majd megnézni a generált dokumentációt. A labor kimenete egy hello nevű bináris crate lesz, amelyet később a Modules és láthatóság alfejezetben könyvtári modullá bővítünk.

2.2.3.1 1. lépés: rustup telepítése (ha még nincs)

Linuxon a hivatalos telepítő:

curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh

A telepítő a ~/.cargo/bin/ könyvtárba helyezi a binárisokat, és a ~/.cargo/env fájlban elérhető környezeti beállítást hoz létre. Új terminálablakban vagy a source ~/.cargo/env kiadása után ellenőrizzük:

rustup --version
rustc --version
cargo --version

A rustup show megjeleníti az aktív toolchaint és a telepített komponenseket. Ha a stable toolchain még nincs telepítve:

rustup default stable
rustup component add rustfmt clippy rust-docs

A rustup component list --installed paranccsal ellenőrizhetjük, hogy minden komponens megvan-e. A pontos verziószámok a kiadástól függnek, ezért a kimenetet itt nem tüntetjük fel.

2.2.3.2 2. lépés: projekt létrehozása

mkdir -p ~/rust-labor/r002
cd ~/rust-labor/r002
cargo new hello
cd hello

A cargo new létrehozza a következő struktúrát:

hello/
├── Cargo.toml
└── src
    └── main.rs

A generált Cargo.toml tartalma:

[package]
name = "hello"
version = "0.1.0"
edition = "2024"

[dependencies]

Az edition a nyelvi kiadást jelöli; a 2024-es edition a jelenlegi stabil Rust által támogatott, de ha a telepített toolchain korábbi, a cargo new automatikusan a 2021-es editiont használja. Az edition nem a toolchain verziója, hanem a nyelvi kompatibilitási szint; erről később, a Függőségek, feature-ök, verziózás és workspace-ek alfejezetben lesz részletesebben szó.

A generált src/main.rs:

fn main() {
    println!("Hello, world!");
}

2.2.3.3 3. lépés: build, futtatás, teszt

cargo build

A parancs lefordítja a programot, és létrehozza a target/debug/hello binárist. A cargo run újrafordít, ha szükséges, majd futtat:

cargo run

Várt kimenet:

    Finished `dev` profile [unoptimized + debuginfo] target(s) in 0.02s
     Running `target/debug/hello`
Hello, world!

A cargo check csak a típushelyességet ellenőrzi, nem generál futtatható kódot; ezért gyorsabb, és akkor hasznos, ha csak a fordítási hibákat akarjuk látni:

cargo check

A teszteléshez adjunk egy egyszerű tesztet a src/main.rs-hez, vagy hozzunk létre egy src/lib.rs-t. Tiszta bináris crate-ben a tesztet a main.rs aljára tehetjük, de idiomatikusabb a könyvtári részt különválasztani. Készítsünk egy src/lib.rs fájlt:

/// Visszaad egy üdvözlő üzenetet a megadott névvel.
pub fn greet(name: &str) -> String {
    format!("Hello, {name}!")
}

#[cfg(test)]
mod tests {
    use super::greet;

    #[test]
    fn greet_matches() {
        assert_eq!(greet("Rust"), "Hello, Rust!");
    }
}

Most a cargo test lefuttatja a tesztet:

cargo test

Várt kimenet (lerövidítve):

running 1 test
test tests::greet_matches ... ok

test result: ok. 1 passed; 0 failed; 0 ignored; 0 measured; 0 filtered out

A hello crate így már bináris és könyvtári célpontot is tartalmaz. A Cargo.toml automatikusan érzékeli a src/lib.rs jelenlétét; ezt a Structok és metódusok alfejezetben fogjuk kihasználni.

2.2.3.4 4. lépés: rustfmt és clippy

A formázó futtatása:

cargo fmt

Ez átalakítja az összes .rs fájlt a hivatalos stílus szerint. Ellenőrzésre a cargo fmt -- --check parancs szolgál, amely hibával tér vissza, ha a kód nincs formázva.

A clippy futtatása:

cargo clippy

A clippy statikus elemzést végez, és idiomatikusabb, gyorsabb vagy biztonságosabb kódot javasol. Példaként szándékosan írjunk rosszabbul olvasható kódot a src/lib.rs-be:

pub fn is_positive(n: i32) -> bool {
    if n > 0 {
        return true;
    } else {
        return false;
    }
}

Ez a változat nem fordul le a clippy alapértelmezett figyelmeztetési szintje mellett? De a clippy warningot ad: needless_return és if_same_then_else. A pontos üzenet verziófüggő, de a lényeg: a return true; és return false; felesleges. A cargo clippy kimenete így nézhet ki:

warning: needless return statement
 --> src/lib.rs:3:9
  |
3 |         return true;
  |         ^^^^^^^^^^^
  = note: `#[warn(clippy::needless_return)]` on by default

A javítás:

pub fn is_positive(n: i32) -> bool {
    n > 0
}

Futtassuk újra a cargo clippy-t, és ellenőrizzük, hogy nincs több figyelmeztetés. Ha a clippy-figyelmeztetéseket hibává akarjuk alakítani (például CI-ban), használhatjuk a -D warnings kapcsolót:

cargo clippy -- -D warnings

Ez minden clippy-warningot fordítási hibává alakít. A munkafolyamatban ez hasznos, mert a figyelmeztetések nem maradnak észrevétlenek.

2.2.3.5 5. lépés: dokumentáció generálása

A cargo doc a /// dokumentációs kommentekből HTML-dokumentációt generál a target/doc/ könyvtárba. A --open kapcsoló megnyitja a böngészőben, de a laborban csak a generálást futtatjuk:

cargo doc

A generált oldal a target/doc/hello/index.html fájlban érhető el. A dokumentációs kommentekben lévő kódpéldák automatikusan tesztelődnek a cargo test során: a /// kommentben elhelyezett ```rust blokkok dok-tesztként futnak le. A cargo test futtatásakor a kimenetben ez is megjelenik:

   Doc-tests hello

running 1 test
test src/lib.rs - greet (line 1) ... ok

A rust-analyzer egy nyelvi szerver, amely a szerkesztőbe integrálva valós idejű kódkiegészítést, hibajelzést és navigációt biztosít. Telepítése toolchain-komponensként lehetséges:

rustup component add rust-analyzer

A pontos IDE-integráció (VS Code, CLion, Neovim) a szerkesztőtől függ; a rust-analyzer a Cargo manifestjét és a target/ könyvtár metaadatait használja a pontos elemzéshez.

2.2.4 A Cargo projekt rétegei

Az alábbi rétegábra a projekt fizikai szerkezetét mutatja.

A Cargo.toml a projekt deklaratív leírása: mi a csomag neve, milyen függőségei vannak, milyen buildprofilokat használ. A Cargo.lock a feloldott függőségi fa pontos verzióit tartalmazza; binárisok esetén commitoljuk, hogy a build reprodukálható legyen. A target/ mindig generált.

2.2.5 Tipikus hibák és átállási csapdák

  1. A target/ könyvtár verziókezelése. C++-projekteknél a build könyvtár (pl. build/) gyakran a repo része vagy a .gitignore-ban szerepel; Rustban a target/ soha nem kerül be a verziókezelésbe. Ha véletlenül mégis, a .gitignore-hoz adjuk hozzá.

  2. A cargo run mindig debug módban fut. A release módú futtatáshoz cargo run --release szükséges. A C++-ban a build típusát a CMake CMAKE_BUILD_TYPE változója szabályozza; Rustban a --release kapcsoló a Cargo parancs része, nem a manifesté.

  3. A Cargo.lock kezelése könyvtár crate-ben. Ha cargo new --lib paranccsal könyvtárat hozunk létre, a generált .gitignore nem tartalmazza a Cargo.lock-ot, mert a könyvtárakat általában függőségként használják, és a lockfájlt a fogyasztó bináris rögzíti. Ha a könyvtár önállóan is futtatható teszteket, a lockfájl commitolható, de ez a crate jellegétől függ.

  4. A clippy figyelmeztetések figyelmen kívül hagyása. A C++-ban a clang-tidy gyakran túl zajos, ezért sokan kikapcsolják; a Rust clippy azonban a nyelv idiomatikus használatát tanítja, és a figyelmeztetések gyakran valós tervezési hibákra utalnak. A -D warnings használata a CI-ban jó gyakorlat.

2.2.6 Feladatok

2.2.6.1 1. Fogalmi kérdés

Mi a különbség a Cargo.toml és a Cargo.lock között? Melyiket commitoljuk bináris, és melyiket könyvtár crate esetén, és miért?

2.2.6.2 2. C++-munkafolyamat átültetése

Adott egy C++-projekt, amely a következő elemekből áll: main.cpp, CMakeLists.txt, egy format.sh szkript (clang-format -i), és egy lint.sh (clang-tidy). Írd le, milyen Cargo-parancsokkal váltanád ki ezeket a Rustban.

2.2.6.3 3. Implementációs feladat

Hozz létre egy új Cargo-projektet counter néven a ~/rust-labor/r002/counter/ könyvtárban. A program tartalmazzon egy src/lib.rs fájlt egy increment függvénnyel, amely egy i32 értékét eggyel növeli, és egy tesztet, amely ellenőrzi a működését. Futtasd a cargo test és a cargo clippy parancsokat.

2.2.6.4 4. Hibajavítás és refaktorálás

A laborban létrehozott hello projekt src/lib.rs-ében szándékosan hagyj clippy-figyelmeztetést (például if n > 0 { true } else { false }). Futtasd a cargo clippy parancsot, olvasd el a figyelmeztetést, javítsd a kódot, majd ellenőrizd, hogy a cargo clippy -- -D warnings már hibamentesen fut le.

2.2.7 Megoldások

2.2.7.1 1. Fogalmi kérdés megoldása

A Cargo.toml a manifest: a projekt neve, verziója, editionje és a függőségek leírása. A Cargo.lock a feloldott függőségi gráf pontos verzióit és ellenőrzőösszegeit tartalmazza. Bináris alkalmazásnál a Cargo.lock-ot commitoljuk, mert így a build reprodukálható: mindenki pontosan ugyanazokat a függőségi verziókat kapja. Könyvtár crate esetén a lockfájl általában nem kerül a verziókezelésbe, mert a könyvtárat függőségként használó bináris crate saját lockfájlja úgyis rögzíti a teljes gráfot; a könyvtár lockfájlja fölösleges zajt vinne a felhasználó buildjébe.

2.2.7.2 2. C++-munkafolyamat átültetése megoldása

  • CMakeLists.txt + make → Cargo.toml + cargo build
  • format.sh → cargo fmt
  • lint.sh → cargo clippy
  • A tesztek futtatása C++-ban gyakran külön célpont, Rustban cargo test
  • A dokumentáció generálása Doxygen helyett cargo doc --open

2.2.7.3 3. Implementációs feladat megoldása

mkdir -p ~/rust-labor/r002/counter
cd ~/rust-labor/r002/counter
cargo new counter
cd counter

A src/lib.rs tartalma:

/// Eggyel növeli a kapott számot.
pub fn increment(n: i32) -> i32 {
    n + 1
}

#[cfg(test)]
mod tests {
    use super::increment;

    #[test]
    fn increments() {
        assert_eq!(increment(41), 42);
    }
}

Futtatás:

cargo test
cargo clippy

A cargo test lefuttatja a tesztet, a cargo clippy pedig nem ad figyelmeztetést.

2.2.7.4 4. Hibajavítás és refaktorálás megoldása

A src/lib.rs rossz változata:

pub fn is_even(n: i32) -> bool {
    if n % 2 == 0 {
        true
    } else {
        false
    }
}

A cargo clippy figyelmeztet: clippy::needless_bool – a if kifejezés helyett közvetlenül a feltétel használandó. Javított változat:

pub fn is_even(n: i32) -> bool {
    n % 2 == 0
}

Futtatás ellenőrzéshez:

cargo clippy -- -D warnings

Nem érkezik hiba, a kód idiomatikus.

2.2.8 Rövid összefoglaló

Ez az alfejezet bemutatta a Rust eszközlánc alapjait. A rustup a toolchaineket és komponenseket kezeli; a Cargo a buildrendszer, csomagkezelő, tesztfuttató és dokumentációgeneráló. Megtanultuk a cargo new, build, run, test, check, fmt, clippy és doc parancsokat, valamint a Cargo.toml és Cargo.lock szerepét. A debug és release profilok a target/debug/ és target/release/ könyvtárakba építenek. A rustfmt a formázást, a clippy a statikus elemzést végzi; a rustdoc a /// kommentekből generál dokumentációt, és a kódpéldák automatikusan tesztelődnek. A Továbbvitt eredmény: ez a Cargo-munkafolyamat az alapja az rkv mintaprojekt indítása: Cargo-workspace és első CLI alfejezetnek, ahol az rkv workspace-t hozzuk létre, a Modulok és láthatóság: header nélküli világ alfejezetnek, ahol a modulokat szervezzük, és az Unit-, integrációs és dokumentációs tesztek alfejezetnek, ahol a tesztelést mélyítjük el.

2.2.9 Források és ellenőrzési hiányok

A fejezet a Rust hivatalos dokumentációjának (rustup, Cargo, Clippy, Edition Guide) stabil ismereteire épít. A pontos parancskimenetek, a crate-verziók és a toolchain-verziók kiadásonként változhatnak; ezeket a hivatalos rustup show, cargo --version és a docs.rs dokumentáció alapján ellenőrizni kell. A 2024-es edition elérhetősége a telepített stable toolchain verziójától függ; ha a cargo new 2021-es editiont generál, az is megfelelő, a nyelvi különbségek a későbbi fejezetekben jelölve lesznek.
