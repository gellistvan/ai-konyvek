4.3 Mintaillesztés: match, if let, let else és a minták

4.3.1 Motiváció

A C++17 switch utasítása csak egész típusokon működik; enumok esetén is csak annyit tud, hogy a felsorolt értékekhez ugrik. Ha egy enum class-szal dolgozunk, a fordító legfeljebb figyelmeztet, ha egy új értéket kihagytunk, de nem tud típusos destrukturálást, kimerítőség-ellenőrzést vagy bonyolult feltételeket. A std::variant és a std::visit már közelebb visz a célhoz, de a látogató sablonok és a generikus lambda körülményesek, és a C++17 kódban a hibaüzenetek gyakran sablonmélységbe vezetnek.

A Rust match kifejezése éppen azt a hiányt pótolja, amit egy C++-fejlesztő a switch-ben és a std::visitben keres: típusos, kimerítő, értékekre, mintákra és feltételekre egyaránt illeszthető, és kifejezésként használható. A fordító fordítási időben észleli, ha egy enum új variánsa után elfelejtettünk egy ágat frissíteni – ez a refaktorálás egyik legerősebb eszköze.

4.3.2 Fogalmak és szabályok

Definíció. A mintaillesztés (pattern matching) olyan szerkezet, amely egy értéket egy mintával (pattern) vet össze, és sikeres illeszkedés esetén a minta változóihoz kötött értékekkel végrehajt egy kódágat. A Rust match kifejezés minden ága minta => kifejezés alakú.

Definíció. A match kimerítő (exhaustive), ha a célérték típusának minden lehetséges értékéhez tartozik legalább egy illeszkedő minta. Enumoknál a fordító ezt ellenőrzi, és ha hiányzik egy variáns, hibát ad.

Szabály. A match kifejezés minden ága ugyanarra a típusra értékelődik ki. Az ágak sorrendben kiértékelődnek, és az első illeszkedő ág hajtódik végre.

Szabály. A _ minta bármely értékre illeszkedik, de nem köt értéket. A _ használata „mindent elnyelő” ágat ad, amely kimerítővé teszi a match-et; ezt azonban megfontoltan kell használni, mert elrejtheti az új variáns kezelését.

Definíció. A guard egy if feltétel a minta után, amely tovább szűkíti az illeszkedést: Some(x) if x > 0 => .... Guard csak akkor fut le, ha a minta már illeszkedett, és ha a guard hamis, a következő ág próbálkozik.

Definíció. A @ binding lehetővé teszi, hogy egy részmintához tartozó teljes értéket elnevezzük: pair @ (x, y) => ... vagy Some(n @ 1..=5) => ....

Definíció. A refutable minta olyan, amely nem feltétlenül illeszkedik (pl. Some(x)), az irrefutable minta mindig illeszkedik (pl. x, _, (a, b)). A let utasítás csak irrefutable mintát fogadhat el; a let else ezt a korlátot oldja fel azzal, hogy ha a minta nem illeszkedik, az else ág fut le.

4.3.3 C++ ↔︎ Rust összevetés

Vegyünk egy C++17 példát, ahol egy std::variant-ot kell feldolgoznunk látogatóval:

#include <variant>
#include <string>
#include <iostream>

using Value = std::variant<int, std::string>;

struct Printer {
    void operator()(int i) const { std::cout << "int: " << i << '\n'; }
    void operator()(const std::string& s) const { std::cout << "string: " << s << '\n'; }
};

int main() {
    Value v = 42;
    std::visit(Printer{}, v);
}

Rustban ugyanez match-csel:

enum Value {
    Int(i32),
    String(String),
}

fn main() {
    let v = Value::Int(42);
    match v {
        Value::Int(i) => println!("int: {i}"),
        Value::String(s) => println!("string: {s}"),
    }
}

A különbség: - A Rust match kifejezés, visszatérési értéke van; a C++ std::visit általában void vagy sablonos eredmény. - A Rust enum variánsai közvetlenül tartalmazzák az értékeket, a minta pedig egyszerre bontja ki azokat; a C++ std::variant alternatíváit az indexek vagy a std::get kezeli, ami hiba esetén futásidejű kivételt dobhat. - Ha a Rust enumhoz új variánst veszünk fel, a match fordítási hibát ad, amíg nincs kezelve; a C++ std::visit látogatója is hibát adhat, de a hibaüzenet kevésbé közvetlen, és a switch alapú megközelítésnél gyakran csak figyelmeztetés sincs.

4.3.4 Kidolgozott példa: kimerítőség-ellenőrzés

Tekintsük a következő hibás Rust kódot, amely nem kezeli az összes variánst:

enum Color {
    Red,
    Green,
    Blue,
}

fn describe(c: Color) -> &'static str {
    match c {
        Color::Red => "piros",
        Color::Green => "zöld",
    }
}

Ez a változat szándékosan nem fordul le. A fordító hibaüzenetének lényege E0004 (nem kimerítő minta):

error[E0004]: non-exhaustive patterns: `Color::Blue` not covered
 --> src/main.rs:8:11
  |
8 |     match c {
  |           ^ pattern `Color::Blue` not covered

A javítás: egészítsük ki a hiányzó ággal, vagy használjunk _ ágat, ha tényleg minden más érték ugyanúgy kezelendő. Itt természetesebb a teljes felsorolás:

match c {
    Color::Red => "piros",
    Color::Green => "zöld",
    Color::Blue => "kék",
}

A kimerítőség-ellenőrzés a refaktorálás során válik igazán értékessé: ha később felveszünk egy Color::Yellow variánst, a fordító azonnal megmutatja az összes olyan match helyet, ahol frissíteni kell a logikát. Ez a C++ switch-ben csak jó esetben, figyelmeztetéssel működik.

4.3.5 Minták fajtái

A match ágak mintái sokfélék lehetnek:

  • Literálminta: 1, "hello", true.
  • Tartományminta: 1..=5 (zárt), 'a'..='z'.
  • Tuple és struct destrukturálás: (x, y), Point { x, y }.
  • Enum variáns destrukturálás: Some(x), Ok(v), Err(e).
  • Alminták kombinálása: Some((x, y)).
  • @ binding: n @ 1..=5 – az n a teljes értéket köti, miközben a tartományra is illeszkedik.
  • Guard: Some(n) if n % 2 == 0 => ....

Példa guard és @ binding használatára:

fn classify(n: i32) -> String {
    match n {
        n @ 0..=9 => format!("egyjegyű: {n}"),
        n if n < 0 => format!("negatív: {n}"),
        n => format!("nagy: {n}"),
    }
}

Itt az első ág a n @ 0..=9 mintával egyszerre köti a teljes értéket és ellenőrzi a tartományt; a második ág guardot használ; a harmadik minden maradékot elkap.

4.3.6 if let, while let, let else

A match gyakran akkor is szükséges, ha csak egyetlen minta érdekel. Az if let kényelmes szintaktikai cukor, amely egyetlen refutable mintát ellenőriz:

let opt: Option<i32> = Some(5);
if let Some(x) = opt {
    println!("van érték: {x}");
} else {
    println!("nincs");
}

A while let hasonlóan működik, amíg a minta illeszkedik; tipikusan iterátoroknál használjuk:

let mut iter = vec![1, 2, 3].into_iter();
while let Some(x) = iter.next() {
    println!("{x}");
}

A let else lehetővé teszi, hogy refutable mintát használjunk egy let-ben, és ha nem illeszkedik, az else ág (amely nem térhet vissza normálisan, pl. return, break, panic!) fusson le:

let Some(config) = load_config() else {
    eprintln!("nincs konfiguráció");
    return;
};
// config itt már a kicsomagolt érték

4.3.7 Referencia-minták és binding-módok (előzetes)

Amikor a match egy referencia mögötti értéket vizsgál, a kötés alapértelmezés szerint referencia marad, nem másolódik. Például:

let opt = Some(String::from("hello"));
match &opt {
    Some(s) => println!("{s}"), // s típusa &String
    None => {}
}

Itt opt típusa Option<String>, de a match &opt-ra illeszkedik, ezért az s kötés &String típusú. Ha a belső értéket mozgatni akarnánk, a match opt kellene, de akkor az opt elveszne. A ref kulcsszóval explicitté tehetjük, hogy referenciát kössünk; a & a mintában pedig referenciát vár. Ez a téma a Borrowing fejezetben mélyül el; itt elég annyi, hogy a binding-módok határozzák meg, hogy a minta által kötött változó milyen módon (érték, &, &mut) kapja meg az értéket.

4.3.8 Labor: az rkv parancsfeldolgozója match-csel

Munkakönyvtár: ~/rust-labor/rkv/

Ebben a laborban a Command enumot és a hozzá tartozó egyszerű parancsértelmezőt építjük meg. Az enum az rkv-core könyvtárba kerül, a parancsfeldolgozó pedig a rkv-cli binárisba.

  1. Nyissuk meg a rkv-core/src/lib.rs fájlt, és adjuk hozzá a Command enumot Debug derive-tal:
#[derive(Debug)]
pub enum Command {
    Get(String),
    Set(String, String),
    Delete(String),
    List(Option<String>),
}
  1. Nyissuk meg a rkv-cli/src/main.rs fájlt, és írjuk be a következő kódot:
use rkv_core::Command;

fn parse_command(line: &str) -> Result<Command, String> {
    let mut parts = line.split_whitespace();
    match parts.next() {
        Some("GET") => {
            let key = match parts.next() {
                Some(k) => k.to_string(),
                None => return Err("GET requires a key".to_string()),
            };
            Ok(Command::Get(key))
        }
        Some("SET") => {
            let key = match parts.next() {
                Some(k) => k.to_string(),
                None => return Err("SET requires a key".to_string()),
            };
            let value = match parts.next() {
                Some(v) => v.to_string(),
                None => return Err("SET requires a value".to_string()),
            };
            Ok(Command::Set(key, value))
        }
        Some("DEL") => {
            let key = match parts.next() {
                Some(k) => k.to_string(),
                None => return Err("DEL requires a key".to_string()),
            };
            Ok(Command::Delete(key))
        }
        Some("LIST") => {
            let prefix = parts.next().map(|p| p.to_string());
            Ok(Command::List(prefix))
        }
        Some(other) => Err(format!("unknown command: {other}")),
        None => Err("empty line".to_string()),
    }
}

fn main() {
    let args: Vec<String> = std::env::args().collect();
    if args.len() < 2 {
        eprintln!("usage: rkv-cli <command>");
        std::process::exit(1);
    }
    match parse_command(&args[1]) {
        Ok(cmd) => println!("parsed: {cmd:?}"),
        Err(e) => eprintln!("error: {e}"),
    }
}
  1. Ellenőrizzük a kódot és futtassuk néhány példával:
cargo run -p rkv-cli -- "GET key"

Várt kimenet:

parsed: Get("key")
cargo run -p rkv-cli -- "SET name value"

Várt kimenet:

parsed: Set("name", "value")
cargo run -p rkv-cli -- "FOO"

Várt kimenet:

error: unknown command: FOO

Továbbvitt eredmény. A Command enum (rkv-core/src/lib.rs) és a parse_command függvény (rkv-cli/src/main.rs) alapjait később a Result, a ? operátor és a panic helye alfejezet finomítja saját hibatípusra, a trait objektumos és haladó típusrendszeri minták pedig újra felhasználják a kimerítő match elvét.

4.3.9 Tipikus hibák és átállási csapdák

  1. Túl korai _ ág. A _ kényelmes, de ha új variánst veszünk fel, a fordító nem figyelmeztet, mert a _ mindent elnyel. Inkább soroljuk fel a tényleges variánsokat, és csak akkor használjunk _-t, ha valóban minden más értékre ugyanaz a viselkedés.

  2. if let túlhasználata. Az if let elveszíti a kimerítőségi ellenőrzést. Ha egy enum több variánsát kell kezelni, a match a megfelelő eszköz; az if let csak akkor indokolt, ha tényleg csak egy ág érdekel, a többi pedig figyelmen kívül hagyandó.

  3. Guard logika erőltetése. A guard if feltétel, nem minta. Ha a feltétel a minta részeként kifejezhető (pl. tartományminta), akkor azt használjuk: 1..=5 jobb, mint n if n >= 1 && n <= 5. A guard akkor hasznos, ha a feltétel nem minta (pl. x % 2 == 0).

  4. Binding-módok félreértése. Amikor match &opt-ot írunk, a minta Some(s) a s-t &String-ként köti, nem String-ként. Ha a mozgatás szándékos, akkor match opt kell; ha a kölcsönzés szándékos referencia nélkül, akkor a ref vagy ref mut használható. Ez a hibás kód gyakran cannot move out of borrowed content hibaüzenethez vezet, amit a Borrowing fejezet tárgyal részletesen.

4.3.10 Feladatok

4.3.10.1 (a) Fogalmi kérdés: lefordul-e és miért?

Az alábbi kód szándékosan hibás:

enum Status {
    Pending,
    Running,
    Done,
}

fn describe(s: Status) -> &'static str {
    match s {
        Status::Pending => "várakozik",
        Status::Running => "fut",
    }
}

Mi a hiba, és hogyan javítható? Mondja ki a kimerítőségi szabályt.

4.3.10.2 (b) C++-kód átírása idiomatikus Rustra

Írja át a következő C++17 std::variant-os kódot Rustra match-csel, enumnal és destrukturálással:

#include <variant>
#include <string>
#include <iostream>

using Result = std::variant<int, std::string>;

int main() {
    Result r = 42;
    std::visit([](auto const& v) {
        if constexpr (std::is_same_v<std::decay_t<decltype(v)>, int>) {
            std::cout << "szám: " << v << '\n';
        } else {
            std::cout << "szöveg: " << v << '\n';
        }
    }, r);
}

4.3.10.3 (c) Implementációs feladat az rkv-ban

Bővítse a parse_command függvényt egy PING paranccsal, amely visszaad egy Command::Ping variánst. Ehhez módosítsa a Command enumot is. A PING parancsnak nincs argumentuma. Tesztelje a cargo run -p rkv-cli -- "PING" parancsot.

4.3.10.4 (d) Hibajavítás, refaktorálás

Az alábbi kód nem kimerítő, és a hibakezelés is if-else lánccal történik. Refaktorálja match-re és let else-re, hogy a kód idiomatikus legyen:

fn process(opt: Option<i32>) {
    if let Some(x) = opt {
        if x > 0 {
            println!("pozitív: {x}");
        } else {
            println!("nem pozitív: {x}");
        }
    } else {
        println!("nincs érték");
    }
}

A cél: egyetlen match használata guarddal.

4.3.11 Megoldások

4.3.11.1 (a)

A hiba: a match nem kimerítő, mert a Status::Done variáns nincs lefedve. A javítás:

match s {
    Status::Pending => "várakozik",
    Status::Running => "fut",
    Status::Done => "kész",
}

A kimerítőségi szabály: minden enum-variánsnak rendelkeznie kell legalább egy illeszkedő mintával, különben a fordító E0004 hibát ad.

4.3.11.2 (b)

Rust megfelelő:

enum Result {
    Number(i32),
    Text(String),
}

fn main() {
    let r = Result::Number(42);
    match r {
        Result::Number(n) => println!("szám: {n}"),
        Result::Text(s) => println!("szöveg: {s}"),
    }
}

A C++ if constexpr helyett a match enum variánsokra illeszkedik, és a destrukturálás automatikus.

4.3.11.3 (c)

A Command enumhoz adjuk hozzá a Ping variánst:

#[derive(Debug)]
pub enum Command {
    Get(String),
    Set(String, String),
    Delete(String),
    List(Option<String>),
    Ping,
}

A parse_command bővítése:

Some("PING") => Ok(Command::Ping),

A teljes függvény:

fn parse_command(line: &str) -> Result<Command, String> {
    let mut parts = line.split_whitespace();
    match parts.next() {
        Some("GET") => { /* mint korábban */ }
        Some("SET") => { /* mint korábban */ }
        Some("DEL") => { /* mint korábban */ }
        Some("LIST") => { /* mint korábban */ }
        Some("PING") => Ok(Command::Ping),
        Some(other) => Err(format!("unknown command: {other}")),
        None => Err("empty line".to_string()),
    }
}

Futtassuk:

cargo run -p rkv-cli -- "PING"

Várt kimenet:

parsed: Ping

4.3.11.4 (d)

Refaktorált változat:

fn process(opt: Option<i32>) {
    match opt {
        Some(x) if x > 0 => println!("pozitív: {x}"),
        Some(x) => println!("nem pozitív: {x}"),
        None => println!("nincs érték"),
    }
}

A let else akkor lenne hasznos, ha az opt értékére a függvény további részében szükség lenne; itt a match elegendő.

4.3.12 Rövid összefoglaló

Ebben az alfejezetben tanulmányoztuk a Rust match kifejezést, amely a C++ switch-nél és std::visit-nél kifejezőbb, kimerítő és típusos. A minták lehetnek literálok, tartományok, destrukturáló tuple/struct/enum minták, @ bindingek és guardok. Az if let, while let és let else a gyakori egyágú esetek kényelmes formái. A kimerítőség-ellenőrzés a refaktorálás során garantálja, hogy új enum-variáns felvételekor minden match frissüljön. Továbbvitt eredmények: a Command enum (rkv-core/src/lib.rs) és a parse_command függvény (rkv-cli/src/main.rs), valamint a kimerítő match elve, amelyet a Result és a ? operátor, a trait objektumok és a haladó típusrendszeri minták használnak tovább.
