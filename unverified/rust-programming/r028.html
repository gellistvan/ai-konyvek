13.1 Closure-ök: Fn, FnMut, FnOnce és a capture

13.1.1 Motiváció

A C++-fejlesztő a lambda-kifejezéseknél megszokta az explicit capture-listát: [&], [=], [x], [x = std::move(x)]. Ez a felsorolás pontosan megmondja, hogy a lambda mit és hogyan rögzít a környezetéből. A Rust ezt a döntést nem a programozóra bízza, hanem a closure törzséből vezeti le: a borrow checker látja, hogy a closure csak olvas, módosít, vagy tulajdonba vesz egy értéket, és ennek megfelelően rendeli hozzá a három lehetséges trait egyikét. Ez eleinte kényelmetlenül szokatlan, de a gyakorlatban megszünteti az elavult lambda-fogásokból adódó hibák egész osztályát. A C++-ban egy [&x] lambda túlélheti az x élettartamát, és futás közben dangling hivatkozást használhat; Rustban ugyanez fordítási időben hibát ad. Ez a fejezet azt mutatja meg, hogyan válasszunk a Fn, FnMut és FnOnce trait-ek, valamint a move kulcsszó között.

13.1.2 Fogalmak és szabályok

Definíció. A closure (zárvány) olyan névtelen függvényérték, amely rögzítheti a környezetében lévő változókat. A Rust closure szintaxisa |paraméterek| törzs, és a capture módját nem deklaráljuk explicit módon: a fordító a törzsben használt változók alapján állapítja meg.

Definíció. A Rust standard könyvtár három closure-traitet definiál, amelyek hierarchikus kapcsolatban állnak:

  • FnOnce: a closure hívható legalább egyszer, de a hívás során felemésztheti (self-et fogyaszt) a rögzített értékeket. Ez a legerősebb követelmény, amelyet minden closure teljesít.
  • FnMut: a closure hívható többször, és módosíthatja a rögzített állapotot (&mut self hívással). Minden Fn closure egyben FnMut is, de nem fordítva.
  • Fn: a closure hívható többször, és csak olvassa a rögzített értékeket (&self hívással). Ez a legszigorúbb trait a három közül.

Szabály. A closure által implementált traitet a rögzített változók használati módja határozza meg. Ha a closure: - csak olvassa a változókat, akkor általában Fn; - módosítja a rögzített változót, akkor FnMut; - tulajdonba veszi a rögzített értéket, és a hívás során kifelé mozgatja vagy eldobja, akkor FnOnce.

Szabály. A move kulcsszó a closure elején minden, a törzsben használt változót by value rögzít. Ha a változó típusa Copy, akkor a move másolatot készít; ha nem Copy, akkor a tulajdonjog átkerül a closure-be. A move nélküli closure a lehető legszűkebb hivatkozást használja: &T-t, ha elég, &mut T-t, ha módosít, és csak akkor mozgat, ha elkerülhetetlen.

Szabály. A trait-hierarchia miatt egy Fn closure átadható olyan függvénynek, amely FnMut vagy FnOnce boundot vár. Egy FnMut closure átadható FnOnce paraméternek, de Fn-t váró paraméternek nem. A fordítási hibák ilyenkor a trait-követelmények megsértését jelzik.

13.1.3 C++ ↔︎ Rust összevetés

A C++ lambda capture-listája és a Rust implicit capture közötti különbség jól látható egy egyszerű példán.

#include <iostream>

int main() {
    int x = 10;
    auto f = [&x]() { return x + 1; };          // hivatkozás
    auto g = [x]() mutable { return ++x; };     // másolat, módosítható
    auto h = [x = std::move(x)]() { return x; }; // move capture
    std::cout << f() << ' ' << g() << ' ' << h() << '\n';
}

A Rust-megfelelő:

fn main() {
    let x = 10;
    let f = || x + 1;                     // &x, Fn
    let mut g = move || { x += 1; x };    // x Copy, move másol, FnMut
    let h = move || x;                    // x Copy, move másol, Fn
    println!("{} {} {}", f(), g(), h());
}

A legfontosabb különbség az, hogy a Rustban a [&x]-nek megfelelő hivatkozás az alapértelmezett, és nincs szükség & jelölésre. A C++ [x] másoló capture-jéhez a Rustban move kell, mert a Rust closure alapból nem másol, hanem hivatkozik. A mutable kulcsszó a Rustban nem létezik ilyen formában; a módosító closure automatikusan FnMut lesz, és a változót mut-tal kell deklarálni. A move closure nem Copy típus esetén felel meg a C++ move capture-nek.

A FnOnce viselkedésére a legjobb példa, amikor a closure egy nem Copy értéket mozgat ki magából.

let s = String::from("hello");
let consume = move || s;   // s mozgatva a closure-be
println!("{}", consume()); // s kikerül a closure-ből
// consume();              // hiba: use of moved value

C++-ban ugyanez a minta gyakran futásidejű hibát vagy nem definiált viselkedést okoz, mert a std::move után a lambda újra hívható egy érvénytelen állapotú stringgel. Rustban a borrow checker ezt kizárja.

13.1.4 Kidolgozott példa

A leggyakoribb feltörekvő hiba, amikor egy closure-t vissza akarunk adni egy függvényből, de a closure a függvény paraméterére hivatkozik.

Ez a változat szándékosan nem fordul le:

fn make_adder(inc: i32) -> impl Fn(i32) -> i32 {
    |x| x + inc
}

A hiba lényege:

E0373: closure may outlive the current function, but it borrows `inc`,
which is owned by the current function

A make_adder visszatérő closure túléli a függvény veremkeretét, tehát az inc-re mutató hivatkozás érvénytelen lenne. Ezt a lifetimes diagram is szemlélteti.

A javítás a move kulcsszóval:

fn make_adder(inc: i32) -> impl Fn(i32) -> i32 {
    move |x| x + inc
}

fn main() {
    let add_five = make_adder(5);
    println!("{}", add_five(10)); // 15
}

Mivel az i32 Copy típus, a move a closure saját másolatát rögzíti az inc-ből, így a visszaadott closure önálló tulajdonú, és nincs élettartam-probléma.

A FnMut működését egy apply_twice függvénnyel mutatjuk be:

fn apply_twice<F: FnMut() -> i32>(mut f: F) -> i32 {
    f() + f()
}

fn main() {
    let mut x = 0;
    let r = apply_twice(|| {
        x += 1;
        x
    });
    println!("r = {r}, x = {x}");
}

A várt kimenet:

r = 3, x = 2

A closure FnMut, mert módosítja az x-et. A apply_twice kétszer hívja, ezért a zárt változó értéke kétszer növekszik.

13.1.5 Labor: rkv parancs-callbackek closure-rel

Munkakönyvtár: ~/rust-labor/rkv/

Ebben a laborban egy callback-alapú parancsdiszpécsert készítünk az rkv-core könyvtárban. A cél egy olyan függvény, amely egy Command slice-on megy végig, és minden parancshoz meghív egy closure-t. Ez a függvény később az iterátor-alapú feldolgozásban (Iterátorok: lusta adapterek és saját iterátor) is újra felhasználható.

A feltételezés az, hogy a Command enum már létezik a korábbi alfejezetekből, és a crate::command modulban található. Ha az elérési út eltér, igazítsd a modulnevet.

13.1.5.1 1. lépés: ellenőrizzük a workspace állapotát

cd ~/rust-labor/rkv
cargo test -p rkv-core

Ennek sikeresen le kell futnia, mielőtt továbblépünk.

13.1.5.2 2. lépés: hozzuk létre a callback modult

Az rkv-core/src/lib.rs fájlban add hozzá a modul deklarációját:

pub mod callback;

Hozd létre az rkv-core/src/callback.rs fájlt a következő tartalommal:

use crate::command::Command;

/// Végigjárja a parancsokat, és mindegyikre meghívja a callbacket.
pub fn visit_commands<F>(commands: &[Command], mut f: F)
where
    F: FnMut(&Command),
{
    for command in commands {
        f(command);
    }
}

A függvény FnMut(&Command) boundot használ, mert a callback módosíthat külső állapotot (például számlálót), de magát a Command értéket nem kell módosítania. A &Command paraméter lehetővé teszi, hogy a closure olvassa a parancs adatait anélkül, hogy tulajdonba venné.

13.1.5.3 3. lépés: írjunk unit tesztet a closure használatára

Az rkv-core/src/callback.rs aljára illeszd be a következő tesztmodult:

#[cfg(test)]
mod tests {
    use super::*;
    use crate::command::Command;

    #[test]
    fn count_set_commands() {
        let commands = vec![
            Command::Set {
                key: "a".to_string(),
                value: vec![1],
            },
            Command::Get {
                key: "b".to_string(),
            },
            Command::Set {
                key: "c".to_string(),
                value: vec![2],
            },
        ];

        let mut count = 0;
        visit_commands(&commands, |cmd| {
            if matches!(cmd, Command::Set { .. }) {
                count += 1;
            }
        });

        assert_eq!(count, 2);
    }
}

Figyeljük meg, hogy itt nincs move a closure előtt, tehát a closure a count változót &mut hivatkozással rögzíti. A visit_commands hívása után a count továbbra is elérhető, és az assert_eq! ellenőrizheti.

13.1.5.4 4. lépés: mutassuk be a hibás move closure-t

Próbáld ki ezt a változatot a tesztben:

let mut count = 0;
visit_commands(&commands, move |cmd| {
    if matches!(cmd, Command::Set { .. }) {
        count += 1;
    }
});
assert_eq!(count, 2); // hiba

Ez a változat szándékosan nem fordul le. A hiba lényege:

E0382: borrow of moved value: `count`

A move kulcsszó miatt a closure tulajdonba veszi a count értéket, így a külső count a hívás után érvénytelen, és az assert_eq! nem tudja használni. A javítás a move elhagyása, ahogy a 3. lépésben látható.

13.1.5.5 5. lépés: futtassuk a tesztet

cargo test -p rkv-core callback::tests::count_set_commands

A várt kimenet:

running 1 test
test callback::tests::count_set_commands ... ok

Ezzel elkészült a visit_commands függvény, amely closure-t fogad paraméterként. Továbbvitt eredmény: ez a callback-minta az iterátoroknál (Iterátorok: lusta adapterek és saját iterátor) az Iterator::for_each-hez hasonló logikát készíti elő, a move closure-ök pedig a párhuzamos (Szálak, Send és Sync: data race fordítási időben kizárva) és aszinkron (Future-ök és async/await: mi történik a motorháztető alatt) kódban lesznek elengedhetetlenek.

13.1.6 Tipikus hibák és átállási csapdák

  1. A C++ [=] mintájára másolást várunk. A Rust closure alapból hivatkozik, nem másol. Ha a closure-t el akarjuk tárolni, és a környezeténél tovább kell élnie, akkor move kell. Ha csak másolatot szeretnénk anélkül, hogy a tulajdonos elérhetetlenné válna, használjunk explicit clone()-t a closure törzsében.

  2. FnMut closure átadása Fn-t váró paraméternek. Gyakori hiba, amikor egy módosító closure-t próbálunk átadni egy olyan függvénynek, amely csak olvasó callbacket vár. A fordítási hiba egyértelmű: a closure nem teljesíti az Fn boundot, mert &mut-tal rögzíti a változót. A megoldás vagy a függvény boundjának lazítása FnMut-ra, vagy a closure áttervezése.

  3. A move closure után a külső változó használata. Amikor egy nem Copy értéket move-val rögzítünk, a külső változó érvénytelenné válik. Ez a hiba különösen a szálaknál (Szálak, Send és Sync: data race fordítási időben kizárva) válik gyakorivá, ahol a move elengedhetetlen, de a külső változó elérése már nem lehetséges. Ilyenkor Arc vagy Clone szükséges.

  4. A Rc<RefCell<T>> túlhasználata. A C++ shared_ptr tapasztalat alapján csábító lehet minden closure-t Rc<RefCell<_>>-kel körbevenni, hogy a borrow checker „ne zavarjon”. Ez azonban futásidejű kölcsönzési hibákhoz vezet, és megkerüli a Rust tervezési előnyeit. A closure-öket elsősorban a természetes capture-szabályokkal érdemes használni.

13.1.7 Feladatok

13.1.7.1 a) Lefordul-e és miért?

fn call<F: Fn()>(f: F) {
    f();
}

fn main() {
    let mut x = 0;
    call(|| x += 1);
}

13.1.7.2 b) C++-kód átírása idiomatikus Rustra

int count = 0;
auto inc = [&count]() { return ++count; };
auto total = inc() + inc();

13.1.7.3 c) rkv implementációs feladat

Bővítsd az rkv-core/src/callback.rs modult egy visit_commands_mut függvénnyel, amely &mut Command-ot ad át a closure-nek, és írj tesztet, amely egy Command::Delete parancsot Command::Get-re módosít a callbackben. (A Command enum definícióját a meglévő forrásban találod; ha a mezők eltérnek, igazítsd a mintát.)

13.1.7.4 d) Hibajavítás

Az alábbi kód nem fordul le. Javítsd úgy, hogy a külső s elérhető maradjon a closure hívása után is, és indokold a választást.

let s = String::from("hello");
let printer = move || println!("{s}");
printer();
println!("{s}");

13.1.8 Megoldások

13.1.8.1 a)

Nem fordul le. A || x += 1 closure módosítja az x-et, ezért FnMut traitet implementál, nem Fn-t. A call függvény Fn boundot vár, így a hívás típushibát ad. A javítás:

fn call<F: FnMut()>(mut f: F) {
    f();
}

fn main() {
    let mut x = 0;
    call(|| x += 1);
}

13.1.8.2 b)

fn main() {
    let mut count = 0;
    let mut inc = || {
        count += 1;
        count
    };
    let total = inc() + inc();
    println!("{total}");
}

A closure FnMut, mert módosítja a count-ot. A mut a closure deklarációjánál szükséges, mert a FnMut hívás &mut self-et igényel.

13.1.8.3 c)

// rkv-core/src/callback.rs
use crate::command::Command;

pub fn visit_commands_mut<F>(commands: &mut [Command], mut f: F)
where
    F: FnMut(&mut Command),
{
    for command in commands {
        f(command);
    }
}

#[cfg(test)]
mod tests {
    use super::*;
    use crate::command::Command;

    #[test]
    fn convert_delete_to_get() {
        let mut commands = vec![Command::Delete {
            key: "k".to_string(),
        }];
        visit_commands_mut(&mut commands, |cmd| {
            if let Command::Delete { key } = cmd {
                *cmd = Command::Get { key: key.clone() };
            }
        });
        assert!(matches!(commands[0], Command::Get { .. }));
    }
}

A visit_commands_mut FnMut(&mut Command) closure-t vár, így a callback módosíthatja a parancsot.

13.1.8.4 d)

A move closure tulajdonba veszi az s-t, ezért a külső s a hívás után érvénytelen. Két lehetséges javítás:

Ha az élettartam engedi, egyszerűen ne használjunk move-ot:

let s = String::from("hello");
let printer = || println!("{s}");
printer();
println!("{s}");

A closure ekkor &s-t rögzít, és s a hívás után is elérhető. Ha viszont a closure-t el kell tárolnunk, vagy a külső s-t továbbra is használni akarjuk a closure mellett, akkor clone()-t kell készíteni:

let s = String::from("hello");
let s2 = s.clone();
let printer = move || println!("{s2}");
printer();
println!("{s}");

A move a s2 másolatot rögzíti, így az eredeti s érintetlen marad.

13.1.9 Rövid összefoglaló

A Rust closure-ök automatikusan rögzítik a környezetüket, és a rögzített változók használati módja határozza meg, hogy a Fn, FnMut vagy FnOnce trait-et implementálják. A Fn closure többször hívható és csak olvas, az FnMut módosíthat, az FnOnce pedig felemésztheti a rögzített értékeket. A move kulcsszó minden használt változót by value rögzít, ami elengedhetetlen, ha a closure túléli a környezetét, például szálakban (Szálak, Send és Sync: data race fordítási időben kizárva) vagy aszinkron taskokban (Future-ök és async/await: mi történik a motorháztető alatt). A laborban létrehoztuk az rkv-core/src/callback.rs modult a visit_commands függvénnyel, amely FnMut(&Command) closure-t fogad. Ez a callback-minta az iterátorok (Iterátorok: lusta adapterek és saját iterátor) adaptereinél köszön vissza, ahol a closure-ök hasonlóan rugalmasan kezelik az elemeket.
