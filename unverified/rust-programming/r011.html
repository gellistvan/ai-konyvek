5.2 Függőségek, feature-ök, verziózás és workspace-ek

5.2.1 Motiváció

Egy C++-projektben a külső függőség többnyire három dologból áll: include-útvonalak, linker-kapcsolók és platformfüggő binárisok. A vcpkg, Conan vagy a CMake FetchContent megoldja a letöltést, de a build-rendszer továbbra is a te felelősséged marad: melyik fejléc, melyik könyvtárfájl, melyik ABI-verzió kerüljön a parancssorba. Az is gyakori, hogy ugyanannak a könyvtárnak két verziója él a gépen, és a hibás find_package csendben a rosszat választja.

A Rust ezt a problémát a Cargo manifest tumbban rendezi: a Cargo.toml deklarálja a függőséget, a verziómegkötést, a fordítási lehetőségeket (feature-ök) és a Cargo gondoskodik a letöltésről, a tranzitív függőségek feloldásáról és a linkelésről. A cél nem az, hogy mindent „varázslatosan” kezeljen, hanem hogy a függőségi fa reprodukálható és ellenőrizhető legyen.

5.2.2 Fogalmak és szabályok

Definíció. A Cargo-manifest (Cargo.toml) a crate leíró állománya; a [dependencies] szekció a normál, a [dev-dependencies] a tesztekhez és példákhoz, a [build-dependencies] a build scripthez szükséges függőségeket sorolja fel.

Definíció. A szemantikus verziózás (semver) MAJOR.MINOR.PATCH alakú. A Cargo alapértelmezett verziómegkötése a caret (^), ami a bal szélső nem nulla komponenst tartja meg: ^1.2.3 jelentése >=1.2.3, <2.0.0, ^0.2.3 jelentése >=0.2.3, <0.3.0. A 1.2.3 rögzítése pontosan ezt a kiadást engedi, a * bármely verziót – utóbbit kerüld, mert nem reprodukálható buildhez vezet.

Definíció. A feature opcionális, additív fordítási lehetőség; a crate-ek [features] szekcióban hivatkozhatnak más feature-ökre vagy opcionális függőségekre. Egy opcionális függőség akkor válik elérhetővé, ha optional = true jelölést kap, és egy feature bekapcsolja. A default feature a default-features = false kapcsolóval letiltható.

Szabály. A Cargo.lock a feloldott függőségek pontos verzióit tárolja. Alkalmazás (bináris crate) esetén a Cargo.lock-ot be kell commitolni; könyvtár esetén a hagyományos ajánlás szerint nem kell, mert a fogyasztó oldja fel a saját környezetében. A gyakorlati reprodukálhatóság miatt egyre több projekt a könyvtáraknál is commitolja – a pontos irányelvet a Cargo-dokumentációban ellenőrizd.

Szabály. A függőségi higiénia része a fa és a biztonsági állapot ellenőrzése: cargo tree a megszűnt/duplikált verziókat, cargo audit az ismert sebezhetőségeket, cargo deny a licenceket és a nemkívánatos függőségeket mutatja. Ez utóbbi kettő külön telepítendő eszköz.

5.2.3 C++ ↔︎ Rust összevetés

C++-ban egy CLI-argumentum feldolgozása gyakran kézi argc/argv-járás vagy getopt; a függőséget a build-rendszer külön kezeli:

// C++: CMake FetchContent + getopt (rövidített vázlat)
#include <getopt.h>
#include <string>
#include <vector>

int main(int argc, char** argv) {
    std::string key, value;
    int opt;
    while ((opt = getopt(argc, argv, "k:v:")) != -1) {
        if (opt == 'k') key = optarg;
        else if (opt == 'v') value = optarg;
    }
    // ellenőrzés, hibaüzenet, súgó kézzel...
}

A megfelelő Rust-kód a clap derive API-jával:

use clap::{Parser, Subcommand};

#[derive(Parser)]
#[command(name = "rkv-cli", version, about = "rkv parancssori kliens")]
struct Cli {
    #[command(subcommand)]
    command: Command,
}

#[derive(Subcommand)]
enum Command {
    /// Kulcs lekérdezése
    Get { key: String },
    /// Kulcs–érték beállítása
    Set { key: String, value: String },
    /// Kulcs törlése
    Del { key: String },
    /// Kulcsok listázása opcionális prefixszel
    List { prefix: Option<String> },
}

fn main() {
    let cli = Cli::parse();
    match cli.command {
        Command::Get { key } => println!("GET {}", key),
        Command::Set { key, value } => println!("SET {} {}", key, value),
        Command::Del { key } => println!("DEL {}", key),
        Command::List { prefix } => match prefix {
            Some(p) => println!("LIST {}", p),
            None => println!("LIST"),
        },
    }
}

A különbség: a Rust-verzió a Cargo.toml egyetlen bejegyzéséből húzza be a clap-ot, a fordítás során a Cargo feloldja a tranzitív függőségeket, a #[derive] makró pedig a típusból generálja a parancssori elemzőt, a hibaüzeneteket és a súgót. Nincs külön include-útvonal, nincs linker-flag, nincs platformfüggő .lib/.so kézi kezelés.

5.2.4 Labor: clap a rkv-cliben

Munkakönyvtár: ~/rust-labor/rkv/ (a workspace gyökere). A korábbi alfejezetben (Modulok és láthatóság) létrehozott workspace tagjai: rkv-core, rkv-cli, rkv-server. A labor célja a rkv-cli bővítése clap-pal.

5.2.4.1 1. lépés – A jelenlegi állapot ellenőrzése

A workspace gyökér Cargo.toml-ja:

[workspace]
resolver = "3"
members = ["rkv-core", "rkv-cli", "rkv-server"]

[workspace.package]
version = "0.1.0"
edition = "2024"

A rkv-cli/src/main.rs még minimális:

fn main() {
    println!("rkv CLI");
}

5.2.4.2 2. lépés – A clap függőség felvétele

Szerkesszük a rkv-cli/Cargo.toml-t:

[package]
name = "rkv-cli"
version.workspace = true
edition.workspace = true

[dependencies]
clap = { version = "4", features = ["derive"] }

A version = "4" caret-megkötés, tehát bármely 4.x.y elfogadott, de az 5-ös főverzió nem. A derive feature engedélyezi a #[derive(Parser)] makrót; e nélkül a clap csak a builder API-t kínálná.

5.2.4.3 3. lépés – A CLI típus implementálása

Cseréljük le a src/main.rs tartalmát a fenti, Cli típust és Command enumot tartalmazó kódra. A #[command(version, about)] automatikusan hozzáadja a --version és --help kapcsolókat; a doc-kommentek (///) a súgó szövegébe kerülnek.

5.2.4.4 4. lépés – Futtatás és a függőségi fa

cd ~/rust-labor/rkv
cargo run --package rkv-cli -- get --key foo

Várt kimenet:

Próbáljuk ki a súgót:

cargo run --package rkv-cli -- --help

Várt kimenet (rövidítve, verziófüggő):

Nézzük meg a feloldott függőségi fát:

A kimenet vázlata:

A clap_derive proc-macro crate fordítási időben bővíti ki a #[derive(Parser)] annotációt.

5.2.4.5 5. lépés – Biztonsági és licenc-ellenőrzés

A cargo audit és a cargo deny nem része a Rust disztribúciónak; telepítésük:

cargo install cargo-audit cargo-deny

Futtatásuk a workspace gyökeréből:

cargo audit
cargo deny check licenses
cargo deny check bans

A cargo audit a RustSec advisory adatbázis alapján jelzi az ismert sebezhetőségeket. A cargo deny a licencek kompatibilitását és a tiltólistára tett crate-eket ellenőrzi. Mindkét eszköz pontos parancskészlete és kimenete verziófüggő; a telepítés utáni --help-pel ellenőrizd.

A rétegábra a működő rendszer függőségi viszonyait mutatja:

Az ábra szavakkal: a rkv-cli a workspace-en belül a rkv-core-t fogja használni (a későbbi laborokban), jelenleg közvetlenül a clap-ra épül. A clap a clap_derive proc-macro crate-tel fordul, ami a derive feature bekapcsolásának következménye.

Továbbvitt eredmény. Ez a Cli típus és a Command enum a rkv-cli/src/main.rs fájlban a clap-alapú parancssori felület alapja. A Hibakezelés: saját hibatípusok alfejezetben a Command feldolgozás hibatípusra köt majd rá, a Záróprojekt: az rkv teljes rendszerként alfejezet pedig a szerver felé kommunikáló klienssé bővíti.

5.2.5 Tipikus hibák és átállási csapdák

  1. Wildcard verziómegkötés. A clap = "*" azt mondja a Cargo-nak, hogy bármely verzió megfelel. Egy féléves projektben már nem reprodukálható a build, mert az új kiadás API-t törhet. Mindig adj meg legalább főverziós caret-megkötést, és a Cargo.lock-ot commitold.
  2. A default-features = false elfelejtése. Sok crate alapértelmezett feature-je a std-et is bekapcsolja. Beágyazott vagy no_std környezetben ez fordítási hibát okoz; a clap esetén a default-features = false a derive-ot is kidobja, ezért olyankor explicit features = ["derive"]-t kell írni.
  3. A cargo update félreértése. Az cargo update az összes függőséget frissíti a megengedett tartományon belül; ha csak egy crate-et akarsz, a cargo update -p <crate> a pontos eszköz. A Cargo.lock törlése nem „megjavítja”, hanem megszünteti a reprodukálhatóságot.

5.2.6 Feladatok

5.2.6.1 (a) Fogalmi kérdés

Adott a Cargo.toml részlet: foo = "0.3.8". Mely verziókat engedélyezi a Cargo? (Válaszd ki a helyeset, és indokold.)

  1. >=0.3.8, <1.0.0
  2. >=0.3.8, <0.4.0
  3. =0.3.8

5.2.6.2 (b) C++-kód átírása

Írd át a következő C++-részletet idiomatikus Rustra clap derive API-val. A program egyetlen --count N opciót vár, alapértelmezett értéke 1, és annyiszor írja ki a hello szót.

#include <cstdlib>
#include <iostream>
#include <string>

int main(int argc, char** argv) {
    int count = 1;
    for (int i = 1; i < argc; ++i) {
        std::string arg = argv[i];
        if (arg == "--count" && i + 1 < argc) {
            count = std::atoi(argv[++i]);
        }
    }
    for (int i = 0; i < count; ++i) std::cout << "hello\n";
}

5.2.6.3 (c) Implementációs feladat az rkv-ban

Bővítsd a rkv-cli/src/main.rs Cli típusát egy --verbose kapcsolóval, amely -v rövid alakkal is elérhető, és ha be van kapcsolva, a program a main elején írja ki: debug: verbose mód bekapcsolva. A kapcsolót úgy add hozzá, hogy az minden alkalmazott parancsnál elérhető legyen (globális opció).

5.2.6.4 (d) Hibajavítás

Az alábbi Cargo.toml részlet nem fordul. Mi a hiba, és hogyan javítanád?

[dependencies]
clap = { version = "4", features = "derive" }

5.2.7 Megoldások

5.2.7.1 (a)

A helyes válasz: 2. A 0.3.8 caret-megkötésben a bal szélső nem nulla komponens a 0 utáni 3, tehát >=0.3.8, <0.4.0.

5.2.7.2 (b)

use clap::Parser;

#[derive(Parser)]
struct Cli {
    /// Ismétlések száma
    #[arg(short, long, default_value_t = 1)]
    count: u32,
}

fn main() {
    let cli = Cli::parse();
    for _ in 0..cli.count {
        println!("hello");
    }
}

A default_value_t használata a u32 típus miatt biztonságos; a #[arg(short, long)] a -c és --count kapcsolókat generálja. A for _ in 0..cli.count a Rust tartományalapú iterációja.

5.2.7.3 (c)

A Cli típus kiegészítve:

use clap::{Parser, Subcommand};

#[derive(Parser)]
#[command(name = "rkv-cli", version, about = "rkv parancssori kliens")]
struct Cli {
    /// Verbose kiírás
    #[arg(short, long, global = true)]
    verbose: bool,

    #[command(subcommand)]
    command: Command,
}

#[derive(Subcommand)]
enum Command {
    Get { key: String },
    Set { key: String, value: String },
    Del { key: String },
    List { prefix: Option<String> },
}

fn main() {
    let cli = Cli::parse();
    if cli.verbose {
        println!("debug: verbose mód bekapcsolva");
    }
    match cli.command {
        Command::Get { key } => println!("GET {}", key),
        Command::Set { key, value } => println!("SET {} {}", key, value),
        Command::Del { key } => println!("DEL {}", key),
        Command::List { prefix } => match prefix {
            Some(p) => println!("LIST {}", p),
            None => println!("LIST"),
        },
    }
}

A global = true azt jelenti, hogy a kapcsolót nemcsak a főparancs után, hanem az alkalmazott parancs után is megadhatod (rkv-cli get --verbose key).

5.2.7.4 (d)

A features mezőnek lista típusúnak kell lennie, nem stringnek. A hibás sor:

features = "derive"

Helyesen:

features = ["derive"]

5.2.8 Rövid összefoglaló

A Cargo manifestben a [dependencies] szekció deklarálja a külső crate-eket, a caret (^) az alapértelmezett semver-megkötés. A feature-ök opcionális, additív fordítási lehetőségek; a default-features = false letiltja az alapértelmezett készletet. A Cargo.lock alkalmazás esetén commitolandó a reprodukálhatóság miatt. A cargo tree, cargo audit és cargo deny a függőségi fa, a sebezhetőségek és a licencek ellenőrzését szolgálják. A laborban a rkv-cli crate-hez vettünk fel clap-ot (version = "4", features = ["derive"]), és létrehoztuk a Cli típust és a Command enumot a rkv-cli/src/main.rs fájlban. Ez a Továbbvitt eredmény a Hibakezelés: saját hibatípusok és a Záróprojekt: az rkv teljes rendszerként alfejezetekben használatos.

5.2.9 Források és ellenőrzési hiányok

  • A Cargo dokumentációja: https://doc.rust-lang.org/cargo/ – a verziómegkötések, feature-ök és Cargo.lock pontos szabályai.
  • A Rust referencia: https://doc.rust-lang.org/reference/ – a nyelvi szintaxis ellenőrzése.
  • A clap derive API pontos formátuma és a #[arg] attribútumok a docs.rs-en ellenőrizendők.
  • A cargo audit és cargo deny parancskészlete verziófüggő; a fent bemutatott hívások a jelenlegi főverziók szokásos formái, de a telepítés utáni --help-pel ellenőrizendők.
