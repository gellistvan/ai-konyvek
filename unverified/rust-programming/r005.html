3.2 Kifejezések, utasítások és vezérlési szerkezetek

3.2.1 Motiváció

Tapasztalt C++-fejlesztőként ismerős helyzet: egy if-ág eredményét változóba kell menteni, és a rövid ? : operátor nem elég, mert mindkét ágban több utasítás kell. Ilyenkor előre deklarált változóhoz, vagy – modern C++-ban – azonnal meghívott lambda-kifejezéshez nyúlunk. A Rust ezt a feszültséget alapvetően oldja fel: a nyelvben szinte minden kifejezés – blokk, if, sőt loop is – képes értéket adni. Ez a kifejezés-orientált stílus az idiomatikus Rust alapja, és a későbbi mintaillesztés, valamint az iterátor-láncok is erre építenek.

3.2.2 Fogalmak és szabályok

Definíció (kifejezés). Egy Rust-szintaktikai egység kifejezés, ha kiértékelésekor értéket ad, és típusa van. Kifejezés például egy literál, egy változó, egy függvényhívás, egy blokk, egy if vagy egy loop.

Definíció (utasítás). Utasítás olyan szintaktikai egység, amely mellékhatást hajt végre, de nincs értéke. A Rust két fő utasításfajtája a deklaráció (let) és a kifejezés-utasítás: ha egy kifejezés után pontosvesszőt írunk, az értékét elvetjük, és az egész utasítássá válik.

Szabály (blokk értéke). A { ... } blokk kifejezés. Értéke az utolsó, pontosvessző nélküli kifejezés értéke. Ha nincs ilyen, vagy az utolsó kifejezés után pontosvessző áll, a blokk típusa ().

Definíció (unit típus). () a Rust üres típusa: egyetlen értéke maga a (). A C++ void-hoz hasonló szerepű, de valódi típus, ezért változóba menthető, visszaadható, összehasonlítható.

Definíció (never típus). ! az olyan kifejezések típusa, amelyek soha nem térnek vissza: panic!, return, break, continue, illetve olyan loop, amelyből nincs break. A ! minden típusba koerciálható, így használható olyan helyeken, ahol egyébként konkrét érték kellene.

A pontosvessző szerepe döntő. Nézzük:

let x = { 42 };
let y = { 42; };

Az első esetben a blokk értéke 42 (típusa i32), ezért x: i32 = 42. A másodikban a 42; kifejezés-utasítás elveti az értéket, így a blokk értéke (), tehát y: () = ().

3.2.3 C++ ↔︎ Rust összevetés

A C++-ban az if utasítás, ezért kifejezésként csak a ternáris operátor jöhet szóba:

int abs_val(int x) {
    return (x >= 0) ? x : -x;
}

Ha az ágakban több utasítás kell, a ternáris operátor elégtelenné válik. A Rustban az if maga kifejezés, így nincs is szükség ternáris operátorra:

fn abs_val(x: i32) -> i32 {
    if x >= 0 { x } else { -x }
}

Az if ágai blokkok, és az ágaknak kompatibilis típusúnak kell lenniük. Ha mindkét ág i32-et ad, a kifejezés típusa i32; ha az egyik ág például (), a másik i32, akkor fordítási hiba keletkezik.

C++-ban gyakori a flag változóval vezérelt kilépés egymásba ágyazott ciklusokból:

bool found = false;
for (int i = 0; i < rows; ++i) {
    for (int j = 0; j < cols; ++j) {
        if (matrix[i * cols + j] == target) {
            found = true;
            break;
        }
    }
    if (found) break;
}

A Rust címkézett break-et kínál:

'outer: for i in 0..rows {
    for j in 0..cols {
        if matrix[i * cols + j] == target {
            break 'outer;
        }
    }
}

A címke ('outer) a ciklus elé kerül, és a break 'outer a megjelölt ciklust töri, nem csak a belsőt.

3.2.4 Kidolgozott példa: a pontosvessző csapdája

A leggyakoribb átállási hiba, amikor a C++-os szokás szerint pontosvesszőt teszünk a blokk végére, nem gondolva arra, hogy ezzel a blokk értékét ()-re változtatjuk.

Ez a változat szándékosan nem fordul le:

fn max(a: i32, b: i32) -> i32 {
    if a > b {
        a
    } else {
        b
    };
}

A cargo build hibaüzenetének lényege (a pontos szöveg verziófüggő, a hibakód E0308):

error[E0308]: mismatched types
 --> src/main.rs:1:28
  |
1 | fn max(a: i32, b: i32) -> i32 {
  |                            ^^^ expected `i32`, found `()`
  |
  = note: the final expression of a block is followed by a semicolon, which
    discards its value

A hiba oka: a pontosvessző az if kifejezés után áll, így annak értékét elveti, és az egész függvénytörzs értéke (). A javítás a pontosvessző elhagyása:

fn max(a: i32, b: i32) -> i32 {
    if a > b { a } else { b }
}

Ugyanez a szabály érvényes bármely blokkra, például:

fn main() {
    let x = {
        let y = 10;
        y + 5
    };
    println!("{x}"); // 15
}

Itt a belső blokk értéke 15, mert az utolsó kifejezés y + 5 után nincs pontosvessző.

3.2.5 Tipikus hibák és átállási csapdák

  1. Felesleges pontosvessző a visszatérési értéknél. Ahogy a fenti példa mutatja, a return kulcsszó nélküli függvényeknél a függvénytörzs utolsó kifejezése adja a visszatérési értéket. Ha oda pontosvessző kerül, a függvény ()-t ad vissza, és a típus nem egyezik. A return használata opcionális; idiomatikus Rustban általában az utolsó kifejezést használjuk, return-t csak korai kilépésre.

  2. A while ciklus értékként való használata. A while feltétel miatt nem garantálható, hogy a törzs legalább egyszer lefut, ezért a while kifejezés mindig () típust ad. Ez a kód hibás:

    let x = while cond {
    // ...
};

    Hiba: expected i32, found (). Ha értéket akarunk kihozni egy feltételes ismétlésből, használjunk loop-ot break értékkel.

  3. Az if ágak típusának inkompatibilitása. Ha az egyik ág i32-et, a másik ()-t ad, a fordítás meghiúsul. Például:

    let x = if cond { 1 } else { println!("nincs érték") };

    A println! típusa (), így az ágak típusa nem egyezik. A megoldás az, ha mindkét ág konkrét értéket ad, vagy ha a () az elfogadott típus.

  4. A return és a blokk értékének keverése. Ha egy függvényben egy korai return-t használunk, az ! típusú, így bármilyen visszatérési típussal kompatibilis; a függvény későbbi blokkja normál értéket adhat. Ezt nem szabad összekeverni azzal, hogy a return utáni kód halott.

3.2.6 Feladatok

3.2.6.1 1. Fogalmi kérdés

Mi lesz az x és y értéke, illetve típusa az alábbi kódban?

let x = { let a = 3; a * a };
let y = { 42; };

3.2.6.2 2. C++-kód átírása idiomatikus Rustra

Írjuk át az alábbi C++ függvényt Rustra úgy, hogy ne használjunk explicit return-t, és az if kifejezésként szerepeljen:

int parity(int x) {
    if (x % 2 == 0) {
        return 0;
    } else {
        return 1;
    }
}

3.2.6.3 3. Implementáció az rkv előkészítéséhez

Írjunk egy collatz nevű függvényt, amely egy pozitív egész számra kiszámolja, hány lépés alatt éri el az 1-et a Collatz-sejtés szerint. A függvény szignatúrája fn collatz(mut n: u64) -> u64. A ciklus használjon loop-ot, és az eredményt break adja át. A lépésszabály: ha n páros, akkor n = n / 2, különben n = 3 * n + 1.

3.2.6.4 4. Hibajavítás

Javítsuk ki az alábbi hibás kódot úgy, hogy a függvény a kisebbik számot adja vissza:

fn min(a: i32, b: i32) -> i32 {
    if a < b {
        a
    } else {
        b
    };
}

3.2.7 Megoldások

3.2.7.1 1. Fogalmi kérdés

Az x értéke 9, típusa i32, mert a blokk utolsó, pontosvessző nélküli kifejezése a * a. Az y értéke (), típusa (), mert a 42; utasítás elveti az értéket, és a blokk értéke a unit.

3.2.7.2 2. C++-kód átírása idiomatikus Rustra

fn parity(x: i32) -> i32 {
    if x % 2 == 0 { 0 } else { 1 }
}

Nincs szükség return-re; az if kifejezés értéke közvetlenül a függvény visszatérési értéke.

3.2.7.3 3. Implementáció az rkv előkészítéséhez

fn collatz(mut n: u64) -> u64 {
    let mut steps = 0;

    let result = loop {
        if n == 1 {
            break steps;
        }
        if n % 2 == 0 {
            n /= 2;
        } else {
            n = 3 * n + 1;
        }
        steps += 1;
    };

    result
}

A loop a break steps; utasítással adja vissza a lépésszámot. A függvény az utolsó result kifejezést adja vissza (ez akár el is hagyható, közvetlenül a loop eredményét is visszaadhatnánk). A mut n kulcsszó jelzi, hogy a paraméter módosítható.

3.2.7.4 4. Hibajavítás

A hiba a pontosvessző az if kifejezés után. Javított változat:

fn min(a: i32, b: i32) -> i32 {
    if a < b { a } else { b }
}

3.2.8 Rövid összefoglaló

A Rust kifejezés-orientált nyelv: a blokkok, az if és a loop is értéket adnak. A pontosvessző a kifejezések értékét elveti, ezért a blokk utolsó kifejezésénél nem szabad kitenni, ha az a visszatérési érték. A () unit típus az üres értéket jelöli, a ! never típus pedig a soha vissza nem térő kifejezéseket. A vezérlési szerkezetek közül a while és a for mindig ()-t ad, a loop viszont break értékkel képes eredményt visszaadni. A címkézett break/continue lehetővé teszi a külső ciklusok közvetlen megszakítását anélkül, hogy flag változókat kellene bevezetni.

Továbbvitt eredmény. A kifejezés-orientált stílus – különösen a blokkok és az if mint érték – alapvető építőköve lesz a Mintaillesztés: match, if let, let else és a minták alfejezetnek, ahol a match kifejezés is ezt a mintát követi, és az Iterátorok: lusta adapterek és saját iterátor alfejezetnek, ahol az adapter-láncok szintén kifejezésként épülnek fel. Az itt megtanult pontosvessző-fegyelem nélkülözhetetlen az idiomatikus Rust-kód írásához.
