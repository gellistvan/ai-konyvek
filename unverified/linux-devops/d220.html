44.5 Cloud API/identity diagnosztikai labor

44.5.1 Motiváció

A cloud API hibák első pillantásra hasonlítanak a C++ kivételekhez: kaptunk egy szöveget, egy hibakódot, és valamit javítani kell. A különbség az, hogy a cloud hibák mögött több, egymástól élesen eltérő réteg áll: a hitelesítés (authentication) kudarca, az engedélyezés (authorization) hiánya, a szolgáltatási kvóta (quota) kimerülése, vagy a rossz régió (region) megválasztása. A diagnosztikai labor célja, hogy ezt a négy okot API válaszokból, offline fixture-ökből és --dry-run hívásokból megbízhatóan elkülönítsük, még mielőtt egyetlen erőforrást is létrehoznánk. A korábbi Accountbaseline, audit, költség és cleanup fejezetben felépítettük a sandbox elszámolási és audit alapjait; most ezt a Működtetési szerződés, runbook és változtatás elvei szerint API-diagnosztikára használjuk.

44.5.2 Definíció és működés

A cloud API hívás legalább négy kérdést tesz fel:

  1. Authentication – ki vagy? A hívó identitását egy token vagy aláírt credential bizonyítja. Ha a token lejárt, hiányzik vagy érvénytelen, a hívás Unauthorized vagy ExpiredToken hibával tér vissza.
  2. Authorization – mit szabad? Az identitáshoz rendelt IAM-policy dönti el, hogy az adott művelet az adott erőforráson engedélyezett-e. Hiány esetén AccessDenied vagy Forbidden hibát kapunk.
  3. Quota – mennyi áll rendelkezésre? A szolgáltatási kvóta nem engedély, hanem erőforráslimit: hány futó instance, hány vCPU, hány API hívás másodpercenként. Túllépéskor QuotaExceeded, LimitExceeded vagy HTTP 429 válasz érkezik.
  4. Region – hol keresed? A legtöbb erőforrás regionális. Ha a hívás a eu-west-1 régióban keresi az us-east-1-ben létrehozott erőforrást, NotFound vagy InvalidParameterValue hibát kapunk – ez nem azt jelenti, hogy az erőforrás nem létezik.

A labor két üzemmódot használ: offline fixture esetén helyi JSON-fájl reprezentálja a várt API-válaszokat, így fizetős erőforrás nélkül gyakorolhatjuk az osztályozást; dedikált sandbox esetén pedig valós, de izolált CLI-hívásokat végzünk. A példákban lab-sandbox profilt és 111122223333 dummy account ID-t használunk; ezek nem valós credentials-ök.

44.5.3 Kidolgozott példa

A következő példa offline fixture-t és valós sandbox parancsokat kombinál. Feltételezzük, hogy a d219-ben beállított CloudTrail és költségriasztás már működik.

Előkészítés: laborprofil és környezet

A parancs egy helyi környezeti fájlt hoz létre; nem módosít cloud erőforrást.

mkdir -p ~/lab-d220/fixtures
cat > ~/lab-d220/profile.env <<'EOF'
# Target: saját sandbox account, régió: eu-west-1
# Privilege: nincs szükség cloud jogra, helyi fájl
# Előfeltétel: d219 sandbox account létrehozva
# Ellenőrzés: tartalom megjelenik a cat paranccsal
# Rollback: a fájl törlésével
export AWS_PROFILE=lab-sandbox
export AWS_REGION=eu-west-1
export LAB_ACCOUNT_ID=111122223333
export LAB_COST_LIMIT_HYPOTHETICAL_USD=10.00
EOF
source ~/lab-d220/profile.env

Caller identity és régióellenőrzés

Első lépés mindig a hívó identitás és az aktuális régió azonosítása. A sts get-caller-identity olvasó hívás, nem módosít.

# Target: lab-sandbox account, UID: saját user
# Privilege: STS:GetCallerIdentity (alapjog)
# Előfeltétel: érvényes sandbox credential
# Ellenőrzés: a kimenetben a várt account ID
# Rollback: nem szükséges
aws sts get-caller-identity --profile lab-sandbox --region eu-west-1

Várt, illusztratív kimenet (dummy érték):

{
    "Account": "111122223333",
    "Arn": "arn:aws:iam::111122223333:user/lab-d220",
    "UserId": "AKIAIOSFODNN7LAB22"
}

A régióinventáriumot a describe-regions adja:

aws ec2 describe-regions --region eu-west-1 \
  --query 'Regions[0:3].{Name:RegionName,Endpoint:Endpoint}' --output table

Hibaosztályozó offline fixture

Hozzunk létre négy jellegzetes hibamintát JSON-ben:

[
  {"case": "expired_token", "code": "ExpiredToken", "http": "403"},
  {"case": "denied_permission", "code": "AccessDenied", "http": "403"},
  {"case": "quota_exceeded", "code": "QuotaExceeded", "http": "429"},
  {"case": "wrong_region", "code": "InvalidAMIID.NotFound", "http": "400"}
]

Az alábbi Python fixture-olvasó osztályozza a hibákat; ez a laborban magyarázó eszközként szolgál, és nem igényel cloud hívást.

cat > ~/lab-d220/classify_errors.py <<'EOF'
#!/usr/bin/env python3
"""Offline fixture: API hibaminták osztályozása."""
import json

CLASSES = {
    "ExpiredToken": "authentication",
    "AccessDenied": "authorization",
    "QuotaExceeded": "quota",
    "InvalidAMIID.NotFound": "region",
}

with open("fixtures/api_errors.json", encoding="utf-8") as f:
    for item in json.load(f):
        kind = CLASSES.get(item["code"], "unknown")
        print(f"{item['case']:20s} -> {kind}")
EOF
python3 ~/lab-d220/classify_errors.py

Várt kimenet:

expired_token        -> authentication
denied_permission    -> authorization
quota_exceeded       -> quota
wrong_region         -> region

Quota smoke test

A következő hívás lekérdezi a futó on-demand instance kvótát. A quota kód és a név a provider aktuális API-jától függ; az itt használt név illusztratív, ezért a műveletet a sandboxban az aktuális lista alapján kell ellenőrizni. A parancs olvasó, nem módosít.

aws service-quotas list-service-quotas --service-code ec2 --region eu-west-1 \
  --query 'Quotas[?contains(QuotaName, `Running On-Demand`)].{Name:QuotaName,Value:Value,Code:QuotaCode}' \
  --output table

Várt kimenet dummy értékkel:

----------------------------------------------------------------

+----------------------+---------------+----------------------+
|        Name          |    Value      |      Code            |
+----------------------+---------------+----------------------+
| Running On-Demand    |  5.0          |  L-DUMMY1234         |
| Standard instances   |               |                      |
+----------------------+---------------+----------------------+

Image és instance smoke test dry-runnal

A --dry-run kulcsértéke, hogy validálja az IAM-engedélyt, a paramétereket és a régióban létező kép azonosítóját anélkül, hogy ténylegesen indítana. Az AMI ID itt dummy; a tényleges pandában a régióban elérhető, támogatott Ubuntu 24.04 AMI-t kell lekérdezni.

aws ec2 run-instances --dry-run --region eu-west-1 \
  --image-id ami-0dummy1234567890ab \
  --instance-type t3.micro \
  --subnet-id subnet-0dummy1234567890ab \
  --profile lab-sandbox

Ha az IAM-engedély és a hivatkozott erőforrások érvényesek, a várt hibaüzenet maga a dry-run megerősítése:

An error occurred (DryRunOperation) when calling the RunInstances operation:
Request would have succeeded, but DryRun flag is set.

Ez a hiba itt siker, mert azt jelenti, hogy a permission meglenne. Ha AccessDenied érkezik, akkor IAM-probléma van; ha QuotaExceeded, akkor a kvóta a szűk keresztmetszet.

Audit trail és cleanup manifest

A hívások utáni auditnyomot a CloudTrail adja. Ez olvasó hívás, feltételezi, hogy a d219-ben bekapcsoltuk a CloudTrailt.

aws cloudtrail lookup-events --region eu-west-1 \
  --lookup-attributes AttributeKey=Username,AttributeValue=lab-d220 \
  --query 'Events[0:3].{Time:EventTime,Event:EventName,Result:ErrorMessage}' \
  --output table

A cleanup manifest rögzíti az owner, az expiry, a cost limit és a ténylegesen létrehozott erőforrásokat. Mivel a laborban eddig csak dry-run volt, a lista üres.

# ~/lab-d220/cleanup-manifest.yaml
owner: lab-d220
account: "111122223333"
region: eu-west-1
cost_limit_hypothetical_usd: 10.00
expiry: "2025-12-31T23:59:59Z"
resources: []
cleanup_commands: []

44.5.4 Hibák és ellenpróbák

Jelenség Hipotézis Ellenőrzés Javítás
401 Unauthorized vagy ExpiredToken A credential hiányzik, lejárt vagy rossz profilban van aws sts get-caller-identity Friss credentialt kérni, --profile ellenőrzése
403 AccessDenied IAM policy hiányos a hívott műveletre aws iam simulate-principal-policy vagy dry-run hívás Minimális policy attach, nem admin jog
429 QuotaExceeded A szolgáltatási kvóta elérte a felső határt service-quotas list-service-quotas Kvótaemelés kérése, más régió vagy kisebb instance
400 InvalidAMIID.NotFound A kép nem létezik ebben a régióban describe-images --owners a régióban A régióhoz tartozó AMI ID használata

Gyakori csapda, hogy a AccessDenied hibát credential-problémaként kezelik, pedig a token érvényes, csak a policy hiányzik. A másik félreértés, hogy a dry-run sikerét tényleges indításként értelmezik; a dry-run nem foglal kapacitást, így később egy valódi InsufficientCapacity hiba még előfordulhat.

44.5.5 Feladatok

  1. Magyarázó feladat: Készítsen egy táblázatot, amely a következő hibakódokat osztályozza a négy kategóriába: Unauthorized, AccessDenied, QuotaExceeded, InvalidAMIID.NotFound, ExpiredToken, LimitExceeded. Mindegyikhez írjon egy mondatos indoklást, amely megkülönbözteti az authentikációt, engedélyt, kvótát és régiót.

  2. Adminisztrációs/konfigurációs feladat: Hozzon létre egy bővített offline fixture-t fixtures/api_errors.json néven legalább öt hibamintával, és írjon hozzá egy saját Python vagy bash osztályozót. A kimenet minden esethez a kategóriát adja meg. A postcondition: a script hiba nélkül fut, és a kategóriák helyesek.

  3. Diagnosztikai/failure/recovery feladat: Válasszon egy AccessDenied hibát a sandboxban: hajtsa végre a run-instances --dry-run hívást egy olyan sandbox userrel, akinek nincs ec2:RunInstances engedélye. Rögzítse a hibát. Ezután csatolja hozzá a minimális policy-t, majd ismételje meg a dry-run hívást. A postcondition: a második hívás DryRunOperation hibát ad, nem AccessDenied. Ha nincs sandbox, szimulálja a folyamatot az offline fixture-ökben.

44.5.6 Megoldások

  1. Megoldás a magyarázó feladathoz: A táblázat:
Hibakód Kategória Indoklás
Unauthorized authentication A hívó identitása vagy credential hiányzik/érvénytelen
AccessDenied authorization A policy nem engedélyezi a műveletet
QuotaExceeded quota A szolgáltatási limit túllépve, nem engedélykérdés
InvalidAMIID.NotFound region A kép nem létezik az adott régióban
ExpiredToken authentication A token lejárt, meg kell újítani
LimitExceeded quota Általában API rate limit vagy erőforráslimit

  1. Megoldás az adminisztrációs feladathoz: A bővített JSON és a Python osztályozó a kidolgozott példa mintájára készül. A postcondition az, hogy a script minden mintát a várt kategóriába sorol, és nem hagy üresen unknown értéket. A script futtatása: python3 ~/lab-d220/classify_errors.py. A várt kimenet minden sorban case -> category.

  2. Megoldás a diagnosztikai feladathoz: A folyamat:

    • Hozza létre vagy válassza ki a lab-d220-deny user-t, akihez nem csatolt ec2:RunInstances engedély.
    • Futtassa a run-instances --dry-run hívást; várható AccessDenied hiba.
    • Csatoljon egy policy-t, amely engedélyezi az ec2:RunInstances és a szükséges ec2:DescribeImages műveletet a sandbox * erőforrására. A módosító parancs target a sandbox IAM, privilege iam:AttachUserPolicy, előfeltétel a deny user létezése, ellenőrzés a policy attach utáni dry-run, rollback a policy detach.
    • Ismételje meg a dry-run hívást. A postcondition: DryRunOperation hiba, ami azt jelzi, hogy az engedély megvan, és a paraméterek érvényesek.

44.5.7 Rövid összefoglaló

A cloud API-diagnosztika alapja a hibakódok rétegek szerinti elkülönítése: authentication, authorization, quota és region. A sts get-caller-identity mindig az első hívás, a --dry-run futtatás pedig erőforrás nélkül teszteli a permissiont és a paramétereket. Az offline fixture-ök lehetővé teszik a hibaminták gyakorlását fizetős erőforrás nélkül. A cleanup manifest rögzíti az owner, expiry és cost limit szerződést.

Továbbhasznált definíciók: authentication – az identitás bizonyítása; authorization – az identitásra vonatkozó engedélyek ellenőrzése; service quota – egy cloud szolgáltatás erőforrás- vagy API-limite.
