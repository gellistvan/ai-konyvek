7.4 Kernel, firmware és bootváltozás kezelése

7.4.1 Motiváció

A kernel a Linux rendszer azon rétege, amely a legalacsonyabb szintű erőforrás-kezelést és hardverabsztrakciót adja. Frissítése biztonsági hibák, új hardvertámogatás vagy élettartam miatt válik szükségessé, de a boothiba a szolgáltatás teljes kiesését okozhatja. A Működtetési szerződés, runbook és változtatás elvei szerint a kernelváltás nem egy egyszerű csomagtelepítés: a modulok, a kezdeti RAM-lemezkép (initial RAM filesystem, initramfs), a boot bejegyzés és a firmware együtt alkotnak egy indítási láncot. C++ fejlesztőként ismerős a shared library ABI fogalma: ha egy függvény aláírása megváltozik, a programod futás közben hibát kap. A kernel esetében nincs stabil belső ABI, így a modulok és a kernelverzió közötti kompatibilitást minden váltásnál ellenőrizni kell.

7.4.2 Definíciók és működés

  • Distribution kernel és upstream kernel. Az upstream vagy mainline kernel a kernel.org-on kiadott forrás. A disztribúciós kernel (distribution kernel) ezt a forrást backportolt hibajavításokkal, disztribúció-specifikus beállításokkal és támogatási ígérettel adja ki. Ubuntu Server 24.04 LTS esetén a kernelcsomagot a linux-image-* csomagok tartalmazzák, a linux-image-generic meta-csomag pedig a legfrissebb, az adott kiadáshoz tartozó stabil kernelre mutat. Az upstream verzió ettől eltérhet: például a 6.8.0-45-generic disztribúciós verzió egy 6.8 upstream alapú backport lehet. A konkrét verzió a labhost inventoryjából ellenőrzendő.
  • Module ABI és DKMS. A kernel moduljai nem hordozhatóak a kernelverziók között. A modinfo által mutatott vermagic string tartalmazza a pontos kernelverziót és a modulbetöltés feltételeit; ha az új kernelre a modul nem lett újraépítve, a betöltés Invalid module format hibával megtagadódik. A Dynamic Kernel Module Support (DKMS) arra szolgál, hogy a disztribúción kívüli, forrásként telepített modulokat minden új kernelverzióhoz automatikusan újrafordítsa. Ezért a linux-headers-* csomag folyamatos jelenléte üzemeltetési előfeltétel.
  • Secure Boot és modul-aláírás. UEFI Secure Boot alatt a firmware csak aláírt boot image-et indít. A disztribúciós kernel a gyártó kulcsával aláírt, de egy egyedileg épített DKMS-modulhoz a Machine Owner Key (MOK) aláírás szükséges. Ha a kernel konfigurációja megköveteli a modulok aláírását, az aláíratlan modul module verification failed hibával nem töltődik be. A diagnosztika a mokutil --sb-state és a dmesg kimenetére épül.
  • Initramfs és boot entry. Az initramfs egy korai userspace-t tartalmazó tömörített image, amely a root fájlrendszerhez szükséges modulokat, firmware-t és udev szabályokat biztosít. A boot entry egy bootloader által felkínált kombináció: kernel image, initramfs, kernel parancssor és fallback opció. A GRUB az EFI boot managerbe telepített bejegyzésekkel menedzseli ezeket, az update-grub újraépíti a /boot/grub/grub.cfg-t.
  • Live patch. A live patch technológia a futó kernelben függvényszintű foltozást végez, de nem helyettesíti a kernel verzióváltását. Csak bizonyos sebezhetőségek javítására alkalmas, nem ad új funkciót, nem frissíti a modulokat, és a reboot utáni állapotot is kezelni kell. A kernelcsomag frissítése esetén a reboot továbbra is szükséges.

A rétegelt adatút, amit a kernelváltás érint: boot firmware → bootloader → kernel → initramfs → root fájlrendszer → udev → modulok → C++ szolgáltatás. A frissítés akkor sikeres, ha ez a lánc minden elemére kiterjedt a kompatibilitásellenőrzés.

7.4.3 Kidolgozott példa: canary host kernelváltás

Labhost: lab-canary-01, UID: lab-admin, privilege: sudo. Előfeltétel: a labhost snapshotja elkészült, a hypervisor konzolja elérhető, a lab inventory rögzíti a jelenlegi kernelverziót és a kritikus modulokat. A lab-app a tipikus C++ szolgáltatás, a lab-net-driver egy DKMS-ből épített, labor-specifikus hálózati modul.

7.4.3.1 1. Baseline és boot entry inventory

# labhost: lab-canary-01, UID: lab-admin, privilege: sudo
# előfeltétel: snapshot, lab inventory
CURRENT_KERNEL=$(uname -r)
echo "jelenlegi kernel: ${CURRENT_KERNEL}"
dpkg -l 'linux-image-*' 'linux-headers-*' | awk '/^ii/{print $2, $3}'
lsblk -o NAME,SIZE,MOUNTPOINT,TYPE
sudo grub-editenv list
sudo dkms status

Várt, illusztratív kimenet:

jelenlegi kernel: 6.8.0-45-generic
linux-image-6.8.0-45-generic 6.8.0-45.45
linux-image-generic 5.15.0.45.45
linux-headers-6.8.0-45-generic 6.8.0-45.45
lab-net-driver/1.2.3, 6.8.0-45-generic, x86_64: installed

A grub-editenv list mutatja a saved_entry-t; a dkms status megerősíti, hogy a modul a jelenlegi kernelhez telepített. A tényleges verziók a labhost csomagforrásától függenek, ezért a célverziót az apt-cache mutatja.

7.4.3.2 2. Kernel-, header- és firmware-csomag frissítése

sudo apt-get update
apt-cache policy linux-image-generic linux-headers-generic linux-firmware
sudo apt-get install --only-upgrade linux-image-generic linux-headers-generic linux-firmware

A --only-upgrade csak a meglévő csomagok frissítésére szolgál; ha nincs új verzió, nem módosít. A kernelcsomag telepítése jellemzően triggereli az initramfs-építést, de ezt explicit ellenőrizzük.

7.4.3.3 3. DKMS és initramfs újraépítés

sudo dkms autoinstall
sudo update-initramfs -c -k all
sudo update-grub
sudo grub-editenv list

A dkms autoinstall minden telepített kernelhez felépíti a hiányzó modulokat. Az update-initramfs -c -k all minden kernelverzióhoz új initramfs-t készít. Az update-grub frissíti a boot entry-ket.

7.4.3.4 4. Újraindítás és smoke test

sudo systemctl reboot

A reboot után a lab admin visszacsatlakozik, és futtatja a labor-specifikus smoke testet:

#!/usr/bin/env bash
# labhost: lab-canary-01, UID: lab-admin, privilege: sudo
set -euo pipefail
EXPECTED_META="${1:-linux-image-generic}"
ACTUAL=$(uname -r)
echo "kernel=${ACTUAL}"
dpkg-query -W -f='${Status}' "${EXPECTED_META}" 2>/dev/null | grep -q 'install ok installed'
systemctl is-active lab-app
curl -fsS http://127.0.0.1:8080/health >/dev/null
modinfo lab-net-driver | grep -E '^(filename|vermagic)'
lsmod | grep '^lab_net_driver' >/dev/null
dmesg | grep -iE 'firmware|microcode' | tail -n 5
echo "SMOKE_TEST_OK"

A lab-app portját és a lab-net-driver nevét a lab inventory adja; a fenti endpoint illusztratív. A postcondition: a rendszer az új kernelt futtatja, a kritikus modul betöltődött, a szolgáltatás healthy, a firmware-üzenetek a kernel logban megjelentek.

7.4.3.5 5. Rollback terv

Ha a smoke test bármely feltétele meghiúsul, az egyszeri visszaálláshoz a GRUB menüben kiválasztjuk az előző kernelt:

# konzolról, a boot menüben válaszd az előző kernel bejegyzést
sudo grub-reboot "1>2"
sudo systemctl reboot

A pontos bejegyzést a grep '^menuentry' /boot/grub/grub.cfg adja; a grub-reboot csak a következő indításra állítja a saved_entry-t. Tartalék megoldásként a labhost snapshot visszaállítható.

7.4.4 Hibák és ellenpróbák

  • DKMS modul nem épült az új kernelre. Tünet: modprobe lab-net-driver → module not found. Adatgyűjtés: dkms status, ls /lib/modules/$(uname -r)/updates. Hipotézis: hiányzó linux-headers-$(uname -r). Ellenpróba: sudo dkms autoinstall, majd modprobe és dmesg.
  • Secure Boot aláírási hiba. Tünet: dmesg | grep 'module verification failed'. Adatgyűjtés: mokutil --sb-state, modinfo lab-net-driver | grep sig_id. Hipotézis: a DKMS modul aláíratlan. Ellenpróba: a modul aláírása a MOK kulccsal, a MOK enrollálás, majd reboot; a Secure Boot kikapcsolása nem megoldás.
  • Initramfs nem frissült. Tünet: boot közben initramfs prompt, a logban gave up waiting for root device. Adatgyűjtés: lsinitramfs /boot/initrd.img-<verzió> | grep <szükséges modul>. Hipotézis: a root fájlrendszerhez szükséges modul hiányzik. Ellenpróba: update-initramfs -u -k $(uname -r), majd újraindítás.
  • Boot entry hiányzik, a rendszer a régi kernelt futtatja. Tünet: reboot után uname -r nem a várt. Adatgyűjtés: grub-editenv list, grep '^menuentry' /boot/grub/grub.cfg. Hipotézis: update-grub nem futott, vagy a saved_entry rossz. Ellenpróba: sudo update-grub, sudo grub-reboot "0", reboot.
  • Live patch téves feltételezés. Hiba: a mérnök azt hiszi, hogy a live patch elkerüli a rebootot. A kernelverzióváltás mindig rebootot igényel; a live patch legfeljebb késlelteti a sürgős sebezhetőségjavítást, de a modul- és firmware-állapot nem frissül.

7.4.5 Feladatok

7.4.5.1 F1. Magyarázó: kompatibilitási térkép

Adott a lab-canary-01 labhost, jelenlegi kernel 6.8.0-45-generic, és a linux-image-generic meta-csomag által kijelölt célverzió 6.8.0-50-generic (illusztratív). Készíts egy kompatibilitási térképet: mi a disztribúciós kernel és mi az upstream kernel? Miért nem stabil a modul ABI? Hogyan kapcsolódik a DKMS, a Secure Boot, az initramfs és a boot entry? Miért nem elegendő pusztán az apt-get upgrade? A megoldásodban szerepeljen a rétegelt ellenőrzés leírása.

7.4.5.2 F2. Adminisztrációs: canary kernelváltás rollback-képesen

A lab-canary-01 labhoston hajts végre kernelváltást a linux-image-generic, linux-headers-generic és linux-firmware csomagok frissítésével. Előfeltétel: snapshot és konzol hozzáférhető. Készíts baseline-t, frissíts, építsd újra az initramfs-t, frissítsd a boot entry-ket, indítsd újra a gépet, és futtasd a smoke testet. Dokumentáld a rollback tervet és a postconditiont. A feladatban ne hajts végre tényleges frissítést; a parancsokat a várt kimenetekkel együtt add meg.

7.4.5.3 F3. Diagnosztikai: Secure Boot és modulhiány a frissítés után

A lab-canary-01 kernelváltása után a lab-net-driver modul nem töltődik be. A dmesg ezt mutatja:

module verification failed: signature and/or required key missing

A mokutil --sb-state kimenete: SecureBoot enabled. A dkms status szerint a modul az új kernelhez installed, de a betöltés sikertelen. Írd le a diagnosztikai lépéseket, és adj recovery tervet anélkül, hogy kikapcsolnád a Secure Boot-ot. A megoldás postconditionje legyen: a modul aláírt, betöltődött, a lab-app healthy.

7.4.6 Megoldások

7.4.6.1 M1

A disztribúciós kernel a disztribúció által backportolt és támogatott kernelcsomag; az upstream a kernel.org mainline. A modul ABI nem stabil, mert a kernel belső interfészei változnak a verziók között. A modulok a vermagic alapján kötődnek a kernelverzióhoz, ezért minden új kernelhez újra kell építeni őket. A DKMS ezt a forrásból automatikusan elvégzi, feltéve, hogy a linux-headers-$(uname -r) elérhető. A Secure Boot esetén a modulokat alá kell írni, különben a kernel nem tölti be. Az initramfs tartalmazza a root fájlrendszerhez szükséges modulokat; hiánya bootpanikhoz vezet. A boot entry a kernel, initramfs és kernel parancssor kombinációja; a grub teszi választhatóvá az előző verziót. Az apt-get upgrade önmagában telepítheti a kernelcsomagot, de nem garantálja a modul-újraépítést, az initramfs frissítést és a boot entry ellenőrzést. A postcondition: az új kernel fut, a kritikus modulok betöltve, a szolgáltatás healthy, a rollback bejegyzés elérhető.

7.4.6.2 M2

A baseline parancsok megegyeznek a kidolgozott példa 1. lépésével. A frissítés:

sudo apt-get update
sudo apt-get install --only-upgrade linux-image-generic linux-headers-generic linux-firmware

Az initramfs és a boot entry:

sudo dkms autoinstall
sudo update-initramfs -c -k all
sudo update-grub

Az újraindítás előtt a rollback bejegyzést rögzítjük:

grep '^menuentry' /boot/grub/grub.cfg
sudo grub-editenv list

A reboot után a smoke test a fenti script. Ha minden ellenőrzés sikeres, a postcondition: a rendszer az új kernel verziót futtatja, a lab-net-driver a vermagic-nek megfelelően betöltődött, a lab-app active és a health endpoint válaszol. Rollback esetén sudo grub-reboot "<előző menüindex>", majd sudo systemctl reboot.

7.4.6.3 M3

Az adatgyűjtés során ellenőrizzük a modul aláírását:

modinfo lab-net-driver | grep -E '^(sig_id|vermagic)'
sudo dkms status
mokutil --sb-state

Ha a sig_id hiányzik vagy nem megbízható, a modul aláíratlan. A recovery lépések: 1) a DKMS modul újraépítése az adott kernelre; 2) a modul aláírása a MOK privát kulccsal; 3) a MOK nyilvános kulcs enrollálása a firmware-be; 4) reboot, hogy a firmware elfogadja a kulcsot. A telepített, aláírt modul betöltése után a lab-app health checkje OK. A postcondition: a lab-net-driver modinfo kimenete érvényes aláírást mutat, a modul a lsmod listában szerepel, a szolgáltatás healthy, a Secure Boot továbbra is enabled.

7.4.7 Rövid összefoglaló

A kernelváltás rétegelt üzemeltetési művelet, nem egyszerű csomagfrissítés. A disztribúciós kernel és az upstream verzió különböző, a modul ABI nem stabil, ezért a DKMS újraépítése, a Secure Boot aláírás és az initramfs újraépítése együtt szükséges. A reboot a hagyományos kernelváltás elkerülhetetlen eleme; a live patch csak korlátozott sebezhetőségjavítást ad. A canary hoston elvégzett, smoke teszttel igazolt váltás után terjeszthető ki a flottára, miközben a korábbi kernel boot entry és snapshot biztosítja a rollbacket.

  • Distribution kernel: a disztribúció által kiadott, backportolt és támogatott kernelcsomag.
  • Module ABI: a kernel és modulok közötti, verzióhoz kötött belső interfész, amelyet a vermagic azonosít.
  • Initramfs: korai userspace image, amely a root fájlrendszerhez szükséges modulokat és firmware-t biztosítja.
