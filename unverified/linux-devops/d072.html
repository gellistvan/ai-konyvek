15.2 POSIX mode, umask, ACL és fájlhozzáférés

15.2.1 Motiváció

A szenior C++ fejlesztő gyakran találkozik üzemeltetési oldalon fájlhozzáférési hibával: a szolgáltatás a saját konfigurációját nem tudja elolvasni, a backup nem látja a kötetet, a csoporttárs a közös projektmappában nem tud létrehozni fájlt. A Permissions denied üzenet félrevezető lehet, ha csak a fájl mode bitjeit nézzük: a hiba gyakran a path egy köztes directory elemén lévő hiányzó execute jogból vagy a rosszul beállított umaskból származik. Célunk, hogy a hozzáférést a directory traversal és a file mode rétegein keresztül le tudjuk vezetni, és az umask/ACL kombinációt dokumentált policy szerint állítsuk be.

15.2.2 Definíció és működés

15.2.2.1 A POSIX mode bitek

Minden fájl és directory inode-ja tárol egy mode mezőt, amely három osztályra (owner, group, other) és három bitre (r, w, x) bontható. A mode oktális jelölése például 0644 vagy 0755, ahol a vezető 0 az oktális bázisjel. Az első három bit az owne-ré, a következő három a groupé, az utolsó három az otheré. Az olvasás r (4), írás w (2), végrehajtás/keresés x (1).

A fájl esetében az r a lemezről való olvasást, a w az írást, az x a futtatást jelenti. Könyvtár esetében a bitek jelentése eltér:

  • r: a directory bejegyzéseinek listázása (pl. ls).
  • w: új bejegyzés létrehozása, átnevezése vagy törlése a directoryban.
  • x: a directory átjárása (search/traversal), vagyis a path feloldás következő komponensének a vizsgálata.

A path feloldás során a kernel a processzet futtató user és a csoporttagságai alapján minden egyes directory komponensre ellenőrzi az x jogot. Ha a path a/b/c.txt, akkor az a directoryra és az a/b directoryra is kell x, mielőtt a c.txt fájl mode bitjeit egyáltalán megvizsgálná. Ezért egy 0755 fájl sem olvasható, ha a szülőkönyvtára 0700, és a kérő nem az owner.

15.2.2.2 Umask és create mode

A open(2), creat(2), mkdir(2) rendszerhívások a kérő process által megadott mode-ot módosítják:

created_mode=requested_mode&(∼umask)\mathrm{created\_mode} = \mathrm{requested\_mode} \;\&\; (\sim \mathrm{umask})

ahol a umask bitek azok, amelyeket a kernel eltüntet. Alap shell esetén gyakori a 022: a csoport és other write bit eltávolítása, így egy 0666 kéréssel 0644 keletkezik. A 002 umask csoportírás megtartást tesz lehetővé, a 077 pedig csak az owner számára ad hozzáférést. A umask a process beállítása, nem a fájlé; a shell umask builtinje megváltoztatja az újabb indított processek számára az értéket. A systemd szolgáltatások UMask= direktívával konfigurálják a szolgáltatás umaskját.

15.2.2.3 chmod, chown, chgrp és szimbolikus linkek

A chmod parancs az inode mode bitjeit módosítja. A chown a user és csoport tulajdonost, a chgrp csak a csoportot. Az owner és a root módosíthatja a mode-ot; chown-t csak a root vagy CAP_CHOWN capability birtokában lévő process hajthat végre. A chgrp feltétele, hogy a végrehajtó a fájl ownerje, vagy a célcsoport tagja, és a fájl csoportja megengedett.

Szimbolikus link esetén a chmod és a chown alapértelmezetten a link által hivatkozott fájlt módosítják, nem a link inode-ját. A chown -h (--no-dereference) a link saját tulajdonosát változtatja. A szimbolikus link mode bitje a legtöbb rendszeren nem használt; a stat a linket 0777 mode-ként mutatja, mert az árulkodó jog a cél fájlon van.

15.2.2.4 Setuid, setgid és sticky bit

A mode oktális ábrázolásában a harmadik oktális számjegy adja a különleges biteket:

  • 4000 setuid (suid): ha a fájl futtatható, a kernel az effective UID-et a fájl tulajdonosára váltja. A passwd, ping tipikus példa.
  • 2000 setgid: fájlra futtatáskor az effective GID a fájl csoportjára vált; directoryra az újonnan létrehozott gyermekek group tulajdonosa a directory csoportját örökli.
  • 1000 sticky bit: directoryra igaz, hogy egy bejegyzést csak a bejegyzés ownerje, a directory ownerje vagy a root törölhet. A /tmp jellemzően 1777 mode-dal rendelkezik.

A setuid binárisokkal való biztonsági kockázat külön fejezetben (d073) kerül részletesen szóba; itt a mode szintjén tanítjuk a bitet, nem a helyes felhasználást.

15.2.2.5 POSIX ACL és mask

A hagyományos mode csak három osztályt tud kifejezni. A POSIX Access Control List (ACL) ezt kiterjeszti: egy fájlhoz rendelhető named user (pl. u:labauditor), named group, valamint a már ismert owner, group, other. Az ACL-eket a setfacl írja, a getfacl olvassa.

A kulcsfogalom az ACL mask. A mask egy olyan érvényességi maximum, amely a named user, named group és a group osztály érvényes jogait korlátozza. Ha a mask például r-- (4), akkor a group és a named user hiába kap rw bejegyzést, csak olvasni fog. A chmod group bitek módosítása az ACL maskot is módosítja, ezért a setfacl-t követő chmod felülírhatja a szándékot. A getfacl kimenete ezért mutatja a mask:: sort. A default ACL-ek directoryra vonatkoznak, és az újonnan létrehozott gyermekekre örökítődnek.

15.2.2.6 namei és getfacl diagnosztika

A namei -l PATH parancs minden path komponenst felold, és kiírja azok mode-ját és tulajdonosát. Ezzel a directory traversal jogokat ellenőrizhetjük. A getfacl az aktuális ACL-t mutatja; a getfacl -p a hagyományos mode bitekből is láthatóvá teszi a mask hatását.

15.2.3 Kidolgozott példa

Cél: közös adatkönyvtár /srv/lab-shared/team-data, ahol a labuser tulajdonos, a labgroup csoport írhat/olvashat, others nem férhet hozzá. A csoportos írás a létrehozott fájlokon is megmaradjon.

Előfeltételek: labhost lab-vm1, user labuser (UID 1000), group labgroup (GID 2000), root jog a beállításhoz.

# root@lab-vm1, UID 0
mkdir -p /srv/lab-shared/team-data
chown labuser:labgroup /srv/lab-shared/team-data
chmod 2770 /srv/lab-shared/team-data

A 2770 setgid és owner/group rwx, others semmi. A setgid miatt az új fájlok group tulajdonosa labgroup lesz.

A shell bejelentkezés után a labuser umaskja 007 (csak others tilt), hogy a létrehozott fájl mode 660 legyen. A beállítás dokumentált policy része:

# labuser@lab-vm1, UID 1000, a policy részeként
umask 007
touch /srv/lab-shared/team-data/foo.cfg
stat -c '%a %U %G %n' /srv/lab-shared/team-data/foo.cfg

Várható kimenet: 660 labuser labgroup /srv/lab-shared/team-data/foo.cfg

Ha az adott csoporttag labauditor (UID 3001) olvasási és traversálási jogot kap a jövőbeli fájlokra is, a default ACL-t kell beállítani:

# root@lab-vm1
setfacl -m u:labauditor:rX /srv/lab-shared/team-data
setfacl -d -m u:labauditor:rX /srv/lab-shared/team-data

Az rX miatt directoryra r+x, fájlra csak olvasás lesz az örökölt ACL-ből. Az új fájl 660 mode-ja mellett a getfacl a named user-t is mutatja, és a mask rw lesz. Ellenőrzés:

# labuser@lab-vm1
touch /srv/lab-shared/team-data/new.cfg
getfacl -p /srv/lab-shared/team-data/new.cfg

Várható kimenet (illusztratív):

# file: /srv/lab-shared/team-data/new.cfg
# owner: labuser
# group: labgroup
user::rw-
user:labauditor:r--
group::rw-
mask::rw-
other::---

Most a labauditor bejelentkezve:

# labauditor@lab-vm1, UID 3001
namei -l /srv/lab-shared/team-data/new.cfg

Várható kimenet:

f: /srv/lab-shared/team-data/new.cfg
drwxr-xr-x root     root     /
drwxr-xr-x root     root     srv
drwxr-x--- labuser  labgroup lab-shared
drwxrws--- labuser  labgroup team-data
-rw-rw---- labuser  labgroup new.cfg

Az ellenőrzési feltétel: a lab-shared directoryn a csoportnak x kell lennie, a team-data directoryn is, és a fájl ACL user:labauditor:r-- sort mutasson. Ha a lab-shared mode 0750 helyett 0700 lenne, a labauditor már a lab-shared belépésénél Permission denied-t kapna, bár a team-data és a fájl jogai engednék.

15.2.4 Hibák és ellenpróbák

Tünet: ls működik a directoryban, de a fájlt cat nem tudja olvasni, Permission denied.

Hipotézis: a directory x bitje hiányzik a group/other osztálytól, de az r megvan. A namei -l megmutatja, melyik komponensnél hiányzik. A javítás egy jogosultság beállítása, pl. chmod g+x /srv/lab-shared. Egy változtatás, majd verifikálás.

Tünet: egy újonnan létrehozott fájl 644 lett a várt 660 helyett, ezért a csoporttárs nem tud írni.

Hipotézis: a folyamat umaskja 022 vagy 002 helyett a policy-től eltérő érték. A umask parancs kilistázza; a folyamat beállításának hibáját okozhatja a shell globális profil vagy a systemd UMask= direktíva hiánya. Javítás után a fájl mode ellenőrzendő.

Tünet: setfacl beállítja a named user jogot, de a felhasználó mégsem fér hozzá.

Hipotézis: az ACL mask korlátozza a jogot. A getfacl mask sora mutatja az érvényes biteket. Egy későbbi chmod 750 például a maskot r-x-re állítja, így a named user rw bejegyzése csak olvasást enged. A javítás setfacl -m mask::rw- vagy az ACL újraállítása, de a policy szerint a mask és a group mode szinkronban tartandó.

Tünet: setuid scriptre ráfuttatva a process nem kapja meg a tulajdonos UID-jét.

Hipotézis: a Linux kernel interpreteres script esetén a setuid bitet figyelmen kívül hagyja; a kockázat miatt nem alkalmaz. A natív binárisra a bit működik, de a használatát biztonsági szempontból a d073-ban vizsgáljuk. Itt a mode bit kimutatása és a várt viselkedés megértése a cél.

15.2.5 Feladatok

  1. Magyarázó feladat: Adott a /srv/lab-a/proj/data.txt fájl, mode 0644, owner labuser, group labgroup. A labuser2 tagja a labgroup csoportnak. A path komponensek mode-jai: / 0755, /srv 0755, /srv/lab-a 0750 (owner root, group root), /srv/lab-a/proj 2770 (owner labuser, group labgroup). Vezesd le lépésenként, milyen jogosultsági ellenőrzéseket végez a kernel a labuser2 processzre a cat /srv/lab-a/proj/data.txt végrehajtásakor. Állapítsd meg, hol és miért hiúsul meg a hozzáférés.

  2. Adminisztrációs/konfigurációs feladat: Állíts be egy új dokumentált policy-hoz tartozó directoryt /srv/lab-shared/audit-data a lab-vm1 hoston. A követelmények: owner labuser, group labaudit (GID 3000), others nem férhetnek hozzá; a csoport írhat és olvashat; az újonnan létrehozott fájlok group tulajdonosa automatikusan labaudit legyen; a fájlok default mode-ja 660. Ehhez válassz umaskot, setgid bitet, és ha szükséges, default ACL-t. Add meg a teljes parancssort és a postconditiont ellenőrző parancsokat.

  3. Diagnosztikai/failure/recovery feladat: A labuser2 jogos lenne a /srv/lab-shared/team-data directoryban lévő new.cfg fájl olvasására, de a cat parancsra Permission denied-t kap. Korábbi beavatkozás során egy admin a /srv/lab-shared directoryn chmod 0700-at futtatott. Használj namei -l parancsot a diagnózisra, majd javítsd a hibát a legkisebb szükséges jogosultság visszaállításával. Indokold a chmod paramétereket.

15.2.6 Megoldások

  1. A path feloldás sorrendje:

    • A processzet labuser2 és annak group tagságai (beleértve labgroup) kísérik. A / 0755 mindenki számára x jogot ad, tehát a traversal engedélyezett.
    • /srv 0755: traversálható.
    • /srv/lab-a 0750, owner root, group root: a labuser2 nem owner, és nem tagja a root csoportnak, ezért az other érvényes, az x bit hiányzik (0). A kernel itt EACCES hibát ad, a data.txt mode-ot már nem is vizsgálja.
    • A további komponensek jogai nem számítanak, mert a traversal itt megszakad. A fájl 0644 egyébként engedné a csoportos olvasást, de a hiányzó directory x megakadályozza.

  2. A beállítás root joggal:

    # root@lab-vm1
groupadd -g 3000 labaudit
mkdir -p /srv/lab-shared/audit-data
chown labuser:labaudit /srv/lab-shared/audit-data
chmod 2770 /srv/lab-shared/audit-data

    A labuser bejelentkezés után:

    # labuser@lab-vm1
umask 007
touch /srv/lab-shared/audit-data/test.txt
stat -c '%a %U %G %n' /srv/lab-shared/audit-data/test.txt

    Várható kimenet: 660 labuser labaudit .../test.txt. A setgid bit miatt a group labaudit. A default ACL-re itt nincs szükség, mert a group hozzáférés a mode-ból adódik. Postcondition: a directory mode 2770, a benne lévő új fájl mode 660, group tulajdonos labaudit, others jog nincs.

  3. Diagnózis:

    # labuser2@lab-vm1
namei -l /srv/lab-shared/team-data/new.cfg

    A kimenet mutatja, hogy a /srv/lab-shared mode-ja 0700, a labshared groupnak nincs x bit. A labuser2 az other osztályba esik, ahol sem r, sem x nincs. A javítás root joggal:

    # root@lab-vm1
chmod 0750 /srv/lab-shared

    A 0750 minimalisan ad traversálási jogot a groupnak, miközben a team-data directory továbbra is a saját szabályait követi. A labuser2 ezután a team-data directory groupjába tartozva beléphet, és a fájl ACL-je engedi az olvasást.

15.2.7 Rövid összefoglaló

A fájlhozzáférés a path minden directory komponensén át vezet; a directory x bit nélkül a kernel már a traversal során EACCES-t ad. A mode bitek owner/group/other osztályokban r/w/x jogot adnak. A umask a create mode-ot redukálja, ezért a policy szerinti fájlmode-hoz explicitté kell tenni. A setgid bit directory esetén a gyermekek group tulajdonosát örökíti. A POSIX ACL named user és named group jogokat ad, de ezeket a mask korlátozza; a chmod group bit változása a maskot módosítja. A namei -l és getfacl a rétegzett diagnózis alapvető eszköze.

Továbbhasznált definíciók:

  • Traversal jog: directory x bit, amely lehetővé teszi a path következő komponensének feloldását.
  • Umask: a create/open/mkdir során a kért mode-ból levont bitmaszk.
  • ACL mask: a named user, named group és group osztály érvényes jogait korlátozó érvényességi maximum.
