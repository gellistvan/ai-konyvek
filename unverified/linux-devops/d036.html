8.1 Process, PID, fork/exec és szülő-gyermek kapcsolat

8.1.1 Motiváció és process-definíció

Egy C++ szolgáltatás indításakor a fejlesztő gyakran csak annyit lát, hogy a rendszer elindít egy folyamatot. Az üzemeltető ezzel szemben a teljes processzfát, a szülő-gyermek viszonyokat, a fájlleíró-öröklést és a kilépési állapotot is kénytelen értelmezni. A ps kimenet nem öncélú adat: egy magas CPU-t használó vagy éppen „nem szűnő” gyermekfolyamat mögött fork/exec/wait folyamatok, file descriptor öröklés vagy akár zombie-felhalmozódás állhat. Ebben az alfejezetben a Linux process-modellt járjuk körbe a kernel task fogalmától a /proc/PID megfigyelésig.

A Alkalmazástól a fizikai gépig: teljes stack fejezetben már elhelyeztük a folyamatot a rendszerhívás határán. Itt a process object részletes életciklusa következik.

Definíció szerint a folyamat (process) a kernel által ütemezhető entitás, amely egy program végrehajtási példánya, és rendelkezik saját azonosítóval, memóriatérképpel, fájlleíró-táblával, hitelesítési adatokkal, környezeti változókkal, aktuális munkakönyvtárral, valamint ütemezési és jelzési állapottal. A POSIX-specifikáció a processz fogalmát process ID, fork, exec, wait és jelzések köré építi; a Linux-implementáció ezt task struktúrával valósítja meg. A mérési interfész a ps, a pstree és a /proc fájlrendszer.

8.1.2 PID, parent, process group és session

A Linux kernel minden végrehajtható entitáshoz egyedi PID-t (process ID) rendel. A folyamatok hierarchiát alkotnak: a szülő PPID-je a létrehozó folyamatra mutat. A hierarchia gyökere a PID 1, a Lab Ubuntu rendszeren a systemd.

A process group (folyamatcsoport) azonos PGID-vel rendelkező folyamatok halmaza. A shell interaktív munkamenetben a háttérbe indított jobot saját processz groupba teszi, hogy a teljes csoportnak jelet lehessen küldeni. A csoportvezér az, akinek PID-je megegyezik a PGID-dal.

A session (munkamenet) több processz groupot foglal magában, és egy kontrolláló terminálhoz tartozik. A session vezér az a folyamat, amelyik a sessiont létrehozta; a session ID az ő processz group ID-je. Egy interaktív SSH-bash megnyitásakor a shell jellemzően session vezérré válik.

A ps több kulcsmezőt jelenít meg:

Mező Jelentés
PID process ID
PPID parent process ID
PGID process group ID
SID/SESS session ID
STAT folyamatállapot-kód
CMD parancssor vagy image-név

A STAT első karaktere a fő állapot: R futó/futtatható, S megszakítható alvás, D megszakíthatatlan alvás, T leállított, Z zombie. Kiegészítő flag például s (session leader), + (foreground job), l (többszálú). A szülő-gyermek viszonyt a pstree -ap folyamatfaként jeleníti meg.

A /proc/PID minden futó taskról kernel által szolgáltatott futásidejű adat: status (Uid, Gid, PPid, PGid, Sid, State, Threads), fd (nyitott fájlleírók), task (thread-ek) és exe (futó programkép).

8.1.3 fork, exec, exit és wait

A process-indítás a POSIX modellben két lépésből áll.

A fork() rendszerhívás létrehoz egy új PID-jel rendelkező gyermekprocesszt. A Linux implementáció a hívó task-ot másolja. A memória-oldalak fizikailag nem másolódnak azonnal; a kernel copy-on-write módon megosztja a lapokat, és csak íráskor készít másolatot. A gyermek saját PID-et, de azonos PPID-t, processz csoportot, sessiont, credentials-t, környezeti változókat, cwd-t és fájlleíró-táblát örököl. A nyitott fájl-leírások (open file description) közösek maradnak, tehát a file offset is közös.

Az execve() nem hoz létre új PID-et. Ugyanaz a task betölti az új programképet: lecserélődik a memória, a stack, a heap és a programutasítások. A PID, PPID, PGID, SID, credentials, cwd és a fájlleíró-tábla megmarad, kivéve a FD_CLOEXEC jelzővel ellátott file descriptorokét, amelyeket a kernel bezár. Ez a fork utáni gyermek tipikus lépése, például a shell a fork után a gyermekben lecseréli a futó programkódot a tényleges programra.

A kilépést a processz az exit_group() rendszerhívással kezdeményezi. A kernel felszabadítja a memóriát, lezárja a fájlleírókat, de maga a task bejegyzés zombie állapotban (Z) megmarad, amíg a szülő be nem gyűjti a kilépési státuszt. A szülő waitpid()-del aratja le a gyermeket; ekkor törlődik a kernelbeli bejegyzés. Ha a szülő korábban meghal, az árva gyermeket a systemd adoptálja, és az le is aratja.

A gyermek exit utáni státuszát a C WIFEXITED(), WEXITSTATUS() makrókkal lehet értelmezni. Egy szülő, amelyik nem hív wait-et, zombie-kat hagy hátra. A zombie folyamat már nem fut, memóriája felszabadult, de a kernel processz-tábla bejegyzése foglalt marad; ezért a kill -9 sem távolítja el.

8.1.4 Credentials, environment, cwd és file descriptor tábla

A folyamat hitelesítési adatai: valós UID/GID, effektív UID/GID, saved UID/GID, kiegészítő csoportok, valamint Linux capabilities. A fork mindet másolja. Az execve megtartja őket, kivéve, ha a betöltött program setuid/setgid bitje miatt a kernel módosítja az effektív UID-et.

A környezeti változók a processz memóriájában élő karakterláncok; a fork megörökli, az execve argumentumként kapja a környezetet. Az aktuális munkakönyvtár (cwd) szintén a task attribútuma; chdir() után a processz relatív útvonalait ez határozza meg, és a fork megörökli.

A fájlleíró-tábla (file descriptor table) a processzenkénti indirekció a nyitott fájlokra. A fork a táblát másolja, ezért a gyermek ugyanazokat az FD-ket látja. A megnyitott fájlból való olvasás és írás közös open file description-t használ, így az offset is megosztott. Az execve a táblát megtartja, ami a shell redirekciók alapja: a dup2() beállítja az FD-t, a gyermek execve-je pedig a beállított FD-kkel indítja az új programot.

Ha egy descriptor FD_CLOEXEC flag nélkül marad, akkor a gyermek az exec után is örökli, ami operatív probléma lehet: hosszú életű child a logfájlt vagy hálózati socketet nyitva tarthatja, miközben a szülő már lezárta volna. A megoldás a descriptor megnyitásakor az O_CLOEXEC flag használata, vagy a fcntl(fd, F_SETFD, O_CLOEXEC) hívás.

8.1.5 Thread versus process, Linux task

A Linux kernel task-okkal ütemez, nem külön processz/thread absztrakcióval. A fork() a clone() rendszerhívást használja minimális flag-ekkel; a pthread_create() a clone()-t CLONE_THREAD flaggel hívja. A thread-ek tehát ugyanazt a memóriát, fájlleíró-táblát, jelzéskezelőket és cwd-t osztják, de külön kernel task azonosítóval rendelkeznek.

A POSIX getpid() thread-ben a thread group ID-t adja vissza, amely a task group azonosítója; a kernelbeli task ID a gettid() hívással érhető el. A /proc/PID/task a thread task-okat sorolja fel, a ps -L szálanként mutatja őket. Egy C++ std::thread tehát OS-szinten egy task a thread groupban, nem külön processz. A fork szálas programban csak a hívó threadet másolja a gyermekbe; a többi thread nem azonos állapotú, ezért a fork után a gyermekben csak async-signal-safe függvényeket szabad hívni.

8.1.6 Kidolgozott példa: folyamatfa és fork/exec

A cél egy interaktív shellből indított háttérfolyamat process-struktúrájának megfigyelése, valamint egy fork/exec/wait program futtatása. A labhost labvm1, a parancsok normál lab felhasználóval futnak (UID 1000).

# Target: labvm1, UID=lab (1000), munkakönyvtár: /home/lab
# Előfeltétel: d003 szerinti labVM elérhető, interaktív bash shell.
cd /home/lab
sleep 300 &
sleep_pid=$!

# A shell és a háttérfolyamat processzadatai
ps -o pid,ppid,pgid,sess,stat,cmd -p "${sleep_pid}" "$$"

# Folyamatfa a shell alatt
pstree -ap "$$"

# Kernel állapot és FD tábla
readlink "/proc/${sleep_pid}/exe"
awk -F: '/^(Uid|PPid|PGid|Sid|State|Threads)/{print}' "/proc/${sleep_pid}/status"
ls -l "/proc/${sleep_pid}/fd"

# Cleanup: csak a labor saját háttérfolyamata
kill "${sleep_pid}"
wait "${sleep_pid}" 2>/dev/null

A várt ps kimenet (a PID-ek a labon eltérnek):

  PID  PPID  PGID  SESS STAT CMD
48211  2871 48211  2871 S    sleep 300
 2871     0  2871  2871 Ss   -bash

A sleep PID-je megegyezik a PGID-dal, tehát a job saját process groupot kapott; a SESS 2871 a shell session ID-je. A shell Ss állapota alvó session leader. A pstree várt fája:

bash,2871
  ├─pstree,48223
  └─sleep,48211

A /proc/48211/status várt kivonata:

Uid:    1000    1000    1000    1000
PPid:   2871
PGid:   48211
Sid:    2871
State:  S (sleeping)
Threads:    1

A /proc/48211/fd mutatja, hogy a sleep örökli a shell terminál descriptorait (0, 1, 2, jellemzően ugyanarra a /dev/pts-re mutatva).

Most a fork/exec/wait példa:

# Target: labvm1, UID=lab, munkakönyvtár: /home/lab/lab-d036
# Előfeltétel: gcc elérhető (Ubuntu Server 24.04 LTS baseline).
mkdir -p /home/lab/lab-d036
cd /home/lab/lab-d036
cat > lab-fork-demo.c <<'EOF'
#include <sys/types.h>
#include <sys/wait.h>
#include <unistd.h>
#include <stdio.h>
#include <stdlib.h>

extern char **environ;

int main(void) {
    pid_t pid = fork();
    if (pid < 0) {
        perror("fork");
        return 1;
    }
    if (pid == 0) {
        printf("child before exec: pid=%ld, parent=%ld\n",
               (long)getpid(), (long)getppid());
        fflush(stdout);
        char *const argv[] = {"/bin/echo", "exec-ok", NULL};
        if (execve("/bin/echo", argv, environ) == -1) {
            perror("execve");
            _exit(127);
        }
        _exit(127); /* ide sikeres exec után nem jutunk */
    }
    int wstatus = 0;
    pid_t w = waitpid(pid, &wstatus, 0);
    if (w == -1) {
        perror("waitpid");
        return 1;
    }
    printf("parent after wait: child=%ld, wait_pid=%ld, status=%d\n",
           (long)pid, (long)w, WEXITSTATUS(wstatus));
    return 0;
}
EOF

gcc -Wall -Wextra -O2 -o lab-fork-demo lab-fork-demo.c
./lab-fork-demo

Várt kimenet:

child before exec: pid=48320, parent=48318
exec-ok
parent after wait: child=48320, wait_pid=48320, status=0

A gyermek a PID-jét az exec előtt kiírja, az execve ugyanabban a PID-ben lefuttatja a /bin/echo programot, a szülő pedig le aratja a kilépési státuszt. Az exec-ok sor onnan jön, hogy az exec után a /bin/echo argumentummá vált.

8.1.7 Hibák és ellenpróbák

Zombie-felhalmozódás. Tünet: új processz indítása fork: Resource temporarily unavailable hibát ad, vagy a ps kimenetében sok Z állapotú sor látható. Adatgyűjtés:

# Target: labvm1, UID=lab, olvasó parancs
ps -eo pid,ppid,stat,cmd | awk '$3 ~ /^Z/'

A kimenet megadja a zombie PID-jét és szülőjét. Hipotézis: a szülő nem hív waitpid-et. Ellenpróba: a kill -9 <zombie_pid> parancs nem szünteti meg a Z állapotot, mert a folyamat már nem fut; csak a kernelbeli bejegyzés vár a szülőre. A javítás egy változtatása: a szülő processz újraindítása, vagy a kódban waitpid hívás hozzáadása. Ha a szülő kilép, a systemd adoptálja a zombie-t, és le aratja.

Fájlleíró-öröklés. Hibás C++ indítóprogram esetén a gyermek execve után is tartja a logfájlt vagy hálózati socketet, ha a descriptor nem kapott O_CLOEXEC flaget. A diagnózis a /proc/<child_pid>/fd könyvtárban látható; a fájl bezáródását a szülő lezárása után sem tapasztaljuk, mert a child még nyitva tartja. A javítás: az FD-t O_CLOEXEC-kal kell nyitni, vagy a fork után a gyermekben a execve előtt a fölösleges FD-ket bezárni.

Pufferelt kimenet duplikálódása. A fork után a gyermek a szülő stdio pufferét is másolja. Ha a fork előtt a szülő puffere nem volt flushelve, a gyermek későbbi exit-je és a szülő flushe egyaránt kiírthatja ugyanazt az adatot. A C++ RAII és destructorok sem futnak le a gyermekben, ha az execve sikerrel lecseréli a programképet; ezért a child ágon _exit-et és fflush-t kell használni.

8.1.8 Feladatok

8.1.8.1 1. Feladat: folyamatfa és ps mezők értelmezése

Futtasd a labVM-en az alábbi parancsot:

# Target: labvm1, UID=lab
ps -eo pid,ppid,pgid,sess,stat,cmd

Azonosítsd a saját interaktív shelled PID-jét, PPID-jét, PGID-jét és SESS értékét. Magyarázd meg a shell STAT mezőjében látható s flaget, és állapítsd meg, ki a session leader.

8.1.8.2 2. Feladat: fork/exec PID-azonosság megfigyelése

Készíts lab-fork-watch.c programot, amely fork() után a gyermekben sleep(5)-öt hív, majd execve()-vel /bin/echo after-exec-et futtat. A szülő waitpid()-del vár. A gyermek az exec előtt írja ki a PID-jét. Futtasd a programot egy shellben, és egy második shellben a gyermek PID-jével figyeld meg a ps -o pid,ppid,pgid,sess,stat,cmd és a readlink /proc/<pid>/exe kimenetét az exec előtt és után. Bizonyítsd, hogy a gyermek PID-je nem változik.

8.1.8.3 3. Feladat: zombie diagnosztika és megszüntetés

Készíts lab-zombie.c programot, amely fork() után a gyermek azonnal _exit(0)-t hív, a szülő pedig sleep(30)-et, és ez idő alatt nem waitpid()-et. Futtasd háttérben. Azonosítsd a zombie-t a ps -eo pid,ppid,stat,cmd kimenetéből. Próbáld meg kill -9-cel megszüntetni, és értelmezd az eredményt. Végül a szülő normál terminálásával szüntesd meg a zombie-t.

8.1.9 Megoldások

8.1.9.1 1. Megoldás

Az interaktív bash shell általában session leader, ezért a shell PID-je megegyezik a SESS értékkel, és a STAT mező s flaget is tartalmaz. A shell PGID-ja ugyanaz, mint a saját PID-je, mert a shell process group vezér. A PPID az SSH daemon vagy a systemd lehet, attól függően, hogyan indult a munkamenet. A ps -eo kimenetben látható többi processz groupok a shell által indított jobok; a PGID mező segít azonosítani, hogy egy job összes folyamata ugyanabba a groupba tartozik-e.

Postcondition: a tanuló meg tudja adni a shell PID/PPID/PGID/SESS értékét, és ismeri a STAT fő állapotkódjait.

8.1.9.2 2. Megoldás

A kód:

#include <sys/types.h>
#include <sys/wait.h>
#include <unistd.h>
#include <stdio.h>
#include <stdlib.h>

extern char **environ;

int main(void) {
    pid_t pid = fork();
    if (pid < 0) { perror("fork"); return 1; }
    if (pid == 0) {
        printf("child pid=%ld before sleep\n", (long)getpid());
        fflush(stdout);
        sleep(5);
        char *const argv[] = {"/bin/echo", "after-exec", NULL};
        if (execve("/bin/echo", argv, environ) == -1) {
            perror("execve");
            _exit(127);
        }
        _exit(127);
    }
    int status = 0;
    pid_t w = waitpid(pid, &status, 0);
    if (w == -1) { perror("waitpid"); return 1; }
    printf("parent: child=%ld wait=%ld status=%d\n",
           (long)pid, (long)w, WEXITSTATUS(status));
    return 0;
}

Futtatás:

# Target: labvm1, UID=lab, munkakönyvtár: /home/lab/lab-d036
$ gcc -Wall -Wextra -O2 -o lab-fork-watch lab-fork-watch.c
$ ./lab-fork-watch
child pid=49123 before sleep
after-exec
parent: child=49123 wait=49123 status=0

A második shellben, amíg a gyermek az 5 másodperces sleep alatt fut, a readlink /proc/49123/exe a lab-fork-watch programot mutatja, a ps stat S. Az exec után, amíg a /bin/echo fut, a PID ugyanaz, de a readlink az /bin/echo-ra mutat, a ps pedig az after-exec parancssort mutathatja. A fontos megfigyelés: exec nem hoz létre új PID-et.

Postcondition: a tanuló rögzíti, hogy a gyermek PID-je az exec előtt és után azonos, és ez bizonyítható a /proc/PID/exe változásával.

8.1.9.3 3. Megoldás

A kód:

#include <sys/types.h>
#include <sys/wait.h>
#include <unistd.h>
#include <stdio.h>

int main(void) {
    pid_t pid = fork();
    if (pid < 0) { perror("fork"); return 1; }
    if (pid == 0) {
        _exit(0);
    }
    printf("child=%ld parent=%ld\n", (long)pid, (long)getpid());
    fflush(stdout);
    sleep(30);
    waitpid(pid, NULL, 0);
    return 0;
}

Futtatás és diagnosztika:

# Target: labvm1, UID=lab
$ gcc -Wall -Wextra -O2 -o lab-zombie lab-zombie.c
$ ./lab-zombie &
child=49330 parent=49329

$ ps -o pid,ppid,stat,cmd -p 49330 49329
  PID  PPID STAT CMD
49329  2871 S    ./lab-zombie
49330 49329 Z    [lab-zombie] <defunct>

$ kill -9 49330
$ ps -o pid,ppid,stat,cmd -p 49330
# A 49330 továbbra is Z, a kill -9 nem hat.

$ kill -TERM 49329
$ wait 49329 2>/dev/null
$ ps -o pid,ppid,stat,cmd -p 49330 49329
# A zombie eltűnik, mert a halott szülőt a systemd adoptálja és le aratja.

A Z állapot azt mutatja, hogy a gyermek kilépett, de a szülő még nem hívott wait-et. A kill -9 nem szünteti meg, mert a zombie nem futó task; csak a wait szünteti meg a kernelbejegyzést. A szülő kilépése után a systemd adoptálja a zombie-t, és wait-et hív.

Postcondition: nincs lab-zombie folyamat a ps kimenetben, és a ps -eo stat | grep Z nem mutat lab-zombie-t. A labhost processztáblája nem tartalmaz a labfeladat által okozott zombie-t.

8.1.10 Rövid összefoglaló

A Linux folyamat a kernel task implementációja, amely PID-del, szülővel, processz csoporttal, sessionnel, hitelesítési adatokkal, memóriával, fájlleíró-táblával és schedüléssel rendelkezik. A fork új PID-et hoz létre, és copy-on-write módon másolja a processzt; az exec ugyanabban a PID-ben lecseréli a programképet. A kilépés után a folyamat zombie marad, amíg a szülő waitpid-del be nem gyűjti. A ps, pstree és /proc/PID ezeket az állapotokat teszi operátorilag megfigyelhetővé.

Továbbhasznált definíciók:

  • PID: kernelbeli azonosító, amely egy taskot az élettartama alatt egyértelműen jelöl.
  • Zombie: olyan befejezett processz bejegyzés, amelyre a szülő még nem hívott wait-et.
  • Fájlleíró-tábla: processzszintű indirekciós tábla, amely a megnyitott fájlokra mutat.
