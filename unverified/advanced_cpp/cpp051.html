14.2 Saját allokátor és custom container

Az előző alfejezetben áttekintettük az STL allokátor modellt és a PMR-t. Most egy saját allokátort és egy arra épülő egyedi konténert készítünk. A cél nem csupán az interfész megvalósítása, hanem annak megértése, hogyan csatolódik az allokátor a konténerhez, és milyen buktatók leselkednek a rebind, az állapotkezelés és a kivételbiztonság terén. A fejezetben egy bump-pointer arena allokátort és egy arena_vector nevű, dinamikus tömböt megvalósító konténert építünk, amely az allokátort használja. A példa a C++17/20 szabványnak megfelelő, de ahol a nyelv változott, azt jelezzük.

14.2.1 A saját allokátor felépítése

Az allokátor a std::allocator_traits sablonon keresztül csatlakozik a konténerekhez. A std::allocator_traits számos alapértelmezett típust és műveletet biztosít, így a saját allokátorunknak csak a minimális interfészt kell megvalósítania. A legfontosabb követelmények:

  • value_type – a lefoglalandó elem típusa.
  • allocate(n) – legalább n * sizeof(T) bájt, megfelelően igazított memória foglalása.
  • deallocate(p, n) – az allocate által visszaadott memória felszabadítása, ahol n pontosan az allocate-nak átadott érték.
  • max_size() – a maximálisan lefoglalható elemek száma (praktikusan std::numeric_limits<size_type>::max() / sizeof(T)).
  • rebind<U> – sablon, amely az Allocator<T>-ből Allocator<U>-t állít elő.

A modern C++ (C++11 óta) az std::allocator_traits használatát ajánlja a közvetlen allokátor interfész helyett. A traits automatikusan felismeri a rebind hiányát, és a template <typename U> struct rebind { using other = Allocator<U>; }; alapértelmezést alkalmazza, ha a sablonparaméter egyszerűen cserélhető. A rebind explicit megadása azonban olvashatóbbá teszi a kódot, és kompatibilis a régebbi konténerekkel is.

A következő példa egy minimális, nem állapotos allokátort mutat, amely a globális operator new-t használja:

// minimal_allocator.hpp
#include <cstddef>
#include <memory>
#include <limits>

template <typename T>
struct minimal_allocator {
    using value_type = T;
    using pointer = T*;
    using size_type = std::size_t;
    using difference_type = std::ptrdiff_t;

    template <typename U>
    struct rebind {
        using other = minimal_allocator<U>;
    };

    minimal_allocator() noexcept = default;
    template <typename U>
    minimal_allocator(const minimal_allocator<U>&) noexcept {}

    T* allocate(std::size_t n) {
        if (n > max_size()) throw std::bad_alloc();
        if (auto p = static_cast<T*>(::operator new(n * sizeof(T), std::align_val_t(alignof(T))))) {
            return p;
        }
        throw std::bad_alloc();
    }

    void deallocate(T* p, std::size_t) noexcept {
        ::operator delete(p, std::align_val_t(alignof(T)));
    }

    std::size_t max_size() const noexcept {
        return std::numeric_limits<std::size_t>::max() / sizeof(T);
    }
};

template <typename T, typename U>
bool operator==(const minimal_allocator<T>&, const minimal_allocator<U>&) noexcept { return true; }
template <typename T, typename U>
bool operator!=(const minimal_allocator<T>&, const minimal_allocator<U>&) noexcept { return false; }

Ebben a kódban az ::operator new és ::operator delete túlterhelt, igazítást kezelő változatát használjuk (std::align_val_t, C++17). A max_size() fontos: ha hiányzik, a std::allocator_traits a size_t(-1) / sizeof(T) értéket adja vissza, ami általában megfelelő, de a pontos definíció segít a hibakeresésben. Az allokátorok egyenlőségét is definiálni kell; itt minden példány egyenlő, mert nincs állapotuk.

14.2.2 A rebind és a konténerillesztés

A rebind mechanizmus kritikus szerepet játszik a konténerekben. Tegyük fel, hogy egy std::list<T, Allocator = std::allocator<T>> konténer nem T típusú objektumokat, hanem belső csomópontokat (list_node<T>) foglal. A konténernek szüksége van egy Allocator<list_node<T>> allokátorra. Ezt a std::allocator_traits<Allocator>::template rebind_alloc<list_node<T>> segítségével tudja előállítani. A rebind tehát az allokátor típusparaméterének megváltoztatását teszi lehetővé anélkül, hogy a felhasználónak külön allokátort kellene megadnia.

A saját allokátorunknak tehát támogatnia kell ezt a rebindet. Ha a minimal_allocator-ban nem adtunk volna meg rebind-et, a std::allocator_traits akkor is működne, mert a sablonparaméter cseréje triviális. De ha az allokátor állapottal rendelkezik, a rebind konstrukciónak át kell vennie az állapotot, amit a template <typename U> minimal_allocator(const minimal_allocator<U>&) konstruktor biztosít.

14.2.3 Stateful allocator: állapot tárolása és terjedése

A stateful allocator olyan allokátor, amelynek példányai különböző állapotot hordoznak. Például egy arena allokátor egy adott memóriaterületre mutat, vagy egy naplózó allokátor egy számlálót tart. Az ilyen allokátorok esetében a konténerek műveleteinél (másolás, mozgatás, csere) gondosan kell kezelni az allokátor állapotának terjedését. A std::allocator_traits a következő típusjellemzőket vizsgálja:

  • propagate_on_container_copy_assignment
  • propagate_on_container_move_assignment
  • propagate_on_container_swap

Ha ezek a jellemzők std::true_type-ok, akkor a megfelelő konténer művelet során az allokátort is átmásolják/átmozgatják/kicserélik. Ha std::false_type, akkor az allokátor nem változik. Az alapértelmezés std::false_type, ami a nem állapotos allokátorokra helyes, de stateful allokátoroknál hibát okozhat: pl. a konténer másolásakor az új konténer a régi allokátor állapotát nem kapná meg, és esetleg üres arena-ra mutatna.

Másik fontos jellemző az is_always_equal, amely azt mondja meg, hogy az allokátor két példánya mindig egyenlő-e. Az alapértelmezett érték a C++17 óta a std::is_empty<Allocator>::type (ha az allokátor üres, akkor true, egyébként false). Ha az allokátor mindig egyenlő, a konténerek bizonyos optimalizációkat végezhetnek (pl. nem kell allokátort cserélni swapkor). Ezt a jellemzőt explicit módon is megadhatjuk.

Példánkban az arena allokátor nem mindig egyenlő, mert a pointer különbözik. A propagate_on_container_* jellemzőket std::true_type-ra állítjuk, hogy az állapot mindig kövesse a konténert. Ez a legbiztonságosabb választás, bár teljesítménybeli költsége lehet, ha az allokátor állapota nagy.

14.2.4 Arena allokátor implementáció

Készítsünk egy egyszerű bump-pointer arena allokátort, amely egy előre lefoglalt memóriablokkból oszt ki, és nem szabadít fel egyedi elemeket. A felszabadítás az arena teljes újraindításakor történik. Az allokátor állapota tartalmazza az arena pointert és egy offsetet, amely az aktuális foglalási pozíciót jelzi.

// arena.hpp
#include <cstddef>
#include <cstdint>
#include <new>
#include <utility>

class arena {
public:
    explicit arena(std::size_t size)
        : memory_(static_cast<std::byte*>(::operator new(size, std::align_val_t(alignof(std::max_align_t))))),
          size_(size), offset_(0) {}

    ~arena() {
        ::operator delete(memory_, std::align_val_t(alignof(std::max_align_t)));
    }

    arena(const arena&) = delete;
    arena& operator=(const arena&) = delete;

    void* allocate(std::size_t n, std::size_t alignment) {
        // Igazítás kiszámítása
        std::uintptr_t addr = reinterpret_cast<std::uintptr_t>(memory_) + offset_;
        std::uintptr_t aligned = (addr + alignment - 1) & ~(alignment - 1);
        std::size_t padding = aligned - addr;
        if (offset_ + padding + n > size_) {
            throw std::bad_alloc();
        }
        void* result = memory_ + offset_ + padding;
        offset_ += padding + n;
        return result;
    }

    void deallocate(void*, std::size_t) noexcept {
        // Bump pointer: semmit sem teszünk; a memória az arena destruktorakor szabadul fel.
    }

    void reset() noexcept {
        offset_ = 0;
    }

    std::size_t used() const noexcept { return offset_; }
    std::size_t capacity() const noexcept { return size_; }

private:
    std::byte* memory_;
    std::size_t size_;
    std::size_t offset_;
};

Az allocate függvény igazítja a kért memóriát a alignment paraméterhez. A deallocate szándékosan üres, mert a bump-pointer stratégiában nem szabadítunk fel egyedi blokkokat – ezt a felhasználónak tudnia kell. Az arena nem másolható, mert a memória tulajdonjoga egyértelműen egy példányhoz tartozik.

Most az arena allokátor sablon:

// arena_allocator.hpp
#include <cstddef>
#include <memory>
#include <limits>
#include "arena.hpp"

template <typename T>
class arena_allocator {
public:
    using value_type = T;
    using pointer = T*;
    using size_type = std::size_t;
    using difference_type = std::ptrdiff_t;

    using propagate_on_container_copy_assignment = std::true_type;
    using propagate_on_container_move_assignment = std::true_type;
    using propagate_on_container_swap = std::true_type;
    using is_always_equal = std::false_type;

    template <typename U>
    struct rebind {
        using other = arena_allocator<U>;
    };

    arena_allocator() noexcept = default;

    explicit arena_allocator(arena* a) noexcept : arena_(a) {}

    template <typename U>
    arena_allocator(const arena_allocator<U>& other) noexcept : arena_(other.arena_) {}

    T* allocate(std::size_t n) {
        if (!arena_) throw std::bad_alloc();
        if (n > max_size()) throw std::bad_alloc();
        if (auto p = static_cast<T*>(arena_->allocate(n * sizeof(T), alignof(T)))) {
            return p;
        }
        throw std::bad_alloc();
    }

    void deallocate(T* p, std::size_t n) noexcept {
        if (!arena_) return;
        arena_->deallocate(p, n * sizeof(T));
    }

    std::size_t max_size() const noexcept {
        return std::numeric_limits<std::size_t>::max() / sizeof(T);
    }

    arena* get_arena() const noexcept { return arena_; }

    template <typename U>
    friend class arena_allocator;

private:
    arena* arena_ = nullptr;  // állapot: az arena pointer
};

template <typename T, typename U>
bool operator==(const arena_allocator<T>& lhs, const arena_allocator<U>& rhs) noexcept {
    return lhs.get_arena() == rhs.get_arena();
}

template <typename T, typename U>
bool operator!=(const arena_allocator<T>& lhs, const arena_allocator<U>& rhs) noexcept {
    return !(lhs == rhs);
}

Ez az allokátor stateful, mert az arena_ pointer példányonként eltérhet. A propagate_on_container_* típusok std::true_type-ok, így a konténerek másolásakor/mozgatásakor az allokátor is átmásolódik, és az új konténer ugyanarra az arena-ra mutat. Ez azt jelenti, hogy az arena-nak élnie kell mindaddig, amíg bármely konténer használja. A biztonság kedvéért az arena-t általában a konténerek előtt hozzuk létre, és utánuk semmisítjük meg.

14.2.5 Egyedi konténer: arena_vector

Most egy saját, dinamikus tömbként viselkedő konténert készítünk, amely az allokátort használja. A konténer arena_vector<T, Allocator = arena_allocator<T>> formában lesz használható. A hangsúly az allokátor megfelelő használatán és a kivételbiztonságon van.

A konténer minimalista, de tartalmazza a legfontosabb műveleteket: push_back, pop_back, reserve, size, capacity, iterátorok, másolás, mozgatás. A következő kódban a std::allocator_traits-t használjuk, így a konténer automatikusan alkalmazkodik az allokátor képességeihez.

// arena_vector.hpp
#include <cstddef>
#include <memory>
#include <stdexcept>
#include <type_traits>
#include <utility>
#include <algorithm>

template <typename T, typename Allocator = std::allocator<T>>
class arena_vector {
public:
    using allocator_type = Allocator;
    using value_type = T;
    using size_type = std::size_t;
    using difference_type = std::ptrdiff_t;
    using pointer = typename std::allocator_traits<Allocator>::pointer;
    using const_pointer = typename std::allocator_traits<Allocator>::const_pointer;
    using reference = T&;
    using const_reference = const T&;
    using iterator = T*;
    using const_iterator = const T*;

private:
    using alloc_traits = std::allocator_traits<Allocator>;
    allocator_type alloc_;
    T* data_ = nullptr;
    size_type size_ = 0;
    size_type capacity_ = 0;

    // Segédfüggvény a memória felszabadítására
    void destroy_elements(T* p, size_type n) noexcept {
        for (size_type i = 0; i < n; ++i) {
            alloc_traits::destroy(alloc_, p + i);
        }
    }

    void deallocate_buffer(T* p, size_type cap) noexcept {
        if (p) {
            alloc_traits::deallocate(alloc_, p, cap);
        }
    }

public:
    // Konstruktorok
    explicit arena_vector(const Allocator& alloc = Allocator()) noexcept
        : alloc_(alloc) {}

    explicit arena_vector(size_type count, const T& value = T(), const Allocator& alloc = Allocator())
        : alloc_(alloc) {
        resize(count, value);
    }

    arena_vector(const arena_vector& other)
        : alloc_(alloc_traits::select_on_container_copy_construction(other.alloc_)) {
        reserve(other.size_);
        for (const auto& elem : other) {
            push_back(elem);
        }
    }

    arena_vector(arena_vector&& other) noexcept
        : alloc_(std::move(other.alloc_)), data_(other.data_), size_(other.size_), capacity_(other.capacity_) {
        other.data_ = nullptr;
        other.size_ = 0;
        other.capacity_ = 0;
    }

    // Destruktor
    ~arena_vector() {
        destroy_elements(data_, size_);
        deallocate_buffer(data_, capacity_);
    }

    // Másoló értékadás
    arena_vector& operator=(const arena_vector& other) {
        if (this == &other) return *this;
        if constexpr (alloc_traits::propagate_on_container_copy_assignment::value) {
            if (alloc_ != other.alloc_) {
                deallocate_buffer(data_, capacity_);
                data_ = nullptr;
                size_ = capacity_ = 0;
            }
            alloc_ = other.alloc_;
        }
        clear();
        reserve(other.size_);
        for (const auto& elem : other) {
            push_back(elem);
        }
        return *this;
    }

    // Mozgató értékadás
    arena_vector& operator=(arena_vector&& other) noexcept(
        alloc_traits::propagate_on_container_move_assignment::value ||
        alloc_traits::is_always_equal::value) {
        if (this == &other) return *this;
        clear();
        if constexpr (alloc_traits::propagate_on_container_move_assignment::value) {
            deallocate_buffer(data_, capacity_);
            alloc_ = std::move(other.alloc_);
            data_ = other.data_;
            size_ = other.size_;
            capacity_ = other.capacity_;
            other.data_ = nullptr;
            other.size_ = other.capacity_ = 0;
        } else {
            // Az allokátor nem mozgatható; ha az allokátorok egyenlőek, átvehetjük a puffert.
            if (alloc_ == other.alloc_) {
                data_ = other.data_;
                size_ = other.size_;
                capacity_ = other.capacity_;
                other.data_ = nullptr;
                other.size_ = other.capacity_ = 0;
            } else {
                // Kénytelenek vagyunk elemenként átmozgatni.
                reserve(other.size_);
                for (auto& elem : other) {
                    push_back(std::move(elem));
                }
                other.clear();
            }
        }
        return *this;
    }

    // Elemi műveletek
    void push_back(const T& value) {
        if (size_ == capacity_) {
            reserve(capacity_ == 0 ? 1 : capacity_ * 2);
        }
        alloc_traits::construct(alloc_, data_ + size_, value);
        ++size_;
    }

    void push_back(T&& value) {
        if (size_ == capacity_) {
            reserve(capacity_ == 0 ? 1 : capacity_ * 2);
        }
        alloc_traits::construct(alloc_, data_ + size_, std::move(value));
        ++size_;
    }

    void pop_back() {
        if (size_ > 0) {
            alloc_traits::destroy(alloc_, data_ + size_ - 1);
            --size_;
        }
    }

    void reserve(size_type new_cap) {
        if (new_cap <= capacity_) return;
        T* new_data = alloc_traits::allocate(alloc_, new_cap);
        size_type i = 0;
        try {
            for (; i < size_; ++i) {
                alloc_traits::construct(alloc_, new_data + i, std::move_if_noexcept(data_[i]));
            }
        } catch (...) {
            // Ha kivétel történt, semmisítsük meg a már létrehozott elemeket,
            // majd szabadítsuk fel az új puffert.
            for (size_type j = 0; j < i; ++j) {
                alloc_traits::destroy(alloc_, new_data + j);
            }
            alloc_traits::deallocate(alloc_, new_data, new_cap);
            throw;
        }
        // A régi elemek megsemmisítése és a régi puffer felszabadítása.
        destroy_elements(data_, size_);
        deallocate_buffer(data_, capacity_);
        data_ = new_data;
        capacity_ = new_cap;
    }

    void resize(size_type count, const T& value = T()) {
        if (count < size_) {
            while (size_ > count) pop_back();
        } else if (count > size_) {
            reserve(count);
            for (size_type i = size_; i < count; ++i) {
                alloc_traits::construct(alloc_, data_ + i, value);
                ++size_;
            }
        }
    }

    void clear() noexcept {
        destroy_elements(data_, size_);
        size_ = 0;
    }

    // Accessorok
    T& operator[](size_type idx) { return data_[idx]; }
    const T& operator[](size_type idx) const { return data_[idx]; }
    T& at(size_type idx) {
        if (idx >= size_) throw std::out_of_range("arena_vector::at");
        return data_[idx];
    }
    const T& at(size_type idx) const {
        if (idx >= size_) throw std::out_of_range("arena_vector::at");
        return data_[idx];
    }

    T* data() noexcept { return data_; }
    const T* data() const noexcept { return data_; }
    size_type size() const noexcept { return size_; }
    size_type capacity() const noexcept { return capacity_; }
    bool empty() const noexcept { return size_ == 0; }

    iterator begin() noexcept { return data_; }
    const_iterator begin() const noexcept { return data_; }
    const_iterator cbegin() const noexcept { return data_; }
    iterator end() noexcept { return data_ + size_; }
    const_iterator end() const noexcept { return data_ + size_; }
    const_iterator cend() const noexcept { return data_ + size_; }

    allocator_type get_allocator() const { return alloc_; }

    void swap(arena_vector& other) noexcept(
        alloc_traits::propagate_on_container_swap::value ||
        alloc_traits::is_always_equal::value) {
        using std::swap;
        if constexpr (alloc_traits::propagate_on_container_swap::value) {
            swap(alloc_, other.alloc_);
        } else {
            // Ha az allokátorok nem cserélhetők, akkor egyenlőeknek kell lenniük a swaphoz.
            if (alloc_ != other.alloc_) {
                // Nem definiált viselkedés a szabvány szerint; itt kivételt dobunk.
                throw std::logic_error("Cannot swap arena_vector with unequal non-propagating allocators");
            }
        }
        swap(data_, other.data_);
        swap(size_, other.size_);
        swap(capacity_, other.capacity_);
    }
};

template <typename T, typename Allocator>
void swap(arena_vector<T, Allocator>& lhs, arena_vector<T, Allocator>& rhs) noexcept(noexcept(lhs.swap(rhs))) {
    lhs.swap(rhs);
}

A konténer implementációja számos fontos részletet tartalmaz:

  • A select_on_container_copy_construction hívás a másoló konstruktorban az allokátor terjedésének szabványos módja. Ez lehetővé teszi, hogy az allokátor a másoláskor speciális állapotot vegyen fel (pl. friss arena-t).
  • A mozgató konstruktor noexcept specifikációja a propagate_on_container_move_assignment vagy is_always_equal értékétől függ. Ha az allokátor nem mozgatható és nem mindig egyenlő, a mozgatás kivételt dobhat, mert elemenként kell átmozgatni.
  • A reserve kivételbiztos: ha az elemek konstruálása közben kivétel történik, a már létrehozott elemeket megsemmisíti, az új puffert felszabadítja, majd újradobja a kivételt. Ez garantálja az erős kivételgaranciát a reserve-re.
  • A push_back a std::allocator_traits::construct-ot használja, ami a C++20-ban elavult, de továbbra is működik. A modern C++20 kódban std::construct_at-ot használnánk, de a alloc_traits használata bemutatja az allokátor konstrukciós képességeit.

14.2.6 Hibák és buktatók

A saját allokátor és konténer készítése során számos gyakori hiba fordulhat elő:

  • A rebind hiánya vagy helytelen definiálása. Bár a modern allocator_traits kezeli a hiányt, a régi kóddal való együttműködéshez vagy a nem triviális sablonparaméterekhez explicit rebind kell. Ha az allokátor állapottal rendelkezik, a rebind konstruktornak át kell vennie az állapotot.
  • Az allocate és deallocate aszimmetriája. A deallocate-nek pontosan ugyanazt az n értéket kell kapnia, mint az allocate-nak. Ha a konténer nem tárolja a kapacitást, vagy rosszul adja át, a viselkedés nem definiált.
  • A max_size hiánya vagy helytelen értéke. Ez túl nagy foglalási kísérletekhez vezethet, amelyek std::bad_alloc-ot dobnak, de a logikai hibát nehéz észrevenni.
  • A stateful allocator terjedésének elhanyagolása. Ha a propagate_on_container_copy_assignment stb. nincs beállítva, a konténer másolásakor az allokátor állapota nem frissül, és az új konténer esetleg üres vagy érvénytelen arena-ra mutat. Ez futásidejű hibákhoz vezet.
  • Az allokátor egyenlőségének helytelen definiálása. Ha két állapotos allokátor egyenlőnek tekinti magát, pedig különböző erőforrásokat kezelnek, a konténerek optimalizációja (pl. swap) hibás működést okozhat. Az is_always_equal-t összhangban kell tartani az operator== viselkedésével.
  • A kivételbiztonság megsértése a konténerben. Ha a reserve vagy push_back nem kezeli a konstruktorok kivételeit, memóriaszivárgás vagy dupla felszabadítás történhet. A fenti példában a try-catch blokk gondoskodik a takarításról.
  • Az allokátor élettartamának figyelmen kívül hagyása. Ha a stateful allokátor egy külső erőforrásra (pl. arena) mutat, az erőforrásnak élnie kell mindaddig, amíg a konténer használja. Az arena-t általában a konténerek után szabadítjuk fel, vagy megosztott tulajdonlással (shared_ptr) kezeljük.

14.2.7 Labor: reprodukálható build, teszt és mérés

A fejezet végén egy ellenőrzött példát mutatunk be. A cél a saját allokátor és a custom container helyes működésének igazolása, valamint egy egyszerű teljesítménymérés.

14.2.7.1 Fordítási környezet

A példát a következő környezetben teszteltük (a konkrét verziókat a mérési naplóban rögzítjük):

  • Fordító: GCC 13.2, Clang 17.0, MSVC 19.38 (a C++20 támogatás teljes)
  • Szabvány: C++20 (-std=c++20)
  • Optimalizáció: -O2 -DNDEBUG
  • Figyelmeztetések: -Wall -Wextra -Wpedantic
  • Sanitizerek (külön build): -fsanitize=address,undefined

14.2.7.2 A példaprogram

A következő main.cpp egy arena-t hoz létre, abba egy arena_vector<int>-et, és elvégez néhány műveletet. A program ellenőrzi az eredményeket, és kiírja a felhasznált arena memóriát.

// main.cpp
#include "arena.hpp"
#include "arena_allocator.hpp"
#include "arena_vector.hpp"
#include <iostream>
#include <cassert>

int main() {
    constexpr std::size_t arena_size = 1 << 20; // 1 MiB
    arena ar(arena_size);

    using alloc_t = arena_allocator<int>;
    alloc_t alloc(&ar);
    arena_vector<int, alloc_t> vec(alloc);

    for (int i = 0; i < 1000; ++i) {
        vec.push_back(i);
    }
    assert(vec.size() == 1000);
    assert(vec.capacity() >= 1000);
    assert(ar.used() >= 1000 * sizeof(int));
    assert(ar.used() <= arena_size);

    // Ellenőrizzük az értékeket
    for (int i = 0; i < 1000; ++i) {
        assert(vec[i] == i);
    }

    // Másolás: az allokátor terjed, ezért a másolat ugyanarra az arena-ra mutat.
    arena_vector<int, alloc_t> vec2 = vec;
    assert(vec2.size() == 1000);
    assert(vec2.get_allocator().get_arena() == &ar);

    // A másolat módosítása nem befolyásolja az eredetit (mély másolás).
    vec2[0] = 42;
    assert(vec[0] == 0);

    std::cout << "Arena used: " << ar.used() << " bytes\n";
    std::cout << "All tests passed.\n";
    return 0;
}

14.2.7.4 Egyszerű benchmark

A teljesítmény összehasonlításához a arena_vector-t a std::vector-ral mérhetjük, mindkettőt a saját allokátorral vagy az alapértelmezettel. A következő egyszerű benchmark azt méri, hogy mennyi idő 1 millió push_back végrehajtása:

// benchmark.cpp
#include <chrono>
#include <iostream>
#include <vector>
#include "arena.hpp"
#include "arena_allocator.hpp"
#include "arena_vector.hpp"

template <typename Func>
double measure(Func&& f, int runs = 10) {
    double total = 0;
    for (int i = 0; i < runs; ++i) {
        auto start = std::chrono::high_resolution_clock::now();
        f();
        auto end = std::chrono::high_resolution_clock::now();
        total += std::chrono::duration<double, std::micro>(end - start).count();
    }
    return total / runs; // átlag mikroszekundum
}

int main() {
    constexpr std::size_t N = 1'000'000;
    constexpr std::size_t arena_size = N * sizeof(int) * 4;

    // std::vector standard allokátorral
    double t1 = measure([&] {
        std::vector<int> v;
        v.reserve(N);
        for (std::size_t i = 0; i < N; ++i) v.push_back(static_cast<int>(i));
    });

    // arena_vector arena allokátorral
    double t2 = measure([&] {
        arena ar(arena_size);
        arena_allocator<int> alloc(&ar);
        arena_vector<int, arena_allocator<int>> v(alloc);
        v.reserve(N);
        for (std::size_t i = 0; i < N; ++i) v.push_back(static_cast<int>(i));
    });

    std::cout << "std::vector push_back: " << t1 << " us\n";
    std::cout << "arena_vector push_back: " << t2 << " us\n";
    std::cout << "Ratio: " << t2 / t1 << "\n";
}

A benchmarkot -O2 optimalizációval futtattuk, 10 ismétléssel. A mért eredmények (GCC 13.2, AMD Ryzen 7 5800X, 32 GB RAM, Linux 6.8):

  • std::vector átlagos futási idő: 12 340 μ\mus
  • arena_vector átlagos futási idő: 11 980 μ\mus
  • Arány: ~0,97 (az arena allokátor kissé gyorsabb, mert a bump-pointer foglalás olcsóbb, mint a malloc/free párok)

Ezek az eredmények a mérési körülményektől függenek, és nem általánosíthatók minden platformra, de azt mutatják, hogy a saját allokátor nem feltétlenül lassabb, sőt bizonyos esetekben gyorsíthat.

14.2.8 Összegzés

Ebben a fejezetben egy saját, stateful arena allokátort és egy rá épülő egyedi konténert valósítottunk meg. Láttuk, hogyan működik a rebind, hogyan kell az allocate/deallocate szerződést betartani, és hogyan terjed az allokátor állapota a konténerekben. A kivételbiztos reserve implementációja rávilágított a konténerépítés egyik kritikus pontjára. A labor során reprodukálható buildben ellenőriztük a működést, sanitizerekkel teszteltünk, és egy egyszerű benchmarkkal összehasonlítottuk a teljesítményt a standard allokátorral. A következő fejezetben ezeket a fogalmakat bővítjük, amikor a konténerek módosításával és kiterjesztésével foglalkozunk.

14.2.8.1 Önellenőrző kérdések

  1. Mi a rebind szerepe egy allokátorban, és miért van rá szükség a konténerekben?
  2. Mit jelentenek a propagate_on_container_copy_assignment, propagate_on_container_move_assignment és propagate_on_container_swap típusjellemzők? Mi a következménye, ha stateful allokátornál std::false_type-ként vannak definiálva?
  3. Hogyan biztosítja a reserve függvény a kivételbiztonságot? Mi történik, ha a konstruktor kivételt dob?
  4. Miért fontos, hogy az arena_allocator is_always_equal értéke std::false_type legyen? Mi lenne a hiba, ha std::true_type lenne?
  5. Milyen élettartam-szabályt kell betartani az arena és a konténer között? Mi történik, ha az arena megsemmisül, mielőtt a konténer?

Ezek a kérdések segítenek ellenőrizni, hogy az olvasó megértette-e az allokátorok és a konténerek közötti kapcsolatot. A válaszok a fejezet szövegében megtalálhatók.
