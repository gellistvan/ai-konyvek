6.1 Function és class templates

A sablonok a C++ nyelv egyik legalapvetőbb eszközei a típusfüggetlen, újrafelhasználható kód írására. Ez az alfejezet a függvény- és osztálysablonok alapjait tárgyalja: mi a template parameter és argument, hogyan történik az implicit és explicit instanciáció, és melyek a leggyakoribb hibák, amelyeket a fejlesztők elkövetnek. A cél, hogy az olvasó pontosan értse a sablonok fordítási modelljét, és képes legyen saját típusparaméteres absztrakciókat tervezni.

6.1.1 Sablonok mint típusparaméteres absztrakciók

A C++ egyik legerősebb eszköze a sablon (template). A sablonok lehetővé teszik, hogy olyan kódot írjunk, amely a használat során konkrét típusokkal paraméterezhető, anélkül hogy a kódot minden típusra külön megírnánk. Ezt a mechanizmust típusparaméteres absztrakciónak nevezzük: a függvény vagy osztály definíciójában egy vagy több helyőrző típusparamétert használunk, és a tényleges kódot a fordító a használat helyén, a konkrét típusargumentumokkal hozza létre. Ez nem makróhelyettesítés, hanem a nyelv típusrendszerébe ágyazott, típusellenőrzött kódgenerálás.

Például egy maximum függvényt nem szeretnénk külön megírni int, double, std::string és más típusokra. Ehelyett egy sablont írunk:

template <typename T>
T maximum(T a, T b) {
    return (a < b) ? b : a;
}

Ez a definíció önmagában nem hoz létre kódot. A T itt egy template paraméter, amely a fordítás során egy konkrét típussal helyettesítődik. Amikor a kódban meghívjuk a maximum függvényt, a fordító a hívás argumentumaiból dedukálja a T típust, és létrehozza a megfelelő függvénypéldányt. Ezt a folyamatot implicit instanciációnak nevezzük.

Ezzel szemben az osztálysablonok esetében a típusargumentumot általában explicit módon kell megadni, mert a fordító nem tudja azt a kontextusból kitalálni (bár C++17 óta a CTAD, azaz Class Template Argument Deduction bizonyos esetekben ezt is lehetővé teszi). Egy Box osztálysablon:

template <typename T>
class Box {
public:
    explicit Box(T value) : value_(std::move(value)) {}
    T get() const { return value_; }
private:
    T value_;
};

Használat: Box<int> intBox{42}; – itt a Box<int> explicit instanciációt jelent, ahol a T paramétert az int argumentummal helyettesítjük. Az osztálysablonból a fordító létrehozza a Box<int> konkrét osztályt, amelynek minden tagja már int típussal működik.

A sablonok tehát két szinten működnek: a definíció szintjén általánosak, a használat szintjén típusbiztosak. A típusbiztonságot a fordító garantálja, mert a konkrét típus helyettesítése után a kódot ugyanúgy ellenőrzi, mint bármely más C++ kódot.

6.1.2 Template parameter és argument

Fontos megkülönböztetni a template paramétert és a template argumentumot. A paraméter a sablon definíciójában szereplő név, például a T a template <typename T> deklarációban. Ez egy formális helyőrző, amely a sablon törzsében típusként használható. Az argumentum az a konkrét típus vagy érték, amelyet a sablon példányosításakor a paraméter helyére írunk. Például a Box<int> kifejezésben az int a template argumentum, amely a T paramétert helyettesíti.

A template paramétereknek több fajtája lehet. A leggyakoribb a típusparaméter, amelyet typename vagy class kulcsszóval jelölünk. A kettő ebben a kontextusban teljesen egyenértékű, bár a typename jobban kifejezi, hogy típusról van szó. Léteznek továbbá nem-típus paraméterek (például template <int N>), amelyek konstans értékeket fogadnak el, és template-template paraméterek, amelyek maguk is sablonokat várnak argumentumként. Ez az alfejezet elsősorban a típusparaméterekre összpontosít, mivel a legtöbb absztrakció ezzel épül fel; a nem-típus paramétereket és a template-template paramétereket a későbbi fejezetek tárgyalják.

A típusparaméter lehet typename vagy class, de van egy árnyalat: a typename használható dependent name esetén, amikor egy sablonparamétertől függő névről akarjuk jelezni, hogy típus. Például:

template <typename Container>
void print_first(const Container& c) {
    typename Container::value_type first = c.front(); // typename szükséges
    std::cout << first << '\n';
}

Itt a Container::value_type egy dependent type, mert a Container egy sablonparaméter. A fordító nem tudja, hogy ez típus-e vagy statikus tag, ezért kötelező a typename kulcsszó. Ez egy gyakori hibaforrás: hiánya fordítási hibát okoz.

6.1.3 Függvénysablonok és implicit instanciáció

A függvénysablonok esetében a használat során a fordító a hívás argumentumaiból következtet a template argumentumokra. Ez a template argument deduction. Például:

int a = 3, b = 5;
auto m = maximum(a, b);        // T dedukálódik: int
auto s = maximum(std::string("alma"), std::string("barack")); // T = std::string

Ha a dedukció nem egyértelmű, a fordító hibát jelez. Például maximum(1, 2.0) nem fordul, mert az első argumentum int, a második double, és a fordító nem tudja eldönteni, hogy a T int vagy double legyen. Ilyenkor explicit template argumentumot adhatunk:

auto m = maximum<double>(1, 2.0); // T explicit: double

Ekkor a T paraméter double, és az int argumentum double-lá konvertálódik. Ez a explicit template argument megadása: a függvény neve után szögletes zárójelben felsoroljuk a kívánt típusokat.

A függvénysablon implicit instanciációja a hívás helyén történik, ha a sablon definíciója látható. Ezért a függvénysablon definícióját általában fejlécfájlba kell tenni, nem pedig csak egy forrásfájlba, mert a fordító csak a definíció ismeretében tudja a kódot előállítani. Ha a definíció más fordítási egységben van, a linker “undefined reference” hibát ad.

6.1.4 Osztálysablonok és implicit instanciáció

Az osztálysablonoknál a típusargumentumot többnyire explicit módon kell megadni, például Box<int> vagy Stack<std::string>. Az osztálysablon implicit instanciációja akkor következik be, amikor a típust teljesen használjuk, például objektumot hozunk létre, vagy a típus nevére hivatkozunk olyan kontextusban, ahol a teljes definíció szükséges. A tagfüggvények azonban csak akkor instanciálódnak, ha ténylegesen hívjuk őket – ez a lazy instantiation. Például a Stack<T> osztálysablon push metódusa csak akkor jön létre, ha egy Stack<int> objektumon meghívjuk a push-t. Ez lehetővé teszi, hogy olyan tagfüggvényeket is definiáljunk egy osztálysablonban, amelyek bizonyos típusokra nem fordulnának le, de ha nem használjuk őket, nincs hiba.

Példa:

template <typename T>
class Stack {
public:
    void push(T value) { data_.push_back(std::move(value)); }
    bool empty() const { return data_.empty(); }
    T pop() {
        if (empty()) throw std::out_of_range("Stack empty");
        T top = std::move(data_.back());
        data_.pop_back();
        return top;
    }
private:
    std::vector<T> data_;
};

Ez az osztálysablon std::vector<T>-t használ, így a T típusnak másolhatónak vagy mozgathatónak kell lennie a std::vector működéséhez. Ha Stack<std::unique_ptr<int>>-et hoznánk létre, a push mozgatná az unique_ptr-t, ami működik, de a pop is mozgat, ami rendben van.

Az osztálysablon definícióját szintén fejlécfájlba kell tenni, mert a tagfüggvények implicit instanciációja a használat helyén történik. Ha a tagfüggvények definícióját külön .cpp fájlba tesszük, akkor a definíciót csak abban az egységben látja a fordító, és a hívás helyén nem tudja előállítani a kódot, így linker hiba lesz. Kivétel az explicit instanciáció, amit rövidesen tárgyalunk.

6.1.5 Explicit instanciáció

Az explicit instanciáció lehetővé teszi, hogy a fejlesztő utasítsa a fordítót egy adott template argumentumkombinációhoz tartozó kód létrehozására egy adott fordítási egységben. Két formája van:

  • Explicit instanciáció definíció: template class Stack<int>;
  • Explicit instanciáció deklaráció: extern template class Stack<int>;

Az első forma azt jelenti, hogy a fordító ebben a fordítási egységben hozza létre az összes tagfüggvényt és statikus adattagot a Stack<int> számára, függetlenül attól, hogy használják-e őket. A második forma azt jelenti, hogy a fordító ne hozza létre implicit módon az adott példányt, mert az definíciója megtalálható egy másik fordítási egységben, ahol explicit instanciáció definíció szerepel. Ez a technika csökkentheti a fordítási időt, ha ugyanazt a sablonpéldányt sok fordítási egység használja.

Példa a használatra:

// stack.hpp
template <typename T>
class Stack { ... }; // definíció headerben

// stack_impl.cpp
#include "stack.hpp"
template class Stack<int>;          // explicit definíció
template class Stack<std::string>;  // explicit definíció

// main.cpp
#include "stack.hpp"
extern template class Stack<int>;   // ne instanciáljon itt
extern template class Stack<std::string>;

int main() {
    Stack<int> s;
    s.push(10);
    std::cout << s.pop() << '\n';
}

Ebben az esetben a main.cpp nem hozza létre a Stack<int> kódját, mert az extern template deklaráció ezt letiltja. A definíció a stack_impl.cpp-ben van, így a linker megtalálja a szimbólumokat. Ez a módszer a sablonok “kódduplikációjának” csökkentésére szolgál, de ügyelni kell arra, hogy az explicit definíció minden használt típusra létezzen.

Az explicit instanciáció előnyei: - Csökkenti a fordítási időt, mert a sablon kódját nem minden fordítási egységben újrafordítja. - Lehetővé teszi a sablon definíciójának elrejtését egy forrásfájlban (bár a definíciónak láthatónak kell lennie az explicit instanciáció helyén, tehát a fejlécben általában a deklarációt tesszük ki, a definíciót pedig a forrásfájlba, de akkor a definíció nem látszik a felhasználónál). Ehhez a fejlécben a sablon deklarációját adjuk meg, a definíciót pedig a .cpp fájlban, és ott explicit instanciáljuk a kívánt típusokat. Ez azonban korlátozza a sablon használhatóságát, mert csak az előre meghatározott típusokra működik. - Javíthatja a bináris kompatibilitást, mert a szimbólumok egyetlen fordítási egységben jönnek létre.

6.1.6 Gyakori hibák és elkerülésük

  1. A sablon definíciója nincs látható a használat helyén. Ahogy említettük, a függvény- és osztálysablonok implicit instanciációja megköveteli a teljes definíció láthatóságát. Ha a definíciót egy .cpp fájlba tesszük, a hívás helyén a fordító nem tud kódot generálni, és linker hibát kapunk. Megoldás: a definíciót tegyük a headerbe, vagy használjunk explicit instanciációt.

  2. Nem egyértelmű dedukció. Példa: maximum(1, 2.0). A fordító nem tudja eldönteni a T típust. Megoldás: explicit template argumentum megadása, vagy a hívás argumentumainak egyértelművé tétele (pl. maximum<double>(1, 2.0)).

  3. A typename hiánya dependent type esetén. Amikor egy sablonparamétertől függő típust akarunk használni, a typename kulcsszó elhagyása hibát okoz. Például:

template <typename Container>
typename Container::value_type front(const Container& c) {
    return c.front();
}

Itt a visszatérési típus typename Container::value_type – a typename nélkül a fordító azt hiszi, hogy egy statikus tag, és hibát ad.

  1. A tagfüggvény definíciójának szintaxisa. Amikor egy osztálysablon tagfüggvényét az osztályon kívül definiáljuk, meg kell ismételni a template deklarációt és a minősített nevet. Például:
template <typename T>
void Stack<T>::push(T value) {
    data_.push_back(std::move(value));
}

Ha elfelejtjük a template <typename T> sort vagy a Stack<T>:: előtagot, fordítási hiba lesz.

  1. A template kulcsszó hiánya dependent névnél. Ha egy sablonon belül egy másik sablont hívunk meg, és a hívott név egy sablonparamétertől függ, a template kulcsszó szükséges lehet. Például:
template <typename T>
void call_foo(T& obj) {
    obj.template foo<int>(); // a template kulcsszó szükséges, mert obj függ T-től
}

Ez ritkább, de fontos haladó eset.

  1. A std:: elhagyása. A szabványos könyvtár elemeit mindig std:: előtaggal használjuk. A sablonokban is ez érvényes, különben névütközések léphetnek fel.

  2. Túlzott kódgenerálás (code bloat). Ha egy sablont nagyon sok különböző típusra példányosítunk, a bináris mérete jelentősen megnőhet, mert minden típusra külön kód generálódik. Ez nem mindig hiba, de teljesítmény- és méretproblémákat okozhat. Megoldás lehet a közös kód kiszervezése nem-sablonos alapfüggvényekbe, vagy az explicit instanciáció használata a gyakori típusokra.

6.1.7 Labor: függvény- és osztálysablon implementálása

A labor célja egy egyszerű, de teljes függvénysablon és osztálysablon megvalósítása, tesztelése és mérése. Az alábbi feladatot kell elvégezni.

6.1.8 Feladat

Implementáljon egy accumulate függvénysablont, amely egy tartomány elemeinek összegét számítja ki, és egy Stack<T> osztálysablont, amely verem adatszerkezetet valósít meg std::vector felhasználásával.

Követelmények: - A accumulate függvénysablon két paramétert fogad: egy kezdő iterátort, egy vég iterátort, és egy kezdőértéket. A visszatérési típus a kezdőérték típusa legyen. A függvény a tartomány elemeit a kezdőértékhez adja hozzá, és visszaadja az összeget. A függvény neve ütközhet a std::accumulate-tel, ezért ajánlott saját névtérbe tenni, vagy más nevet használni (pl. my_accumulate). - A Stack<T> osztálysablon a következő metódusokat biztosítsa: push, pop, empty, size. A pop dobjon std::out_of_range kivételt, ha a verem üres. A belső tároló std::vector<T> legyen. - A sablonok definícióit egy template_utils.hpp fejlécfájlba helyezze. - Készítsen egy test_template.cpp fájlt, amely az alábbi teszteseteket futtatja.

Tesztesetek: 1. my_accumulate üres std::vector<int>-re visszaadja a kezdőértéket (0). 2. my_accumulate std::vector<int>{1,2,3,4,5}-re 15-öt ad. 3. my_accumulate std::list<double>{1.5, 2.5, 3.0}-re 7.0-t ad, ha a kezdőérték 0.0. 4. Stack<int>: push 10-et, 20-at; pop 20-at ad vissza, majd pop 10-et; empty igaz lesz. 5. Stack<int>: üres veremből pop hívásakor std::out_of_range kivétel dobódik.

Buildparancs (GCC 13.2, C++20):

g++ -std=c++20 -O2 -Wall -Wextra -Werror -o test_template test_template.cpp

Futtatás: ./test_template

Várt eredmény: a program kimenete “All tests passed” és a kilépési kód 0.

Megoldás vázlat (a teljes kód a laboranyagban):

template_utils.hpp (a #pragma once széles körben támogatott, bár nem szabványos; hordozhatóbb az include guard):

#pragma once
#include <stdexcept>
#include <vector>

namespace my {

template <typename InputIt, typename T>
T accumulate(InputIt first, InputIt last, T init) {
    for (; first != last; ++first) {
        init = init + *first;
    }
    return init;
}

template <typename T>
class Stack {
public:
    void push(T value) {
        data_.push_back(std::move(value));
    }
    bool empty() const { return data_.empty(); }
    std::size_t size() const { return data_.size(); }
    T pop() {
        if (empty()) throw std::out_of_range("Stack empty");
        T top = std::move(data_.back());
        data_.pop_back();
        return top;
    }
private:
    std::vector<T> data_;
};

} // namespace my

test_template.cpp:

#include "template_utils.hpp"
#include <cassert>
#include <iostream>
#include <list>
#include <vector>

int main() {
    // Test 1
    {
        std::vector<int> empty;
        int result = my::accumulate(empty.begin(), empty.end(), 0);
        assert(result == 0);
    }
    // Test 2
    {
        std::vector<int> v{1,2,3,4,5};
        int result = my::accumulate(v.begin(), v.end(), 0);
        assert(result == 15);
    }
    // Test 3
    {
        std::list<double> l{1.5, 2.5, 3.0};
        double result = my::accumulate(l.begin(), l.end(), 0.0);
        assert(result == 7.0);
    }
    // Test 4
    {
        my::Stack<int> s;
        s.push(10);
        s.push(20);
        assert(s.pop() == 20);
        assert(s.pop() == 10);
        assert(s.empty());
    }
    // Test 5
    {
        my::Stack<int> s;
        bool caught = false;
        try {
            s.pop();
        } catch (const std::out_of_range&) {
            caught = true;
        }
        assert(caught);
    }
    std::cout << "All tests passed\n";
    return 0;
}

Ez a kód szemlélteti a sablonok használatát. A tesztesetek assert-et használnak, amelyek NDEBUG mellett kiiktathatók, de itt nem definiáljuk az NDEBUG-t.
