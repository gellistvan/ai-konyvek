11.1 Type erasure alapelvei

A type erasure (típuskitörlés) az egyik leghatékonyabb C++-technika, amely lehetővé teszi, hogy különböző, egymással semmilyen kapcsolatban nem álló típusokat egységes, értékalapú interfészen keresztül kezeljünk. Ahelyett, hogy minden konkrét típusnak egy közös ősosztályból kellene származnia, a type erasure egy sablonos adapterréteggel rejti el a konkrét típust, miközben a használó számára egyetlen, jól definiált interfészt kínál. Ebben az alfejezetben az alapelveket, a value semantics szerepét és a hagyományos örökléssel való összehasonlítást járjuk körül, majd egy ellenőrzött labor keretében egyszerű type erasure-t implementálunk.

11.1.1 A típusinformáció elrejtése és a közös interfész

A hagyományos dinamikus polimorfizmus C++-ban az öröklésen és virtuális függvényeken alapul. Egy Shape ősosztályból származtatjuk a Circle, Rectangle stb. osztályokat, és mindegyik felüldefiniálja a virtuális draw() és area() tagfüggvényeket. A használó Shape* vagy Shape& típuson keresztül hívja ezeket, a dinamikus objektum pedig a vtable segítségével a megfelelő implementációt futtatja.

Ez a modell azonban több korláttal jár:

  • Közös ősosztály kényszer: minden típusnak öröklődnie kell a közös interfészből. Külső, harmadik féltől származó típusok vagy primitívek (pl. int, double) nem illeszthetők ilyen hierarchiába anélkül, hogy wrapper osztályt írnánk.
  • Referencia-szemantika: a virtuális polimorfizmus pointerrel vagy referenciával működik, ami manuális élettartam-kezelést, new/delete párokat és gyakran std::unique_ptr-eket igényel. A value semantics (értékalapúság) elveszik – a másolásnál nem tudjuk egyszerűen lemásolni a dinamikus objektumot, mert a statikus típus csak az ősosztály.
  • Intruzivitás: a típust módosítani kell, hogy illeszkedjen a rendszerbe, ami nem mindig lehetséges.

A type erasure ezzel szemben nem követeli meg a közös ősosztályt. Helyette egy absztrakt, belső interfészt definiál, amelyet egy sablonos tároló osztály valósít meg a konkrét típushoz. A külső wrapper osztály ezt az interfészt birtokolja, gyakran std::unique_ptr formájában, és a hívásokat delegálja. A konkrét típus csak a sablonos konstruktorban jelenik meg, utána a statikus típusból “kitörlődik”. A viselkedés azonban megmarad, mert a belső modell objektum virtuális függvényei továbbítják a hívást a tárolt objektumhoz.

A type erasure tehát végrehajtódás idejű polimorfizmust ad anélkül, hogy a résztvevő típusoknak bármilyen rokonságban kellene állniuk. A közös interfészt a wrapper osztály definiálja, és bármely típus, amely megfelel a szükséges műveleteknek (azaz concept-szerű követelményeknek), beilleszthető.

11.1.2 Value semantics és concept-based interfész

A modern C++-ban a value semantics (értékalapú szemantika) kiemelt fontosságú: az objektumok úgy viselkednek, mint a beépített típusok – másolhatók, mozgathatók, értékadhatók, és élettartamukat a scope határozza meg. A type erasure gyakori célja, hogy ezt a value semantics-t biztosítsa heterogén típusok számára anélkül, hogy a használó pointerekkel bajlódna.

A concept-based interfész alatt azt értjük, hogy a wrapper osztály nem egy konkrét típust, hanem egy műveleti követelményhalmazt (concept) ír elő. A C++20 bevezette a concept nyelvi elemet, de a type erasure esetén a “concept” nem feltétlenül nyelvi concept, hanem egy implicit szerződés: a típusnak rendelkeznie kell bizonyos tagfüggvényekkel vagy szabad függvényekkel, amelyeket a sablonos modell meg tud hívni.

A tipikus megvalósítás három rétegű:

  1. Absztrakt interfész (ShapeConcept): tisztán virtuális függvényekkel definiálja a nyilvános műveleteket, valamint a value semantics-hoz szükséges klónozó műveletet.

    class ShapeConcept {
public:
    virtual ~ShapeConcept() = default;
    virtual void draw() const = 0;
    virtual double area() const = 0;
    virtual std::unique_ptr<ShapeConcept> clone() const = 0;
};

  2. Sablonos modell (ShapeModel<T>): tárolja a konkrét T objektumot, és implementálja az absztrakt interfészt a T műveleteire delegálva.

    template<typename T>
class ShapeModel final : public ShapeConcept {
public:
    explicit ShapeModel(T value) : value_(std::move(value)) {}

    void draw() const override { value_.draw(); }
    double area() const override { return value_.area(); }

    std::unique_ptr<ShapeConcept> clone() const override {
        return std::make_unique<ShapeModel<T>>(value_);
    }

private:
    T value_;
};

  3. Wrapper (Shape): értékalapú interfész, amely std::unique_ptr<ShapeConcept>-et tart, és a speciális tagfüggvényeket a klónozás segítségével valósítja meg.

    class Shape {
public:
    template<typename T>
    Shape(T value)
        : pimpl_(std::make_unique<ShapeModel<T>>(std::move(value))) {}

    Shape(const Shape& other)
        : pimpl_(other.pimpl_ ? other.pimpl_->clone() : nullptr) {}

    Shape& operator=(const Shape& other) {
        if (this != &other) {
            pimpl_ = other.pimpl_ ? other.pimpl_->clone() : nullptr;
        }
        return *this;
    }

    Shape(Shape&&) noexcept = default;
    Shape& operator=(Shape&&) noexcept = default;
    ~Shape() = default;

    void draw() const { pimpl_->draw(); }
    double area() const { return pimpl_->area(); }

private:
    std::unique_ptr<ShapeConcept> pimpl_;
};

Ennek a szerkezetnek köszönhetően a Shape objektum értékként másolható, mozgatható, és a használó számára egyetlen típusnak látszik. A konkrét típus (pl. Circle) csak a konstruktorban jelenik meg explicit módon; a Shape belsejében a ShapeModel<Circle> példány végzi a tényleges munkát.

A value semantics megvalósításának kulcsa a clone() metódus. Ez egy virtuális “copy constructor”, amely a dinamikus objektum pontos típusának ismeretében lemásolja a tárolt értéket, és visszaad egy új std::unique_ptr-t az absztrakt interfészre. Ha ezt kihagynánk, a Shape másoló konstruktora csak a pointert másolná, ami sekély másoláshoz és kettős felszabadításhoz vezetne. A clone() megléte teszi lehetővé, hogy a Shape értékalapú maradjon, miközben a háttérben dinamikus allokációt használ.

A sablonos konstruktor miatt a Shape implicit konverziót biztosít bármely olyan típusból, amely rendelkezik a szükséges draw() és area() tagfüggvényekkel. Ez a “concept-based interfész” gyakorlati megvalósítása: nincs explicit interfész deklaráció a konkrét típusban, csak a wrapper által támasztott követelmények. Ha egy típus nem felel meg, a fordítási hiba a sablonos konstruktor példányosításakor jelentkezik, ami néha nehezen olvasható lehet. C++20 conceptekkel ezt a hibát korlátozhatjuk, de az alap type erasure minta C++11 óta elérhető.

11.1.3 Type erasure vs. inheritance

A type erasure nem helyettesíti teljesen az öröklést, hanem egy alternatív eszköz a dinamikus polimorfizmus megvalósítására, amikor a hagyományos hierarchia nem megfelelő. A két megközelítés összehasonlítása:

Szempont Öröklés (virtuális polimorfizmus) Type erasure
Közös ősosztály Szükséges Nem szükséges
Value semantics Nem természetes (pointer/referencia) Igen, értékalapú
Külső típusok adaptálása Nehézkes (wrapper osztály kell) Természetes (sablonos konstruktor)
Dinamikus allokáció Jellemzően igen (new) Igen, általában (de optimalizálható)
Virtuális hívás költsége Van Van (két indirekció: wrapper -> modell -> konkrét)
Kódgenerálás Kevésbé (egy vtable) Több (sablonos modell minden típushoz)
Típusbiztonság Fordítási időben ellenőrzött a közös interfész Fordítási időben ellenőrzött a konstruktorban, utána típusbiztos a wrapper
Kiterjeszthetőség Új típus hozzáadása = új osztály, az ősosztály ismerete nélkül Új típus hozzáadása = nincs változás a wrapperben
Bináris interfész Stabil (ha az ősosztály ABI-ja stabil) Kevésbé stabil (sablon miatt a wrapper ABI-ja függ a modelltől)

Az öröklés előnye, hogy a közös ősosztály explicitté teszi a szerződést, és a virtuális függvények vtable-je egyetlen, jól meghatározott helyen van. A típusok közötti kapcsolat dokumentált, és a fordító segít a helyes használatban. Emellett az öröklési hierarchia lehetővé teszi a dinamikus típus vizsgálatát (dynamic_cast), ami type erasure esetén nem elérhető (legalábbis nem triviálisan).

A type erasure előnye, hogy nem invazív: bármely meglévő típust be lehet illeszteni anélkül, hogy módosítanánk. A használó egyetlen értékalapú típust lát, amelyet könnyű tárolni, átadni, visszaadni. A különböző konkrét típusok keverhetők egyetlen konténerben (std::vector<Shape>), ami heterogén gyűjteményeket tesz lehetővé értékalapú módon.

A type erasure hátránya a nagyobb futási költség: minden hívás két indirekción megy keresztül (a Shape pointere a ShapeConcept-re, majd a virtuális függvény hívása, amely a ShapeModel<T>-re delegál). A hagyományos öröklésnél csak egy virtuális hívás van. Emellett a sablonos modell minden konkrét típushoz külön kódot generál, ami növelheti a bináris méretet. A dinamikus allokáció is gyakori, bár kis objektum optimalizációval (small buffer optimization) csökkenthető.

Mikor válasszuk a type erasure-t? - Amikor a típusok nem hozhatók közös ősosztály alá (pl. primitívek, külső típusok). - Amikor value semantics-t szeretnénk (pl. std::function, std::any). - Amikor a használó felé egyetlen, egyszerű interfészt akarunk adni, és a konkrét típusokat nem akarjuk kiszivárogtatni. - Amikor a típusok gyakran változnak, és a hierarchia karbantartása nehézkes.

Mikor maradjunk az öröklésnél? - Amikor a típusok természetesen hierarchiába szervezhetők, és a közös ősosztály valódi “is-a” kapcsolatot fejez ki. - Amikor szükség van a dinamikus típus vizsgálatára (dynamic_cast, RTTI). - Amikor a teljesítmény kritikus, és a plusz indirekció nem engedhető meg. - Amikor bináris kompatibilitást kell fenntartani (az absztrakt interfész ABI-ja stabil, a sablonos type erasure ABI-ja kevésbé).

Fontos megjegyezni, hogy a type erasure nem zárja ki az öröklést a belső megvalósításban: a ShapeConcept és ShapeModel<T> közötti kapcsolat éppen öröklés. A type erasure lényege, hogy ezt a hierarchiát a wrapper mögé rejti, és a használó számára értékalapú interfészt ad.

11.1.6 Forráskód

A teljes kód egyetlen fájlban van (shape_erasure.cpp), de a fejezet laborjában külön header és forrásfájl is lehet. A következő kódot használjuk:

#include <iostream>
#include <memory>
#include <vector>
#include <string>

// Belső absztrakt interfész
class ShapeConcept {
public:
    virtual ~ShapeConcept() = default;
    virtual void draw() const = 0;
    virtual double area() const = 0;
    virtual std::unique_ptr<ShapeConcept> clone() const = 0;
};

// Sablonos modell a konkrét típushoz
template<typename T>
class ShapeModel final : public ShapeConcept {
public:
    explicit ShapeModel(T value) : value_(std::move(value)) {}

    void draw() const override { value_.draw(); }
    double area() const override { return value_.area(); }

    std::unique_ptr<ShapeConcept> clone() const override {
        return std::make_unique<ShapeModel<T>>(value_);
    }

private:
    T value_;
};

// Nyilvános, értékalapú wrapper
class Shape {
public:
    template<typename T>
    Shape(T value)
        : pimpl_(std::make_unique<ShapeModel<T>>(std::move(value))) {}

    Shape(const Shape& other)
        : pimpl_(other.pimpl_ ? other.pimpl_->clone() : nullptr) {}

    Shape& operator=(const Shape& other) {
        if (this != &other) {
            pimpl_ = other.pimpl_ ? other.pimpl_->clone() : nullptr;
        }
        return *this;
    }

    Shape(Shape&&) noexcept = default;
    Shape& operator=(Shape&&) noexcept = default;
    ~Shape() = default;

    void draw() const { pimpl_->draw(); }
    double area() const { return pimpl_->area(); }

private:
    std::unique_ptr<ShapeConcept> pimpl_;
};

// Konkrét típusok – semmilyen közös ősosztályt nem igényelnek
class Circle {
public:
    explicit Circle(double radius) : radius_(radius) {}
    void draw() const { std::cout << "Drawing circle with radius " << radius_ << '\n'; }
    double area() const { return 3.14159 * radius_ * radius_; }
private:
    double radius_;
};

class Rectangle {
public:
    Rectangle(double width, double height) : width_(width), height_(height) {}
    void draw() const { std::cout << "Drawing rectangle " << width_ << "x" << height_ << '\n'; }
    double area() const { return width_ * height_; }
private:
    double width_, height_;
};

int main() {
    std::vector<Shape> shapes;
    shapes.emplace_back(Circle{2.0});
    shapes.emplace_back(Rectangle{3.0, 4.0});

    for (const auto& shape : shapes) {
        shape.draw();
        std::cout << "Area: " << shape.area() << '\n';
    }

    // Másolás tesztelése
    Shape copied = shapes[0];
    copied.draw(); // ugyanazt rajzolja, mint az eredeti
    std::cout << "Copied area: " << copied.area() << '\n';

    return 0;
}

11.1.9 Ellenőrző kérdés

Miért van szükség a clone() metódusra a ShapeConcept interfészben? Mi történne, ha a Shape másoló konstruktora egyszerűen lemásolná a pimpl_ pointert?

Válasz: A clone() metódus az úgynevezett “virtuális másoló konstruktor”, amely a dinamikus típus ismeretében új, azonos típusú dinamikus objektumot hoz létre. Ha a Shape másoló konstruktora csak a pimpl_ pointert másolná (pimpl_ = other.pimpl_), akkor a másolat ugyanarra a dinamikus objektumra mutatna, mint az eredeti. Ez sekély másolást eredményezne: ha az egyik objektum megsemmisül, a másik érvénytelen pointert kapna, és kettős felszabadítás (double free) lépne fel. A clone() nélkül a value semantics nem valósítható meg biztonságosan; ezért minden type erasure wrappernek, amely értékalapú másolást ígér, rendelkeznie kell valamilyen klónozó mechanizmussal.

11.1.10 Összegzés

A type erasure alapelve a típusinformáció elrejtése egy belső absztrakt interfész mögött, és a konkrét típusok sablonos modellen keresztüli adaptálása. Ezáltal heterogén típusokat értékalapú, egységes interfészen keresztül kezelhetünk anélkül, hogy közös ősosztályra lenne szükség. A value semantics fenntartásához klónozó műveletre van szükség, amely a dinamikus objektum pontos típusát ismerve készít másolatot. A type erasure és az öröklés egymást kiegészítő eszközök: az öröklés explicit hierarchiát és alacsonyabb futási költséget ad, míg a type erasure rugalmasságot és értékalapúságot biztosít. A következő alfejezetben a standard könyvtár type erasure eszközeit (std::any, std::variant, std::function) vizsgáljuk meg, amelyek ezt a mintát készen kínálják.
