15.1 Iterátorkategóriák és hierarchia

Az STL egyik legnagyobb absztrakciós ereje abban rejlik, hogy az algoritmusokat elválasztja az adatszerkezetektől. Ezt az elválasztást az iterátorok teszik lehetővé: egy jól megírt algoritmus nem tudja, hogy az elemek egy std::vector-ban, egy láncolt listában vagy éppen egy bemeneti adatfolyamban vannak-e, csak annyit tud, hogy a kapott iterátor milyen műveleteket támogat. Az iterátorok képességeit a szabvány iterátorkategóriákba sorolja, ezek a kategóriák pedig egy – hagyományosan és a C++20-as conceptekben is – jól definiált hierarchiát alkotnak az input iterátortól a random access (és C++20-tól a contiguous) iterátorig. Ebben az alfejezetben ezt a hierarchiát vizsgáljuk meg, megértjük az iterator_traits szerepét, és egy saját iterátoron keresztül bemutatjuk a helyes kategóriaválasztást és a tipikus hibákat.

15.1.1 Az iterátorkategóriák áttekintése

A C++ szabvány már a kezdetektől öt alapvető iterátorkategóriát különböztet meg, amelyeket a std::iterator_traits<It>::iterator_category típusa jelöl. Ezek a következők:

Kategória Leírás Tipikus példa
std::input_iterator_tag Csak olvasás, egymenetes bejárás, a bejárás során az elemeket legfeljebb egyszer lehet meglátogatni. std::istream_iterator<T>
std::forward_iterator_tag Olvasás, többmenetes bejárás: ugyanaz a sorozat többször is bejárható, az iterátor másolatai egymástól függetlenek. std::forward_list<T>::iterator
std::bidirectional_iterator_tag A forward iterátor összes képessége, valamint a visszafelé lépés (operator--). std::list<T>::iterator
std::random_access_iterator_tag A bidirectional iterátor összes képessége, valamint konstans idejű tetszőleges elérés (operator[], operator+, operator-, rendezési relációk). std::vector<T>::iterator, beépített pointer
std::contiguous_iterator_tag C++20-tól: a random access iterátor képességei, és garantáltan folytonos memóriában lévő elemekre mutat, így a pointer-aritmetika érvényes. std::vector<T>::iterator, std::array<T,N>::iterator, std::span<T>::iterator

Fontos megjegyezni, hogy az output_iterator_tag nem illeszkedik ebbe a hierarchiába: az output iterátor írásra szolgál, és képességei nem tartalmazzák a fenti „bejáró” iterátorok tulajdonságait. Egy output iterátor lehet akár csak írási, egymenetes, és nem feltétlenül összehasonlítható. A std::ostream_iterator<T> és a std::back_insert_iterator<Container> tipikus példák. A hierarchia tehát a bejárási irány és az elérési mód szerinti, és az output iterátor külön ágként kezelendő.

A C++20 bevezette a concept-eket, amelyek az iterátorkategóriákat sokkal pontosabban definiálják. A std::input_iterator, std::forward_iterator, std::bidirectional_iterator, std::random_access_iterator és std::contiguous_iterator conceptek hierarchiája megegyezik a fenti tag-osztályok által képviselt sorrenddel, de a conceptek a tényleges műveleteket és a szemantikát is ellenőrzik, nem csupán egy típusdefiníciót. Ezenkívül a std::input_or_output_iterator concept az alap, amely minden iterátorra igaz, beleértve az output iterátorokat is. A gyakorlatban a modern kódban ezeket a concepteket használjuk, de a régebbi kódokkal való kompatibilitás miatt az iterator_category tag továbbra is fontos.

15.1.2 Az iterator_traits szerepe

Az algoritmusok számára az iterátor tulajdonságait (mint például az elem típusa, a különbség típusa, a referencia típusa és a kategória) egységes módon kell elérni. Erre szolgál a std::iterator_traits<It> sablon. Az iterator_traits elsődleges sablonja a megadott iterátor típus belső típusdefinícióit használja:

template<class It>
struct iterator_traits {
    using value_type        = typename It::value_type;
    using difference_type   = typename It::difference_type;
    using pointer           = typename It::pointer;
    using reference         = typename It::reference;
    using iterator_category = typename It::iterator_category;
};

Az STL kompatibilitás érdekében a beépített pointerekre is van specializáció:

template<class T>
struct iterator_traits<T*> {
    using value_type        = std::remove_cv_t<T>;
    using difference_type   = std::ptrdiff_t;
    using pointer           = T*;
    using reference         = T&;
    using iterator_category = std::random_access_iterator_tag; // C++20-ban: std::contiguous_iterator_tag is elérhető
};

A C++20 szabvány bevezetett további segédtípusokat is, amelyek az iterator_traits-ra épülnek, de a conceptekkel jobban integrálhatók:

  • std::iter_value_t<It> – az iterátor value_type-ja.
  • std::iter_reference_t<It> – az iterátor reference típusa.
  • std::iter_difference_t<It> – az iterátor difference_type-ja.
  • std::iter_rvalue_reference_t<It> – az iterátor rvalue referencia típusa.
  • std::iter_common_reference_t<It> – az iterátor value_type és reference közös referencia típusa.

Ezek a típusok a conceptekben és a generikus kódban teszik lehetővé, hogy az iterátor tulajdonságait anélkül kérdezzük le, hogy közvetlenül az iterator_traits-ot bántanánk.

15.1.3 Az egyes kategóriák műveleti követelményei

A kategóriák közötti különbségek a támogatott műveletekben és azok szemantikájában rejlenek. Az alábbiakban röviden összefoglaljuk a legfontosabb elvárásokat. (A pontos formális követelményeket a szabvány és a cppreference definiálja; itt a gyakorlati megértésre helyezzük a hangsúlyt.)

15.1.3.1 Input iterátor

Egy input iterátor (std::input_iterator concept) a következő műveleteket támogatja:

  • *it – az aktuális elem olvasása (általában reference típus, ami lehet érték vagy referencia).
  • ++it és it++ – előre lépés.
  • it1 == it2 és it1 != it2 – összehasonlítás (általában csak a sorozat végének érzékelésére).
  • A másolás és a destruálás.
  • A std::default_initializable követelmény (C++20-tól) – az iterátor alapértelmezésben létrehozható.

Az input iterátor egymenetes: ha egyszer már továbbléptünk, nem feltétlenül tudunk visszamenni, és a korábbi másolatok esetleg érvénytelenek lesznek. Az operator* eredménye lehet prvalue (pl. egy stream-iterátor esetén), így nem garantált, hogy az eredmény címe stabil. Az std::istream_iterator<int> tipikus példa: a bemeneti folyamot olvassa, és minden ++ művelet új elemet olvas be.

15.1.3.2 Forward iterátor

A forward iterátor (std::forward_iterator) mindent tud, amit az input iterátor, de többmenetes: a sorozat többször is bejárható, és az iterátor másolatai függetlenek. Az operator* eredményének reference típusa lvalue referencia kell legyen (általában T&), így az elem címe stabil, és a másolatok ugyanarra az elemre mutatnak. A forward iterátor lehetővé teszi a std::forward_list vagy egy saját láncolt lista bejárását. A std::forward_iterator concept megköveteli az std::input_iterator-t és a std::semiregular tulajdonságot (ami a másolhatóságot és az alapértelmezett konstruálhatóságot foglalja magában).

15.1.3.3 Bidirectional iterátor

A bidirectional iterátor (std::bidirectional_iterator) a forward iterátor összes képességét bővíti a hátrafelé lépéssel: --it és it-- műveletek. Ezáltal olyan adatszerkezetek bejárhatók, amelyekben a visszafelé mutató link is rendelkezésre áll, mint például a std::list vagy a std::set. A bidirectional iterátor a fordított bejárást is támogatja, ami lehetővé teszi a std::reverse_iterator használatát.

15.1.3.4 Random access iterátor

A random access iterátor (std::random_access_iterator) a bidirectional iterátor képességeit egészíti ki konstans idejű tetszőleges eléréssel:

  • it + n, it - n, it += n, it -= n, n + it – az iterátor léptetése egész számmal.
  • it[n] – az n-edik elem elérése (ekvivalens *(it + n)-nel).
  • it1 - it2 – két iterátor különbsége (visszatérési típus difference_type).
  • Rendezési relációk: it1 < it2, it1 > it2, it1 <= it2, it1 >= it2 – ezek a műveletek a mutatott elemek sorrendjét tükrözik.

A beépített pointer természetesen teljesíti ezeket a követelményeket, és a std::vector<T>::iterator is (általában pointer, de az implementáció definiálhatja osztályként is). A random access iterátorok lehetővé teszik a std::sort, a std::binary_search és más, indexelést igénylő algoritmusok hatékony használatát.

15.1.3.5 Contiguous iterátor (C++20)

A C++20 bevezette a std::contiguous_iterator conceptet, amely a random access iterátor képességeit tovább szigorítja: az iterátor által mutatott elemek folytonos memóriaterületen helyezkednek el, és a pointer-aritmetika érvényes. Ez azt jelenti, hogy ha it egy ilyen iterátor, akkor a *(it + n) ekvivalens a *(std::to_address(it) + n) kifejezéssel. A std::vector, std::array, std::basic_string és a std::span iterátorai contiguous iterátorok. Ez a tulajdonság kritikus például a std::memcpy-vel való optimalizálásokhoz vagy a C API-kkal való átjárhatósághoz.

A hagyományos iterator_category tag-osztály a C++17 előtt nem tartalmazta a contiguous_iterator_tag típust, ezért a C++20-as kódban egy iterátor iterator_concept tagje lehet std::contiguous_iterator_tag, míg az iterator_category tagje továbbra is std::random_access_iterator_tag marad a kompatibilitás érdekében. Ezt a különbséget a std::iterator_traits<It>::iterator_concept (C++20) típusdefiníció kezeli.

15.1.3.6 Output iterátor

Az output iterátor (std::output_iterator<It, T> concept) az írásra szolgál. A *it = value művelet kiírja az értéket, a ++it pedig továbblép a következő írási pozícióra. Az output iterátor általában egymenetes, és nem feltétlenül támogatja az olvasást vagy az összehasonlítást. Példák: std::ostream_iterator<int>, std::back_insert_iterator<std::vector<int>>, std::insert_iterator<std::set<int>>. A C++20 std::output_iterator concept két paramétert vár: az iterátor típusát és az írandó érték típusát, így ellenőrzi, hogy a *it = value kifejezés érvényes-e.

15.1.4 Az iterátorkategóriák és a C++20 conceptek kapcsolata

A C++20 szabvány az iterátorokat a <iterator> fejlécben definiált conceptekkel írja le. A hierarchia a következő:

  • std::input_or_output_iterator – az alap, minden iterátorra igaz.
  • std::input_iterator – az input_or_output_iterator-t bővíti olvasási képességekkel.
  • std::forward_iterator – az input_iterator-t bővíti többmenetes bejárással.
  • std::bidirectional_iterator – a forward_iterator-t bővíti a -- támogatásával.
  • std::random_access_iterator – a bidirectional_iterator-t bővíti a véletlen eléréssel.
  • std::contiguous_iterator – a random_access_iterator-t bővíti a folytonos memória garanciával.

Ezen kívül külön concept az std::output_iterator<It, T>, amely az írási képességet ellenőrzi.

Fontos, hogy a conceptek nem csupán a iterator_category típusdefiníciót nézik, hanem a tényleges műveletek meglétét és a visszatérési típusokat is. Ez lehetővé teszi, hogy egy iterátor akkor is teljesítse a conceptet, ha az iterator_category tag hiányzik, feltéve, hogy a szükséges műveletek rendelkezésre állnak – bár a std::iterator_traits specializáció nélkül az iterator_traits nem tudja levezetni a típusokat, ezért a gyakorlatban érdemes a tag-eket megadni.

15.1.5 Gyakorlati példa: egyszerű forward iterátor láncolt listához

A kategóriák megértéséhez hozzunk létre egy minimális, saját láncolt listát, amelynek iterátora forward iterátor. A példa szemlélteti a szükséges típusdefiníciókat, a műveleteket, és azt, hogyan ellenőrizhetjük a conceptekkel a kategóriát. A kód C++20-as, de a hagyományos iterator_category tag-et is tartalmazza.

#include <iterator>
#include <cstddef>
#include <concepts>
#include <type_traits>
#include <iostream>
#include <algorithm>
#include <vector>

// Minimális csomópont
template <typename T>
struct Node {
    T data;
    Node* next = nullptr;
};

// Forward iterátor a láncolt listához
template <typename T>
class ForwardListIterator {
public:
    // ----- Iterator traits -----
    using value_type        = T;
    using difference_type   = std::ptrdiff_t;
    using pointer           = T*;
    using reference         = T&;
    using iterator_category = std::forward_iterator_tag; // Hagyományos jelölés
    // C++20: az iterator_concept is megadható, de ha elhagyjuk,
    // az iterator_traits az iterator_category-ból következtet.
    using iterator_concept  = std::forward_iterator_tag; // Opcionális, de ajánlott

    // Konstruktorok
    ForwardListIterator() = default;
    explicit ForwardListIterator(Node<T>* node) : current_(node) {}

    // Hozzáférés
    reference operator*() const { return current_->data; }
    pointer operator->() const { return &current_->data; }

    // Léptetés
    ForwardListIterator& operator++() {
        current_ = current_->next;
        return *this;
    }
    ForwardListIterator operator++(int) {
        ForwardListIterator tmp = *this;
        ++(*this);
        return tmp;
    }

    // Összehasonlítás
    bool operator==(const ForwardListIterator& other) const {
        return current_ == other.current_;
    }
    // C++20: az operator!= automatikusan generálódik az operator== -ből,
    // de explicit is megadható a régebbi szabványokhoz.

private:
    Node<T>* current_ = nullptr;
};

// Egyszerű láncolt lista konténer
template <typename T>
class SimpleForwardList {
public:
    using iterator = ForwardListIterator<T>;

    SimpleForwardList() = default;
    ~SimpleForwardList() {
        while (head_) {
            Node<T>* next = head_->next;
            delete head_;
            head_ = next;
        }
    }

    void push_front(const T& value) {
        Node<T>* newNode = new Node<T>{value, head_};
        head_ = newNode;
    }

    iterator begin() { return iterator(head_); }
    iterator end()   { return iterator(nullptr); }

private:
    Node<T>* head_ = nullptr;
};

int main() {
    // Statikus ellenőrzés: az iterátor teljesíti a forward_iterator conceptet
    static_assert(std::forward_iterator<ForwardListIterator<int>>);
    static_assert(std::input_iterator<ForwardListIterator<int>>);
    // Nem teljesíti a bidirectional_iterator-t, mert nincs operator--
    static_assert(!std::bidirectional_iterator<ForwardListIterator<int>>);

    // Az iterator_traits ellenőrzése
    static_assert(std::same_as<std::iterator_traits<ForwardListIterator<int>>::iterator_category,
                               std::forward_iterator_tag>);
    static_assert(std::same_as<std::iter_value_t<ForwardListIterator<int>>, int>);
    static_assert(std::same_as<std::iter_reference_t<ForwardListIterator<int>>, int&>);

    SimpleForwardList<int> list;
    list.push_front(3);
    list.push_front(2);
    list.push_front(1);

    // Algoritmus használata
    std::for_each(list.begin(), list.end(), [](int x) { std::cout << x << ' '; });
    std::cout << '\n';

    // std::copy működik, mert forward iterátor
    std::vector<int> from_list;
    std::copy(list.begin(), list.end(), std::back_inserter(from_list));
    // from_list: {1, 2, 3}
}

Ez a példa bemutatja:

  • A szükséges öt típusdefiníciót (value_type, difference_type, pointer, reference, iterator_category).
  • A C++20 iterator_concept megadását (opcionális, de hasznos).
  • A static_assert-ekkel történő ellenőrzést a conceptek és az iterator_traits alapján.
  • A std::for_each és std::copy használatát, amelyek forward iterátort igényelnek.

15.1.6 Tipikus hibák és elkerülésük

Az iterátorok implementálása során számos gyakori hiba fordul elő, amelyek közül a legfontosabbakat érdemes ismerni.

15.1.6.1 1. Hiányzó vagy helytelen iterator_category

Ha az iterátor osztály nem definiálja az iterator_category típusdefiníciót, akkor az std::iterator_traits nem tudja levezetni a kategóriát, és a generikus algoritmusok vagy nem fordulnak le, vagy (régebbi szabványokban) hibásan feltételezik az input iterátort. A C++20 conceptek bizonyos esetekben működhetnek a tag nélkül is, de a hagyományos std::iterator_traits-ra épülő algoritmusok (különösen a régebbi kódok) megkövetelik. Ezért mindig adjuk meg az öt típusdefiníciót, vagy származtassunk a std::iterator segédosztályból (bár a std::iterator C++17-ben elavult, a saját típusdefiníciók megadása a preferált).

15.1.6.2 2. Helytelen reference típus

A forward iterátoroknál a reference típusnak lvalue referencia típusúnak kell lennie (pl. T&), különben a std::forward_iterator concept nem teljesül, és az algoritmusok sem működnek helyesen. Ha az operator* visszatérési értéke prvalue (pl. egy proxy objektum), akkor az iterátor legfeljebb input iterátor lehet (vagy speciális proxy iterátor, de ez már haladó téma). Például a std::vector<bool> iterátora nem forward iterátor a klasszikus értelemben, mert az operator* egy proxy referenciát ad vissza, nem bool&-et. Ezért a std::vector<bool> iterátor kategóriája a C++20 conceptek szerint std::random_access_iterator, de nem std::contiguous_iterator, és a std::iter_reference_t nem bool&.

15.1.6.3 3. A postincrement (operator++(int)) helytelen visszatérési típusa

A postincrement operátornak a régi iterátor másolatát kell visszaadnia (általában érték szerint), nem referenciát. Ha referenciát adunk vissza, az érvénytelen lehet a függvényből való visszatérés után (dangling reference). A legtöbb implementációban a postincrement a fenti mintát követi: másolatot készít, előlépteti az aktuális iterátort, majd visszaadja a másolatot.

15.1.6.4 4. Hiányzó operator== vagy operator!=

A C++20 előtt mindkét összehasonlító operátort meg kellett adni. Bár a C++20-ban az operator!= automatikusan generálódik az operator==-ből, a régebbi szabványokkal való kompatibilitás érdekében érdemes mindkettőt explicit definiálni, vagy a C++20-ra támaszkodni, ha a projekt csak azt támogatja. A std::input_or_output_iterator concept megköveteli az == operátort.

15.1.6.5 5. A difference_type rossz megválasztása

A difference_type-nak előjeles egész típusnak kell lennie, amely képes reprezentálni a konténer két iterátora közötti maximális különbséget. Általában std::ptrdiff_t a megfelelő választás. Ha túl kicsi típust választunk (pl. int egy hatalmas konténerhez), túlcsordulás léphet fel. A std::iter_difference_t<It> segítségével ellenőrizhetjük.

15.1.6.6 6. A std::iterator_traits specializáció hiánya beépített pointerekre

Ez nem a saját iterátor hibája, de a generikus kód írásakor gondolni kell arra, hogy a beépített pointerek is iterátorok, és az std::iterator_traits már tartalmazza a szükséges specializációt. Ha saját iterator_traits-t írunk, ne feledkezzünk meg a pointerek specializációjáról, különben a pointereket használó algoritmusok nem fognak működni.

15.1.6.7 7. Az iterator_concept és az iterator_category összekeverése C++20-ban

A C++20 bevezette az iterator_concept típusdefiníciót, amely a conceptek által használt kategóriát pontosítja. Ha egy iterátor iterator_category-ja std::random_access_iterator_tag, de a tényleges műveletei nem teljesítik a random access követelményeit, akkor a conceptek ezt észlelik, és a std::random_access_iterator concept hamis lesz, annak ellenére, hogy az iterator_category azt állítja. Az iterator_concept arra szolgál, hogy ezt a különbséget kezeljük: ha megadjuk, az iterator_traits<It>::iterator_concept fogja meghatározni a conceptek viselkedését, és az iterator_category továbbra is a hagyományos, esetleg „bőkezűbb” kategóriát jelölheti a régi algoritmusok számára. A legtöbb esetben az iterator_concept megegyezik az iterator_category-val, de a trükkös esetekben (pl. proxy iterátorok) eltérhet.

15.1.7 Labor: iterátorkategória-teszt készítése

A labor célja, hogy a fenti ismereteket egy reprodukálható, ellenőrizhető példán keresztül gyakoroljuk. A feladat egy saját iterátor implementálása, amely legalább forward iterátor, és annak ellenőrzése static_assert-ekkel és futási tesztekkel. Az alábbiakban egy lehetséges laborleírást adunk, amelyet a hallgatóknak kell elvégezniük.

15.1.7.1 Feladat

  1. Hozz létre egy saját, egyszerű konténert (pl. egy láncolt lista, mint a fenti SimpleForwardList, de lehet más is, például egy dinamikus tömb vagy egy fix méretű tömb).
  2. Implementálj hozzá egy iterátort, amely legalább forward iterátor kategóriájú. Ha kedved tartja, készíthetsz bidirectional vagy random access iterátort is.
  3. Az iterátor osztályban add meg a szükséges típusdefiníciókat (value_type, difference_type, pointer, reference, iterator_category, és opcionálisan iterator_concept).
  4. Írj static_assert-eket annak ellenőrzésére, hogy az iterátor teljesíti-e a std::forward_iterator (vagy magasabb) conceptet, és hogy az std::iterator_traits megfelelő típusokat ad vissza.
  5. Írj egy main() függvényt, amely feltölti a konténert, bejárja az elemeit std::for_each segítségével, és ellenőrzi a helyes sorrendet.
  6. Készíts build parancsot, amely legalább GCC és Clang fordítóval, -std=c++20 kapcsolóval, -Wall -Wextra -pedantic figyelmeztetésekkel fordít. Futtasd a programot, és rögzítsd a kimenetet.
  7. (Opcionális) Adj hozzá egy tesztesetet, amely a std::copy-t használja, és ellenőrzi, hogy a másolás helyesen működik.
  8. A mérési naplóban rögzítsd a használt fordítót, verziót, standardverziót, a program kimenetét, és a static_assert-ek sikerességét (fordítási időben). A mért és a várt eredményt külön jelöld.

15.1.7.2 Példa a laborhoz (részlet)

A fenti SimpleForwardList példa jó kiindulópont. A hallgatók ezt kiegészíthetik a static_assert-ekkel és a build scripttel. Az alábbiakban egy lehetséges static_assert sorozat:

// Az iterátor típusa: SimpleForwardList<int>::iterator
using It = SimpleForwardList<int>::iterator;

static_assert(std::forward_iterator<It>);
static_assert(std::input_iterator<It>);
static_assert(!std::bidirectional_iterator<It>); // ha nincs operator--
static_assert(std::same_as<std::iter_value_t<It>, int>);
static_assert(std::same_as<std::iter_reference_t<It>, int&>);
static_assert(std::same_as<std::iter_difference_t<It>, std::ptrdiff_t>);
static_assert(std::same_as<std::iterator_traits<It>::iterator_category,
                           std::forward_iterator_tag>);

A build parancs (Linux környezetben, GCC):

g++ -std=c++20 -Wall -Wextra -pedantic -O2 -o iterator_lab iterator_lab.cpp

Futtatás:

./iterator_lab

Várt kimenet (a példában szereplő lista {1, 2, 3} esetén):

1 2 3

A mérési naplóban ezt rögzíteni kell. A static_assert-ek fordítási időben futnak le, így ha a program lefordult, azok sikeresek.

15.1.7.3 Kiértékelés

A labor értékelésekor a következőket ellenőrizzük:

  • Az iterátor típusdefiníciói helyesek-e.
  • A static_assert-ek sikeresek-e.
  • A program futása a várt kimenetet produkálja-e.
  • A build script reprodukálható-e (a parancs lefuttatható).
  • A mérési napló tartalmazza-e a szükséges adatokat (fordító, verzió, standard, kimenet, várt vs. mért).

15.1.8 Önellenőrző kérdés

Az alábbi kérdéssel ellenőrizheted, hogy megértetted-e az anyagot:

Kérdés: Egy iterátor osztály a következő típusdefiníciókat tartalmazza:

using value_type        = int;
using difference_type   = std::ptrdiff_t;
using pointer           = int*;
using reference         = int;
using iterator_category = std::forward_iterator_tag;

Mi a hiba ebben a definícióban, és hogyan javítanád? Melyik concept nem fog teljesülni emiatt, és miért?

Válasz: A reference típusnak int&-nek kell lennie, nem int-nek. A forward iterátor reference típusa lvalue referencia kell legyen, hogy az operator* az elemre mutató referenciát adjon. Ha int értékű, akkor az operator* nem tudja biztosítani a stabil címet, és a std::forward_iterator concept nem teljesül, mert az std::iter_reference_t nem lesz int&. A javítás: using reference = int&;.

Ez a kérdés a leggyakoribb hibatípust emeli ki, és segít a figyelem felkeltésében.

Ezzel az alfejezettel lefedtük az iterátorkategóriák hierarchiáját az input iterátortól a random access (és contiguous) iterátorig, megismertük az iterator_traits szerepét, és egy gyakorlati példán keresztül bemutattuk a helyes implementációt és a tipikus hibákat. A következő alfejezetben (Saját iterátorok) a saját iterátorok készítésének részleteire térünk ki, építve az itt bevezetett fogalmakra.
