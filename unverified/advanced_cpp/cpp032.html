9.3 Compile-time adatszerkezetek és algoritmusok

Az előző alfejezetben a type traits és a típusmanipuláció alapjait tekintettük át. Most a sablonmeta-programozás (TMP) egyik legfontosabb építőkövét, a típuslistát és a hozzá kapcsolódó compile-time algoritmusokat tárgyaljuk. A típuslista egy olyan fordítási idejű adatszerkezet, amely típusok sorozatát reprezentálja anélkül, hogy futásidejű objektumot hozna létre belőle. Ez a technika lehetővé teszi, hogy típusokon végezzünk műveleteket – szűrés, keresés, rendezés, transzformáció – még a program futása előtt. A cél nem csupán az „okos kód” bemutatása, hanem annak megértése, hogyan építhetünk karbantartható, kifejező és hatékony absztrakciókat a fordító segítségével.

9.3.1 A típuslista fogalma és reprezentációi

A típuslista lényege, hogy típusokat foglal egyetlen típusba, hasonlóan ahhoz, ahogy egy std::tuple értékeket tartalmaz. A különbség az, hogy a típuslista maga egy típus, nem pedig érték. Legegyszerűbb, modern C++-os definíciója variadic template segítségével:

template<typename... Ts>
struct TypeList {};

Ez az üres struktúra csak a sablonparaméterekben hordozza a típusokat. Például a TypeList<int, double, std::string> egy típus, amely három típust reprezentál. Nincs belőle objektum, nincs memóriafoglalás, a teljes reprezentáció a fordító szimbólumtáblájában létezik.

A variadic template előtt a klasszikus megoldás rekurzív, fej-farok szerkezetű volt:

struct NullType {};

template<typename H, typename T = NullType>
struct Typelist {
    using head = H;
    using tail = T;
};

Ez a Loki könyvtárból ismert stílus, amely ma is használható, de a modern variadic sablonokkal sokkal kényelmesebb és olvashatóbb a kód. A továbbiakban a variadic TypeList-et használjuk, de a rekurzív reprezentáció tanulmányozása hasznos a TMP történeti gyökereinek megértéséhez.

A típuslista gyakran összekapcsolódik a std::tuple-lal: a típuslista a típusok sorozatát adja meg, a std::tuple pedig az adott típusú értékek tárolására szolgáló sablon. Kölcsönösen átalakíthatók egymásba, ami lehetővé teszi, hogy a típuslistán végzett algoritmusok eredményét futásidejű adatszerkezetté alakítsuk.

9.3.2 Alapvető metafüggvények típuslistákhoz

A típuslistákon végzett műveletekhez metafüggvényeket írunk, amelyek típust vagy konstans értéket adnak vissza. Az eredményt általában egy type (vagy value) taggel tesszük elérhetővé, hasonlóan a standard <type_traits> fejlécben megszokott konvencióhoz.

9.3.2.1 Hossz

A lista hosszának meghatározása a legegyszerűbb, hiszen a sizeof...(Ts) közvetlenül megadja a paramétercsomag méretét:

template<typename List>
struct length;

template<typename... Ts>
struct length<TypeList<Ts...>>
    : std::integral_constant<std::size_t, sizeof...(Ts)> {};

A std::integral_constant biztosítja a value statikus konstans taget, így az length<TypeList<int, double>>::value értéke 2.

9.3.2.2 Elem elérése index alapján

Az at metafüggvény egy adott indexű típust ad vissza. A legegyszerűbb trükk a std::tuple_element használata, amely pontosan erre a célra készült:

template<std::size_t I, typename List>
struct at;

template<std::size_t I, template<typename...> class List, typename... Ts>
struct at<I, List<Ts...>> {
    static_assert(I < sizeof...(Ts), "Index out of range");
    using type = std::tuple_element_t<I, std::tuple<Ts...>>;
};

A template<typename...> class List template template paraméter lehetővé teszi, hogy a metafüggvény ne csak a TypeList-re, hanem bármilyen hasonló variadic template-re működjön (például std::tuple-ra is, ha a template template paraméter elfogadja). A static_assert fordítási időben ellenőrzi az index érvényességét, így hibás használat esetén értelmes hibaüzenetet kapunk.

9.3.2.3 Elem hozzáadása elöl és hátul

A push_front és push_back metafüggvények új típust szúrnak be a lista elejére vagy végére:

template<typename T, typename List>
struct push_front;

template<typename T, template<typename...> class List, typename... Ts>
struct push_front<T, List<Ts...>> {
    using type = List<T, Ts...>;
};

template<typename T, typename List>
struct push_back;

template<typename T, template<typename...> class List, typename... Ts>
struct push_back<T, List<Ts...>> {
    using type = List<Ts..., T>;
};

9.3.2.4 Két lista összefűzése

Az append metafüggvény két típuslistát kapcsol össze:

template<typename L1, typename L2>
struct append;

template<template<typename...> class List, typename... Ts1, typename... Ts2>
struct append<List<Ts1...>, List<Ts2...>> {
    using type = List<Ts1..., Ts2...>;
};

9.3.2.5 Megfordítás

A reverse metafüggvény egy lista elemeit fordított sorrendben adja vissza. Rekurzív megvalósítása akkumulátort használ:

template<typename Acc, typename List>
struct reverse_impl;

template<typename Acc, template<typename...> class List>
struct reverse_impl<Acc, List<>> {
    using type = Acc;
};

template<typename Acc, template<typename...> class List, typename H, typename... Ts>
struct reverse_impl<Acc, List<H, Ts...>> {
    using type = typename reverse_impl<List<H, Acc>, List<Ts...>>::type;
};

template<typename List>
struct reverse : reverse_impl<TypeList<>, List> {};

Itt az akkumulátor (Acc) kezdetben üres TypeList<>, majd minden lépésben a fej elemet az akkumulátor elejére helyezzük. Az eredmény a lista megfordítása lesz. Mivel a reverse_impl rekurziója a listaelemek számával arányos, a fordítási idő lineárisan nő a lista méretével – ezt érdemes szem előtt tartani nagy listák esetén.

9.3.3 Compile-time algoritmusok

A típuslistákhoz kapcsolódó legfontosabb algoritmusok a keresés, a transzformáció, a szűrés és a rendezés. Mindegyik rekurzív metafüggvényként valósítható meg, és a modern C++ if constexpr vagy std::conditional_t segítségével tömöríthető.

9.3.3.1 Keresés: contains és find

A contains metafüggvény megadja, hogy egy adott típus szerepel-e a listában:

template<typename T, typename List>
struct contains;

template<typename T, template<typename...> class List>
struct contains<T, List<>> : std::false_type {};

template<typename T, template<typename...> class List, typename H, typename... Ts>
struct contains<T, List<H, Ts...>>
    : std::bool_constant<std::is_same_v<T, H> || contains<T, List<Ts...>>::value> {};

Az implementáció rekurzívan ellenőrzi a lista fejét, és ha nem egyezik, továbblép a farokra. A std::bool_constant a std::integral_constant<bool, ...> típusaliasa. A rekurzió az üres lista esetén std::false_type-tal zárul.

A find metafüggvény az első előfordulás indexét adja vissza, vagy a lista hosszát, ha nem található:

template<typename T, typename List>
struct find;

template<typename T, template<typename...> class List>
struct find<T, List<>> : std::integral_constant<std::size_t, 0> {};

template<typename T, template<typename...> class List, typename H, typename... Ts>
struct find<T, List<H, Ts...>>
    : std::integral_constant<
          std::size_t,
          std::is_same_v<T, H> ? 0 : 1 + find<T, List<Ts...>>::value> {};

Ez a változat a „nem talált” esetet 0-val jelzi, ami üres lista esetén megegyezik a hosszal. A gyakorlatban érdemes lehet egy explicit npos értéket használni, például a lista hosszát.

9.3.3.2 Transzformáció: transform

A transform metafüggvény egy unáris metafüggvényt alkalmaz a lista minden elemére, és az eredményekből új listát készít:

template<template<typename> class F, typename List>
struct transform;

template<template<typename> class F, template<typename...> class List>
struct transform<F, List<>> {
    using type = List<>;
};

template<template<typename> class F, template<typename...> class List, typename H, typename... Ts>
struct transform<F, List<H, Ts...>> {
    using transformed_tail = typename transform<F, List<Ts...>>::type;
    using type = typename push_front<typename F<H>::type, transformed_tail>::type;
};

Itt a F egy sablon template paraméter, amely egy típust vár és egy típust ad vissza (például std::add_pointer). A rekurzió során minden elemre alkalmazzuk a függvényt, majd az eredményt a lista elejére helyezzük. A sorrend megőrzése miatt a push_front rekurzív alkalmazása helyes sorrendet ad.

9.3.3.3 Szűrés: filter

A filter metafüggvény egy predikátumot (szintén sablon template paraméter) alkalmaz minden elemre, és csak azokat tartja meg, amelyekre a predikátum igaz:

template<template<typename> class Pred, typename List>
struct filter;

template<template<typename> class Pred, template<typename...> class List>
struct filter<Pred, List<>> {
    using type = List<>;
};

template<template<typename> class Pred, template<typename...> class List, typename H, typename... Ts>
struct filter<Pred, List<H, Ts...>> {
    using filtered_tail = typename filter<Pred, List<Ts...>>::type;
    using type = std::conditional_t<
        Pred<H>::value,
        typename push_front<H, filtered_tail>::type,
        filtered_tail>;
};

A std::conditional_t választja ki, hogy a fej elemet hozzáadjuk-e az eredményhez. Ez a minta jól mutatja, hogyan kombinálhatók a korábban definiált metafüggvények. A filter kimenete egy új típuslista, amely csak a predikátumnak megfelelő típusokat tartalmazza.

9.3.3.4 Rendezés: sort

A típuslista rendezése egy kételemű predikátum (például sizeof szerinti összehasonlítás) alapján történik. A legegyszerűbb bemutatható algoritmus az insertion sort, amely rekurzívan rendez:

Először definiálunk egy predikátumot:

template<typename T, typename U>
struct less_size {
    static constexpr bool value = sizeof(T) < sizeof(U);
};

Ez a predikátum a típusok méretét hasonlítja össze; a sizeof fordítási időben ismert. Természetesen bármilyen más összehasonlítás is használható, például std::is_base_of vagy egyedi trait.

Az insert_sorted metafüggvény egy elemet szúr be egy már rendezett listába:

template<typename T, typename List, template<typename, typename> class Less>
struct insert_sorted;

template<typename T, template<typename...> class List, template<typename, typename> class Less>
struct insert_sorted<T, List<>, Less> {
    using type = List<T>;
};

template<typename T, template<typename...> class List, typename H, typename... Ts,
         template<typename, typename> class Less>
struct insert_sorted<T, List<H, Ts...>, Less> {
    using type = std::conditional_t<
        Less<T, H>::value,
        List<T, H, Ts...>,
        typename push_front<H, typename insert_sorted<T, List<Ts...>, Less>::type>::type>;
};

A sort maga a lista rekurzív rendezése:

template<typename List, template<typename, typename> class Less>
struct sort;

template<template<typename...> class List, template<typename, typename> class Less>
struct sort<List<>, Less> {
    using type = List<>;
};

template<template<typename...> class List, typename H, typename... Ts,
         template<typename, typename> class Less>
struct sort<List<H, Ts...>, Less> {
    using sorted_tail = typename sort<List<Ts...>, Less>::type;
    using type = typename insert_sorted<H, sorted_tail, Less>::type;
};

Az insertion sort egyszerűsége miatt jól érthető, de nagy listák esetén a fordítási idő O(n²) lehet. A gyakorlatban hatékonyabb compile-time rendezési algoritmusok is léteznek (például merge sort), de a tanulás szempontjából az insertion sort kiválóan szemlélteti a rekurzív TMP működését.

9.3.4 Típuslista és std::tuple kapcsolata

A típuslista és a std::tuple közötti átjárhatóság lehetővé teszi, hogy a típuslistán végzett algoritmusok eredményét közvetlenül használjuk futásidejű kódban. Például egy filter utáni típuslistából std::tuple-t hozhatunk létre, amely csak a kívánt típusú elemeket tartalmazza.

Egy egyszerű konverzió típuslistáról std::tuple-ra:

template<typename List>
struct to_tuple;

template<template<typename...> class List, typename... Ts>
struct to_tuple<List<Ts...>> {
    using type = std::tuple<Ts...>;
};

Fordítva, std::tuple-ból típuslista:

template<typename Tuple>
struct from_tuple;

template<typename... Ts>
struct from_tuple<std::tuple<Ts...>> {
    using type = TypeList<Ts...>;
};

Ezek a konverziók hasznosak, ha egy típuslistából szeretnénk tényleges értékeket tárolni, vagy ha egy meglévő std::tuple típuson kell compile-time algoritmusokat futtatni.

9.3.5 Gyakorlati példa: filter használata

Tekintsünk egy konkrét példát, amelyben egy típuslistából kiválasztjuk az egész típusokat:

#include <type_traits>
#include <string>

// Típuslista definíciója (mint korábban)
template<typename... Ts> struct TypeList {};

// Metafüggvények: length, push_front, filter (a fentiek szerint)

int main() {
    using MyTypes = TypeList<int, double, char, std::string, unsigned, float>;
    using IntegralTypes = typename filter<std::is_integral, MyTypes>::type;

    static_assert(std::is_same_v<IntegralTypes, TypeList<int, char, unsigned>>);
    static_assert(length<IntegralTypes>::value == 3);
    return 0;
}

Ebben a példában a std::is_integral egy standard type trait, amelyet predikátumként használunk. A filter eredménye egy TypeList<int, char, unsigned>. A static_assert ellenőrzi a helyességet fordítási időben, tehát futás közben nem történik semmilyen művelet.

A filter kimenete tovább alakítható std::tuple-vá:

using IntegralTuple = typename to_tuple<IntegralTypes>::type;
// IntegralTuple = std::tuple<int, char, unsigned>

Ezután már futásidejű objektumot is létrehozhatunk belőle, ha szükséges.

9.3.6 Tipikus hibák és elkerülésük

A típuslistás TMP során több gyakori buktatóval találkozhatunk:

  1. Hiányzó typename és template kulcsszavak: A függő nevek (dependent names) esetén a fordító nem tudja eldönteni, hogy egy név típus vagy érték, ezért szükséges a typename és a template diszambiguáló kulcsszavak használata. Például a typename F<H>::type esetén a typename jelzi, hogy a type típusnév. Hasonlóan, ha egy függő néven sablont hívunk meg, template kulcsszó szükséges: obj.template foo<T>().

  2. Túl mély rekurzió: A rekurzív metafüggvények mélysége a lista elemszámával arányos. A fordítók általában korlátozzák a sablonpéldányosítás mélységét (például 900 vagy 1024). Nagy listák esetén ez hibát okozhat. Megoldás lehet a rekurzió mélységének csökkentése (például felező rekurzióval) vagy modernebb, if constexpr-es technikák alkalmazása, bár utóbbi sem növeli a maximális mélységet, csak a kód olvashatóságát javítja.

  3. ODR és többszörös definíció: A compile-time metafüggvények általában csak típusokat és konstansokat definiálnak, ezért nem okoznak ODR-problémát, ha headerben vannak. Ügyeljünk arra, hogy a statikus konstans tagokat (static constexpr) C++17-től inline-ként kezeljük, de ha C++14 előtti szabványt használunk, a static constexpr adattag definícióját a forrásfájlban is meg kell adni. A std::integral_constant származtatással ez a probléma elkerülhető, mert a value statikus tag a standard könyvtár által definiált.

  4. Helytelen template template paraméter: A template<typename...> class List paraméter csak olyan sablonokat fogad el, amelyek pontosan egy típusparaméter-csomagot várnak. Ha egy sablonnak más paraméterezése van (például alapértelmezett paraméterek), az nem feltétlenül illeszkedik. Ezért a std::tuple nem mindig használható közvetlenül ilyen paraméterként (a std::tuple második paramétere egy allokátor). A gyakorlatban érdemes saját TypeList-et használni, és a std::tuple-lal való konverziót külön metafüggvényekkel kezelni.

  5. Hibaüzenetek olvashatósága: A mélyen ágyazott TMP hibák nehezen értelmezhető üzeneteket produkálhatnak. A static_assert-ek tudatos elhelyezése sokat segít. Például az at metafüggvénynél a static_assert(I < sizeof...(Ts), "Index out of range") értelmes hibát ad ahelyett, hogy a std::tuple_element hibáját látnánk.

  6. Felesleges futásidejű költség: A típuslisták és metafüggvények önmagukban nem generálnak futásidejű kódot, de ha az eredményt nem használjuk fel konstans kifejezésként, a fordító esetleg nem optimalizálja ki teljesen. A legtöbb esetben azonban a TMP eredménye beépül a típusrendszerbe, és nincs futásidejű hatása.

9.3.7 Labor: Típuslista és compile-time filter

A labor célja egy saját típuslista és egy filter metafüggvény elkészítése, valamint annak ellenőrzése, hogy a szűrés helyesen működik. A feladat előírja a reprodukálható buildet, a tesztkörnyezetet, valamint a mérési naplót, amelyben elkülönítjük a mért és a várt eredményeket.

9.3.7.1 Feladat

  1. Definiálj egy TypeList sablont variadic template paraméterekkel.
  2. Implementáld a következő metafüggvényeket:
    • length<TypeList> – a lista hossza.
    • push_front<T, TypeList> – új elem a lista elejére.
    • filter<Pred, TypeList> – szűrés predikátum alapján.
  3. Használj egy standard predikátumot, például std::is_integral vagy std::is_floating_point.
  4. Írj static_assert teszteket, amelyek ellenőrzik:
    • üres lista esetén a filter eredménye üres lista,
    • egy elem esetén a predikátumtól függően szerepel-e az elem,
    • több elem esetén a szűrés helyes sorrendet és tartalmat ad,
    • a length és push_front helyes működését.
  5. Ellenőrizd, hogy a filter eredménye típuslistaként használható tovább (például to_tuple konverzióval).

9.3.7.2 Build és tesztkörnyezet

A kód C++17 vagy újabb szabvány szerint forduljon (a std::conditional_t, std::is_same_v elérhetősége miatt C++17 ajánlott, de C++11/14 is működik, ha a _t és _v aliasokat helyettesítjük). A javasolt build parancsok:

# GCC
g++ -std=c++17 -Wall -Wextra -Werror -pedantic -O2 -o filter_test filter_test.cpp

# Clang
clang++ -std=c++17 -Wall -Wextra -Werror -pedantic -O2 -o filter_test filter_test.cpp

# MSVC (Developer Command Prompt)
cl /std:c++17 /W4 /WX /O2 /EHsc filter_test.cpp

A static_assert tesztek a fordítás során futnak le, tehát a program sikeres fordítása egyben a tesztek sikeres lefutását is jelenti. A futtatás opcionális, de a main függvény legyen üres vagy tartalmazzon egy kiírást a sikeres fordítás jelzésére.

A várt és a mért eredmény elkülönítése fontos: a várt az elméleti következmény, a mért a ténylegesen megfigyelt viselkedés. Jelen esetben a fordítás sikere bizonyítja a típushelyességet, de a konkrét típusösszehasonlítást static_assert-ekkel végezzük.

9.3.7.4 Példa tesztkód

#include <type_traits>
#include <string>
#include <tuple>

template<typename... Ts> struct TypeList {};

// length
template<typename List> struct length;
template<typename... Ts>
struct length<TypeList<Ts...>> : std::integral_constant<std::size_t, sizeof...(Ts)> {};

// push_front
template<typename T, typename List> struct push_front;
template<typename T, template<typename...> class List, typename... Ts>
struct push_front<T, List<Ts...>> { using type = List<T, Ts...>; };

// filter
template<template<typename> class Pred, typename List> struct filter;
template<template<typename> class Pred, template<typename...> class List>
struct filter<Pred, List<>> { using type = List<>; };

template<template<typename> class Pred, template<typename...> class List, typename H, typename... Ts>
struct filter<Pred, List<H, Ts...>> {
    using filtered_tail = typename filter<Pred, List<Ts...>>::type;
    using type = std::conditional_t<
        Pred<H>::value,
        typename push_front<H, filtered_tail>::type,
        filtered_tail>;
};

// to_tuple konverzió
template<typename List> struct to_tuple;
template<template<typename...> class List, typename... Ts>
struct to_tuple<List<Ts...>> { using type = std::tuple<Ts...>; };

int main() {
    using MyTypes = TypeList<int, double, char, std::string, unsigned, float>;

    static_assert(length<MyTypes>::value == 6, "length mismatch");

    using Pushed = typename push_front<bool, MyTypes>::type;
    static_assert(length<Pushed>::value == 7, "push_front length error");
    static_assert(std::is_same_v<Pushed, TypeList<bool, int, double, char, std::string, unsigned, float>>);

    using IntegralTypes = typename filter<std::is_integral, MyTypes>::type;
    static_assert(std::is_same_v<IntegralTypes, TypeList<int, char, unsigned>>, "filter integral error");

    using FloatingTypes = typename filter<std::is_floating_point, MyTypes>::type;
    static_assert(std::is_same_v<FloatingTypes, TypeList<double, float>>, "filter floating error");

    using EmptyFilter = typename filter<std::is_integral, TypeList<>>::type;
    static_assert(std::is_same_v<EmptyFilter, TypeList<>>, "empty filter error");

    using IntegralTuple = typename to_tuple<IntegralTypes>::type;
    static_assert(std::is_same_v<IntegralTuple, std::tuple<int, char, unsigned>>, "tuple conversion error");

    return 0;
}

A fenti kód önállóan fordítható, és a static_assert-ek minden állítást ellenőriznek. A labor során ezt a kódot kell létrehozni és a fenti buildparancsokkal lefordítani.

9.3.8 Önellenőrző kérdések

  1. Mi a különbség a típuslista és a std::tuple között? Melyiket mikor érdemes használni?
  2. Hogyan működik a filter metafüggvény rekurziója? Miért van szükség a std::conditional_t-re, és mi történik, ha a predikátum hamis?
  3. Miért okozhat gondot a túl mély rekurzió a compile-time algoritmusokban? Adj példát olyan listaméretre, ahol a fenti reverse implementáció esetleg hibát okozhat.
  4. Milyen előnyei és hátrányai vannak a variadic template alapú TypeList-nek a klasszikus fej-farok rekurzív reprezentációhoz képest?
  5. Hogyan ellenőrizhető a compile-time metafüggvények helyessége? Miért elegendő a fordítás sikere a helyesség bizonyításához, ha static_assert-eket használunk?

9.3.9 Összegzés

A típuslista és a hozzá kapcsolódó compile-time algoritmusok a sablonmeta-programozás alapvető eszközei. Lehetővé teszik, hogy típusokon végezzünk műveleteket fordítási időben, csökkentve a futásidejű költségeket és növelve a típusbiztonságot. A fejezetben bemutatott TypeList, length, push_front, append, reverse, transform, filter és sort metafüggvények egy koherens keretrendszert alkotnak, amelyre a későbbi fejezetek (például a CRTP, a policy-based design és a type erasure) építeni fognak. A labor során elsajátított filter megvalósítás a gyakorlatban is hasznos minta, hiszen sok helyen szükség van típusok szűrésére – például interfészek összeállítása, eseménykezelők típuslistája vagy generikus komponensek konfigurációja során. A compile-time algoritmusok nem csupán elméleti kuriózumok, hanem a modern C++ könyvtárak és keretrendszerek alapját képezik.
