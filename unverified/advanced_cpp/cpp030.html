9.1 Rekurzív sablonok és metafüggvények

A fordítási időben végzett számítás a C++ egyik legrégebbi, mégis ma is releváns absztrakciós eszköze. A sablonok Turing-teljes metaprogramozási nyelvet alkotnak, amelyben a rekurzió a ciklus, a specializáció a feltétel, az értékek és típusok pedig a változók szerepét töltik be. Ez az alfejezet a sablon-alapú metaprogramozás legalapvetőbb építőköveit, a rekurzív sablonokat és a metafüggvényeket tárgyalja. A cél nem a receptgyűjtemény, hanem annak megértése, hogyan válik a sablonpéldányosítás mechanizmusa fordítási idejű kiértékelővé, és hogyan különböztethetők meg a típus- és értékeredményt adó metafüggvények.

9.1.1 1. Miért számolunk sablonokkal?

A hagyományos megközelítés szerint a C++ program futási időben hajtja végre az utasításokat. A fordítási időben azonban a konstansértékek, a típusok és a kódstruktúrák is ismertek lehetnek. Ha egy számítást már a fordító el tud végezni, az eredmény konstansként beépülhet a binárisba: nincs futási idejű költség, nincs kivétel, nincs késői hiba. A sablonmetaprogramozás (template metaprogramming, TMP) ezt a lehetőséget használja ki: a programozó a típusrendszeren keresztül fejez ki algoritmusokat, amelyeket a fordító a példányosítás során kiértékel.

A C++11 óta a constexpr függvények is lehetővé teszik a fordítási idejű számítást, és a modern C++-ban sok esetben elegendőek. A sablonmetaprogramozás azonban továbbra is elengedhetetlen, ha a számítás típusoktól függ, típusokat állít elő, vagy ha a kódstruktúrát (pl. túlterhelésválasztást, specializációt) kell befolyásolni. A constexpr függvények értékekkel dolgoznak, a metafüggvények viszont típusokkal és értékekkel egyaránt, és a sablonrendszer szabályai (dedukció, specializáció, SFINAE) adnak számukra kifejezőerőt.

A fejezet fókuszában a klasszikus, rekurzív sablonstílus áll. Ez nem csak történeti érdekesség: a rekurzív példányosítás logikája áthatja a type trait-eket, a variadic sablonokat és számos modern könyvtárat. Aki érti a rekurzív sablonokat, az képes megérteni a std::tuple elemeinek feldolgozását, a típuslisták manipulációját vagy a fordító hibaüzeneteiben megjelenő mélységi láncokat.

9.1.2 2. A sablonrekurzió alapelve

A rekurzív sablon olyan osztálysablon, amelynek definíciója saját magát hivatkozza, de az argumentumai minden rekurzív lépésben közelítenek egy alapesethez. Az alapesetet sablonspecializáció adja meg, amely leállítja a rekurziót. A klasszikus példa a faktoriális:

#include <cstddef>

template <std::size_t N>
struct Factorial {
    static constexpr std::size_t value = N * Factorial<N - 1>::value;
};

template <>
struct Factorial<0> {
    static constexpr std::size_t value = 1;
};

static_assert(Factorial<5>::value == 120);
static_assert(Factorial<0>::value == 1);
static_assert(Factorial<1>::value == 1);

A Factorial<5> példányosításakor a fordító rekurzívan példányosítja a Factorial<4>, Factorial<3>, Factorial<2>, Factorial<1> és végül a Factorial<0> sablont. A Factorial<0> már a teljes specializációt használja, amely nem hivatkozik további példányra, így a rekurzió leáll. A value tag minden példányban konstansérték, amelyet a fordító behelyettesít a kifejezésbe.

A rekurzió terminációja tehát a sablonspecializáción alapul. Fontos megérteni, hogy a példányosítás nem „fut” a szokásos értelemben: a fordító a szimbólumtáblában felépíti a példányok láncát, és mindegyikhez hozzárendeli a value konstans értékét. A kifejezés kiértékelése ezen konstansok felhasználásával történik. Ha egy példány hivatkozik egy nem létező vagy hiányos típusra, fordítási hiba keletkezik.

A rekurzív sablonok két alapvető formája:

  1. Érték-rekurzió: a sablon paramétere érték, az eredmény érték (pl. Factorial).
  2. Típus-rekurzió: a sablon paramétere típus, az eredmény típus vagy érték (pl. típuslista hossza, típus transzformáció).

A Fibonacci-számítás hasonló módon fejezhető ki:

template <std::size_t N>
struct Fibonacci {
    static constexpr std::size_t value =
        Fibonacci<N - 1>::value + Fibonacci<N - 2>::value;
};

template <>
struct Fibonacci<0> {
    static constexpr std::size_t value = 0;
};

template <>
struct Fibonacci<1> {
    static constexpr std::size_t value = 1;
};

static_assert(Fibonacci<0>::value == 0);
static_assert(Fibonacci<1>::value == 1);
static_assert(Fibonacci<2>::value == 1);
static_assert(Fibonacci<10>::value == 55);

Itt két alapeset van (N == 0 és N == 1). A rekurzió exponenciálisan sok példányt hozhat létre, ami már kis N esetén is hosszú fordítási időt okozhat. A gyakorlatban a Fibonacci-számítást sablonrekurzióval inkább demonstrációs céllal használjuk, mert a naiv változat nem hatékony a példányosítások számát tekintve.

9.1.3 3. Metafüggvény fogalma és a ::type konvenció

A metafüggvény olyan absztrakció, amely a sablonparaméterekből (típusok vagy értékek) egy eredményt állít elő. Az eredmény lehet:

  • Érték: általában static constexpr tag, konvenció szerint value néven.
  • Típus: a metafüggvény egy type nevű nested típust definiál.

A std:: számos metafüggvénye ezt a mintát követi: std::is_integral<T>::value, std::remove_reference<T>::type, std::conditional<B, T, F>::type. Az értékeredményű metafüggvények gyakran osztálysablonok, amelyek egy static constexpr bool vagy más konstans value tagot tartalmaznak. A típuseredményűek egy typedef vagy using deklarációval adják meg a type tagot.

A ::type konvenció azért fontos, mert a típusok nem helyezhetők el közvetlenül a sablonargumentum-listában, ha a sablonparaméter típusfüggő. A typename kulcsszóval kell jelezni, hogy egy dependent qualified name típust jelöl. Példa egy egyszerű típus-metafüggvényre, amely egy bool feltétel alapján választ típust:

template <bool Condition, typename TrueType, typename FalseType>
struct IfThenElse {
    using type = TrueType;
};

template <typename TrueType, typename FalseType>
struct IfThenElse<false, TrueType, FalseType> {
    using type = FalseType;
};

static_assert(std::is_same_v<IfThenElse<true, int, double>::type, int>);
static_assert(std::is_same_v<IfThenElse<false, int, double>::type, double>);

Itt a IfThenElse a std::conditional leegyszerűsített változata. A type tagot mindkét specializáció definiálja, így a metafüggvény típuseredményt ad. A felhasználó oldalán typename IfThenElse<...>::type szükséges, ha a kifejezés függő kontextusban jelenik meg (pl. sablonon belül).

A metafüggvények gyakran kombinálhatók: egy típuseredményt adó metafüggvény eredményét továbbadhatjuk egy másik metafüggvénynek. A ::type tag neve konvenció, de nem kötelező; a std:: könyvtárban azonban egységes.

9.1.4 4. Rekurzív típusmetafüggvény: típuslista mérete

Az érték-rekurzió mellett a típusokon végzett rekurzió is alapvető. Tegyük fel, hogy van egy típuslista sablonunk:

template <typename... Ts>
struct TypeList {};

Egy metafüggvény, amely a lista méretét adja vissza, rekurzívan bontható le:

template <typename List>
struct SizeOf;

template <typename... Ts>
struct SizeOf<TypeList<Ts...>> {
    static constexpr std::size_t value = sizeof...(Ts);
};

Ez a specializáció nem rekurzív, mert a variadic sablon elemszámát közvetlenül lekérdezi. A rekurzív típuslista-feldolgozás klasszikus példája az első elem típusának kiválasztása vagy a lista elemeinek feldolgozása. Rekurzív megközelítéssel:

template <typename List>
struct Front;

template <typename Head, typename... Tail>
struct Front<TypeList<Head, Tail...>> {
    using type = Head;
};

static_assert(std::is_same_v<Front<TypeList<int, double, char>>::type, int>);

A rekurzív típusfeldolgozás azonban akkor válik szükségessé, ha a művelet nem fejezhető ki közvetlenül a csomagbontással. Például a lista utolsó elemének meghatározása rekurzívan:

template <typename List>
struct Last;

template <typename Head, typename... Tail>
struct Last<TypeList<Head, Tail...>> {
    // Rekurzív hívás a maradék listára, ha van farok.
    using type = typename Last<TypeList<Tail...>>::type;
};

template <typename Only>
struct Last<TypeList<Only>> {
    using type = Only;
};

Itt az első sablon deklarálja a Last metafüggvényt, a második a legalább két elemet tartalmazó listát kezeli, a harmadik pedig az egy elemű lista alapesetét. A rekurzió során a lista minden lépésben egy elemmel rövidül, amíg el nem éri az alapesetet. A typename kulcsszó szükséges a dependent Last<...>::type előtt.

9.1.5 5. Gyakori hibák és buktatók

9.1.6 5.1. Hiányzó alapeset

Ha a rekurzív sablonnak nincs termináló specializációja, a fordító a példányosítás során végtelen rekurzióba kerül, és eléri a sablonmélységi korlátot. A hibaüzenet általában hosszú, és mélységi láncot mutat. A megoldás: minden rekurzív sablonhoz legalább egy alapeset-specializáció vagy if constexpr elágazás tartozik.

9.1.7 5.2. A typename hiánya

A függő típusnevek (dependent type names) előtt kötelező a typename. Például:

template <typename T>
struct Wrapper {
    using Inner = typename T::type; // Hiba, ha nincs typename
};

A T::type egy függő típus, mert a T sablonparamétertől függ. A fordító nem tudhatja, hogy a type típus-e vagy érték (pl. statikus tag), ezért explicit jelölést vár.

9.1.8 5.3. template kulcsszó függő sablonneveknél

Ha egy függő kifejezésben sablontagot hívunk, a template kulcsszó szükséges:

template <typename T>
void f() {
    T::template foo<int>(); // helyes
}

A metafüggvények láncolásakor is előfordulhat, hogy a ::template diszambiguálás szükséges, bár a legtöbb esetben az egyszerű typename elegendő.

9.1.9 5.4. Túl mély rekurzió és fordítási idő

A rekurzív példányosítás minden lépése növeli a fordító memóriahasználatát és a fordítási időt. A GCC alapértelmezett sablonmélysége 900, ez a -ftemplate-depth kapcsolóval módosítható. Az MSVC alapértelmezett mélysége 500 vagy 1024, verziófüggő. A gyakorlatban 100-200 feletti mélység már problémás lehet, és a Fibonacci naiv implementációja még kis N esetén is rengeteg példányt hoz létre. A rekurzív sablonoknál mindig mérlegelni kell a példányosítások számát és a mélységet.

9.1.10 5.5. static constexpr és ODR

A static constexpr tagok C++17 óta inline változók, tehát nem igényelnek definíciót a névtérben. Korábbi szabványokban (C++11/14) a static constexpr tagot osztályon kívül is definiálni kellett, ha ODR-használat történt (pl. referencia vagy pointer a tagra). A modern kódban ez a probléma megszűnt, de a hordozhatóság érdekében érdemes a szabványverziót rögzíteni a buildben.

9.1.11 5.6. enum vs. static constexpr

A régi C++-ban (C++03) a static const tagok nem voltak integral constant expression-ök, ezért gyakran enum trükköt használtak a konstansértékekhez. A C++11 óta a static constexpr a preferált megoldás. A régi kódban találkozhatunk enum { value = ... }; formával is; ennek megértése hasznos a legacy kódok olvasásakor, de új kódban kerülendő.

9.1.12 6. Modern alternatívák: if constexpr és constexpr függvények

A C++17 if constexpr lehetővé teszi a feltételes fordítási elágazást sablonon belül, ami sok esetben kiváltja a specializációt. Például a faktoriális constexpr függvénnyel:

constexpr std::size_t factorial(std::size_t n) {
    std::size_t result = 1;
    for (std::size_t i = 2; i <= n; ++i) {
        result *= i;
    }
    return result;
}

static_assert(factorial(5) == 120);

Ez a megoldás egyszerűbb és olvashatóbb, és futási időben is használható. A sablonrekurzió azonban továbbra is szükséges, ha a feltétel típusoktól függ, vagy ha a rekurzió során típusokat kell előállítani. A if constexpr akkor használható, ha a rekurzió egyetlen sablonon belül kifejezhető, és az alapeset a feltétel hamis ágában szerepel. Példa ugyanarra a faktoriálisra sablonnal, if constexpr használatával:

template <std::size_t N>
struct FactorialModern {
    static constexpr std::size_t value = [] {
        if constexpr (N == 0) {
            return 1;
        } else {
            return N * FactorialModern<N - 1>::value;
        }
    }();
};

Ez a forma elkerüli a specializációt, de a rekurzív példányosítás továbbra is megtörténik. A választás a stílus és a karbantarthatóság kérdése.

9.1.13 7. Labor: Faktoriális és Fibonacci metafüggvény

A labor célja, hogy a rekurzív sablonokat és a metafüggvény-konvenciót gyakorlatban is alkalmazzuk, reprodukálható buildben és tesztkörnyezetben. A feladat két metafüggvény implementálása: Factorial<N>::value és Fibonacci<N>::value. Az eredményeket static_assert-ekkel ellenőrizzük, és rögzítjük a build- és mérési naplót.

9.1.14 7.1. Forráskód (tmp_factorial_fibonacci.cpp)

#include <cstddef>
#include <type_traits>

// Faktoriális metafüggvény klasszikus rekurzív specializációval.
template <std::size_t N>
struct Factorial {
    static constexpr std::size_t value = N * Factorial<N - 1>::value;
};

template <>
struct Factorial<0> {
    static constexpr std::size_t value = 1;
};

// Fibonacci metafüggvény két alapesettel.
template <std::size_t N>
struct Fibonacci {
    static constexpr std::size_t value =
        Fibonacci<N - 1>::value + Fibonacci<N - 2>::value;
};

template <>
struct Fibonacci<0> {
    static constexpr std::size_t value = 0;
};

template <>
struct Fibonacci<1> {
    static constexpr std::size_t value = 1;
};

// Statikus ellenőrzések (fordítási időben futnak le).
static_assert(Factorial<0>::value == 1, "Factorial<0> must be 1");
static_assert(Factorial<1>::value == 1, "Factorial<1> must be 1");
static_assert(Factorial<5>::value == 120, "Factorial<5> must be 120");
static_assert(Factorial<10>::value == 3628800, "Factorial<10> must be 3628800");

static_assert(Fibonacci<0>::value == 0, "Fibonacci<0> must be 0");
static_assert(Fibonacci<1>::value == 1, "Fibonacci<1> must be 1");
static_assert(Fibonacci<2>::value == 1, "Fibonacci<2> must be 1");
static_assert(Fibonacci<10>::value == 55, "Fibonacci<10> must be 55");
static_assert(Fibonacci<20>::value == 6765, "Fibonacci<20> must be 6765");

int main() {
    // A static_assert-ek már bizonyítják a helyes értékeket.
    // Futási idejű teszt nem szükséges, de egy kiíratás hasznos lehet.
    return 0;
}

9.1.15 7.2. Buildparancs és tesztelés

A buildhez rögzítjük a fordítót, a szabványverziót és a kapcsolókat. A példa GCC-t használ, de a kód bármely C++17 vagy újabb fordítóval fordul.

g++ -std=c++20 -Wall -Wextra -Wpedantic -Werror -O2 -c tmp_factorial_fibonacci.cpp -o tmp_factorial_fibonacci.o

A -Werror biztosítja, hogy a figyelmeztetések hibaként jelenjenek meg. A sanitizerek ebben a példában nem relevánsak, mert nincs futási idejű memóriakezelés, de a teljes tesztkörnyezetben futtatható a bináris is (ha van main). A teszt maga a fordítás: ha a static_assert-ek sikeresen lefordulnak, az eredmények helyesek.

9.1.16 7.3. Mérési napló

A mérési naplóban elkülönítjük a mért és a várt értékeket. A fordítási idő a sablonrekurzió költségét mutatja, a futási idő gyakorlatilag nulla, mert a main üres.

Mérési pont Várt érték Mért érték Megjegyzés
Fordítási idő (GCC 13.2, -O2) < 1 s (kis N-ek) ~0.4 s A sablonmélység alacsony (max. 20)

A mérés hardvere: x86_64, 4 mag, 8 GB RAM (a pontos adatokat a reprodukálhatóság érdekében rögzíteni kell). A futtatások száma: a fordítás 1 alkalom, a futás 3 alkalom (a nulla közeli idők miatt ez formális).

9.1.17 7.4. Ellenőrzési pontok

  1. A Factorial<0> és Factorial<1> specializációk helyesen terminálnak.
  2. A Fibonacci két alapesete lefedi a rekurzió minden ágát.
  3. A static constexpr tagok C++17 óta inline-ok, nincs szükség osztályon kívüli definícióra.
  4. A buildparancsban a -std=c++20 biztosítja a modern nyelvi szintet, de a kód C++11-ben is működne (kivéve a static_assert szintaxisát, ami C++11-től elérhető).
  5. A naplóban a mért és várt értékek külön oszlopban szerepelnek.

9.1.18 8. Összefoglalás és továbbvitel

A rekurzív sablonok és a metafüggvények a C++ sablonmetaprogramozás alapkövei. A rekurzív példányosítás teszi lehetővé a ciklusok kifejezését fordítási időben, a specializáció a terminációt, a ::type és ::value konvenció pedig a metafüggvények egységes interfészét. Bár a modern C++ constexpr függvényei sok értékalapú számítást egyszerűbbé tesznek, a típusmanipuláció és a típusoktól függő metaprogramozás továbbra is sablonrekurzióra épül.

A következő alfejezet (Type traits és type manipulation) a type trait-ekre és a típusmanipulációra összpontosít, ahol az itt bemutatott ::type konvenció és a rekurzív levezetés még hangsúlyosabbá válik. Az olvasónak a labor elvégzése után képesnek kell lennie saját rekurzív metafüggvény írására, és felismerni a termináció hiányából adódó fordítási hibákat.

  2. Mi a különbség a ::value és a ::type eredményű metafüggvények között? Adj példát mindkettőre!
  3. Miért szükséges a typename kulcsszó a Last<TypeList<Tail...>>::type kifejezésben? Milyen esetben elegendő a ::type typename nélkül?
  4. Hogyan befolyásolja a sablonmélységi korlát a rekurzív sablonok használatát? Milyen értékeknél okozhat problémát a naiv Fibonacci-implementáció?
