17.2 std::string_view, span és mdspan

A nem birtokló nézetek a modern C++ egyik legfontosabb absztrakciói: lehetővé teszik, hogy egy függvény vagy algoritmus egy meglévő adatsorozatra hivatkozzon anélkül, hogy másolatot készítene vagy tulajdonjogot szerezne. A std::string_view (C++17), a std::span (C++20) és a std::mdspan (C++23) ezt a gondolatot valósítják meg három különböző dimenzióban: karakterláncok, egydimenziós sorozatok és többdimenziós tömbök felett. A fejezet célja, hogy ezeket az eszközöket a gyakorlatban is biztonságosan alkalmazza, különös tekintettel az élettartam-kezelésre – a nem birtokló nézetek ugyanis csak akkor hasznosak, ha nem válnak lógó (dangling) hivatkozássá.

17.2.1 A nem birtokló nézetek alapelve

A C++ típusrendszerében hagyományosan kétféle szemantikát különböztetünk meg: az értékeket birtokló típusokat (mint a std::string vagy a std::vector) és a rájuk mutató, nem birtokló hivatkozásokat (pointerek, referenciák). Az utóbbiak azonban nem hordoznak méretinformációt, ezért a határok ellenőrzése nehézkes, és könnyen vezetnek hibákhoz. A view típusok ezt a hiányosságot orvosolják: úgy viselkednek, mint egy „pointer + hossz” pár, de a nyelv szintjén biztonságosabb interfészt nyújtanak. Nem birtokolnak, tehát a rájuk mutató adat élettartamáért nem felelnek, de a méretüket ismerik, így a túlindexelés és a határon túli olvasás kockázata csökken.

A három eszköz közös tulajdonságai:

  • Nem birtokló: nem foglalnak memóriát, nem szabadítanak fel, nem változtatják meg az alatta lévő tároló méretét.
  • Sekély másolás: a másolásuk olcsó, csak a pointert és a hosszt másolja.
  • Referencia-szemantika: a view módosítása nem módosítja az eredeti adatot, de ha a view konstans, az adatot sem módosíthatja rajta keresztül (kivéve, ha a view nem konstans).
  • Korlátozott garanciák: a view érvényessége szigorúan az alatta lévő objektum élettartamához kötött, ezért a view létrehozása után az eredeti objektumot nem szabad felszabadítani vagy olyan módon módosítani, amely invalidálja a mutatót (például std::vector esetén újraallokáció).

A nem birtokló nézetek elsődleges haszna a teljesítmény és a rugalmasság: függvényparaméterként lehetővé teszik, hogy ugyanaz a kód elfogadjon std::string-et, karakterliterált, karaktertömböt vagy akár egy másik std::string_view-t anélkül, hogy konverzióra vagy túlterhelésre lenne szükség. Emellett a másolás elkerülése jelentős futásidő-megtakarítást eredményezhet nagy adatsorozatok esetén.

17.2.2 std::string_view

A std::string_view (a <string_view> fejlécben) egy nem birtokló nézet egy karakterlánc felett. Gyakorlatilag egy const char* és egy std::size_t hossz párosa, de a std::string interfészének jelentős részét biztosítja: substr, find, compare, iterátorok, operator[], at, starts_with, ends_with (C++20), és így tovább. A fontos különbség, hogy a substr itt O(1)O(1) költségű, hiszen csak egy új nézetet hoz létre, nem másol.

Példa: függvényparaméter std::string_view-val

#include <string_view>
#include <iostream>

void print_line(std::string_view sv) {
    // sv nem birtokol, csak hivatkozik
    if (sv.empty()) return;
    auto pos = sv.find('\n');
    if (pos != std::string_view::npos) {
        std::cout << sv.substr(0, pos); // O(1) részsorozat
    } else {
        std::cout << sv;
    }
}

A fenti függvény meghívható std::string objektummal, const char* literállal, std::array<char, N>-nel és std::string_view-val is. A konverzió implicit, és nem jár másolással. A std::string_view a std::string-ből implicit módon konstruálható, de fordítva nem – a std::string konstruálása std::string_view-ból explicit, mert potenciálisan drága másolást jelent.

Előnyök a std::string paraméterrel szemben

Ha egy függvény const std::string& paramétert vár, akkor egy karakterliterál átadása ideiglenes std::string objektumot hoz létre, ami felesleges foglalást és másolást jelent. A std::string_view ezt elkerüli. Ugyanakkor ügyelni kell arra, hogy a std::string_view nem feltétlenül null-terminált, ezért olyan C API-khoz, amelyek null-terminált stringet várnak, nem adható át közvetlenül; ilyenkor a std::string-gé konvertálás vagy a data() és size() használata után c_str() hívás szükséges.

17.2.3 std::span

A std::span (a <span> fejlécben, C++20) egy nem birtokló nézet tetszőleges típusú elemek egydimenziós sorozata felett. Hasonlít a std::string_view-ra, de tetszőleges T típusra működik, és lehet konstans vagy nem konstans. Két formája van:

  • std::span<T, N>: statikus kiterjedésű, ahol N fordítási időben ismert. A méretet nem tárolja, csak a pointert.
  • std::span<T, std::dynamic_extent>: dinamikus kiterjedésű, a méretet futásidőben tárolja.

A std::span konstruálható beépített tömbből, std::array-ből, std::vector-ból és más konténerekből, feltéve, hogy az elemek folytonos memóriában helyezkednek el. Ez a folytonossági követelmény fontos: std::deque, std::list vagy std::forward_list nem használható span létrehozására.

Példa: std::span paraméterű függvény

#include <span>
#include <numeric>
#include <iostream>
#include <vector>

double average(std::span<const double> values) {
    if (values.empty()) return 0.0;
    double sum = std::accumulate(values.begin(), values.end(), 0.0);
    return sum / values.size();
}

int main() {
    std::vector<double> v = {1.0, 2.0, 3.0, 4.0};
    double arr[] = {5.0, 6.0, 7.0};
    std::cout << average(v) << '\n';   // span a vektor felett
    std::cout << average(arr) << '\n'; // span a tömb felett
}

A std::span előnye, hogy egységes interfészt ad a különböző folytonos tárolókhoz, és lehetővé teszi az alnézetek (subspan, first, last) létrehozását O(1)O(1) költséggel. A nem konstans std::span<T> módosíthatja is az elemeket, de a méret nem változtatható.

17.2.4 std::mdspan

A std::mdspan (a <mdspan> fejlécben, C++23) a nem birtokló nézetek többdimenziós általánosítása. A std::span-nel ellentétben nem csak egy dimenziót, hanem tetszőleges számú dimenziót kezel, és támogatja a különböző memóriaelrendezéseket (layout policy). Alapértelmezésben a C++ tömböknél megszokott row-major (sor-folytonos) elrendezést használja, de testreszabható.

A std::mdspan sablonparaméterei a következők:

template<
    class T,
    class Extents,
    class LayoutPolicy = std::layout_right,
    class AccessorPolicy = std::default_accessor<T>
> class mdspan;

Az Extents egy fordítási időben rögzített vagy dinamikus méreteket tartalmazó típus, amelyet általában std::extents segítségével adunk meg. Például std::extents<int, 3, std::dynamic_extent> egy olyan 2D nézetet ír le, ahol az első dimenzió mérete 3 (statikus), a második dimenzió mérete futásidőben adott (dinamikus).

Példa: mátrix nézet std::mdspan-nel

#include <mdspan>
#include <iostream>
#include <vector>

int main() {
    std::vector<int> data = {
        1, 2, 3,
        4, 5, 6,
        7, 8, 9
    };

    // 3x3-as nézet, row-major elrendezéssel
    std::mdspan<int, std::extents<int, 3, 3>> mat(data.data());

    for (int i = 0; i < mat.extent(0); ++i) {
        for (int j = 0; j < mat.extent(1); ++j) {
            std::cout << mat[i, j] << ' ';
        }
        std::cout << '\n';
    }

    // Dinamikus méretezésű nézet ugyanarra az adatra
    std::mdspan<int, std::dextents<int, 2>> mat_dyn(data.data(), 3, 3);
    std::cout << mat_dyn[2, 1] << '\n'; // 8
}

A std::mdspan indexelése a operator[] több argumentumos változatával történik (mat[i, j]), ami a C++23 újdonsága. A std::mdspan támogatja a szubnézeteket (submdspan) és a különböző layout policy-ket, például a std::layout_left (column-major) elrendezést, ami hasznos lehet lineáris algebrai könyvtáraknál vagy más nyelvekkel való interop esetén.

Fontos: a std::mdspan C++23-as szabvány, és a fordítói támogatottság még nem teljes. Használat előtt ellenőrizni kell a __cpp_lib_mdspan makrót (a <version> fejlécben), vagy a buildrendszerben feature detectiont kell alkalmazni. A példakódban feltételezzük, hogy a fordító támogatja.

17.2.5 View lifetime és dangling

A nem birtokló nézetek legnagyobb kockázata az élettartam-kezelés. Mivel a view nem birtokolja az adatot, az alatta lévő tároló élettartamának szigorúan hosszabbnak kell lennie, mint a view élettartamának. Ha ez nem teljesül, a view lógó hivatkozássá válik, és a használata undefined behavior.

Tipikus hibás esetek

  1. View visszaadása függvényből lokális objektumra hivatkozva
std::string_view get_name() {
    std::string local = "Alice";
    return local; // HIBA: a local megsemmisül, a view lógó lesz
}

A fenti kód lefordul, de a visszaadott std::string_view egy már megsemmisült std::string belső pufferére mutat. A hívó oldalon történő használat UB.

  1. Ideiglenes objektumhoz kötött view
std::string_view sv = std::string("temporary");
// sv most egy ideiglenes stringre mutat, amely a sor végén megsemmisül
std::cout << sv; // HIBA: lógó view
  1. std::span ideiglenes vektorra
std::span<int> get_span() {
    std::vector<int> v = {1, 2, 3};
    return std::span<int>(v); // HIBA: v megsemmisül
}
  1. std::mdspan élettartama

Ugyanez a szabály érvényes: a std::mdspan csak akkor érvényes, ha az alatta lévő puffert túléli a nézet. Például:

std::mdspan<int, std::dextents<int, 1>> create_span() {
    std::vector<int> v = {1, 2, 3};
    return std::mdspan<int, std::dextents<int, 1>>(v.data(), v.size()); // HIBA
}

Helyes megoldások

  • Tartsuk életben a tulajdonost: ha a view-t vissza kell adni, a tulajdonos objektumot is vissza kell adni (pl. std::string vagy std::vector), és a view-t csak a hívó oldalon hozzuk létre rövid élettartammal.
  • Ne kössünk view-t ideigleneshez: ha ideiglenesből akarunk view-t, előbb mentsük le az értéket egy meghosszabbított élettartamú változóba, vagy használjuk a view-t azonnal, mielőtt az ideiglenes megsemmisül.
  • Használjunk std::string_view-t csak paraméterként vagy rövid élettartamú helyi változóként: a bemeneti paraméterek esetén a hívó garantálja az élettartamot.

Példa helyes használatra

#include <string>
#include <string_view>
#include <iostream>

void print_first_word(std::string_view text) {
    auto pos = text.find(' ');
    if (pos != std::string_view::npos)
        std::cout << text.substr(0, pos);
    else
        std::cout << text;
}

int main() {
    std::string s = "Hello world";
    print_first_word(s); // OK: s túléli a hívást
    print_first_word("literal"); // OK: string literal statikus élettartamú
    // string_view helyi használata:
    std::string_view sv = s;
    std::cout << sv.substr(0, 5); // OK, sv a main scope-ban él
}

A std::span és std::mdspan esetében ugyanez a logika: a view-t általában függvényparaméterként adjuk át, vagy ha helyben hozzuk létre, ügyelünk arra, hogy a mögöttes adat élettartama lefedje a view használatát.

17.2.6 Gyakorlati minták

17.2.6.1 Függvények általánosítása std::span-nel

A std::span lehetővé teszi, hogy egy függvény egységesen kezeljen különböző folytonos tárolókat anélkül, hogy sablonokra vagy túlterhelésekre lenne szükség. Például egy átlagoló vagy összegző függvény:

#include <span>
#include <numeric>
#include <iostream>
#include <vector>
#include <array>

double sum(std::span<const double> data) {
    return std::accumulate(data.begin(), data.end(), 0.0);
}

int main() {
    std::vector<double> v = {1.0, 2.0, 3.0};
    std::array<double, 3> a = {4.0, 5.0, 6.0};
    double c_arr[] = {7.0, 8.0};

    std::cout << sum(v) << '\n';
    std::cout << sum(a) << '\n';
    std::cout << sum(c_arr) << '\n';
}

17.2.6.2 Alnézetek készítése

A std::span::subspan, first, last és a std::string_view::substr O(1)O(1) műveletek, amelyek új nézetet adnak anélkül, hogy másolnák az adatot. Ez hasznos, ha egy nagyobb puffer egy részét szeretnénk feldolgozni.

#include <span>
#include <vector>
#include <iostream>

void process_chunk(std::span<int> chunk) {
    for (int& x : chunk) x *= 2;
}

int main() {
    std::vector<int> v = {1, 2, 3, 4, 5, 6};
    auto first_half = std::span<int>(v).first(3);
    process_chunk(first_half); // v: {2, 4, 6, 4, 5, 6}
}

17.2.6.3 std::mdspan mátrixműveletekhez

A std::mdspan különösen hasznos numerikus kódokban, ahol a mátrixok folytonos tömbben tárolódnak, de logikailag 2D vagy magasabb dimenziójúak. A nézet segítségével elkerülhető a kézi indexelés vagy a drága másolás.

#include <mdspan>
#include <vector>
#include <iostream>

void print_matrix(std::mdspan<const int, std::dextents<int, 2>> mat) {
    for (size_t i = 0; i < mat.extent(0); ++i) {
        for (size_t j = 0; j < mat.extent(1); ++j) {
            std::cout << mat[i, j] << ' ';
        }
        std::cout << '\n';
    }
}

int main() {
    std::vector<int> data = {1, 2, 3, 4, 5, 6};
    std::mdspan<const int, std::dextents<int, 2>> mat(data.data(), 2, 3);
    print_matrix(mat);
}

17.2.7 Tipikus hibák és elkerülésük

17.2.7.1 Dangling view

Ahogy fentebb láttuk, a leggyakoribb hiba a view élettartamának túlnyújtása a mögöttes objektum élettartamán. Ezt statikus elemzők és szanitizerek (például AddressSanitizer) segíthetnek felderíteni, de a legjobb védekezés a fegyelmezett kód: soha ne adjunk vissza view-t függvényből, hacsak nem garantált, hogy a mögöttes adat is elérhető marad.

17.2.7.2 std::string_view és std::string összekeverése

A std::string_view nem konvertálódik implicit módon std::string-gé, mert ez másolással járna. Ha szükség van std::string-re, explicit konstrukciót kell használni:

std::string_view sv = "hello";
std::string s = std::string(sv); // OK, explicit másolás

Fordítva, a std::string implicit konvertálódik std::string_view-vá, ami kényelmes, de az előbb említett élettartam-problémához vezethet, ha az átadott std::string ideiglenes.

17.2.7.3 std::span és konténer módosítása

A std::span nem követi a mögöttes konténer változásait. Ha egy std::vector-ból hozunk létre spant, majd a vektort módosítjuk olyan módon, amely újraallokálja a memóriát (pl. push_back kapacitás túllépésekor), a span érvénytelenné válik.

std::vector<int> v = {1, 2, 3};
std::span<int> sp(v);
v.push_back(4); // lehetséges újraallokáció -> sp lógó
sp[0] = 10;     // HIBA: undefined behavior

17.2.7.4 std::mdspan inicializálása nem folytonos adatra

A std::mdspan alapértelmezésben folytonos memóriát feltételez. Ha a data() pointer nem egy folytonos blokkra mutat, a viselkedés nem definiált. Csak folytonos tárolókból (pl. std::vector, std::array, nyers tömb) hozzunk létre mdspan-t.

17.2.7.5 std::mdspan és a operator[] használata C++23 előtt

A std::mdspan operator[] több argumentummal csak C++23-ban elérhető. Korábbi szabványban a operator() használata volt jellemző. A C++23-as szintaxis mat[i, j] használata esetén a fordítónak támogatnia kell a C++23-at és a megfelelő nyelvi képességet (többdimenzionális subscript). Ha a cél C++20, akkor mat(i, j) formát kell használni, de ez nem szabványos a std::mdspan esetén, mert az mdspan C++23-as. Ezért a std::mdspan használatakor mindig C++23-as módban kell fordítani.

17.2.8 Labor: string_view és span teljesítmény-összehasonlítás

A labor célja, hogy gyakorlatban mérje a nem birtokló nézetek előnyét a másolással szemben, és reprodukálható módon dokumentálja az eredményeket. A feladat egy egyszerű szövegfeldolgozó függvény és egy numerikus feldolgozó függvény megvalósítása, majd futásidő-mérés.

Követelmények

  • Fordító: GCC 13.2, Clang 17 vagy MSVC 19.38 (választható, de rögzíteni kell).
  • Szabványverzió: C++20 (a std::span miatt; std::mdspan nem szerepel ebben a laborban).
  • Optimalizáció: -O2 (release mód).
  • Build rendszer: CMake vagy közvetlen g++ parancs.
  • Tesztkörnyezet: izolált konténer vagy virtuális gép, a mérési eredményeket naplófájlba kell írni.

Megvalósítandó kód

#include <string_view>
#include <span>
#include <vector>
#include <string>
#include <chrono>
#include <iostream>
#include <numeric>
#include <cassert>

// 1. Függvény string_view paraméterrel
std::string_view first_token(std::string_view sv) {
    auto pos = sv.find(' ');
    if (pos == std::string_view::npos) return sv;
    return sv.substr(0, pos);
}

// 2. Függvény span paraméterrel
int sum_span(std::span<const int> values) {
    return std::accumulate(values.begin(), values.end(), 0);
}

// Összehasonlító függvény, amely másolással dolgozik
std::string first_token_copy(const std::string& s) {
    auto pos = s.find(' ');
    if (pos == std::string::npos) return s;
    return s.substr(0, pos); // másolatot készít
}

int sum_vector_copy(const std::vector<int>& v) {
    return std::accumulate(v.begin(), v.end(), 0); // nincs másolás, de a paraméter vektorra korlátoz
}

int main() {
    constexpr int N = 1000000;
    std::string text = "Hello world, this is a test string with some words to process.";
    std::vector<int> numbers(N);
    std::iota(numbers.begin(), numbers.end(), 1);

    // Melegítés
    volatile auto warm1 = first_token(text);
    volatile auto warm2 = sum_span(numbers);
    (void)warm1; (void)warm2;

    // Mérés: string_view vs string másolás
    auto start = std::chrono::high_resolution_clock::now();
    for (int i = 0; i < 10000; ++i) {
        auto token = first_token(text);
        if (token.empty()) return 1;
    }
    auto end = std::chrono::high_resolution_clock::now();
    double time_sv = std::chrono::duration<double, std::micro>(end - start).count();

    start = std::chrono::high_resolution_clock::now();
    for (int i = 0; i < 10000; ++i) {
        auto token = first_token_copy(text);
        if (token.empty()) return 1;
    }
    end = std::chrono::high_resolution_clock::now();
    double time_copy = std::chrono::duration<double, std::micro>(end - start).count();

    // Mérés: span vs vector const ref
    start = std::chrono::high_resolution_clock::now();
    for (int i = 0; i < 1000; ++i) {
        int s = sum_span(numbers);
        if (s == 0) return 2;
    }
    end = std::chrono::high_resolution_clock::now();
    double time_span = std::chrono::duration<double, std::micro>(end - start).count();

    start = std::chrono::high_resolution_clock::now();
    for (int i = 0; i < 1000; ++i) {
        int s = sum_vector_copy(numbers);
        if (s == 0) return 2;
    }
    end = std::chrono::high_resolution_clock::now();
    double time_vec = std::chrono::duration<double, std::micro>(end - start).count();

    std::cout << "string_view: " << time_sv << " us\n";
    std::cout << "string copy: " << time_copy << " us\n";
    std::cout << "span:        " << time_span << " us\n";
    std::cout << "vector ref:  " << time_vec << " us\n";

    return 0;
}

Várt eredmény

A string_view-t használó verzió várhatóan gyorsabb, mint a másoló verzió, mivel elkerüli a heap-allokációt és a stringmásolást. A span és a const std::vector<int>& paraméterű verzió teljesítménye közel azonos, mivel mindkettő csak iterátorokat használ, de a span általánosabb interfészt ad. A mérési eredményeket a naplóban rögzíteni kell, és a várt eredménytől való eltérés esetén elemezni kell az okokat (pl. optimalizáló viselkedése, cache-hatások).

Teszteset

A laborhoz tartozik egy egyszerű teszt is:

#include <cassert>
#include <string>
#include <string_view>
#include <span>

void test_views() {
    std::string s = "Hello world";
    std::string_view sv = s;
    assert(sv.substr(0, 5) == "Hello");
    assert(sv.size() == 11);

    int arr[] = {1, 2, 3, 4};
    std::span<int> sp(arr);
    assert(sp.size() == 4);
    assert(sp[2] == 3);

    // Élettartam-teszt: a view ne élje túl a forrást
    // (nem fordítható, csak szemléltetés)
    // std::string_view bad = []() -> std::string_view {
    //     std::string local = "temp";
    //     return local;
    // }();
}

int main() {
    test_views();
    return 0;
}

A tesztet a build részeként le kell futtatni, és az eredményt a naplóba kell írni.

17.2.9 Önellenőrző kérdés

Tekintsük a következő kódot:

std::string_view create_view() {
    std::string s = "Hello";
    return s;
}

void use_view() {
    std::string_view sv = create_view();
    std::cout << sv; // Mi történik?
}

Magyarázza meg, mi a probléma a fenti kóddal, és hogyan lehetne helyesen megoldani úgy, hogy a hívó továbbra is std::string_view-t kapjon? (Tipp: a megoldás az, hogy a tulajdonost is vissza kell adni, vagy a view-t nem szabad visszaadni.)

A válasz elvárt elemei:

  • A create_view függvényben a s lokális std::string a függvény visszatérésekor megsemmisül, így a visszaadott std::string_view egy érvénytelen memóriaterületre mutat.
  • A use_view függvényben a sv használata undefined behavior.
  • Helyes megoldás: a create_view térjen vissza std::string-gel, és a hívó oldalon hozzunk létre std::string_view-t, vagy a create_view fogadjon el egy kimeneti paramétert, amelyben a tulajdonost tárolja.

17.2.10 Összefoglalás

A std::string_view, std::span és std::mdspan a nem birtokló nézetek három szintjét képviselik. Közös előnyük a másolásmentesség és a rugalmas interfész, de mindegyikük használata megköveteli az élettartam-szabályok szigorú betartását. A következő fejezet (17.3) ezekre az alapokra építve a tulajdonló tárolók (std::vector, std::array, std::deque, flat konténerek) haladó használatát tárgyalja, ahol a nézetek és a tárolók közötti egyensúly kulcsszerepet kap. A laborban bemutatott mérési módszertan pedig előkészíti a későbbi teljesítményelemzési fejezeteket.
