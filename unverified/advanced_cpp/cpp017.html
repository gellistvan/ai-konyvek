5.4 C++20/23 kényelmi eszközök: format, span, expected, source_location

A C++20 és C++23 kényelmi eszközei közül négy olyan komponenst vizsgálunk, amelyek a mindennapi kódban közvetlenül csökkentik a hibalehetőséget és növelik a kifejezőerőt: std::format, std::span, std::expected és std::source_location. Mindegyik egy-egy klasszikus C++ fájdalompontra ad típusbiztos, a nyelv szemantikájába illeszkedő választ. A std::format a printf-család és a lassú, nehézkes iostream formázás alternatívája; a std::span a pointer+hossz párosok biztonságos, nem birtokló nézete; az std::expected a kivételek és hibakódok közötti értékalapú hibakezelés eszköze; a std::source_location pedig a __FILE__/__LINE__ makrók típusos, hordozható leváltása. A fejezet célja, hogy ezeket az eszközöket ne csak szintaktikailag, hanem a mögöttes tervezési döntésekkel együtt értse meg az olvasó, és felismerje a tipikus hibákat.

5.4.1 std::format – típusbiztos, fordítási időben ellenőrzött formázás

A C++20-ban bevezetett std::format a formázási igényekre ad modern, biztonságos választ. A hagyományos printf család vararg jellege miatt nem tud típusellenőrzést végezni: egy rossz formátumsztring vagy nem illeszkedő argumentum futási idejű hibát, esetleg undefined behavior-t okozhat. Az std::format ezzel szemben a formátumsztringet fordítási időben ellenőrzi, ha az állandó kifejezés, és a megfelelő argumentumtípusokat a std::formatter specializációkon keresztül kezeli.

A legalapvetőbb használat:

#include <format>
#include <iostream>

int main() {
    int answer = 42;
    double pi = 3.14159265358979;
    std::string msg = std::format("answer = {}, pi = {:.3f}", answer, pi);
    std::cout << msg << '\n';
}

A formátumsztring szintaxisa a Python str.format-jához hasonló, és a {} helyettesítő mezők tartalmazzák az argumentumindexet, a kitöltést, az igazítást, a szélességet, a pontosságot és a típuskonverziót. Például:

  • {} – automatikus következő argumentum;
  • {1} – explicit indexelés;
  • {:*>10} – jobbra igazítás * kitöltéssel, legalább 10 karakter szélességben;
  • {:.3f} – három tizedesjegyű lebegőpontos formázás;
  • {:x} – hexadecimális egész.

A std::format első argumentuma egy std::format_string<Args...> típusú objektum. Ennek konstruktora consteval, tehát a formátumsztringnek fordítási időben ismertnek kell lennie, és a fordító az argumentumok típusa alapján ellenőrzi a helyettesítő mezők számát, sorrendjét és típuskompatibilitását. Az alábbi példa fordítási hibát eredményez:

std::string s = std::format("{} {}", 42); // hibás: hiányzik a második argumentum

Futásidejű, dinamikusan előállított formátumsztring esetén a std::vformat használható, de ekkor az ellenőrzés futási időben történik, és hibás formátum esetén std::format_error kivétel dobódik:

#include <format>
#include <string>

std::string dynamic_format(const std::string& fmt, int value) {
    return std::vformat(fmt, std::make_format_args(value));
}

A std::format a std::formatter sablon specializációin keresztül testreszabható saját típusokra is, ami a sablonos gondolkodásmódhoz kapcsolódik, és a későbbi fejezetekben részletesen foglalkozunk vele. A formázás nem lokalizált; ha nyelvi beállítások szerinti megjelenítésre van szükség, a std::format önmagában nem elegendő.

A std::format előnyei a printf-fel szemben:

  • Típusbiztosság: a fordító ellenőrzi az argumentumok és a formátumsztring illeszkedését.
  • Biztonság: nincs vararg, nincs buffer-túlcsordulás.
  • Kiterjeszthetőség: saját formatter specializációval új típusok formázhatók.
  • Olvashatóság: a formátumsztringek közelebb állnak a modern nyelvekhez.
  • Teljesítmény: a std::format tervezése a hatékonyságot szem előtt tartva történt, bár a tényleges méréshez mindig konkrét környezet szükséges.

5.4.2 std::span – nem birtokló, biztonságos nézet

A C++20 std::span osztálysablon egy nem birtokló nézet egy összefüggő elemekből álló sorozatra. Célja, hogy a függvényparamétereknél a pointer + length párosokat egyetlen, önleíró objektummal váltsa ki, amely megőrzi a méretinformációt, és a range-alapú for ciklusokkal, valamint a standard algoritmusokkal is jól együttműködik.

A span legfontosabb tulajdonságai:

  • Nem birtokol: nem foglal memóriát, és nem szabadít fel; a mögöttes adat élettartamát a hívónak kell biztosítania.
  • Kétféle extent: a dinamikus extent std::dynamic_extent (a méret futási időben változhat), vagy egy rögzített méret, például std::span<int, 3>.
  • Implicit konstruktorok: C stílusú tömbből, std::array-ből, std::vector-ból és más span-ből is létrehozható.
  • Alnézetek: a first, last és subspan tagfüggvényekkel a nézet részei érhetők el.

Példa:

#include <span>
#include <vector>
#include <iostream>

void print(std::span<const int> data) {
    for (int value : data) {
        std::cout << value << ' ';
    }
    std::cout << '\n';
}

int main() {
    int c_array[] = {1, 2, 3, 4};
    std::vector<int> vec = {5, 6, 7};
    std::array<int, 3> arr = {8, 9, 10};

    print(c_array); // implicit konverzió
    print(vec);
    print(arr);

    std::span<int, 3> fixed = arr; // rögzített méret
    // fixed = c_array; // fordítási hiba: a C tömb mérete nem 3
}

A rögzített extent esetén a méret a típus része, ami lehetővé teszi a fordító számára a méretellenőrzést és bizonyos optimalizációkat. A span range-ként viselkedik: rendelkezik begin(), end(), size(), empty() tagfüggvényekkel, és a C++20 range-koncepcióinak is megfelel, így a std::ranges algoritmusai közvetlenül alkalmazhatók rá.

A span használatakor különös figyelmet kell fordítani az élettartamra. Mivel a span nem birtokol, a mögöttes adat megszűnése után a span lógóvá válik, és a hozzáférés undefined behavior. Tipikus hiba:

std::span<int> bad() {
    std::vector<int> v{1, 2, 3};
    return std::span<int>{v}; // lógó span: v megsemmisül a függvény végén
}

A span a std::string_view-hez hasonló szerepet tölt be, de tetszőleges elemtípusra, nem csak karakterekre. A C++23 std::mdspan pedig többdimenziós nézetet ad, amely a numerikus számításoknál hasznos; ezzel a fejezet nem foglalkozik részletesen.

5.4.3 std::expected – értékalapú hibakezelés

A C++23-ban szabványosított std::expected<T, E> egy olyan osztálysablon, amely egy várt T értéket vagy egy E típusú hibát tárol. Célja, hogy a hibakezelést visszatérési értékként, kivételek nélkül lehessen kifejezni, megtartva a típusbiztonságot és a kompozíciós lehetőségeket. A std::optional<T>-hez képest a különbség, hogy nem csak az érték hiányát jelzi, hanem a hiba okát is magával hordozza.

Alapvető használat:

#include <expected>
#include <system_error>
#include <string>

std::expected<int, std::error_code> parse_int(const std::string& text) {
    if (text.empty()) {
        return std::unexpected{std::make_error_code(std::errc::invalid_argument)};
    }
    // ... értelmezési logika ...
    return 42;
}

int main() {
    auto result = parse_int("");
    if (result) {
        // siker: *result vagy result.value()
    } else {
        // hiba: result.error()
    }
}

A std::expected legfontosabb műveletei:

  • has_value() – igaz, ha értéket tárol;
  • operator bool() – ugyanaz, mint has_value();
  • value() – visszaadja az értéket, vagy ha hiba van, std::bad_expected_access<E> kivételt dob;
  • error() – visszaadja a hibát (csak akkor hívható, ha hiba van);
  • value_or(default_value) – értéket ad, vagy hiba esetén a megadott alapértelmezést;
  • operator->, operator* – közvetlen hozzáférés az értékhez.

A C++23 monadikus műveletek is elérhetők, amelyek lehetővé teszik a hibakezelési láncok kifejező felépítését:

std::expected<int, std::error_code> process(const std::string& s) {
    return parse_int(s)
        .and_then([](int value) -> std::expected<int, std::error_code> {
            if (value < 0) {
                return std::unexpected{std::make_error_code(std::errc::invalid_argument)};
            }
            return value * 2;
        })
        .transform([](int value) {
            return value + 1;
        });
}

Itt az and_then egy olyan függvényt vár, amely std::expected-et ad vissza, és csak akkor hívódik meg, ha az előző fázis sikeres volt. A transform pedig az értéket alakítja át, hibát változatlanul hagyva. Az or_else a hibaágon hajt végre műveletet, a transform_error pedig a hibát alakítja át.

A std::expected számos előnnyel bír a kivételekkel szemben bizonyos környezetekben:

  • Kivételmentes kód: beágyazott vagy valós idejű rendszerekben, ahol a kivételek tiltottak vagy költségesek.
  • Explicit hibakezelés: a hívó kénytelen tudomást venni a hibáról, mert a visszatérési típus jelzi.
  • Költség: a sikeres útban nincs stack unwinding, a hiba tárolása gyakran olcsóbb, mint egy kivétel eldobása.
  • Kompozíció: a monadikus műveletek tömör, olvasható hibakezelési láncokat tesznek lehetővé.

Ugyanakkor az expected nem helyettesíti a kivételeket minden helyzetben: mélyen beágyazott hívásoknál a hibák kézi továbbítása fárasztó lehet, és a kivételek által nyújtott automatikus stack unwinding hiányzik. A választás mindig a projekt kontextusától függ.

A std::expected<void, E> specializáció is létezik, amely csak a siker tényét vagy a hibát tárolja. Ez olyan függvényeknél hasznos, amelyeknek nincs értékük, de hibát jelezhetnek.

5.4.4 std::source_location – modern forráskód-hely

A std::source_location (C++20) a hagyományos __FILE__, __LINE__, __FUNCTION__ makrók típusos, hordozható alternatívája. Egy osztály, amely a forráskód egy adott pontját írja le, és a current() statikus tagfüggvénye consteval, tehát a hívás helyén a fordító beilleszti a megfelelő adatokat.

A leggyakoribb minta a naplózáshoz használt alapértelmezett paraméter:

#include <source_location>
#include <iostream>
#include <string>

void log(const std::string& message,
         const std::source_location location = std::source_location::current()) {
    std::cout << location.file_name() << ':' << location.line()
              << " (" << location.function_name() << "): "
              << message << '\n';
}

int main() {
    log("Hello, source_location!");
}

A kimenet hasonló:

main.cpp:10 (int main()): Hello, source_location!

A consteval kulcsszó ellenére a hívás nem igényel konstans kiértékelési kontextust; a fordító a hívás helyén azonnal behelyettesíti a forráskód-koordinátákat. A current() tehát a hívás helyét adja meg, nem a definíció helyét, ami a naplózásnál éppen a kívánt viselkedés.

A std::source_location tagfüggvényei:

  • file_name() – a fájl neve (const char*);
  • line() – sor száma (std::uint_least32_t);
  • column() – oszlop száma (std::uint_least32_t);
  • function_name() – a befoglaló függvény neve (const char*).

A makrókhoz képest a std::source_location előnye, hogy típusos, átadható értékként, és nem igényel preprocesszortrükköket. Használható szerződések (contracts) vagy diagnosztikai üzenetek gazdagítására is, és a C++26 reflection irányába mutató egyik első lépés.

5.4.5 Gyakorlati együttes minta

Az alábbi példa a négy eszközt egyetlen kis, ellenőrizhető függvényben ötvözi: a span nem birtokló bemenetet fogad, az expected értékalapú hibát ad vissza, a hibaszöveget a format állítja elő, és a hívás helyét a source_location rögzíti.

#include <expected>
#include <format>
#include <source_location>
#include <span>
#include <string>
#include <vector>

std::expected<double, std::string> average(
    std::span<const double> values,
    const std::source_location loc = std::source_location::current()) {

    if (values.empty()) {
        return std::unexpected{
            std::format("empty span at {}:{}", loc.file_name(), loc.line())
        };
    }

    double sum = 0.0;
    for (double v : values) {
        sum += v;
    }
    return sum / static_cast<double>(values.size());
}

int main() {
    std::vector<double> data{1.0, 2.0, 3.0, 4.0};
    auto result = average(data);
    if (result) {
        // *result használata
    } else {
        // result.error() kezelése
    }
}

Ez a minta jól mutatja, hogy a modern eszközök nem egymást helyettesítik, hanem komplementer módon építhetők egymásra.

5.4.6 Labor – reprodukálható build és teszt

A labor célja, hogy az olvasó saját környezetben kipróbálja a format, span, expected és source_location használatát, és a szerződésnek megfelelően rögzítse a környezetet és az eredményeket.

Feladat: Készíts egy C++23 programot, amely:

  1. Definiál egy parse_numbers függvényt, amely std::span<const int> bemenetet kap, és std::expected<std::vector<int>, std::string> értéket ad vissza. A függvény minden bemeneti elemet ellenőriz: ha bármelyik negatív, hibát ad std::format segítségével, belefoglalva a hívás helyét std::source_location-ból.
  2. A program hívja meg a függvényt egy érvényes és egy hibás bemenettel, és a std::format segítségével írja ki az eredményt.
  3. A program tartalmazzon egy egyszerű tesztesetet: az érvényes bemenetre a várt eredményt assert-tel ellenőrzi.

Buildparancs (egy lehetséges környezet, GCC 13, Linux):

g++ -std=c++23 -Wall -Wextra -Wpedantic -Werror -O2 main.cpp -o lab017

Clang esetén a kapcsoló hasonló, de a -std=c++23 támogatása verziófüggő; MSVC esetén /std:c++latest ajánlott. A példa a GCC 13-at feltételezi; minden más környezetben a támogatást ellenőrizni kell.

Tesztcsomag: Egy test.sh script, amely lefuttatja a programot, és összehasonlítja a kimenetet egy elvárt fájllal, vagy assert-eket használ a programon belül.

Mérési napló (séma):

Környezet Várt eredmény Mért eredmény Megjegyzés
GCC 13.2, -O2, Linux x86-64, standard C++23 Sikeres teszt, kimenet: OK: [1, 2, 3] / Error: ... (a tényleges futtatáskor rögzítendő)
Clang 17, -O2, Linux x86-64 Ugyanaz (rögzítendő) A -std=c++23 elérhetősége ellenőrzendő
Bináris méret (strip-elés nélkül) Várt nagyságrend (mért érték) A format és expected kódméret-hatása

A mérési naplóban a várt és a mért értéket mindig külön kell feltüntetni; a fenti táblázatban a mért oszlopot a tényleges futtatás után kell kitölteni.

5.4.7 Önellenőrző kérdés

Az alábbi kód miért nem fordul le? Milyen módosítással lehetne mégis futásidejű formátumsztringet használni?

#include <format>
#include <string>

std::string make_message(const std::string& format_string, int value) {
    return std::format(format_string, value);
}

Válasz: A std::format első argumentuma std::format_string, amelynek konstruktora consteval, ezért a formátumsztringnek fordítási időben ismertnek kell lennie. Egy futásidejű std::string nem konvertálható format_string-gé. A std::vformat használatával és std::make_format_args segítségével lehet futásidejű formátumsztringet feldolgozni, de ekkor a formátum ellenőrzése futási időben történik, és hibás formátum esetén std::format_error kivétel dobódik.

5.4.8 Továbbvitt eredmények

A következő fejezet (6.1) a sablonok alapjaival foglalkozik. Az itt bevezetett eszközök közül több is sablonos gondolkodást igényel: a std::expected és a std::span osztálysablonok, a std::format a std::formatter specializációkon keresztül bővíthető, a std::source_location::current() pedig a consteval szemantikát példázza. A fejezetben megismert típusbiztos, nem birtokló és értékalapú hibakezelési minták megalapozzák a sablonokkal, kényszerekkel és a generikus programozással kapcsolatos ismereteket.
