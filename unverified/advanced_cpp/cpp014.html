5.1 auto, structured bindings, if constexpr és consteval/constinit

A modern C++ egyik legfontosabb fordulata, hogy a típusok nemcsak explicit deklarációkkal, hanem a fordító által levezetve is megjelenhetnek. A auto, a decltype, a structured binding, az if constexpr, a consteval és a constinit mind ugyanazt a célt szolgálják: a típusinformációt és a vezérlést a lehető legkorábbra, jellemzően fordítási időbe helyezzük, miközben a kód rugalmas marad. A következőkben ezeket az eszközöket nem puszta szintaxisként, hanem a fordító viselkedése, a dedukciós szabályok és a gyakori hibák felől vizsgáljuk.

5.1.1 auto és a típusdedukció

A auto kulcsszó C++11 óta létezik, de a jelentése később finomodott. A legfontosabb szabály: a auto soha nem vezet le referenciát és konstans minősítést, ha azt explicit módon nem kérjük. Az alábbi példa ezt mutatja be:

#include <string>
#include <vector>

void demo_auto() {
    int value = 42;
    const int& cref = value;

    auto a = value;        // int
    auto b = cref;         // int  (a const és a referencia eltűnik)
    auto& c = value;       // int&
    const auto& d = value; // const int&

    auto&& e = value;      // int&  (lvalue-ra dedukál int&-et)
    auto&& f = 42;         // int&& (rvalue-ra dedukál int&&-et)
}

A auto&& kifejezés a perfect forwarding vagy az univerzális referencia alapsémája. Az auto&& sablonkontextusban a kifejezés értékkategóriájától függően lehet lvalue vagy rvalue referencia. Ez a szabály analóg a sablonparaméter T&& dedukciójával.

Külön figyelmet érdemel a kapcsos zárójeles inicializálás: a auto std::initializer_list-et hoz létre, ha a kapcsos lista minden eleme azonos típusú:

auto x = {1, 2, 3};   // std::initializer_list<int>
auto y{1};            // C++17-től: int, korábbi szabványokban ambiguous lehetett

A C++17 óta a közvetlen listainicializálás (auto y{1}) értéktípusú, míg a másolásos (auto y = {1}) továbbra is initializer_list. Ez a különbség gyakori buktató, ezért érdemes a auto mellett mindig egyértelmű zárójelezést használni, vagy explicit típust adni, ha a kifejezés listainicializált.

A auto használható függvény visszatérési típusaként is, de ilyenkor a függvény deklarációja előtt rendelkezésre kell állnia a visszatérési kifejezésnek. A auto visszatérés C++14 óta legalizálja a levezetést, de a levezetés a kifejezés típusát követi a fenti szabályok szerint:

auto make_value() {
    int local = 10;
    return local;          // int
}

auto& make_ref(int& input) {
    return input;          // int&
}

A auto esetében nem jön létre referencia automatikusan, így a make_value egy másolatot ad. Ha referenciát szeretnénk visszaadni, akkor auto& vagy decltype(auto) szükséges.

5.1.2 decltype és a kifejezés–entitás megkülönböztetés

A decltype nem dedukál, hanem a zárójelben lévő kifejezés vagy entitás deklarált típusát adja vissza. A pontos szemantika attól függ, hogy a zárójelben entitás (például változó név) vagy kifejezés áll.

int x = 0;
decltype(x)    y = 1;   // int
decltype((x))  z = x;   // int&  (a zárójelezett x kifejezés lvalue)

A decltype((x)) esetében a zárójelben lévő kifejezés lvalue, ezért a levezetett típus int&. Ez a szabály gyakran okoz lógó referenciát, ha függvény visszatérési típusában használjuk:

decltype(auto) bad_forward(int& x) {
    return (x);   // int&  – rendben van, mert x élettartama a hívónál van
}

decltype(auto) dangling() {
    int local = 5;
    return (local);   // int& – lógó referencia, UB!
}

A bad_forward függvény helyes, mert a visszaadott referencia a hívó által biztosított objektumra mutat. A dangling azonban egy lokális változóra ad referenciát, ami a visszatérés után érvénytelen memóriaterületre mutat. A decltype(auto) használata tehát akkor biztonságos, ha a kifejezés mögött álló entitás élettartama a hívónál biztosított, vagy ha a kifejezés prvalue.

A decltype(auto) a auto-tól eltérően megtartja a cv-minősítést és a referenciát is. Ezért használják gyakran tökéletes továbbítású wrapper függvényekben:

template <typename T>
decltype(auto) forward_value(T&& arg) {
    return std::forward<T>(arg);
}

Itt a visszatérési típus pontosan az lesz, amit a std::forward kifejezés képvisel: lvalue esetén T&, rvalue esetén T&&.

5.1.3 Structured bindings

A C++17-ben bevezetett structured binding lehetővé teszi, hogy egy összetett objektum tagjait egyetlen deklarációban, nevesített változókba bontsuk. A szintaxis:

auto [a, b, c] = expression;

A mechanizmus egy rejtett, névtelen változót hoz létre, majd a jelölt nevek erre a rejtett objektum megfelelő tagjaira hivatkoznak. A auto itt is ugyanazt a dedukciós logikát követi, de a referenciák kezelése kiemelt figyelmet igényel.

#include <tuple>
#include <string>
#include <cassert>

std::tuple<int, std::string> make_tuple() {
    return {7, "hello"};
}

void demo_sb() {
    auto [num, text] = make_tuple(); // int, std::string – másolatok
    num = 10;
    // az eredeti tuple nem változott
}

A fenti esetben a jobb oldali kifejezés prvalue, ezért a rejtett objektum egy std::tuple<int, std::string> érték, és a num, text nevek ennek a másolatnak a tagjaira vonatkoznak. Ha a jobb oldalt referenciaként akarjuk megőrizni, explicit auto& kell:

std::tuple<int, std::string> data{3, "world"};

auto& [n, t] = data;
n = 42;                       // data első eleme is 42 lesz
assert(std::get<0>(data) == 42);

A const auto& változat kiolvasást tesz lehetővé másolás nélkül, de a hivatkozott objektum konstans marad. Az auto&& változat megőrzi az értékkategóriát, ami továbbításhoz hasznos.

A strukturált kötés nem csak std::tuple-re, hanem bármilyen publikus, nem statikus adattaggal rendelkező struct-ra, std::array-re és C-tömbökre is működik:

struct Point {
    int x;
    double y;
};

Point p{5, 2.5};
auto [px, py] = p;    // int, double – másolatok
px = 7;               // p.x nem változik

A rejtett objektum típusa itt a Point másolata, így a px és py nevek a másolat tagjaira mutatnak. Ha az eredeti objektumot akarjuk módosítani, auto& [px, py] = p; szükséges.

Fontos korlátozás: a strukturált kötés nem működik tetszőleges osztállyal, például std::vector-ral, mert annak nincs megfelelő get mechanizmusa. A lebontás a tuple_size és a get függvényekkel vagy a publikus adattagokkal történik.

A bitmezőknél a strukturált kötés másolatot hoz létre, mert bitmezőre nem lehet referencia:

struct BitFields {
    unsigned int a : 3;
    unsigned int b : 5;
};

BitFields bf{2, 9};
auto [ba, bb] = bf;   // int-ek, nem referenciák

A fenti deklaráció érvényes, de a ba és bb független másolatok.

5.1.4 if constexpr: fordítási idejű elágazás

A if constexpr C++17-ben jelent meg, és lehetővé teszi, hogy a fordítási időben ismert feltétel alapján a nem kiválasztott ág ne kerüljön be a példányosításba. Ez különösen sablonokban hasznos, ahol a típusoktól függően más kódot szeretnénk.

#include <type_traits>

template <typename T>
constexpr T abs_generic(T x) {
    if constexpr (std::is_signed_v<T>) {
        return x < 0 ? -x : x;
    } else {
        return x;
    }
}

A abs_generic függvény egyetlen forrásszöveggel kezeli az előjeles és előjel nélküli egészeket. Az if constexpr feltételének fordítási időben eldönthetőnek kell lennie, és a feltételhez kapcsolódó ágak közül csak a kiválasztott példányosul. A nem kiválasztott ág hibás kódot is tartalmazhat, feltéve, hogy a hiba nem szintaktikai, hanem csak szemantikai (például egy nem létező tag hívása):

template <typename T>
std::string describe(const T& obj) {
    if constexpr (std::is_arithmetic_v<T>) {
        return "number";
    } else if constexpr (requires { obj.size(); }) {
        return "container";
    } else {
        return "unknown";
    }
}

A fenti példában a requires kifejezés segítségével a size() meglétét ellenőrizzük. A C++20 requires a C++17 if constexpr-rel együtt is működik, de a if constexpr önmagában is elég a std::is_* típusjellemzőkkel.

A if constexpr másik fontos tulajdonsága, hogy a kiválasztott ág return-je nem feltétlenül zárja le a függvényt; a hibás szerkezeteknél a fordító figyelmeztethet hiányzó return-re, ezért gyakran egy else ágba tett static_assert-tel zárjuk a lehetőségeket:

template <typename T>
constexpr T half(T x) {
    if constexpr (std::is_integral_v<T>) {
        return x / 2;
    } else if constexpr (std::is_floating_point_v<T>) {
        return x * 0.5;
    } else {
        static_assert(!std::is_same_v<T, T>, "Unsupported type");
    }
}

A static_assert(!std::is_same_v<T,T>, ...) a static_assert(false)-hoz hasonlóan mindig hibát ad, de a if constexpr nem példányosítja a nem kiválasztott ágat, így a hiba csak akkor jelentkezik, ha oda kerül a vezérlés. A C++20-ban egyszerűbb a requires vagy a static_assert(!sizeof(T*)) használata, de a lényeg azonos.

A if constexpr nem változtatja meg a függvény aláírását, és nem módosítja a túlterhelési szabályokat. Csupán a függvénytörzsnek egy részét szelektíven hagyja ki a példányosításból.

5.1.5 consteval és constinit: azonnali és statikus inicializáció

A C++20 két új kulcsszót hozott a fordítási idejű értékelés szabályozására: a consteval függvényeket és a constinit változókat.

A consteval deklarációjú függvény csak fordítási időben értékelhető ki. A constexpr-től eltérően nem hívható futásidőben, és a hívás eredménye mindig konstans kifejezés kell legyen.

consteval int square(int x) {
    return x * x;
}

int main() {
    constexpr int a = square(3);   // OK: fordítási idő
    // int b = square(4);          // Hiba: consteval nem hívható futásidőben
    constinit int c = square(5);   // OK: statikus inicializáció
}

A consteval függvényben minden argumentumnak konstans kifejezésnek kell lennie. Ezért a square(4) egy nem-constexpr változó inicializálására nem fordul le, még akkor sem, ha a kifejezés kontextusa egyébként futásidőben is kiértékelhető lenne.

A constinit ezzel szemben változóra vonatkozik. A constinit azt garantálja, hogy a változó inicializálása statikus, azaz fordítási időben vagy a program indulásakor megtörténik, nem pedig dinamikus inicializációval a main előtt. A constinit változó nem lesz automatikusan const, tehát futásidőben módosítható:

consteval int compute_config() {
    return 42;
}

constinit int g_config = compute_config(); // statikus inicializálás

int main() {
    g_config = 10;   // OK: a változó nem konstans
}

A constinit használható static vagy thread_local tárolási időtartamú változókra. A leggyakoribb hiba az, ha a constinit-et const-tal keverik: a constinit nem jelenti a változó konstansságát, csupán az inicializálás idejét rögzíti. A constinit és a constexpr kombinálható is, de a constexpr változó alapértelmezetten is statikus inicializálású.

A consteval és a constinit együttesen segít elkerülni a statikus inicializációs sorrend problémáit (static initialization order fiasco), mert a statikus inicializálás determinisztikus sorrendben, a main előtt végleg lezárul.

5.1.6 Labor: auto- és constexpr-példák elemzése

A labor célja, hogy a fenti eszközöket egyetlen, reprodukálható fordítófutásban vizsgáljuk. Az alábbi cpp014_lab.cpp szemlélteti a dedukciós szabályokat, a structured binding-ot, az if constexpr-t és a consteval/constinit-et. A kód önellenőrző static_assert-ekkel és futásidőbeli assert-tel rendelkezik.

// cpp014_lab.cpp
#include <type_traits>
#include <tuple>
#include <cassert>
#include <string>

consteval int square(int x) {
    return x * x;
}

template <typename T>
constexpr T abs_generic(T x) {
    if constexpr (std::is_signed_v<T>) {
        return x < 0 ? -x : x;
    } else {
        return x;
    }
}

struct Point {
    int x;
    double y;
};

constinit int g_config = square(5);   // statikus inicializáció

int main() {
    // auto: a referenciák és kv-minősítők eltűnnek
    int value = 10;
    const int& cref = value;
    auto a = cref;          // int, nem const int&
    auto& b = value;        // int&
    const auto& c = value;  // const int&
    static_assert(std::is_same_v<decltype(a), int>);
    static_assert(std::is_same_v<decltype(b), int&>);
    static_assert(std::is_same_v<decltype(c), const int&>);

    // structured binding: másolat és referencia viselkedése
    Point p{3, 4.5};
    auto [px, py] = p;      // int, double – másolatok
    auto& [rx, ry] = p;     // int&, double& – referenciák
    rx = 7;
    assert(px == 3);        // a másolat nem változik
    assert(p.x == 7);       // az eredeti igen

    // if constexpr: a megfelelő ág kerül példányosításra
    static_assert(abs_generic(-10) == 10);
    static_assert(abs_generic(20u) == 20u);

    // consteval és constinit
    static_assert(square(6) == 36);
    assert(g_config == 25); // square(5) eredménye
    g_config = 100;         // constinit nem konstans
    assert(g_config == 100);

    return 0;
}

A kód lefordításának és futtatásának ajánlott parancssora GCC-vel, C++20 szabvánnyal:

g++ -std=c++20 -O0 -g -Wall -Wextra -pedantic -Werror cpp014_lab.cpp -o cpp014_lab
./cpp014_lab
echo "exit: $?"

A példa szemléltetés, nem éles rendszeren végrehajtott parancs. A laborban a konkrét környezetben rögzíteni kell a fordítóverziót, az optimalizálási szintet és a standardverziót. Az alábbi táblázat a labor eredményeinek rögzítésére szolgáló mintát mutatja (az értékek illusztrációk):

5.1.7 Összefoglalás és továbbvitt eredmények

A auto és a decltype segítségével a típusdedukció a kifejezések mögött rejlő típusinformációt használja, de a referenciák és a cv-minősítők kezelése tudatos döntést igényel. A decltype((x)) zárójelezési szabálya és a decltype(auto) referenciamegőrző viselkedése gyakori forrása lógó referenciáknak. A structured binding a leképzést rejtett objektumon keresztül végzi, ezért a auto& és const auto& használata nélkül másolatok jönnek létre. Az if constexpr a sablonoknál szelektív fordítási egységet hoz létre, a consteval és a constinit pedig a fordítási idejű kiértékelést és a statikus inicializálást szabályozza.

Ezek az eszközök alapozzák meg a következő fejezetek (cpp015 modulok, cpp016 ranges, cpp017 kényelmi eszközök) hatékony használatát: a modulok interfészén a auto és a structured binding csökkenti a felesleges típusismétlést, a if constexpr a generic kódokban szelektál, a consteval/constinit pedig a fordítási idejű konfigurációkat ellenőrzi.

5.1.8 Önellenőrző kérdés

Adott az alábbi kódrészlet:

int x = 5;
decltype(auto) f() {
    return (x);
}

int main() {
    auto y = f();
    auto& z = f();
}

Milyen típusú y és z? Mi történik, ha a f egy lokális változóra alkalmazná ugyanezt a zárójelezést? Válaszát indokolja a decltype entitás–kifejezés szabálya alapján.

Megoldásvázlat: f visszatérési típusa int&, mert a return (x); kifejezés lvalue, és a decltype(auto) ezt referenciaként őrzi meg. A auto y = f(); esetén a auto nem tart meg referenciát, így y típusa int, értéke az x másolata. A auto& z = f(); esetén z típusa int&, ami x-re hivatkozik. Ha a f egy lokális változóra mutatna referenciát, a visszatérés után lógó referencia keletkezne, ami undefined behavior.
