6.4 Variadic templates és parameter pack

A variadic template-ek és a parameter pack a C++11 óta a nyelv egyik legnagyobb hatású absztrakciós eszköze. Lehetővé teszik, hogy egyetlen sablon tetszőleges számú, eltérő típusú argumentumot fogadjon, miközben a típusbiztonság és a fordítási idejű ellenőrzés teljes mértékben megmarad. A korábbi C stílusú varargs (...) mechanizmussal szemben a parameter pack nem igényel futásidőbeni típuskódolást, nem veszíti el a típusinformációt, és a fordító a hívás helyén mindent ellenőrizni tud. Ez a fejezet a változó számú típusparaméterek kezelését, a parameter pack és a fold expression működését, valamint a rekurzív és iteratív feldolgozási mintákat tárgyalja.

6.4.1 Parameter pack alapfogalmak

A parameter pack (paramétercsomag) egy sablonparaméter, amely nulla vagy több sablonargumentumot reprezentál. Három fő kategóriája van:

  • Típusparaméter-pack: typename... Args vagy class... Args
  • Nem típus paraméter-pack: int... Is, auto... Vs (C++17 óta)
  • Template template paraméter-pack: template<typename...> class... Ts

A csomag a sablonparaméter-listában a ... (ellipszis) szintaxissal jelölhető. Egy függvényparaméter-pack olyan függvényparaméter, amelynek típusa egy típusparaméter-pack: Args... args. A ... itt a pack kiterjesztését (expansion) jelöli, vagyis azt, hogy a kifejezést minden csomagelemre ki kell terjeszteni.

A sizeof...(Args) kifejezés a csomag elemszámát adja meg fordítási időben, std::size_t típusú konstansként. Ez gyakran hasznos a feltételes fordításban vagy a lezárási feltételekben.

Példa egy alapvető sablonra, amely csak megszámolja az argumentumokat:

#include <iostream>

template<typename... Args>
void print_count(Args... args) {
    std::cout << "Number of arguments: " << sizeof...(Args) << '\n';
}

Ez a függvény tetszőleges számú argumentumot fogad, de egyelőre nem dolgozza fel őket. A csomag kiterjesztése nélkül az args paraméter nem használható közvetlenül értékként; ahhoz a ... operátort kell alkalmazni.

A pack expansion általános szabálya: ha egy kifejezésben egy csomag szerepel, és utána ... áll, akkor a kifejezést minden csomagelemre kiterjeszti. Például:

  • args... – az összes argumentum felsorolása
  • &args... – az összes argumentum címe
  • std::forward<Args>(args)... – az összes argumentum tökéletes továbbítása
  • f(args)... – az f függvény meghívása minden argumentumra külön-külön

Fontos megjegyezni, hogy a ... a teljes kifejezésre vonatkozik, nem csak a közvetlenül előtte álló tokenre. Ezért a std::forward<Args>(args)... kifejezés helyes, míg a std::forward<Args...>(args...) hibás, mert a std::forward nem vár paramétercsomagot, hanem egyetlen típusparamétert.

Egy másik fontos szabály: ha egy kifejezésben több csomag is szerepel (például típus- és nem típus csomag), akkor azoknak azonos hosszúságúnak kell lenniük, és a kiterjesztés párhuzamosan történik.

6.4.2 Rekurzív pack-feldolgozás

A csomagok feldolgozásának klasszikus módja a rekurzív bontás. A függvény kiveszi az első argumentumot (a „fejet”), feldolgozza, majd a maradék csomagot (a „farkat”) rekurzívan hívja. A rekurzió lezárásához egy üres csomagot fogadó túlterhelésre van szükség.

Klasszikus példa egy típusbiztos print függvény:

#include <iostream>

// Alapeset: üres csomag – a rekurzió lezárása
void print() {
    std::cout << '\n';
}

// Rekurzív eset: fej + farok
template<typename First, typename... Rest>
void print(First first, Rest... rest) {
    std::cout << first;
    if constexpr (sizeof...(Rest) > 0) {
        std::cout << ", ";
    }
    print(rest...);  // rekurzív hívás a maradék csomaggal
}

A print(rest...) kiterjeszti a maradék argumentumokat, és meghívja a megfelelő túlterhelést. Ha a Rest csomag üres, akkor a nem-template print() függvény hívódik, amely lezárja a rekurziót. Az if constexpr (C++17) biztosítja, hogy az utolsó elem után ne írjunk vesszőt.

Hasonló rekurzív minta az összegzés:

template<typename T>
T sum(T value) {
    return value;
}

template<typename First, typename... Rest>
auto sum(First first, Rest... rest) {
    return first + sum(rest...);
}

Ez a változat az utolsó elemnél a nem-template túlterhelést hívja, így nincs szükség üres csomagot kezelő függvényre; azonban ha a hívás üres argumentumlistával történik, fordítási hibát kapunk, mert nincs sum() túlterhelés.

A rekurzív feldolgozás előnye a rugalmasság: bármilyen bonyolult logika megvalósítható, akár típusváltásokkal, akár állapot átadásával. Hátránya, hogy a kód hosszabb, a hibák nehezebben olvashatók, és a fordító rekurziós mélységhatárt érhet el nagyon hosszú argumentumlisták esetén (a tipikus sablonrekurziós limit 900 körül van, de ez implementációfüggő).

6.4.3 Fold expressions (C++17)

A C++17 bevezette a fold expressions-t, amely tömör és olvasható módot ad a csomagok feletti műveletek végrehajtására. A fold expression egy csomag elemeit egy bináris operátorral összekapcsolja, és a kifejezést a megadott irányban kiértékeli. Négy formája van:

  1. Unary left fold: (pack op ...) – kiterjesztés: ((a1 op a2) op a3) op ...
  2. Unary right fold: (... op pack) – kiterjesztés: a1 op (a2 op (a3 op ...))
  3. Binary left fold: (pack op ... op init) – kiterjesztés: (((init op a1) op a2) op a3) op ...
  4. Binary right fold: (init op ... op pack) – kiterjesztés: a1 op (a2 op (a3 op init))

Az operátor a legtöbb bináris operátor lehet: +, -, *, /, %, &&, ||, ,, <<, >>, ==, !=, <, >, stb. A , operátor különösen hasznos mellékhatások egymás utáni végrehajtására.

Példa összegzés folddal:

template<typename... Args>
auto sum(Args... args) {
    return (0 + ... + args);  // binary left fold, üres csomagra is 0
}

Üres csomag esetén az unary fold csak a && (true), || (false) és , (void()) operátorokra érvényes. A + és * operátorokra az unary fold üres csomaggal fordítási hibát (ill-formed) ad, mert ezeknek nincs a szabványban rögzített üres identitásértékük. Ha üres csomagot is kezelni akarunk, binary foldot kell használni kezdeti értékkel, például (0 + ... + args) vagy (1 * ... * args); a -, /, << operátorokra szintén binary fold kell.

A vessző operátoros fold gyakori minta kiíráshoz:

template<typename... Args>
void print(Args... args) {
    ((std::cout << args << ' '), ...);
    std::cout << '\n';
}

Ez a kifejezés balról jobbra végrehajtja a kiírást minden argumentumra. A , operátor garantálja a balról jobbra értékelési sorrendet, így a kiírás sorrendje meghatározott.

Binary fold kezdeti értékkel:

template<typename... Args>
bool all(Args... args) {
    return (true && ... && args);  // binary right fold
}

Itt a true a kezdeti érték, és a kifejezés logikai ÉS-t számol. Üres csomag esetén az eredmény true. A binary fold lehetővé teszi üres csomag kezelését bármely operátorral, mert a kezdeti érték mindig jelen van.

A fold expression segítségével a rekurzió elkerülhető, a kód tömörebb, és a fordítási idő is általában csökken, mert nincs mély sablonrekurzió.

6.4.4 Iteratív (nem rekurzív) pack-feldolgozás

A fold expression mellett más iteratív technikák is léteznek, elsősorban a C++17 előtti kódbázisokban. Az egyik elterjedt trükk az inicializálólista használata:

template<typename... Args>
void print(Args... args) {
    int dummy[] = { (std::cout << args, 0)... };
    (void)dummy;
}

Itt a (std::cout << args, 0)... kifejezés minden argumentumra kiírja az értéket, majd visszaadja 0-t, így az inicializálólista minden eleme 0 lesz. A lista inicializálásának kiértékelési sorrendje C++11 óta balról jobbra biztosított. A dummy tömböt csak a mellékhatásokért hozzuk létre; a (void)dummy elnyomja a nem használt változó figyelmeztetést. Ez a módszer ma már kevésbé ajánlott; a fold expression áttekinthetőbb és hatékonyabb.

Egy másik fontos eszköz a std::index_sequence és a std::apply, amelyek lehetővé teszik, hogy egy csomagot indexeljünk, vagy egy tuple elemeit függvényhívás argumentumává alakítsuk.

#include <tuple>
#include <utility>

template<typename F, typename Tuple, std::size_t... I>
auto apply_impl(F&& f, Tuple&& t, std::index_sequence<I...>) {
    return std::forward<F>(f)(std::get<I>(std::forward<Tuple>(t))...);
}

template<typename F, typename Tuple>
auto apply(F&& f, Tuple&& t) {
    return apply_impl(std::forward<F>(f), std::forward<Tuple>(t),
                      std::make_index_sequence<std::tuple_size_v<std::decay_t<Tuple>>>{});
}

Ez a minta jól mutatja, hogyan lehet egy csomagot (I...) a std::get hívásban kiterjeszteni. A std::index_sequence lebontja a tuple-t, és a std::get<I> hívások a csomag kiterjesztésével párhuzamosan történnek.

A C++20 std::apply már beépített, de a fenti példa a mechanizmust szemlélteti.

A variadic lambda is hasznos: a lambda paraméter-listája lehet auto... args (generic lambda variadic paraméter), amely a lambda belsejében parameter pack-ként kezelhető.

auto print_all = [](auto... args) {
    ((std::cout << args << ' '), ...);
};

6.4.5 Parameter pack típusok és class template-ek

A parameter pack nem csak függvényeknél, hanem osztálysablonoknál is használható. Például:

template<typename... Ts>
struct Tuple {};

A csomagot a bázisosztály-listában is kiterjeszthetjük:

template<typename... Ts>
class MyClass : Ts... {
public:
    using Ts::foo...;  // C++17 variadic using-declaration
};

Ez a minta gyakori a mixin-alapú tervezésben, ahol több funkcionalitást kombinálunk. A using Ts::foo... az összes bázisosztály foo tagfüggvényét láthatóvá teszi a derived osztályban. A variadic using-declaration C++17 óta érhető el.

6.4.6 Perfect forwarding és parameter pack

A variadic template-ek egyik leggyakoribb alkalmazása a perfect forwarding. A cél, hogy egy gyártófüggvény (factory) a paramétereit változtatás nélkül, érték- és hivatkozástípusuk megtartásával adja át egy másik függvénynek.

#include <memory>
#include <utility>

template<typename T, typename... Args>
std::unique_ptr<T> make_unique(Args&&... args) {
    return std::unique_ptr<T>(new T(std::forward<Args>(args)...));
}

Itt az Args&& forwarding reference (mivel sablonparaméter), a std::forward<Args>(args)... pedig a csomagot elemenként tökéletesen továbbítja. Fontos, hogy a ... a std::forward kifejezés után áll, nem a típusparaméter után.

A perfect forwarding a referencia-kollapszálási szabályokra épül: ha az Args egy lvalue referencia, akkor az Args&& lvalue referenciává kollapszál; ha rvalue, akkor rvalue marad. A std::forward a megfelelő értékkategóriát állítja vissza.

6.4.7 Tipikus hibák és csapdák

  1. Hiányzó lezáró rekurzió: ha a rekurzív feldolgozásnál nincs üres csomagot kezelő túlterhelés, a fordítás végtelen rekurzióba vagy hibába torkollik. A if constexpr segíthet a lezárásban egyetlen függvényben is, de a rekurzív hívásnál szükség lehet az üres esetre.

  2. Üres pack fold expression-nél: unáris fold használatakor az operátortól függ, hogy van-e alapértelmezett érték. Ha nincs, fordítási hibát kapunk. Például (args - ...) üres csomag esetén hibás. Megoldás: binary fold kezdeti értékkel, vagy rekurzív lezárás.

  3. A ... helytelen elhelyezése: std::forward<Args...>(args...) hibás, mert a std::forward egy típusparamétert vár, nem packot. Helyes: std::forward<Args>(args)....

  4. Túl mély rekurzió: nagyszámú argumentum (több száz) esetén a rekurzív feldolgozás a fordító template rekurziós mélységkorlátját (általában 900 körül) túllépheti. Fold expression-öknél nincs ilyen korlát, mert a kiterjesztés síkban történik.

  5. Dedukciós problémák: ha a sablonparamétereket nem lehet egyértelműen levezetni, pl. template<typename... Args> void f(Args... args, int x) hibás, mert a paraméterpack nem lehet nem utolsó a paraméterlistában (kivéve, ha default argumentumok vannak). A csomagnak mindig a paraméterlista végén kell lennie.

  6. Sorrendi garanciák: a fold expression és az inicializálólista esetén a kiértékelési sorrend balról jobbra biztosított, de más kontextusban (pl. függvényargumentumok) a sorrend nem meghatározott. Ha a mellékhatások sorrendje fontos, explicit sorrendet kell biztosítani.

  7. Értékkategória elvesztése: ha a forwarding reference-eket nem std::forward-dal adjuk tovább, hanem érték szerint, akkor felesleges másolások történhetnek, és a move szemantika elvész. Mindig std::forward<Args>(args)...-et használjunk.

6.4.8 Labor: variadic printf-szerű wrapper

A labor célja, hogy a tanult eszközökkel egy típusbiztos, printf-szerű függvényt implementáljunk. A feladat egy safe_format függvény megírása, amely egy formátumsztringet és tetszőleges számú argumentumot fogad, és egy std::string-et ad vissza a formázott szöveggel. A függvény a C++20 std::format szolgáltatásait használja, de a lényeg a parameter pack kezelése és a perfect forwarding.

Specifikáció:

  • Függvény szignatúra: template<typename... Args> std::string safe_format(std::string_view fmt, Args&&... args).
  • A formátumsztring std::format szintaxisú (pl. "Hello, {}!").
  • A függvény std::vformat-ot hív, mert a formátumsztring futásidőben érkezik, így nem használható a consteval std::format (amely fordítási időben ellenőriz). A std::vformat ugyanazt a formázást végzi, de a formátumsztringet futásidőben dolgozza fel.
  • A függvény kivételbiztos: ha a formátumsztring érvénytelen, std::format_error kivételt dob, amit a hívó kezelhet.
  • A paramétereket a safe_format belsejében std::make_format_args kapja meg. A make_format_args C++20/23-ban Args&... lvalue referenciákat vár, ezért itt szándékosan nem használunk std::forward-t: a paramétercsomag elemei a függvényen belül névvel ellátott lvalue-k, amelyek élettartama a vformat hívás végéig tart, így biztonságosan hivatkozhatók.
  • A függvény a std::vformat-ot a <format> fejlécből használja (C++20).

Lehetséges implementáció (vázlat):

#include <format>
#include <string>
#include <string_view>
#include <utility>

template<typename... Args>
std::string safe_format(std::string_view fmt, Args&&... args) {
    return std::vformat(fmt, std::make_format_args(args...));
}

Itt a std::make_format_args egy variadic függvény, amely a std::basic_format_args típust állítja elő a std::vformat számára. A std::make_format_args a paramétereket lvalue referenciaként veszi át, és csak a formázás idejére hivatkozik rájuk; ezért az args... közvetlen átadása a helyes, a std::forward itt rontaná ahelyett, hogy javítana.

Fontos: a std::make_format_args C++20-ban a <format> fejléc része, és a std::vformat a <format>-ban van. A std::basic_format_args a formázási argumentumokat típusbiztosan tárolja, de nem birtokolja azokat: a hivatkozott objektumoknak a vformat hívás teljes ideje alatt életben kell maradniuk. A safe_format paraméterei ezt garantálják, mert a függvény futása alatt élnek.

Build és tesztelés:

A laborhoz használjunk CMake-et és egy tesztkeretrendszert (például doctest). A build parancs:

cmake -B build -DCMAKE_CXX_STANDARD=20 -DCMAKE_CXX_COMPILER=g++-13
cmake --build build
ctest --test-dir build

Fordítási kapcsolók: -Wall -Wextra -Wpedantic -Wconversion -Wshadow -Werror.

A tesztesetek: - Alap formázás: safe_format("Hello, {}!", "World") várt: "Hello, World!". - Több argumentum: safe_format("{} + {} = {}", 2, 3, 5) várt: "2 + 3 = 5". - Üres argumentumlista: safe_format("No args") várt: "No args". - Hivatkozás átadása: egy std::string változó, majd a safe_format("{}", str) ne másoljon? Ezt nehéz mérni, de a std::make_format_args az lvalue-t referenciaként tárolja, és a std::string-et a formázás során std::string_view-ként kezeli. A tesztben ellenőrizhetjük, hogy a string tartalma helyes. - Érvénytelen formátum: safe_format("{} {}", "onlyone") várt: std::format_error kivétel.

Ellenőrzés:

A labor elvégzése után a tanuló futtassa a tesztcsomagot, győződjön meg arról, hogy minden teszt sikeres, és a sanitizerek (pl. AddressSanitizer, UndefinedBehaviorSanitizer) nem jeleznek hibát.

6.4.9 Összefoglalás

A variadic template-ek és a parameter pack a modern C++ egyik alappillére. Lehetővé teszik típusbiztos, tetszőleges számú argumentumot feldolgozó függvények és osztályok írását. A feldolgozás két fő módja a rekurzív bontás és a C++17 fold expression, utóbbi ma már az ajánlott. A perfect forwardinggal kombinálva hatékony gyártófüggvényeket és wrapper-eket készíthetünk. A leggyakoribb hibák a rekurzió lezárásának hiánya, az üres csomag kezelése és a ... helytelen elhelyezése.
