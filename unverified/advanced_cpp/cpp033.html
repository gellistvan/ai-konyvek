9.4 Metafunction classes és modern constexpr

9.4.1 Metafunction classes: amikor a típus maga a művelet

A klasszikus template metaprogramming (TMP) egyik alapvető eszköze a metafüggvény: egy olyan sablon, amely típusokat vagy konstansokat képez le típusokra vagy konstansokra. A legegyszerűbb formája a std::integral_constant specializálása, például:

template<typename T>
struct is_pointer : std::false_type {};

template<typename T>
struct is_pointer<T*> : std::true_type {};

Itt az is_pointer<T>::value egy fordítási idejű logikai érték, az is_pointer<T>::type pedig az örökölt std::true_type vagy std::false_type. Ez a minta azonban hamar korlátokba ütközik, ha a metafüggvényt argumentumként akarjuk átadni egy másik metafüggvénynek, vagy ha egy általános algoritmust akarunk paraméterezni vele. A C++ sablonok nem teszik lehetővé, hogy egy metafüggvényt közvetlenül függvényparaméterként adjunk át; a metafüggvényeket típusként kell becsomagolnunk. Erre szolgál a metafüggvény-osztály (metafunction class) fogalma.

9.4.2 A metafüggvény-osztály definíciója

A metafüggvény-osztály egy olyan osztály (vagy struktúra), amely tag sablonként vagy beágyazott típusként hordoz egy metafüggvényt. A legismertebb konvenció szerint egy apply nevű tag sablont definiál:

struct add_pointer {
    template<typename T>
    struct apply {
        using type = T*;
    };
};

Ez a szerkezet lehetővé teszi, hogy az add_pointer típust átadjuk egy olyan metafüggvénynek, amely egy típuslistán végighaladva minden elemre alkalmazza a műveletet. Például egy transform metafüggvény, amely egy típuslista minden elemét átalakítja:

// Típuslista reprezentáció: egyszerű variadikus sablon
template<typename... Ts>
struct type_list {};

// transform metafüggvény
template<typename List, template<typename> class F>
struct transform;

template<template<typename> class F, typename... Ts>
struct transform<type_list<Ts...>, F> {
    using type = type_list<typename F<Ts>::type...>;
};

Itt az F egy sablon template paraméter, amely egyetlen típusparamétert vár, és rendelkezik ::type beágyazott típussal. Ez a klasszikus TMP-stílus, de ha a műveletet metafüggvény-osztályként akarjuk átadni, akkor a transform-ot úgy kell megírni, hogy a F ne sablon template paraméter legyen, hanem egy közönséges típusparaméter, amelynek van egy beágyazott apply sablonja:

template<typename List, typename MetafunctionClass>
struct transform;

template<typename MetafunctionClass, typename... Ts>
struct transform<type_list<Ts...>, MetafunctionClass> {
    using type = type_list<
        typename MetafunctionClass::template apply<Ts>::type...
    >;
};

Itt a MetafunctionClass::template apply<Ts>::type a metafüggvény-osztály műveletének meghívása minden típusra. A template kulcsszó azért szükséges, mert a MetafunctionClass függő név, és a fordító nem tudja, hogy az apply tag sablon-e; a template kulcsszóval jelezzük, hogy a :: után egy sablonnév következik.

A metafüggvény-osztály előnye, hogy a műveletet típusként lehet tárolni, továbbadni, kombinálni, és a metafüggvény-osztályhoz kapcsolódó állapot vagy konfiguráció is tárolható (például egy konstanssal paraméterezett művelet). A hátránya viszont a szintaktikai zaj és a hosszú hibaüzenetek.

9.4.3 Placeholder-ök és a Boost.MPL / Boost.HOF hagyaték

A metafüggvény-osztályok gyakran placeholder-ökkel együtt jelennek meg. A placeholder egy olyan típus, amely egy argumentum helyét jelöli egy kifejezésben. A leghíresebb példa a Boost.MPL-ből származó _1, _2, _3, amelyek a boost::mpl::placeholders névtérben élnek. A Boost.HOF (korábban Fit) könyvtár boost::hof::placeholders::_1 hasonló szerepet tölt be.

A placeholder-ök akkor hasznosak, ha egy metafüggvényt részlegesen alkalmazunk, vagy ha egy összetett kifejezést akarunk felépíteni anélkül, hogy minden lépéshez új típust definiálnánk. Például a Boost.MPL-ben egy transform hívás így nézhet ki:

using result = boost::mpl::transform<
    boost::mpl::vector<int, char, double>,
    boost::mpl::add_pointer<boost::mpl::_1>
>::type;

Itt a boost::mpl::add_pointer<boost::mpl::_1> egy lambda kifejezés a típusok világában: a placeholder _1 jelöli azt a típust, amelyre a transform az aktuális elemet behelyettesíti. A boost::mpl::add_pointer maga is metafüggvény-osztály, amely a _1 placeholder-t várja.

A modern C++-ban ezt a mintát nagyrészt felváltotta a constexpr függvények és a if constexpr használata, de a metafüggvény-osztályok és placeholder-ök továbbra is fontosak, ha típusokon kell műveleteket végezni, nem csak értékeken.

9.4.4 Saját placeholder és metafüggvény-osztály készítése

Tegyük fel, hogy szeretnénk egy olyan metafüggvény-osztályt, amely egy típushoz hozzáadja a const minősítőt, és ezt átadjuk egy transform-nak. A placeholder nélkül így nézne ki:

struct add_const {
    template<typename T>
    struct apply {
        using type = const T;
    };
};

using input = type_list<int, char, double>;
using result = typename transform<input, add_const>::type;
static_assert(std::is_same_v<result, type_list<const int, const char, const double>>);

Ha viszont azt akarjuk, hogy a transform egy olyan műveletet hajtson végre, amely két típust kombinál (például std::pair-t hoz létre), akkor placeholder-ökre van szükség. A Boost.MPL stílusú placeholder-ök lényegében üres struktúrák, amelyeket a metafüggvény-osztályok speciális apply tagjai felismernek. Például a std::pair-t létrehozó metafüggvény-osztály a következőképpen definiálható:

struct make_pair {
    template<typename T1, typename T2>
    struct apply {
        using type = std::pair<T1, T2>;
    };
};

Ha ezt a transform-nak akarjuk átadni, a transform csak egyetlen típust ad át minden apply-nak, így a make_pair nem használható közvetlenül. A placeholder-ök segítségével azonban a transform felismerheti, hogy a metafüggvény-osztály apply tagja több paramétert is elfogadhat, és a placeholder-öket a listából vett típusokkal helyettesítheti. Ennek megvalósítása bonyolult, és a gyakorlatban ritkán éri meg.

A modern C++ sokkal egyszerűbb utat kínál: a constexpr függvényeket és a consteval kulcsszót.

9.4.5 A constexpr átmenet: miért és hogyan?

A C++11 bevezette a constexpr függvényeket, amelyek fordítási időben is kiértékelhetők, de futásidőben is hívhatók. A C++14 lazította a szabályokat: a constexpr függvény teste tartalmazhat ciklusokat, lokális változókat, és nem csak egyetlen return utasítást. A C++17 tovább bővítette a lehetőségeket (például if constexpr), a C++20 pedig bevezette a consteval és a constinit kulcsszavakat, valamint a std::is_constant_evaluated() függvényt.

Ez a fejlődés lehetővé tette, hogy a klasszikus TMP-minták nagy részét sima függvényekkel váltsuk ki. A metafüggvény-osztályok apply sablonjai helyett constexpr függvényeket írunk, amelyek értékeket számítanak ki, a típusok közötti műveleteket pedig if constexpr és decltype segítségével kezeljük. Az eredmény olvashatóbb, könnyebben debuggolható, és gyakran gyorsabban fordul.

9.4.6 Példa: faktoriális régi és új stílusban

Klasszikus TMP rekurzív sablonnal:

template<unsigned N>
struct factorial {
    static constexpr unsigned value = N * factorial<N - 1>::value;
};

template<>
struct factorial<0> {
    static constexpr unsigned value = 1;
};

static_assert(factorial<5>::value == 120);

Modern constexpr függvénnyel:

constexpr unsigned factorial(unsigned n) {
    unsigned result = 1;
    for (unsigned i = 2; i <= n; ++i) {
        result *= i;
    }
    return result;
}

static_assert(factorial(5) == 120);

A második változat ugyanazt a fordítási idejű eredményt adja, de sokkal egyszerűbb, és futásidőben is hívható. A static_assert bizonyítja, hogy a függvény fordítási időben kiértékelődik.

9.4.7 A constexpr függvények szabályai

A constexpr függvény teste C++14-től tartalmazhat:

  • ciklusokat (for, while, do-while),
  • lokális változókat,
  • feltételes utasításokat (if, switch),
  • más constexpr függvények hívásait,
  • return utasításokat.

A C++20 további lazításokat hozott:

  • a constexpr függvényben lehet try blokk (de kivétel nem dobható),
  • a constexpr függvényben lehet virtual függvényhívás, ha az objektum fordítási időben ismert,
  • a constexpr destruktor lehet constexpr, és a std::vector bizonyos műveletei is constexpr-ek lettek.

Fontos: egy constexpr függvény nem garantálja, hogy a hívása fordítási időben történik. Ha a hívást olyan kontextusban használjuk, ahol konstans kifejezés szükséges (pl. sablon paraméter, static_assert, tömbméret), akkor a fordító fordítási időben értékeli ki. Ha futásidőben hívjuk, akkor normál függvényként viselkedik.

9.4.8 A consteval kulcsszó

A consteval (C++20) egy erősebb garanciát ad: a függvény csak fordítási időben hívható. Ha futásidőben próbáljuk hívni, a program nem fordul le. Ez hasznos, ha olyan műveletet akarunk kikényszeríteni, amelynek nincs értelme futásidőben, vagy ha a fordítási idejű kiértékelést szeretnénk garantálni.

consteval unsigned square(unsigned x) {
    return x * x;
}

constexpr unsigned val = square(5); // OK
// unsigned x = square(5); // Hiba: a square konsteval, nem hívható futásidőben

A consteval függvények kiválóan alkalmasak arra, hogy a metafüggvény-osztályok helyett típusból értéket vagy értékből típust állítsunk elő, miközben a fordító ellenőrzi, hogy minden hívás fordítási időben történik.

9.4.9 A if constexpr szerepe

A if constexpr (C++17) egy fordítási idejű feltételes elágazás. A hagyományos if utasítással ellentétben a if constexpr feltétele egy konstans kifejezés kell legyen, és a nem kiválasztott ág nem kerül be a fordítási egységbe (bár a szintaktikai ellenőrzés megtörténik). Ez lehetővé teszi, hogy olyan kódot írjunk, amely különböző típusokra különböző utasításokat hajt végre, anélkül hogy sablon specializációkat vagy SFINAE-t kellene használnunk.

Példa: egy print függvény, amely egész számra és lebegőpontosra másképp viselkedik:

template<typename T>
void print(const T& value) {
    if constexpr (std::is_integral_v<T>) {
        std::cout << "integral: " << value << '\n';
    } else if constexpr (std::is_floating_point_v<T>) {
        std::cout << "floating: " << value << '\n';
    } else {
        std::cout << "other: " << value << '\n';
    }
}

A if constexpr különösen hasznos a metafüggvény-osztályok apply sablonjainak kiváltására, amikor a művelet típusfüggő viselkedést igényel. Például egy get_value függvény, amely egy std::variant-ból kinyeri az értéket, if constexpr-rel választhatja ki a megfelelő típust.

9.4.10 A constexpr és a metafüggvény-osztályok kapcsolata

A metafüggvény-osztályok továbbra is hasznosak, ha típusok közötti leképezést kell paraméterként átadni. Például egy transform algoritmusnak szüksége van arra, hogy egy típusból egy másik típust állítson elő. Ezt constexpr függvénnyel közvetlenül nem tudjuk megtenni, mert a függvények értékekkel dolgoznak, nem típusokkal. Itt a metafüggvény-osztályok és a placeholder-ök továbbra is relevánsak.

Azonban a C++20 std::type_identity, std::type_identity_t és a decltype kombinációja lehetővé teszi, hogy típusleképezéseket constexpr függvényekkel is kifejezzünk, ha a bemenő és kimenő típusokat típusparaméterként (nem értékként) kezeljük. Például:

template<typename T>
constexpr auto add_pointer() {
    return std::type_identity<T*>{};
}

using result_type = typename decltype(add_pointer<int>())::type;
static_assert(std::is_same_v<result_type, int*>);

Itt az add_pointer egy constexpr függvény, amely egy std::type_identity objektumot ad vissza, amely a T* típust hordozza. A decltype segítségével kinyerjük a típust. Ez a minta nem teszi lehetővé, hogy a függvényt közvetlenül átadjuk egy algoritmusnak, mert a függvény neve nem típus. Ahhoz, hogy paraméterként átadhassuk, továbbra is egy osztályba kell csomagolni:

struct add_pointer_mfc {
    template<typename T>
    constexpr auto operator()(std::type_identity<T>) const {
        return std::type_identity<T*>{};
    }
};

Ez a function object (funktor) minta már közelebb áll a modern C++-hoz: egy osztály, amelynek van egy operator() sablonja. Ezt a funktort át lehet adni egy olyan transform-nak, amely a funktort std::type_identity<T> objektummal hívja meg. Ez a megközelítés ötvözi a metafüggvény-osztályok rugalmasságát a constexpr függvények kényelmével.

9.4.11 Labor: metafüggvény átírása constexpr függvényre

Ebben a laborban egy klasszikus metafüggvény-osztályt írunk át modern constexpr függvénnyé, és ellenőrizzük a helyességét, a fordítási időt és a futási viselkedést.

9.4.12 Feladat

Adott egy egyszerű típuslista reprezentáció és egy contains metafüggvény, amely eldönti, hogy egy típus szerepel-e a listában. A klasszikus TMP-megoldás:

#include <type_traits>

template<typename... Ts>
struct type_list {};

template<typename List, typename T>
struct contains;

template<typename T>
struct contains<type_list<>, T> : std::false_type {};

template<typename T, typename... Rest>
struct contains<type_list<T, Rest...>, T> : std::true_type {};

template<typename T, typename U, typename... Rest>
struct contains<type_list<U, Rest...>, T> : contains<type_list<Rest...>, T> {};

Ezt a metafüggvényt kell átírni constexpr függvénnyé, amely a típuslista elemeit std::is_same_v segítségével hasonlítja össze. A cél, hogy a függvény fordítási időben kiértékelhető legyen, és futásidőben is hívható legyen.

9.4.13 Megoldás vázlata

A constexpr függvény nem tud közvetlenül típuslistákkal dolgozni, mert a típuslista típus, nem érték. Ezért a típuslistát típusparaméterként kell átadni, és a benne lévő típusokat if constexpr és std::is_same_v segítségével ellenőrizni.

Egy lehetséges megoldás a variadikus sablon és a fold expression (C++17) használata. A type_list<Ts...> paraméter típusából a Ts... csomag közvetlenül kinyerhető, így nincs szükség rekurzív típusboncolásra:

#include <type_traits>

template<typename T, typename... Ts>
constexpr bool contains(type_list<Ts...>) {
    return (std::is_same_v<T, Ts> || ...);
}

Ez a függvény egy type_list<Ts...> típusú paramétert vár (amely lehet egy üres lista is), és a fold expression az összes elemet ellenőrzi. A függvény constexpr, tehát fordítási időben kiértékelhető.

Használat:

using my_list = type_list<int, double, char>;

static_assert(contains<int>(my_list{}));
static_assert(!contains<float>(my_list{}));

A my_list{} egy érték, de mivel a contains függvény paramétere type_list<Ts...>, a my_list{} érték átadható, és a függvény a típusparamétereket a sablon argumentumából nyeri ki. A függvény teste nem használja a paraméter értékét, csak a típusát.

Ez a megoldás kiváltja a klasszikus contains metafüggvényt, és sokkal egyszerűbb.

9.4.14 A teljes fordítható példa

#include <type_traits>
#include <iostream>
#include <chrono>

template<typename... Ts>
struct type_list {};

// Klasszikus TMP contains (referencia)
template<typename List, typename T>
struct contains_tmp;

template<typename T>
struct contains_tmp<type_list<>, T> : std::false_type {};

template<typename T, typename... Rest>
struct contains_tmp<type_list<T, Rest...>, T> : std::true_type {};

template<typename T, typename U, typename... Rest>
struct contains_tmp<type_list<U, Rest...>, T> : contains_tmp<type_list<Rest...>, T> {};

// Modern constexpr contains
template<typename T, typename... Ts>
constexpr bool contains(type_list<Ts...>) {
    return (std::is_same_v<T, Ts> || ...);
}

int main() {
    using my_list = type_list<int, double, char, long, float, short, unsigned, bool>;

    // Fordítási idejű ellenőrzés
    static_assert(contains<int>(my_list{}));
    static_assert(!contains<std::string>(my_list{}));

    // Összehasonlítás a klasszikus TMP-vel
    static_assert(contains_tmp<my_list, int>::value);
    static_assert(!contains_tmp<my_list, std::string>::value);

    // Futásidejű hívás (bár itt a típus fix, de a függvény hívható)
    bool b1 = contains<int>(my_list{});
    bool b2 = contains<std::string>(my_list{});
    std::cout << "contains<int>: " << b1 << '\n';
    std::cout << "contains<string>: " << b2 << '\n';

    // Mérési pont: futásidő nem mérvadó, mert a függvény üres
    auto start = std::chrono::steady_clock::now();
    for (int i = 0; i < 1'000'000; ++i) {
        volatile bool b = contains<int>(my_list{});
        (void)b;
    }
    auto end = std::chrono::steady_clock::now();
    std::chrono::duration<double> elapsed = end - start;
    std::cout << "1M hivas ideje: " << elapsed.count() << " s\n";
}

Ez a példa bemutatja a régi és az új megoldást, static_assert-ekkel ellenőrzi a helyességet, és egy egyszerű futásidejű mérést is végez.

9.4.15 Build és tesztelés

A kódot C++20-as szabvánnyal, -Wall -Wextra -Wpedantic kapcsolókkal, GCC és Clang alatt is le kell fordítani. A static_assert-ek már fordítási időben ellenőrzik a helyességet, de futtassunk egy tesztet is, amely a futásidejű eredményeket hasonlítja össze a várt értékekkel.

Példa build parancs (GCC):

g++ -std=c++20 -Wall -Wextra -Wpedantic -O2 -o metafunction_lab metafunction_lab.cpp

MSVC esetén:

cl /std:c++20 /W4 /O2 /EHsc metafunction_lab.cpp /Fe:metafunction_lab.exe

A teszteléshez használhatunk egyszerű assert-et vagy egy tesztkeretet, de a static_assert-ek már elegendőek a fordítási idejű helyesség igazolására. A futásidejű teszt:

#include <cassert>
#include <type_traits>

template<typename... Ts>
struct type_list {};

template<typename T, typename... Ts>
constexpr bool contains(type_list<Ts...>) {
    return (std::is_same_v<T, Ts> || ...);
}

int main() {
    using my_list = type_list<int, double, char>;
    assert(contains<int>(my_list{}));
    assert(contains<char>(my_list{}));
    assert(!contains<float>(my_list{}));
}

A mérési napló rögzítse a fordító verzióját, a szabvány szintjét, az optimalizációs szintet, valamint a mért fordítási időt és a bináris méretet a régi és az új megoldásra külön-külön. Ez lehetővé teszi annak demonstrálását, hogy a constexpr függvényes megoldás gyakran gyorsabban fordul és kisebb binárist eredményez, mivel a sablon rekurzió mélysége csökken.

9.4.16 Mérési napló minta

Mérés Régi TMP Új constexpr
Fordítási idő (GCC 13.2, -O2) 0.82 s 0.31 s
Bináris méret (stripped) 23 456 B 22 112 B

A táblázatban a „Régi TMP” futásidő nem értelmezhető, mert a klasszikus contains_tmp csak fordítási időben létezik. Az új megoldás futásidejű költsége minimális, mert a fold expression gyakorlatilag egy üres ciklussá fordul le, vagy teljesen kioptimalizálódik.

9.4.17 Tipikus hibák és elkerülésük

  1. A typename és template kulcsszavak elhagyása függő neveknél.
    Ha egy metafüggvény-osztály apply tagját hívjuk, és a metafüggvény-osztály típusa sablonparaméter, akkor a ::template és typename kulcsszavakat megfelelően kell használni. Például:

    using result = typename MetafunctionClass::template apply<T>::type;

    A typename azt jelzi, hogy a type egy típus, a template pedig, hogy az apply egy sablon.

  2. A constexpr függvényben nem lehet goto, nem lehet static változó inicializálása stb.
    A constexpr függvényekre vonatkozó szabályok szigorúak, de a C++14 óta sokkal rugalmasabbak, mint sokan gondolják. Gyakori hiba, hogy valaki static lokális változót próbál használni, vagy throw-t ír a függvénybe. Ezt a fordító egyértelműen jelzi.

  3. A consteval függvény futásidejű hívásának kísérlete.
    A consteval függvényt nem lehet futásidőben hívni; ha mégis megpróbáljuk, fordítási hiba lesz. Ez szándékos, de néha meglepő, ha egy consteval függvényt egy nem konstans kifejezésben akarunk használni.

  4. A if constexpr feltételének nem konstans kifejezés.
    A if constexpr feltétele csak akkor működik, ha a feltétel fordítási időben kiértékelhető. Ha a feltétel egy futásidejű értéktől függ, a program nem fordul le. Gyakori hiba, hogy valaki if constexpr (x > 0)-t ír, ahol x egy futásidejű változó.

  5. A placeholder-ök félreértése.
    A placeholder-ök (pl. _1) nem varázslatosak; egyszerű üres struktúrák, amelyeket a metafüggvény-osztályok apply sablonjai felismernek és helyettesítenek. Ha saját placeholder-t akarunk definiálni, gondoskodnunk kell arról, hogy a metafüggvény-osztályok megfelelően kezeljék őket, ami sok boilerplate kódot igényel. A modern C++-ban gyakran egyszerűbb elkerülni a placeholder-öket, és explicit constexpr függvényeket használni.

  6. A constexpr függvény nem garantálja a fordítási idejű kiértékelést.
    Ha egy constexpr függvényt futásidőben hívunk, az normál függvényként fut. Ha garantálni akarjuk a fordítási idejű kiértékelést, használjunk consteval-t vagy helyezzük a hívást konstans kifejezést igénylő kontextusba.

  7. A fold expression üres paramétercsomaggal.
    A (std::is_same_v<T, Ts> || ...) egy üres Ts... esetén false értéket ad, mivel az || művelet alapértelmezett értéke false (az && esetén true). Ez a viselkedés szabványos, de meglepő lehet; érdemes tesztelni üres listával is.

9.4.18 Önellenőrző kérdés

Magyarázza el, mi a különbség a constexpr és a consteval függvények között, és adjon példát arra, amikor a consteval használata indokolt. Hogyan segít a if constexpr a metafüggvény-osztályok kiváltásában? Válaszában térjen ki arra, hogy milyen esetekben érdemes mégis metafüggvény-osztályt használni a modern C++-ban.

9.4.19 Összegzés és átvezetés

A metafüggvény-osztályok és a placeholder-ök a C++ template metaprogramming klasszikus eszközei, amelyek lehetővé teszik a műveletek típusként való átadását. A C++14/17/20 constexpr fejlődése azonban lehetővé tette, hogy a metafüggvények nagy részét egyszerű, olvasható függvényekkel váltsuk ki. A consteval garantálja a fordítási idejű kiértékelést, az if constexpr pedig a típusfüggő elágazásokat teszi természetessé. A metafüggvény-osztályok továbbra is relevánsak, ha típusok közötti leképezéseket kell paraméterként átadni, de a modern C++-ban gyakran elegendő a funktor + std::type_identity minta.

A következő alfejezet (10.1) az expression templates témakörét vezeti be, amely a metafüggvény-osztályok és a constexpr függvények ötvözésével hatékony numerikus kifejezéseket épít fel. Az itt megszerzett ismeretek alapozzák meg az expression templates értő használatát.
