16.2 Rendezett range-ek és binary search

A rendezett tartományok a hatékony keresés, a halmazműveletek és a tartományműveletek alapjai. Amikor egy szekvencia rendezett, a lineáris keresésnél aszimptotikusan gyorsabb, logaritmikus bonyolultságú algoritmusok válnak elérhetővé. Ez az alfejezet a rendezést és a rendezett tartományokon működő bináris kereső algoritmusokat tárgyalja, kiemelt figyelmet fordítva a komparátorokra és a szigorú gyenge rendezés (strict weak ordering) követelményére. A cél nem csupán a függvények ismertetése, hanem annak megértetése, hogy mikor és miért használjuk őket, és milyen hibákhoz vezet a helytelen használat.

16.2.1 A rendezett tartomány fogalma

Egy [first, last) tartományt akkor tekintünk rendezettnek egy comp komparátor szerint, ha minden i < j indexpárra a comp(*(first + j), *(first + i)) kifejezés hamis. Ez formálisan azt jelenti, hogy a komparátor által definiált reláció szerint az elemek nem csökkenő sorrendben követik egymást. Az alapértelmezett std::less{} esetén ez a szokásos numerikus vagy lexikografikus növekvő sorrend.

A rendezettség ellenőrzésére a std::is_sorted szolgál, amely logikai értéket ad vissza, a std::is_sorted_until pedig azt az iterátort, ahol a rendezettség először megszakad. C++20-tól a ranges változat std::ranges::is_sorted néven érhető el. Haladó kódban érdemes ezt használni a bináris keresést megelőzően, különösen akkor, ha a tartomány forrása nem garantáltan rendezett.

#include <algorithm>
#include <vector>

void example_is_sorted() {
    std::vector<int> v = {1, 2, 2, 3, 5, 8};
    bool sorted = std::ranges::is_sorted(v); // true
}

Fontos, hogy a rendezettség mindig egy adott komparátorhoz kötött. Egy tartomány lehet rendezett a std::less szerint, de nem rendezett egy egyéni, például case-insensitive string-komparátorral. A bináris keresésnél is pontosan ugyanazt a komparátort kell használni, mint amivel a tartományt rendeztük; ennek figyelmen kívül hagyása gyakori hibaforrás.

16.2.2 Strict weak ordering

A rendező és a bináris kereső algoritmusok komparátora nem lehet akármilyen bool-t visszaadó függvény. A szabvány szigorú gyenge rendezést ír elő, amely a következő tulajdonságokkal rendelkezik:

  • Irreflexivitás: comp(x, x) mindig hamis.
  • Aszimmetria: ha comp(x, y) igaz, akkor comp(y, x) hamis.
  • Tranzitivitás: ha comp(x, y) és comp(y, z) igaz, akkor comp(x, z) is igaz.
  • Az ekvivalencia tranzitivitása: ha sem comp(x, y), sem comp(y, x) nem igaz (vagyis x és y ekvivalens), és ugyanez igaz y és z között, akkor x és z is ekvivalens.

A gyakorlatban a std::less{} és a < operátorral definiált komparátorok teljesítik ezt. A leggyakoribb hiba a <= operátor használata, amely megsérti az irreflexivitást, mert x <= x igaz. Az ilyen komparátort átadva a rendező algoritmusnak undefined behavior (UB) lép fel, ami hibás sorrendet, végtelen ciklust vagy memóriahibát okozhat. A szövegben a hibás példákat mindig UB-ként jelöljük.

// HIBÁS: ne használjuk, UB-t okoz!
struct BadComparator {
    bool operator()(int a, int b) const {
        return a <= b; // irreflexív, nem strict weak ordering
    }
};

Egy másik gyakori hiba a nem tranzitív komparátor, amely például kerekített lebegőpontos értékeket hasonlít össze. A std::sort ilyenkor kiszámíthatatlanul viselkedhet. A megoldás az, hogy a komparátort mindig úgy írjuk meg, hogy az ekvivalencia reláció tranzitív legyen, vagy használjunk olyan típusokat, ahol a rendezés egyértelmű.

16.2.3 Rendező algoritmusok: std::sort és std::stable_sort

A rendezett tartományok előállításának leggyakoribb eszköze a std::sort, amely az [first, last) tartományt a comp komparátor szerint rendezi. A szabvány O(NlogN)O(N \log N) összehasonlítást ír elő átlagosan, a gyakorlati implementációk tipikusan introsortot használnak, amely gyors, de instabil: az ekvivalens elemek relatív sorrendje nem garantált. A std::sort véletlen hozzáférésű iterátort igényel, tehát std::list-en nem működik.

A std::stable_sort ezzel szemben stabil, azaz megőrzi az ekvivalens elemek eredeti relativ sorrendjét. Ennek ára a magasabb erőforrásigény: O(Nlog2N)O(N \log^2 N) összehasonlítás, ha a memória korlátozott, vagy O(NlogN)O(N \log N) elegendő extra memória esetén. Stabil rendezést akkor érdemes választani, ha a rendezés több kulcs szerint történik, és az előző rendezés eredményét meg akarjuk őrizni.

#include <algorithm>
#include <string>
#include <vector>

struct Person {
    std::string name;
    int age;
};

void example_stable_sort() {
    std::vector<Person> people = {
        {"Anna", 30}, {"Béla", 25}, {"Cili", 30}, {"Dénes", 25}
    };

    // Először név szerint rendezünk.
    std::ranges::sort(people, {}, &Person::name);

    // Majd kor szerint stabilan rendezünk.
    std::ranges::stable_sort(people, {}, &Person::age);

    // Az azonos korúak névsorrendje megmarad:
    // (Anna, 30), (Cili, 30), (Béla, 25), (Dénes, 25)
}

A C++20 std::ranges::sort és std::ranges::stable_sort harmadik paraméterként egy projekciót fogad, amelyet az elemre alkalmaz, mielőtt a komparátort meghívná. Az &Person::age tagmutató az életkort választja ki, így a default std::less{} komparátor az életkor szerint rendez. A hagyományos std::sort esetén ezt lambda-komparátorral kellene kifejezni.

16.2.4 Bináris keresés rendezett tartományon

Ha a tartomány rendezett, a keresés logaritmikus időben elvégezhető. A C++ szabvány három alapvető függvényt kínál:

  • std::binary_search(first, last, value) – logikai értéket ad vissza: az elem szerepel-e a tartományban.
  • std::lower_bound(first, last, value) – az első olyan elemre mutató iterátort adja, amely nem kisebb a keresett értéknél.
  • std::upper_bound(first, last, value) – az első olyan elemre mutató iterátort adja, amely nagyobb a keresett értéknél.
  • std::equal_range(first, last, value) – egy std::pair-t ad vissza, amely a lower_bound és upper_bound iterátorpárt tartalmazza.

Mindegyik algoritmus O(logN)O(\log N) összehasonlítást végez, és véletlen hozzáférésű iterátorok esetén a lépésszám is logaritmikus. Forward iterátoroknál a lépésszám O(logN)O(\log N), de a távolságszámítás miatt a teljes futási idő O(N)O(N) lehet, ezért érdemes véletlen hozzáférésű konténert (például std::vector) használni.

A formális előfeltétel a lower_bound és upper_bound esetén nem feltétlenül a teljes rendezettség, hanem a tartomány partíciója a keresett értékhez képest: a lower_bound esetén minden elem, amelyre comp(element, value) igaz, megelőzi azokat, amelyekre hamis. Ez gyengébb feltétel, mint a teljes rendezettség, de a gyakorlatban szinte mindig rendezett tartománnyal dolgozunk. Ha a tartomány nem felel meg ennek az előfeltételnek, a viselkedés UB.

#include <algorithm>
#include <vector>

void example_binary_search() {
    std::vector<int> v = {1, 2, 2, 3, 4, 4, 4, 5};

    bool found = std::binary_search(v.begin(), v.end(), 4); // true

    auto lower = std::lower_bound(v.begin(), v.end(), 4);
    // lower az első 4-esre mutat (index 4)

    auto upper = std::upper_bound(v.begin(), v.end(), 4);
    // upper az 5-ösre mutat (index 7)

    auto range = std::equal_range(v.begin(), v.end(), 4);
    // range.first == lower, range.second == upper
    // az összes 4-es a [range.first, range.second) intervallumban van
}

A lower_bound és upper_bound közötti különbség duplikátumok esetén válik nyilvánvalóvá. Ha a cél az összes előfordulás elérése, az equal_range a legkényelmesebb. Ha csak egyetlen előfordulás szükséges, a binary_search elegendő, de ha az elem pozícióját is ismerni akarjuk, a lower_bound-ot használjuk.

16.2.5 Komparátorok és projekciók a gyakorlatban

A hagyományos std::binary_search és társai két túlterheléssel rendelkeznek: az egyik a default std::less{}-t használja, a másik egy egyéni comp komparátort vár. A komparátor szignatúrája bool(const T&, const T&) vagy azzal ekvivalens. A lower_bound esetén a komparátor első paramétere a tartomány eleme, a második a keresett érték. Az upper_bound esetén ez megfordul: az első a keresett érték, a második a tartomány eleme. Ezt a konvenciót érdemes megjegyezni, mert a helytelen sorrend fordítási hibát vagy logikai hibát okozhat.

#include <algorithm>
#include <vector>

struct Record {
    int id;
    std::string name;
};

void example_custom_comparator() {
    std::vector<Record> records = {
        {1, "alma"}, {2, "barack"}, {3, "citrom"}, {4, "dió"}
    };

    // Rendezés id szerint a hagyományos módon
    std::sort(records.begin(), records.end(),
              [](const Record& a, const Record& b) { return a.id < b.id; });

    // Keresés id = 3-ra
    auto it = std::lower_bound(records.begin(), records.end(), 3,
        [](const Record& r, int value) { return r.id < value; });

    // it a 3-as id-jű rekordra mutat
}

C++20-tól a ranges változatok projekciót is elfogadnak, ami kiküszöböli a lambda-komparátort akkor, ha csak egy tagot szeretnénk összehasonlítani:

#include <algorithm>
#include <vector>

struct Record {
    int id;
    std::string name;
};

void example_ranges_projection() {
    std::vector<Record> records = {
        {1, "alma"}, {2, "barack"}, {3, "citrom"}, {4, "dió"}
    };

    std::ranges::sort(records, {}, &Record::id);

    auto it = std::ranges::lower_bound(records, 3, {}, &Record::id);
    // it a 3-as id-jű rekordra mutat
}

A projekció nem változtatja meg a rendezés vagy keresés logikáját, csupán egy transzformációt alkalmaz az elemre. Ez különösen hasznos akkor, ha a rendezési kulcs egy tagfüggvény vagy egy drága számítás. Ügyeljünk arra, hogy a projekció eredménye ugyanaz a típus legyen, mint a komparátor paramétere.

A rendezés és a keresés komparátorának konzisztensnek kell lennie. Ha a tartományt case-insensitive string-komparátorral rendeztük, akkor a keresésnél is ugyanazt a komparátort kell használni. Ellenkező esetben a lower_bound vagy binary_search rossz eredményt adhat, mert a tartomány a default std::less szerint nem rendezett.

#include <algorithm>
#include <cctype>
#include <string>
#include <vector>

// Case-insensitive komparátor
struct CaseInsensitiveLess {
    bool operator()(const std::string& a, const std::string& b) const {
        return std::lexicographical_compare(
            a.begin(), a.end(), b.begin(), b.end(),
            [](char ca, char cb) {
                return std::tolower(static_cast<unsigned char>(ca)) <
                       std::tolower(static_cast<unsigned char>(cb));
            });
    }
};

void example_consistent_comparator() {
    std::vector<std::string> words = {"alma", "Barack", "citrom", "DiO"};

    std::sort(words.begin(), words.end(), CaseInsensitiveLess{});

    // Helyes keresés ugyanazzal a komparátorral
    bool found = std::binary_search(words.begin(), words.end(), "barack",
                                    CaseInsensitiveLess{}); // true

    // HIBÁS: default std::less-sel keresünk egy case-insensitive rendezett tartományban
    // Ez UB, mert a tartomány nem a std::less szerint rendezett.
    // bool bad = std::binary_search(words.begin(), words.end(), "barack"); // NE!
}

16.2.6 Tipikus hibák és elkerülésük

A rendezett tartományok algoritmusainak használata során a leggyakoribb hibák a következők:

  1. Nem rendezett tartományon futtatott bináris keresés. Ez UB. Mindig ellenőrizzük a rendezettséget std::is_sorted-tal, vagy használjunk olyan tárolót, amely eleve rendezett, például std::set, std::map, vagy C++23-tól std::flat_set.

  2. Hibás komparátor. A <= operátor vagy a nem tranzitív reláció UB-t okoz a rendezésnél és a keresésnél is. A komparátornak szigorú gyenge rendezést kell megvalósítania.

  3. A rendezés és a keresés komparátora eltér. Ha a rendezéshez case-insensitive komparátort használunk, a kereséshez is ugyanazt kell használni, különben a tartomány nem felel meg az algoritmus előfeltételének.

  4. A lower_bound és upper_bound félreértése. A lower_bound az első nem kisebb, az upper_bound az első nagyobb elemet adja. Duplikátumok esetén a különbség lényeges: a lower_bound az első előfordulásra, az upper_bound az utolsó utáni elemre mutat.

  5. Iterátorok érvényessége. A rendezés módosítja a tartományt, így a rendezés előtt megszerzett iterátorok érvénytelenné válhatnak (különösen std::vector esetén, ha a kapacitás nem elegendő). A keresést mindig a rendezés után végezzük.

  6. Teljesítménycsapda: minden keresés előtt rendezni. Ha a tartomány gyakran módosul, ritkán keresünk, akkor a rendezés költsége dominálhat. Ilyenkor érdemes lehet rendezett asszociatív konténert használni, vagy a módosításokat kötegelve kezelni.

16.2.7 Labor: lower_bound/upper_bound példa

A labor célja egy gyakorlati minta bemutatása, amelynek során egy rendezett eseménynaplóban időintervallum alapján keresünk. A feladat az alsó és felső határ meghatározása std::lower_bound és std::upper_bound segítségével.

Feladat: Adott egy std::vector<Event>, amely időbélyeg szerint rendezett. Egy lekérdezés adott [t_min, t_max) intervallumba eső eseményeket ad vissza. Az eredmény egy iterátorpár, amely a kiválasztott tartományt határolja.

A kód C++20-at használ, és a teszteléshez assert-eket, a méréshez std::chrono-t alkalmaz. A build parancs rögzíti a fordítót, a szabványt és a figyelmeztetéseket.

// algorithms_lab.cpp
#include <algorithm>
#include <cassert>
#include <chrono>
#include <cstdint>
#include <iostream>
#include <random>
#include <string>
#include <vector>

struct Event {
    std::uint64_t timestamp;
    std::string payload;
};

// Az eseményeket timestamp szerint hasonlítjuk össze.
bool operator<(const Event& lhs, const Event& rhs) {
    return lhs.timestamp < rhs.timestamp;
}

// Visszaadja a [t_min, t_max) intervallumba eső események iterátorpárját.
// Előfeltétel: a log rendezett timestamp szerint.
auto events_in_range(const std::vector<Event>& log,
                     std::uint64_t t_min,
                     std::uint64_t t_max)
    -> std::pair<std::vector<Event>::const_iterator,
                 std::vector<Event>::const_iterator>
{
    // lower_bound: az első elem, amely nem kisebb t_min-nél
    auto lower = std::lower_bound(log.begin(), log.end(), t_min,
        [](const Event& e, std::uint64_t value) {
            return e.timestamp < value;
        });

    // upper_bound: az első elem, amely nagyobb t_max-nál
    auto upper = std::upper_bound(log.begin(), log.end(), t_max,
        [](std::uint64_t value, const Event& e) {
            return value < e.timestamp;
        });

    return {lower, upper};
}

int main() {
    // Teszteset: kis, ismert napló
    std::vector<Event> log = {
        {1, "start"},
        {2, "tick"},
        {2, "tick"},
        {3, "stop"},
        {3, "report"},
        {4, "flush"},
        {5, "exit"}
    };

    // Ellenőrizzük a rendezettséget
    assert(std::is_sorted(log.begin(), log.end()));

    auto [lo, hi] = events_in_range(log, 2, 4);
    // Várt: a 2-es (két tick) és 3-as (stop, report) időbélyegű események,
    // összesen 4 elem.
    assert(std::distance(lo, hi) == 4);
    assert(lo->payload == "tick");
    assert((hi - 1)->payload == "report");

    std::cout << "Functional test passed.\n";

    // Mérési rész: nagy rendezett log, sok lekérdezés
    constexpr std::size_t N = 1'000'000;
    constexpr int queries = 10'000;
    std::vector<Event> big_log;
    big_log.reserve(N);
    std::mt19937_64 rng(42);
    std::uniform_int_distribution<std::uint64_t> dist(0, 1'000'000'000);

    for (std::size_t i = 0; i < N; ++i) {
        big_log.push_back(Event{dist(rng), "event"});
    }
    std::sort(big_log.begin(), big_log.end());

    // A méréshez rögzítjük az időt a lekérdezések előtt és után.
    auto start = std::chrono::steady_clock::now();
    volatile std::size_t sum = 0; // megakadályozza a kihagyást
    for (int q = 0; q < queries; ++q) {
        auto t_min = dist(rng);
        auto t_max = t_min + 1000;
        auto [lo2, hi2] = events_in_range(big_log, t_min, t_max);
        sum += static_cast<std::size_t>(std::distance(lo2, hi2));
    }
    auto end = std::chrono::steady_clock::now();
    auto elapsed = std::chrono::duration_cast<std::chrono::milliseconds>(end - start).count();

    std::cout << "Queries: " << queries << ", total elements found: " << sum << '\n';
    std::cout << "Elapsed time: " << elapsed << " ms\n";

    return 0;
}

16.2.8 Önellenőrző kérdés

Adott egy std::vector<std::string> szavakkal, amelyet case-insensitive módon rendeztünk egy CaseInsensitiveLess komparátorral. Miért hibás a std::binary_search(words.begin(), words.end(), "barack") hívás, és hogyan kell helyesen elvégezni a keresést? Válaszát indokolja a rendezett tartomány és a szigorú gyenge rendezés fogalmával.

A kérdésre a válasz: a hívás UB, mert a tartomány nem a std::less szerint rendezett, ezért a bináris keresés előfeltétele nem teljesül. Helyesen a CaseInsensitiveLess komparátort kell átadni a kereséshez is.
