25.1.2 Az osztályozó adatfolyam szerződése

Definíció (osztályozási adatfolyam). Legyen a bemeneti tér 𝒳=ℝCin×H×W\mathcal X=\mathbb R^{C_{in}\times H\times W}, a célhalmaz 𝒴={0,…,K−1}\mathcal Y=\{0,\ldots,K-1\}, ahol a GlyphLab alapbeállításán Cin=1C_{in}=1, H=W=24H=W=24, K=3K=3. Egy osztályozó adatfolyam az alábbi komponensekből áll:

  • Dataset schema: minden indexhez kép, célindex, valamint a csoport- és splitazonosító tartozik. GlyphLab: data/images.npy alakja (360,1,24,24)(360,1,24,24) float32; data/labels.npy alakja (360,)(360,) int64; data/metadata.csv rekordonként index, scene_id, view_id, label, split, xmin, ymin, xmax, ymax mezőket ad. A split jelenetszinten független (120/30/30 jelenet). A GlyphLab minden jelenetéhez két nézet tartozik, ezért a 120/30/30 jelenet 240/60/60 képet jelent, és egy jelenet két nézete nem kerülhet különböző splitbe. Az xmin, ymin, xmax, ymax mezők a forrásséma részei (a későbbi detekciós feladatokhoz); az osztályozó adatfolyam nem használja őket, a doboz nem bemenet és nem címke.
  • Preprocessing: minden kép ugyanazt a determinisztikus, címkemegőrző leképezést kapja. A GlyphLab képek eleve [0,1][0,1]-re normalizáltak, ezért a betöltés után közvetlenül bemenetként használhatók. Ha a modellt μ,σ\mu,\sigma jellemzőkkel normalizáljuk, akkor ez a pár a modellszerződés része, és a betanításkor, a validációnál, a tesztnél és az inference-nél is azonos módon alkalmazandó. A csak tanításkor mintavételezett augmentációk (22.4. Augmentációs kísérlet és domainváltozás) a modell mentése után nem részei az inference-szerződésnek.
  • Backbone: fB:ℝN×Cin×H×W→ℝN×Cout×H′×W′f_B:\mathbb R^{N\times C_{in}\times H\times W}\to\mathbb R^{N\times C_{out}\times H'\times W'} feature extractor, amely a térbeli leképezések után jellemzőtérképet ad; a kilapítás a head elején, a forward-ban történik. A kilapítás PyTorch-konvenciója csatorna-sorrendű: (N,Cout,H′,W′)→(N,Cout⋅H′⋅W′)(N,C_{out},H',W')\to(N,C_{out}\cdot H'\cdot W').
  • Head: fH:ℝN×D→ℝN×Kf_H:\mathbb R^{N\times D}\to\mathbb R^{N\times K} lineáris (affin) rétegek és köztük ReLU-aktivációk kompozíciója; az utolsó réteg aktiváció nélküli, azaz logitot ad.
  • Logits: a modell kimenete Z=fH(fB(X))∈ℝN×KZ=f_H(f_B(X))\in\mathbb R^{N\times K}, ahol zn,k∈ℝz_{n,k}\in\mathbb R nem valószínűség. A többosztályos eset a logitokra számolt CrossEntropyLoss-t használ; a cél int64 osztályindex, és a modellben nincs softmax ([D07]).
  • Label mapping: az ℓ:𝒴→ℒ\ell:\mathcal Y\to\mathcal L leképezés, a GlyphLabon ℓ(0)=vertical,ℓ(1)=horizontal,ℓ(2)=diagonal.\ell(0)=\text{vertical},\qquad \ell(1)=\text{horizontal},\qquad \ell(2)=\text{diagonal}. A mapping a mentett modell szerződésének része, nem a logit értékéből következik.

A konkrét modell legyen

fB:Conv1→16k=3,p=1→BN16→ReLU→MaxPool2→Conv16→32k=3,p=1→BN32→ReLU→MaxPool2, f_B:\quad \text{Conv}_{1\to16}^{k=3,p=1}\to\text{BN}_{16}\to\text{ReLU}\to\text{MaxPool}_2\to \text{Conv}_{16\to32}^{k=3,p=1}\to\text{BN}_{32}\to\text{ReLU}\to\text{MaxPool}_2,

majd a head

fH:Flatten1152→Linear1152→64→ReLU→Linear64→3. f_H:\quad \text{Flatten}_{1152}\to\text{Linear}_{1152\to64}\to\text{ReLU}\to\text{Linear}_{64\to3}.

25.1.3 Batch-végigkövetés: betöltéstől a logitsig

Számítás (a GlyphCNN shape-lánca). A fenti modellre, ha X∈ℝN×1×24×24X\in\mathbb R^{N\times1\times24\times24}, akkor a közbülső alakok:

(N,1,24,24)→Conv1(N,16,24,24)→Pool(N,16,12,12)→Conv2(N,32,12,12)→Pool(N,32,6,6) (N,1,24,24)\xrightarrow{\ \text{Conv1}\ }(N,16,24,24)\xrightarrow{\ \text{Pool}\ }(N,16,12,12) \xrightarrow{\ \text{Conv2}\ }(N,32,12,12)\xrightarrow{\ \text{Pool}\ }(N,32,6,6)

→Flatten(N,1152)→Head(N,64)→(N,3). \xrightarrow{\ \text{Flatten}\ }(N,1152)\xrightarrow{\ \text{Head}\ }(N,64)\xrightarrow{\ }(N,3).

Levezetés. A 14.1. Stride, padding, dilation és outputméret alfejezetben levezetett kimeneti méret

Hout=⌊H+2p−ks⌋+1 H_{out}=\left\lfloor\frac{H+2p-k}{s}\right\rfloor+1

szerint a Conv1-re H=24H=24, p=1p=1, k=3k=3, s=1s=1, tehát Hout=24H_{out}=24; a MaxPool k=2k=2, s=2s=2, p=0p=0, tehát 1212. A Conv2-re ugyanez 12→1212\to12, a második pool 12→612\to6. A kilapítás 32⋅6⋅6=115232\cdot6\cdot6=1152 skalárt ad mintánként, a lineáris rétegek pedig a mátrixszorzás definíciójából (N,1152)→(N,64)(N,1152)\to(N,64) és (N,64)→(N,3)(N,64)\to(N,3) alakot. ▫\square

A modell paraméterszáma, K=3K=3 esetén:

Conv2d(16,32,3) + bias 16⋅32⋅9+32=464016\cdot32\cdot9+32=4640

25.1.4 Kézi kis példa és ellenőrzés

A kézi ellenőrzéshez nem kell adathalmazt betölteni: a modellt véletlen inputon definiáljuk, és assert-ekkel rögzítjük az alakokat.

# lab/model_def.py
import torch
import torch.nn as nn

class GlyphCNN(nn.Module):
    def __init__(self, num_classes: int = 3):
        super().__init__()
        self.features = nn.Sequential(
            nn.Conv2d(1, 16, 3, padding=1), nn.BatchNorm2d(16), nn.ReLU(),
            nn.MaxPool2d(2),
            nn.Conv2d(16, 32, 3, padding=1), nn.BatchNorm2d(32), nn.ReLU(),
            nn.MaxPool2d(2),
        )
        self.head = nn.Sequential(
            nn.Linear(32 * 6 * 6, 64), nn.ReLU(), nn.Linear(64, num_classes),
        )

    def forward(self, x: torch.Tensor) -> torch.Tensor:
        return self.head(torch.flatten(self.features(x), 1))

# lab/train_classifier.py
import numpy as np, pandas as pd
import torch
from torch.utils.data import DataLoader, TensorDataset
from model_def import GlyphCNN

torch.manual_seed(20261020)
torch.set_num_threads(1)
device = torch.device("cpu")
X = np.load("data/images.npy")          # (360,1,24,24) float32
y = np.load("data/labels.npy")          # (360,) int64
meta = pd.read_csv("data/metadata.csv")
# A `index` oszlop (nem a CSV sorszáma) köti a rekordot az images.npy sorához.
assert list(meta.columns) == ["index", "scene_id", "view_id", "label", "split",
                              "xmin", "ymin", "xmax", "ymax"], meta.columns
assert len(meta) == len(X) == len(y) == 360, (len(meta), X.shape, y.shape)
assert X.shape == (360, 1, 24, 24) and X.dtype == np.float32, (X.shape, X.dtype)
assert y.shape == (360,) and y.dtype == np.int64, (y.shape, y.dtype)
assert meta["index"].tolist() == list(range(len(meta)))
assert set(meta.split) <= {"train", "val", "test"}, set(meta.split)
tr = meta.loc[meta.split == "train", "index"].to_numpy()
va = meta.loc[meta.split == "val", "index"].to_numpy()
te = meta.loc[meta.split == "test", "index"].to_numpy()
assert (len(tr), len(va), len(te)) == (240, 60, 60), (len(tr), len(va), len(te))

Xt, yt = torch.from_numpy(X[tr]), torch.from_numpy(y[tr])
Xv, yv = torch.from_numpy(X[va]), torch.from_numpy(y[va])
Xte, yte = torch.from_numpy(X[te]), torch.from_numpy(y[te])
dl = DataLoader(TensorDataset(Xt, yt), batch_size=32, shuffle=True)

model = GlyphCNN().to(device)
opt = torch.optim.AdamW(model.parameters(), lr=3e-3, weight_decay=1e-4)
lossf = torch.nn.CrossEntropyLoss()

best_acc = -1.0
best_epoch = 0
best_state = None
for epoch in range(20):
    model.train()
    for xb, yb in dl:
        xb, yb = xb.to(device), yb.to(device)
        opt.zero_grad()
        loss = lossf(model(xb), yb)
        loss.backward()
        opt.step()
    model.eval()
    with torch.inference_mode():
        vacc = (model(Xv.to(device)).argmax(1) == yv.to(device)).float().mean().item()
    print(f"epoch {epoch+1:02d} val_acc={vacc:.4f}")
    if vacc > best_acc:   # szigorú javítás: az első legjobb marad
        best_acc = vacc
        best_epoch = epoch + 1
        best_state = {k: v.detach().clone() for k, v in model.state_dict().items()}

assert best_state is not None
model.load_state_dict(best_state)
model.eval()
with torch.inference_mode():
    test_acc = (model(Xte.to(device)).argmax(1) == yte.to(device)).float().mean().item()
print(f"best epoch {best_epoch:02d} val_acc={best_acc:.4f} test_acc={test_acc:.4f}")

torch.save({
    "model": model.state_dict(),
    "arch": "GlyphCNN",
    "input_schema": "float32 NCHW 1x24x24 [0,1]",
    "labels": {0: "vertical", 1: "horizontal", 2: "diagonal"},
    "best_epoch": best_epoch,
    "val_acc": best_acc,
}, "glyph_cls.pt")
print("saved glyph_cls.pt")

# lab/infer.py
import torch, argparse
from model_def import GlyphCNN

def make_sample(kind: str) -> torch.Tensor:
    x = torch.zeros(1, 1, 24, 24, dtype=torch.float32)
    if kind == "vertical":
        x[..., 6:18, 10:14] = 1.0
    elif kind == "horizontal":
        x[..., 10:14, 6:18] = 1.0
    elif kind == "diagonal":
        idx = torch.arange(24)
        for d in range(-1, 3):      # 4 px széles sáv, mint a másik két minta
            col = (idx + d).clamp(0, 23)
            x[..., idx, col] = 1.0
    return x

p = argparse.ArgumentParser()
p.add_argument("--kind", choices=["vertical", "horizontal", "diagonal"], required=True)
p.add_argument("--ckpt", default="glyph_cls.pt")
a = p.parse_args()

ckpt = torch.load(a.ckpt, weights_only=True)
if "labels" not in ckpt:
    raise KeyError("a checkpoint nem tartalmaz labels leképezést")
labels = {int(k): str(v) for k, v in ckpt["labels"].items()}
model = GlyphCNN()
model.load_state_dict(ckpt["model"])
model.eval()
x = make_sample(a.kind)
with torch.inference_mode():
    z = model(x)
    prob = z.softmax(dim=1)
    yhat = int(z.argmax(dim=1).item())
    logits_np, probs_np = z.numpy(), prob.numpy()
print("logits:", logits_np)
print("probs:", probs_np)
print("predicted:", labels[yhat])

25.1.7 Megoldások és indoklás

F1. Az inference-szerződésbe csak determinisztikus, címkemegőrző leképezések kerülhetnek: a GlyphLab esetében a float32 NCHW [0,1][0,1] tartomány már adott, esetleg a rögzített μ,σ\mu,\sigma normalizálás. A véletlen transzláció, forgatás vagy zaj csak a tanítási augmentáció része; ha a betanított modell kiértékelésekor is véletlenítünk, a P(Y∣X)P(Y\mid X) becslés nem a szerződött bemenetre vonatkozik, és a clean/corrupt párosítás (22.4. Augmentációs kísérlet és domainváltozás) is felborul. Forgatásnál ügyelni kell a címkemegőrzésre: a 180°-os forgatás megőrzi a vonalorientációt, a 90°-os viszont a vertical és a horizontal osztályt felcseréli, ezért az orientációcímke szempontjából nem címkemegőrző.

F2. Az egyes lépések: 32→Conv32→Pool16→Conv16→Pool832\xrightarrow{\text{Conv}}32\xrightarrow{\text{Pool}}16\xrightarrow{\text{Conv}}16\xrightarrow{\text{Pool}}8. Az utolsó aktivációs tér N×24×8×8N\times24\times8\times8, tehát a kilapított dimenzió 24⋅8⋅8=153624\cdot8\cdot8=1536. A head első lineáris rétegének bemenete ezért 15361536.

25.1.8 Rövid összefoglaló

Az osztályozó adatfolyam a dataset schema, a determinisztikus preprocessing, a backbone, a head, a logits és a label mapping együttes szerződése.
