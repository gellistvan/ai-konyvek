7.1 Firmware, bootloader, initramfs és root filesystem

7.1.1 Motiváció

Amikor egy kiszolgáló nem bootol, a tünetek gyakran csak annyit mutatnak, hogy „a gép nem jön fel”. A hiba azonban lehet firmware, bootloader, kernel vagy userspace rétegbeli. Szenior C++ fejlesztőként a build és a release artifact időbeli életciklusát jól ismeri, de a bootlánc ennél mélyebb: itt a firmware, a bootloader, a kernel és az initramfs együtt hozza létre azt a minimális környezetet, amelyben a systemd elindulhat. A d019 ismeretében most a platforminicializálás utáni lépéseket vizsgáljuk, és minden szakaszhoz hozzárendelünk egy diagnosztikai eszközt és egy recovery pontot.

Az üzemeltetési cél: ha a boot megakad, a mérnök ne a kernel image-t vagy a root fájlrendszert kezdje újratelepíteni, hanem először a boot egyes szakaszainak határához rendelje a hibát. A bootlánc komponensenként diagnosztizálható, és a kernel parancssor (kernel command line) az egyik legfontosabb állapotleíró felület.

7.1.2 Definíciók és működés

7.1.2.1 Bootszakaszok és felelősségük

A Linux bootlánc négy fő szakaszra bontható, amelyek felelőssége élesen különválik:

  1. Firmware (UEFI/BIOS) – hardverinicializálás, boot eszköz kiválasztása, majd átadás egy bootloadernek. Az UEFI a d019-ben tárgyalt boot manager és runtime interface szerepet tölti be. Az UEFI az EFI System Partition-on (ESP) lévő, .efi kiterjesztésű bootloader binary-t futtatja.
  2. Bootloader – betölti a kernel image-et (például vmlinuz) és az initramfs-t, majd átadja a vezérlést a kernelnek. A bootloader az UEFI által futtatott program, amely a kernel parancssort is összeállítja.
  3. Kernel – inicializálja a CPU-t, a memóriát, a buszokat, a beépített driver-eket, majd az initramfs-ből elindítja a userspace első folyamatát.
  4. Userspace init rendszer – a systemd (vagy más init) elindítja a szolgáltatásokat, és betölti a tényleges root fájlrendszert.

A hiba hozzárendelése ehhez a négy szakaszhoz:

Szakasz Jellemző tünet Recovery eszköz
Firmware nincs konzol, nincs boot menü UEFI setup, efibootmgr, BMC
Bootloader „error: file not found”, „unknown command” boot menü, grub>, systemd-boot shell
Kernel kernel panic, nincs root kernel command line, initramfs shell
Userspace init systemd hiba, szolgáltatás nem indul emergency mode, journal

A példa disztribúció: Ubuntu Server 24.04 LTS UEFI módban, GRUB 2 bootloaderrel. A GRUB verziója a 2.12 körüli stabil kiadást jelenti, de ezt a laborban pontosan rögzíteni kell (grub-install --version). Alternatívaként a systemd-boot is létezik, de az Ubuntu Server alapértelmezése a GRUB.

7.1.2.2 Kernel image és initramfs

A kernel image a vmlinuz nevű, tömörített, bootolható fájl. Ez tartalmazza a kernel kódját és a beépített (built-in) illesztőprogramokat. A moduláris rendszerekben azonban sok eszköz driver (például NVMe, XFS, LVM) külön kernel modul fájlokban található. Ahhoz, hogy a kernel a modulokat a root fájlrendszer betöltése előtt elérje, egy ideiglenes, memóriában lévő kis fájlrendszerre van szükség: ez az initramfs (vagy initrd). Az initramfs egy cpio archívum, amelyet a bootloader a kernel image mellé tölt be.

Az initramfs feladatai: - betölti a szükséges modulokat (pl. nvme, ext4, dm-crypt) - felderíti a root eszközt (UUID, LVM LV, titkosított eszköz) - esetleg drop-in mentőshellt ad (emergency), ha a root nem található - a root fájlrendszert pivot_root-tal átadja a valódi userspace-nek

Az Ubuntu alatt az initramfs-et a initramfs-tools csomag generálja, és a /boot/initrd.img-<version> néven található. A update-initramfs -u parancs újraépíti. A kernel image és initramfs párját a bootloader konfigurációja határozza meg.

7.1.2.3 Bootloader konfiguráció

A GRUB a /boot/grub/grub.cfg fájlt olvassa, amely azonban nem kézzel szerkesztendő, hanem a /etc/default/grub és a /etc/grub.d/ szkriptek alapján generálódik. A fő bejegyzés a kernel parancssort is tartalmazza:

# Példa GRUB menübejegyzés (részlet)
menuentry 'Ubuntu' {
    linux /vmlinuz-6.8.0-31-generic root=UUID=... ro quiet splash
    initrd /initrd.img-6.8.0-31-generic
}

A példában a linux sor adja a kernel image elérési útját, a root=UUID=... paramétert, valamint a ro, quiet és splash kapcsolókat. Az initrd sor az initramfs útját adja meg. A root=UUID=... az root filesystem felfedezésére szolgál; az UUID a fájlrendszer-azonosító, amely független a fizikai eszköznév sorrendjétől. A kernel parancssor tehát a bootloader és a kernel közötti szerződés.

A systemd-boot ezzel szemben a /boot/EFI/systemd/loader/entries/ alatt tárol bejegyzéseket, szöveges fájlokban.

7.1.2.4 Kernel command line és /proc/cmdline

A kernel parancssor olyan paramétereket ad át a kernelnek és a korai userspace-nek, mint: - root=: a root eszköz (UUID, PARTUUID, device path) - ro / rw: a root mount írásvédett vagy írható módban - console=ttyS0,115200n8: soros konzol beállítás - systemd.unit=emergency.target: a systemd indítandó targetje

A paramétereket a kernel a /proc/cmdline fájlban teszi elérhetővé. Ez a fájl a rendszer futása közben is olvasható, és mutatja, hogy pontosan milyen paraméterekkel indult a kernel. Példa ellenőrzés:

cat /proc/cmdline
# Példa kimenet:
# BOOT_IMAGE=/vmlinuz-6.8.0-31-generic root=UUID=0f2b... ro quiet splash

Itt a BOOT_IMAGE a bootloader által bejegyzett kép elérési útja. A UUID az /etc/fstab-ban is megjelenik, így a konzisztencia ellenőrizhető.

7.1.2.5 Root discovery, UUID és driver

A root fájlrendszer megtalálása többlépcsős folyamat: 1. A kernel parancssor root= paramétere alapján az initramfs keresni kezdi az eszközt. 2. Ha UUID-t adunk meg, az initramfs a /dev/disk/by-uuid/ szimbolikus linkeket olvassa. 3. A szükséges block device driver (pl. nvme, virtio_blk) és a fájlrendszer modul betöltődik. 4. Az initramfs mountolja a root-ot, majd átadja a valódi initnek. 5. Ha a meghatározott eszköz nem található, az initramfs rendszerint emergency shell-t indít, ahol megvizsgálhatók a rendelkezésre álló /dev eszközök.

A UUID előnye a /dev/sda1 típusú névvel szemben: nem változik meg akkor sem, ha például egy virtuális gépben átrendeződik a disk sorrend. A laborban a root eszköz UUID-ját a blkid parancs mutatja.

7.1.2.6 Konzol, emergency és rescue út

A boot hibáinak diagnosztikájához elengedhetetlen a konzol. A soros konzol vagy a VGA framebuffer mellett a kernel parancssor console= paramétere határozza meg, hová kerülnek a boot üzenetek. A quiet paraméter csökkenti a kiírást, ezért ha a boot elakad, érdemes eltávolítani.

Az initramfs emergency shell akkor indul, ha a root mount nem sikerül. A shellben a root eszköz manuálisan mountolható, majd a boot folytatható. A systemd az emergency.target-et indítja, ha valamelyik alapvető service meghibásodik. A rescue mode (mentő mód) egy minimális, root shell-t adó cél, amely nem indítja el a szokásos hálózati szolgáltatásokat. A boot menüben ezek a célok kernel parancssorral aktiválhatók (systemd.unit=emergency.target), vagy a GRUB menüből a e billentyűvel szerkeszthetők.

7.1.3 Kidolgozott példa

Labkörnyezet: izolált labVM, Ubuntu Server 24.04 LTS, UEFI mód, GRUB bootloader, egy lab-root nevű diszk. A VM nevét lab-boot01-nek adjuk, a parancsok ezen futnak.

Cél: ellenőrizni a bootláncot, a kernel parancssort, az initramfs tartalmát, és bemutatni a parancssor módosításának hatását.

  1. Firmware és bootloader információk gyűjtése
# Ellenőrzés: boot mód (UEFI vagy BIOS)
test -d /sys/firmware/efi && echo "UEFI boot" || echo "BIOS boot"
# Várható kimenet: UEFI boot

# GRUB verzió
grub-install --version
# Várható kimenet: grub-install (GRUB) 2.12-... (vagy hasonló, a labban ellenőrizendő)
  1. Kernel image és initramfs azonosítása
ls -l /boot/vmlinuz-* /boot/initrd.img-*
# Várható: /boot/vmlinuz-6.8.0-31-generic, /boot/initrd.img-6.8.0-31-generic
  1. Kernel parancssor ellenőrzése
cat /proc/cmdline
# Várható példa:
# BOOT_IMAGE=/vmlinuz-6.8.0-31-generic root=UUID=0f2b... ro quiet splash
  1. Root UUID és fstab konzisztencia
# Root fájlrendszer UUID-ja
blkid -o value -s UUID /dev/disk/by-label/lab-root
# Vagy ha ismert a root device: blkid /dev/vda2

# fstab ellenőrzése
grep ' / ' /etc/fstab
# Várható: UUID=0f2b... / ext4 defaults 0 1

# Annak ellenőrzése, hogy a /proc/cmdline root paramétere és az fstab UUID egyezik-e
  1. Initramfs tartalom ellenőrzése

Az initramfs egy cpio archívum, a következőképp listázható:

# Az initramfs kilistázása (a labban a megfelelő verzióval)
lsinitramfs /boot/initrd.img-6.8.0-31-generic | grep -E 'nvme|ext4|dm-crypt' | head
# Várható: a szükséges modulok listája
  1. Konzol elérési út ellenőrzése

A VM konzolja általában a virtualizációs réteg által biztosított VGA konzol. A kernel parancssorban console=ttyS0,115200n8 soros konzolt is be lehet állítani, ha a laborban használt hypervisor ezt támogatja. A példában a quiet eltávolításával a boot üzenetek láthatóvá válnak.

  1. GRUB parancssor módosítása (tranziens, nem persistens)

A VM bootolásakor a GRUB menüben az e billentyűvel szerkeszthetjük a kiválasztott bejegyzést. Adjuk hozzá a kernel sorhoz:

systemd.unit=rescue.target

Ez a módosítás csak a következő bootra érvényes, nem írja át a /etc/default/grub fájlt. A boot ezzel rescue módban indul, ahol root jelszó nélkül (vagy a laborban beállított jelszóval) beléphetünk, és elvégezhetjük a diagnosztikát.

Ellenőrzés: a rendszer boot után a systemctl get-default kimenetétől eltérően a rescue target aktív, a prompt pedig root@lab-boot01:~# lesz.

7.1.4 Tipikus hibák és ellenpróbák

Hiba 1: „error: file not found” a GRUB-tól, vagy „unknown command ‘linux’”

Tünet: a boot a GRUB promptnál megáll. Hipotézis: a GRUB nem találja a kernel image-et vagy az initramfs fájlt; esetleg a GRUB_CMDLINE_LINUX rossz. Adatgyűjtés: a GRUB promptban ls parancs mutatja a lemezeket és partíciókat; cat /boot/grub/grub.cfg a konfigurációt. Egy változtatás: ellenőrizni a grub.cfg linux és initrd sorait, majd szükség esetén újragenerálni (update-grub). Verification: a boot folytatódik.

Hiba 2: kernel panic – „Unable to mount root fs on unknown-block(0,0)”

Tünet: a kernel betöltődik, de nem találja a root eszközt. Hipotézis: a root= paraméter rossz UUID-t ad meg, vagy a szükséges block driver nem töltődött be az initramfs-ben. Adatgyűjtés: indítsuk el az initramfs emergency shelljét, és nézzük meg a /dev/disk/by-uuid/ tartalmát, valamint a dmesg kimenetet. Egy változtatás: adjuk meg a helyes UUID-t a GRUB-ban, vagy frissítsük az initramfs-et (update-initramfs -u). Verification: a root mount sikerül.

Hiba 3: a rendszer elindul, de a /proc/cmdline nem azt mutatja, amit a /etc/default/grub beállítottunk

Tünet: a beállított paraméter nincs érvényben. Hipotézis: a update-grub után nem lett újraindítva, vagy a GRUB a régi grub.cfg-t olvassa. Adatgyűjtés: grep menuentry /boot/grub/grub.cfg és a cat /proc/cmdline összehasonlítása. Egy változtatás: futtassuk le a update-grub parancsot, majd indítsuk újra. Verification: a /proc/cmdline már tartalmazza az új paramétert.

Ellenpróba: ha a root= paramétert UUID helyett /dev/sda1-re cseréljük, a boot egy másik diszk csatlakoztatásakor megváltozhat. Az UUID használata stabilabb.

7.1.5 Feladatok

1. feladat (magyarázó): Rajzolja fel a bootlánc négy szakaszát, és minden szakaszhoz rendelje hozzá a legjellemzőbb meghibásodási tünetet és a recovery eszközt. Magyarázza el, miért van szükség az initramfs-re a root fájlrendszer előtt.

2. feladat (adminisztrációs/konfigurációs): A labVM-en ellenőrizze, hogy a root=UUID=... paraméter konzisztens-e a /etc/fstab-tal és a tényleges blokk eszköz UUID-jával. Írja le a parancsokat, amelyekkel az UUID-t lekérdezi, és mutassa be, hogyan generálna új initramfs-et, ha például egy új NVMe drivert kellene beletenni.

3. feladat (diagnosztikai/failure): Szimuláljon egy olyan hibát, hogy a GRUB-ban a root UUID-t rosszra módosítja (csak a következő bootra). A boot várhatóan kernel panicet ad. Dokumentálja, milyen hibaüzenet jelenik meg, és hogyan lép be az initramfs emergency shellbe. Mutassa be, hogyan lehet onnan megkeresni a helyes UUID-t és a bootot úgy folytatni, hogy ne kelljen újraindítani az installációt.

7.1.6 Megoldások

1. feladat megoldása: A bootlánc szakaszai: firmware (hardverinit, boot eszköz), bootloader (kernel és initramfs betöltése, parancssor átadása), kernel (CPU/memória init, beépített driverek, userspace első folyamata), init (userspace szolgáltatások). Az initramfs azért szükséges, mert a kernel bizonyos eszközök driverét modulként tartalmazza, és a root fájlrendszer mountolásához ezekre szükség van. Az initramfs egy ideiglenes memória-fájlrendszer, amely a root mount előtt rendelkezésre áll. Postcondition: a hallgató szóban vagy írásban azonosítja mind a négy szakaszt és azok felelősségét.

2. feladat megoldása: A parancsok:

# a használt root eszköz UUID-ja
blkid -o value -s UUID /dev/disk/by-label/lab-root
# vagy közvetlenül a root device-ra
findmnt -no SOURCE /   # pl. /dev/vda2
blkid -s UUID /dev/vda2
# fstab ellenőrzése
grep ' / ' /etc/fstab
# initramfs frissítése, ha driver változás lenne
sudo update-initramfs -u

A parancs a labVM-en futtatható, privilege: a sudo a lab-admin felhasználónak van. Ellenőrzés: az UUID megegyezik az fstab-ban és a /proc/cmdline-ban. Postcondition: az UUID konzisztens, az initramfs frissült, a boot továbbra is működik.

3. feladat megoldása: A GRUB menüben az e billentyűvel a kernel sor root=UUID=... értékét módosítjuk egy nem létező UUID-ra, majd bootolunk. Várható: kernel panic „Unable to mount root fs”. Amikor az initramfs emergency shellbe kerül, futtassuk:

blkid -o value -s UUID /dev/vda2  # vagy a helyes device
# vagy lsblk --fs a fájlrendszerek listájáért

Majd a shellben:

mount -o rw /dev/vda2 /mnt
exit  # vagy a boot folytatása a megfelelő módon

A példában a helyreállítás a helyes UUID megadása a GRUB-ban és újrabootolás; az initramfs shellben a root mount utáni exit nem mindig folytatja a bootot, ezért a leggyakoribb recovery a mentett változtatás nélküli reboot. A feladat célja a diagnosztikai lépések bemutatása. Postcondition: a helyes UUID azonosítva, a boot folyamat helyreállt.

7.1.7 Rövid összefoglaló

A bootlánc a firmware-től a userspace initig terjed. A firmware a hardvert inicializálja, a bootloader betölti a kernel image-et és az initramfs-et, a kernel pedig a parancssor alapján megtalálja a root fájlrendszert. Az initramfs a root mount előtt biztosítja a szükséges modulokat. A /proc/cmdline a tényleges kernel-paramétereket mutatja, amelyeket a bootloader konfigurációjából lehet származtatni. A hibákat szakaszokhoz rendeljük: firmware, bootloader, kernel, init. A recovery eszközök: UEFI/efibootmgr, GRUB menü, initramfs shell, emergency/rescue célok.

Továbbhasznált definíciók: initramfs – ideiglenes memóriában lévő fájlrendszer, amely a root mount előtt betölti a szükséges modulokat; kernel command line – a bootloader által a kernelnek átadott paraméterek, amelyeket a /proc/cmdline fájl tükröz; root=UUID= – a root fájlrendszer megadása univerzális azonosítóval, amely stabil eszköznévtől függetlenül.
