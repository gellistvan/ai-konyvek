13.1 Shell parsing, quoting és expansion

13.1.1 Motiváció és nyelvi szerződés

A szenior C++ fejlesztő a std::string és argv modellt jól ismeri: a string egy immutable vagy mutable érték, az argumentumvektor pedig az operációs rendszer felé már kész, határokkal rendelkező tömb. A shell ezzel szemben először szövegként kapja meg a parancssort, majd egy többlépcsős parser alakítja argumentumvektorrá. A kettő közötti félreértés a leggyakoribb adminisztrációs hibaforrás: a $file nem olyan, mint egy C++ változó, hanem egy szövegrész, amelyet a shell szétvághat, fájlmintává alakíthat vagy akár parancsként futtathat.

A cél itt nem a Bash mint programozási nyelv teljes bemutatása, hanem az a pontos szerződés, amellyel egy adminisztrációs script kiszámíthatóvá, idempotenssé és nem megbízható inputok esetén is biztonságossá válik.

13.1.2 Definíció: argumentumvektor versus shell string

Argumentumvektor (argv): a Unix execve(2) syscall a folyamatnak egy char **argv tömböt ad, például argv[0] a programnév, argv[1] az első argumentum. A program innentől már nem lát shell-szintű idézőjelet vagy $ jelet; minden argumentum egyértelmű határokkal rendelkezik. Ez a réteg ismerős a C++ main függvényből.

Shell string: a shell által feldolgozott forrásszöveg, például printf '<%s>\n' $file *.txt. Ebből a shell a saját parsing szabályai szerint állítja elő az argv-t. A parsing és az expansion sorrendje a következő:

Lépés Művelet Példa
1 Brace expansion {a,b}.txt → a.txt b.txt
2 Tilde expansion ~/x → /home/user/x
3 Parameter expansion $file, ${file}
4 Command substitution $(cmd), `cmd`
5 Arithmetic expansion $(( 1 + 2 ))
6 Word splitting IFS szerinti vágás
7 Pathname expansion (globbing) *.txt

A lépések után a shell az execve-t már a kész argumentumvektorral hívja. A bash -x és a printf '<%s>\n' "$@" azért hasznos, mert a már kész argv-t mutatja meg, nem a forrásszöveget.

13.1.3 Quoting és escape

A shell három fő mechanizmust használ a parser vezérlésére:

  • Single quote ('...'): minden karaktert szó szerint vesz; nincs expansion, nincs escape, a $ is közönséges karakter. Egyetlen kivétel nincs, maga az aposztróf sem tehető bele közvetlenül.
  • Double quote ("..."): a legtöbb karakter szó szerinti, de a $, a backtick, a \ és (interaktív shellben) a ! megőrzi speciális jelentését. A double quote-on belül a parameter expansion, command substitution és arithmetic expansion végrehajtódik, de a word splitting és a globbing nem.
  • Escape (\c): a következő karaktert szó szerintivé teszi. Double quote-on belül csak a $, backtick, ", \ és newline előtt van hatása.

A C++-ból ismert string-escape szabályokhoz képest a shellben a backslash nem általános karakterkódoló, hanem parser-escape: a \n a shellben gyakran csak n betű, hacsak a printf vagy más program nem értelmezi.

13.1.4 Expansion fajták és csapdák

Parameter expansion akkor használható biztonságosan, ha a változót idézőjelbe tesszük:

file="my report.txt"
printf '<%s>\n' "$file"    # egy argumentum: <my report.txt>
printf '<%s>\n' $file      # két argumentum: <my> és <report.txt>

A $file idézőjel nélkül word splittingen esik át, mert az IFS alapértelmezetten szóköz, tab és újsor. Üres változó esetén az unquoted $file eltűnik az argumentumlistából; idézőjelben viszont egy üres argumentum marad. Ez különösen fontos test vagy [ ] parancsoknál:

[ -f $file ]   # hibás, ha $file üres: [ -f ] szintaxis hibát adhat
[ -f "$file" ] # helyes

Command substitution a $(...) formában használható; a régi backtick forma kerülendő, mert a nested idézőjelezés nehezebb. A command substitution kimenete szintén word splittingen és globbingon megy át, ha nincs idézőjelben:

f=$(basename "$path")       # a belső "$path" védett
printf '%s\n' $f            # ha a basename szóközt ad, szétesik
printf '%s\n' "$f"          # egyben marad

Arithmetic expansion a $(( ... )) formátumú, és a benne lévő változóneveket idézőjel nélkül is lehet használni:

n=5
printf '%s\n' "$(( n + 1 ))"   # 6

A $(( ... )) kimenete nem esik át word splittingen, de idézőjelezni akkor is jó gyakorlat.

13.1.5 Word splitting, globbing és IFS

A word splitting csak a nem idézett expansion eredményét vágja fel az IFS karakterek mentén. Az IFS módosítása hatással van a shell beépített read parancsára is. A globbing (pathname expansion) akkor fut le, ha egy szóban *, ? vagy [ minta van, és a shell a mintát a fájlrendszerben található nevekkel helyettesíti. Ha nincs találat, a legtöbb shellben a minta változatlanul marad, de a Bash nullglob beállítással üres listává is tehető.

A kettő kombinációja a klasszikus hiba:

for f in $(ls "$dir"); do
    stat "$f"
done

Ez törékeny, mert a ls kimenete szóközönként és új soronként szétesik, a fájlnevekben lévő wildcardok újra globbingon mennek át, és a relatív elérési utak is elvesznek. A biztonságos minta a NUL-szeparált kimenet és a nullbyte-ra olvasás:

while IFS= read -r -d '' f; do
    printf '<%s>\n' "$f"
done < <(find "$dir" -maxdepth 1 -type f -print0)

13.1.6 Bash array versus POSIX sh

A Bash tömbök (array=(a b c)) segítenek megőrizni az argumentumhatárokat, de a POSIX sh nem támogatja őket. A biztonságos terjeszkedési formák:

files=("a b" "c d" "*.txt")
printf '<%s>\n' "${files[@]}"  # három argumentum, a *.txt nem globbingolódik
printf '<%s>\n' "${files[*]}"  # egyetlen string, IFS első karakterével összefűzve

A "${files[@]}" a C++ std::vector<std::string>-hez hasonlóan megőrzi a határokat, míg a "${files[*]}" egyetlen stringgé lapít. POSIX sh-ban ilyen nincs; ott a NUL-szeparált stream az általános megoldás.

13.1.7 Fájlnév és nem megbízható input kezelése

Fájlnév lehet szóköz, újsor, csillag vagy akár -n kezdetű is. A nem megbízható inputot mindig idézőjelben kell átadni, és az opciókat a -- lezáróval kell leválasztani:

printf '<%s>\n' -- "$file"
rm -- "$file"

A -- megakadályozza, hogy a fájlnév opcióként értelmeződjön. A find -print0 és a read -d '' a NUL-szeparációval kezeli a fájlnevekben lévő tetszőleges karaktert. A command substitutionbe beágyazott felhasználói inputot soha nem szabad közvetlenül eval-be vagy shellként futtatandó kódba illeszteni.

13.1.8 Kidolgozott példa

A következő példa egy izolált labhoston fut, labhost1 nevű VM-en, labuser felhasználóval (UID 1000). Cél: egy könyvtárban létrehozunk fájlokat, majd bemutatjuk a parsing különbségeket.

# Cél: labhost1, labuser (UID 1000), előfeltétel: /tmp/lab-d061 nem létezik
labhost1:~$ mkdir -p /tmp/lab-d061
labhost1:~$ cd /tmp/lab-d061
labhost1:/tmp/lab-d061$ touch "my report.txt" "--weird name" "*.txt"
labhost1:/tmp/lab-d061$ ls -l
total 0
-rw-r--r-- 1 labuser labuser 0 Mar 10 09:00 '--weird name'
-rw-r--r-- 1 labuser labuser 0 Mar 10 09:00 '*.txt'
-rw-r--r-- 1 labuser labuser 0 Mar 10 09:00 'my report.txt'

Most egy változóval és globbinggal:

labhost1:/tmp/lab-d061$ file='my report.txt'
labhost1:/tmp/lab-d061$ printf '<%s>\n' "$file"
<my report.txt>
labhost1:/tmp/lab-d061$ printf '<%s>\n' $file
<my>
<report.txt>
labhost1:/tmp/lab-d061$ printf '<%s>\n' *.txt
<my report.txt>

A *.txt minta a *.txt nevű fájlra is illik, mert a * bármilyen karaktersorozatot jelöl. A pontos kimenet a fájlrendszer aktuális állapotától függ; a fenti illusztratív, várt kimenet.

A biztonságos iteráció:

labhost1:/tmp/lab-d061$ while IFS= read -r -d '' f; do
    printf '<%s>\n' "$f"
done < <(find . -maxdepth 1 -type f -print0)
<./--weird name>
<./*.txt>
<./my report.txt>

Ellenőrzés: a printf '<%s>\n' "$file" kimenete pontosan egy sor, a NUL-szeparált ciklus pedig három fájlt sorol fel, mindegyik nevet ./ előtaggal, egyetlen argumentumként.

13.1.9 Tipikus hibák és ellenpróbák

Hiba: egy script for f in $(ls "$dir"); do stat "$f"; done módon listáz fájlokat. Tünet: szóközös fájlneveknél hibás útvonal, wildcardos fájlneveknél nem kívánt globbing, üres könyvtárnál semmi. Hipotézis: a ls szöveges kimenete word splittingen és globbingon megy át. Adatgyűjtés: set -x bekapcsolása megmutatja, hogy a shell hány argumentumot ad át a stat-nak. Egy változtatás: cseréljük le a ciklust find -print0 és read -d '' használatára. Verification: a script futtatása a fenti tesztkönyvtárban minden fájlt pontosan egyszer, hibátlanul kezel.

Hiba: egy fájlnév -n vagy --help kezdetű, és a rm opcióként értelmezi. Tünet: fájl nem törlődik, sőt a parancs segítséget ír ki. Javítás: rm -- "$file".

Hiba: egy üres változó unquoted használata [ -f $file ] feltételben. Tünet: [: too many arguments vagy hamis negatív eredmény. Javítás: [ -f "$file" ].

Ellenpróba: a $file idézőjel nélküli használata nem csak szóközöknél törik, hanem akkor is, ha a fájlnév glob karaktert tartalmaz. Például a *.txt nevű fájl a rm $file esetén a könyvtár összes .txt fájljára bővülhet, ami katasztrófa.

13.1.10 Feladatok

13.1.10.1 1. Magyarázó: parancs argumentumainak meghatározása

Adott a következő parancs egy olyan könyvtárban, ahol létezik a.txt és b.txt:

printf '<%s>\n' "a b" c\ d $(echo e f) *.txt

Hány formázandó argumentumot kap a printf, és melyek azok? Válaszát indokolja a parsing lépései szerint.

13.1.10.2 2. Adminisztrációs/konfigurációs: biztonságos fájlkilistázó script

Írjon egy Bash szkriptet /tmp/lab-d061/list-files.sh néven, amely egy argumentumban megadott könyvtár összes fájlját kilistázza, NUL-szeparált find és read -d '' használatával. A script ne omoljon össze szóközös, újsoros vagy - kezdetű fájlneveknél. A script elején ellenőrizze, hogy pontosan egy argumentum érkezett, és az egy létező könyvtár legyen.

13.1.10.3 3. Diagnosztikai/failure/recovery: hibás script javítása

Az alábbi script hibásan működik:

#!/bin/bash
dir="$1"
for f in $(ls "$dir"); do
    stat "$f"
done

Futtassa a /tmp/lab-d061 könyvtárra. Milyen tüneteket észlel? Javítsa a scriptet úgy, hogy minden fájlnevet hibátlanul kezeljen, és indokolja a változtatást.

13.1.11 Megoldások

13.1.11.1 1. Magyarázó feladat megoldása

A parser sorrendben:

  1. A "a b" double quote miatt egy szó lesz, tartalma a b.
  2. A c\ d escape miatt egy szó lesz, tartalma c d.
  3. A $(echo e f) command substitution lefut: a kimenet e f (újsor a végén). A kimenet nincs idézőjelben, ezért word splittingen esik át: két szó lesz, e és f.
  4. A *.txt globbing lefut: a könyvtárban lévő a.txt és b.txt miatt két szó lesz.

A printf a formátumstring után mind a hat szót formázza, tehát 6 argumentumot kap: a b, c d, e, f, a.txt, b.txt.

13.1.11.2 2. Adminisztrációs script megoldása

#!/bin/bash
set -euo pipefail

if [ "$#" -ne 1 ]; then
    printf 'Usage: %s DIR\n' "$0" >&2
    exit 2
fi

dir="$1"
if [ ! -d "$dir" ]; then
    printf 'Not a directory: %s\n' "$dir" >&2
    exit 2
fi

while IFS= read -r -d '' f; do
    printf '<%s>\n' "$f"
done < <(find "$dir" -maxdepth 1 -type f -print0)

Postcondition: a script minden fájlt pontosan egyszer ír ki, a fájlnevek egy-egy <> közé zárt argumentumként jelennek meg, így a határok ellenőrizhetők.

13.1.11.3 3. Diagnosztikai feladat megoldása

A hibás script tünetei:

  • A my report.txt nevű fájl esetén a stat először my-t, majd report.txt-t próbál megnyitni, ami hibát ad.
  • A --weird name fájlnál a stat a --weird szót opciónak nézheti.
  • A *.txt fájl a globbing miatt nem önmagát, hanem a könyvtár .txt kiterjesztésű fájljait jelenti.

Javítás:

#!/bin/bash
set -euo pipefail

dir="$1"
if [ ! -d "$dir" ]; then
    printf 'Not a directory: %s\n' "$dir" >&2
    exit 2
fi

while IFS= read -r -d '' f; do
    stat -- "$f"
done < <(find "$dir" -maxdepth 1 -type f -print0)

A find -print0 NUL-szeparált streamet ad, a read -d '' pedig NUL-ig olvas, így a fájlnévben lévő szóköz, újsor és wildcard nem befolyásolja a feldolgozást. A -- megakadályozza az opcióértelmezést.

13.1.12 Rövid összefoglaló

A shell stringből argumentumvektort készít egy fix parsing és expansion sorrendben. A biztonságos adminisztráció alapja, hogy minden változót idézőjelbe teszünk, kivéve amikor szándékosan kérünk word splittinget vagy globbingot. A find -print0 és a read -d '' NUL-szeparált adatúttal kezeli a tetszőleges fájlneveket; a -- pedig leválasztja az opciókat. A Bash tömbök "${arr[@]}" formája megőrzi az argumentumhatárokat, de POSIX sh-ban NUL-szeparált stream a megoldás. A diagnosztikában a set -x és a printf '<%s>\n' "$@" a már kész argv-t ellenőrzi.

Továbbhasznált definíciók: argumentumvektor (execve előtti, határokkal rendelkező tömb), word splitting (unquoted expansion IFS menti vágása), pathname expansion/globbing (wildcard minták fájlnevekké bővítése).
