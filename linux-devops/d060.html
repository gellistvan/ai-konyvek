12.5 Golden host és rendszerbaseline labor

12.5.1 Motiváció és működtetési feladat

Az adminisztrációs kötet további laborjai akkor adnak megbízható bizonyítékot, ha a kiinduló rendszerprofil pontosan ismert. A C++-fejlesztői párhuzam itt az immutable build artifact: egy determinisztikus build output és annak hash-e nélkül egy későbbi teszt hibaüzenete nem reprodukálható. Ugyanígy egy Linux hoston sem azt akarjuk, hogy „valamilyen” Ubuntu legyen, hanem azt, hogy egy adott kiadás, egy adott kernel, egy adott csomagkészlet és egy adott konfigurációs forrás együttese legyen visszakereshető.

A d060 célja, hogy a labhost01 nevű, izolált labVM-ből olyan golden host kiindulópontot építsen, amelyhez a további labokban mind a kívánt állapot (desired state), mind a megfigyelt állapot (observed state) mérhető.

12.5.2 Definíció és scope

Baseline: egy adott host verzióval és időbélyeggel rögzített állapotleírása, amely az OS/kernel/csomagok, az alapvető erőforrások, valamint a konfigurációs források stabil jellemzőit tartalmazza. A baseline nem maga a futó rendszer, hanem egy ellenőrizhető referencia.

Golden host: olyan reprodukálható host-forrás, amelyből a labhost01 profil újraépíthető. A golden host kettős természetű: tartalmazza a kiindulási OS image/telepítési forrást, és tartalmazza a konfigurációs állapotot (hostname, hálózat, time/locale/DNS, csomagok), amelyet a baseline report rögzít.

Smoke test: minimális, gyors ellenőrzés, amely a diszk/infrastruktúra, memória, hálózat, hozzáférés és alapvető szolgáltatások életképességét igazolja anélkül, hogy teljes terheléses vagy funkcionális tesztet futtatnánk.

Drift: a megfigyelt állapot eltérése a baseline-tól. A drift nem automatikusan hiba, hanem egy változás, amelyet osztályozni kell: szándékolt konfigurációváltozás, biztonsági frissítés, vagy nem kívánt eltérés.

A scope ebben a laborban kizárólag a labhost01 profilja, nem egy egész fleet. A lab prefix elvén minden új object lab- előtagot kap. Nem formázunk diszket, nem módosítunk éles hálózatot, és nem kapcsolunk ki hozzáférést; a visszaút a lab konzolon végig megmarad.

12.5.3 A baseline komponensei

A baseline report az alábbi stabil forrásokat gyűjti össze:

Komponens Mit rögzít Példa forrás
OS/kernel disztribúció, release, kernelverzió /etc/os-release, uname -rvm
packages telepített csomagok verzióval dpkg-query -W
disk blokkeszközök, kötetek, kihasználtság lsblk, df -hT
memory teljes és szabad memória, swap free -h
network interface címek, route, listen socketek ip -br addr, ip route, ss -lnt
access admin user, UID, sudo állapot id, getent passwd, sudo -n
time/locale/DNS időzóna, NTP szinkronizáció, locale, resolver timedatectl, localectl, resolvectl
service failed systemd unitok systemctl --failed --all
configuration source konfigurációs fájlok helye és tartalma /etc/hostname, /etc/netplan/, /etc/locale.conf

A configuration source és a host naming együtt biztosítják, hogy a futó állapot mögött mindig van egy fájlba mentett kívánt állapot. A labhost01 esetén például a hostname forrása az /etc/hostname, a hálózati konfiguráció forrása az /etc/netplan/50-cloud-init.yaml, a resolver beállítás pedig a systemd-resolved kezelésében áll. A smoke test ezeket a forrásokat és a futó értékeket is ellenőrzi, hogy a kettő ne térjen el.

A rebuild jegyzet egy rövid Markdown fájl, amely rögzíti: milyen image-ből, milyen csomagokkal, milyen konfigurációs másolatokkal és milyen snapshotból állítható vissza a host. A lab snapshot pedig egy VM-szintű állapotpillanat, amely a baseline elfogadása után készül. A snapshot nem a backup helyettesítője, hanem a lab munkamásolat gyors visszaállítását szolgálja.

12.5.4 Kidolgozott példa: labhost01 baseline

A labor környezet:

Tulajdonság Érték
Target labhost01
Admin user lab-admin, UID 1000
OS Ubuntu Server 24.04 LTS amd64
Hálózat enp1s0, 192.0.2.15/24, gateway 192.0.2.1
DNS resolver 192.0.2.53
NTP forrás 192.0.2.123
Diszk /dev/vda, labdisks
Privilege lab-admin saját user, a sudo csak a szükséges parancsokra

Az alábbi parancsok a labhost01-en futnak lab-admin userrel, UID 1000. A sudo használatát a felhasználó már ismeri a d059-ből.

12.5.4.1 OS/kernel és packages inventory

# target: labhost01; user: lab-admin; UID: 1000
# Nem módosít, csak olvas.
cat /etc/os-release
uname -rvm
dpkg-query -W --showformat='${Package}\t${Version}\n' | sort

Az os-release tartalmazza az Ubuntu Server 24.04 LTS PRETTY_NAME-jét, a kernel pedig például 6.8.0-XX-generic formátumú verziót ad. A csomaglista a dpkg-query kimenetével a lab-baseline mappába menthető; a rendezés fontos a későbbi drift-diff miatt.

12.5.4.2 Disk/memory/network és access smoke check

# target: labhost01; user: lab-admin; UID: 1000
lsblk -o NAME,SIZE,TYPE,MOUNTPOINTS,MODEL,SERIAL
df -hT
free -h
ip -br addr
ip route
ss -lnt
id
sudo -n true && echo "sudo-ok"

A sudo -n true non-interactive ellenőrzés, amely megmutatja, hogy a lab-admin user rendelkezik-e jelszó nélküli sudo joggal. Ha a labor policy jelszót kér, akkor a smoke test itt egy explicit interaktív ellenőrzést igényel.

12.5.4.3 Time/locale/DNS preconditions

# target: labhost01; user: lab-admin; UID: 1000
timedatectl show --property=NTPSynchronized --property=Timezone
localectl status
resolvectl dns
resolvectl query labhost01.lab.internal

A DNS query itt a lab belső nevére vonatkozik, nem publikus internetes névre, mert a documentation címtartományú laborhálózat nem feltétlenül rendelkezik kifelé irányuló útvonallal. Ha a resolvectl query nem fut le, akkor a DNS előfeltétel nem teljesül, és ezt a baseline reportba hibaként kell bejegyezni.

12.5.4.4 Baseline report készítő script

A következő script a labhost01-en futtatható. A cél az, hogy a report determinisztikus és secret-mentes legyen.

#!/usr/bin/env bash
set -euo pipefail
# target: labhost01; user: lab-admin; UID: 1000
# A script csak olvas, kivéve a saját report könyvtár létrehozását.
OUT="/home/lab-admin/lab-baseline"
STAMP="$(date -u +%Y%m%dT%H%M%SZ)"
REPORT="$OUT/labhost01-baseline-$STAMP.txt"
mkdir -p "$OUT"

{
  echo "# labhost01 baseline report"
  echo "generated: $STAMP (UTC)"
  echo
  echo "## OS/kernel"
  sed -n 's/^PRETTY_NAME=//p' /etc/os-release
  uname -rvm
  echo
  echo "## packages"
  dpkg-query -W --showformat='${Package}\t${Version}\n' | sort
  echo
  echo "## disk"
  lsblk -o NAME,SIZE,TYPE,MOUNTPOINTS,MODEL,SERIAL
  df -hT
  echo
  echo "## memory"
  free -h
  echo
  echo "## network"
  ip -br addr
  ip route
  ss -lnt
  echo
  echo "## time/locale/dns"
  timedatectl show --property=NTPSynchronized --property=Timezone
  localectl status
  resolvectl dns || true
  echo
  echo "## access"
  id
  getent passwd lab-admin
  sudo -n true && echo "sudo-ok" || echo "sudo-needs-password"
  echo
  echo "## failed services"
  systemctl --failed --all --no-pager
} > "$REPORT"

echo "report: $REPORT"
sha256sum "$REPORT"

A reportot ezután ellenőrizni kell, hogy nem tartalmaz-e privát kulcsot, jelszót vagy árulkodó accountadatot. Példa:

# target: labhost01; user: lab-admin; UID: 1000
grep -En 'BEGIN (RSA|OPENSSH|PRIVATE) KEY|password|secret|token' "$REPORT" || echo "no-secret-marker"

A grep kimenetének üresnek kell lennie, vagy a no-secret-marker üzenetnek meg kell jelennie. A report nem tartalmazhatja a /etc/shadow, /root/.ssh, vagy a .git-credentials tartalmát.

12.5.4.5 Rebuild jegyzet és lab snapshot

A rebuild jegyzet mentése:

# target: labhost01; user: lab-admin; UID: 1000
cat > /home/lab-admin/lab-rebuild/labhost01-rebuild.md <<'EOF'
# labhost01 rebuild notes
- base: Ubuntu Server 24.04 LTS amd64
- hostname: labhost01.lab.internal
- config source:
  - /etc/hostname
  - /etc/netplan/50-cloud-init.yaml
  - /etc/systemd/timesyncd.conf
- packages: /home/lab-admin/lab-baseline/labhost01-baseline-latest.txt
- restore:
  1. install base Ubuntu 24.04 LTS
  2. copy config source
  3. install package list from baseline
  4. run baseline smoke test
EOF

A lab snapshot a labor management konzolon készül. Mivel a KVM/libvirt kezelést a d166-tól tanítjuk, itt csak a platformfüggő parancs helyét jelöljük. A labor inventory szerint a snapshot célja a labhost01 VM állapotának rögzítése. Az ellenőrzés szerint a snapshot nevének tartalmaznia kell a labhost01 azonosítót és a baseline időbélyegét.

# target: lab-mgmt; user: lab-admin; privilege: libvirt group
# Illusztratív, a d166 előtt nem tanított parancs; a lab saját hypervisorához igazítandó.
virsh snapshot-create-as labhost01 "baseline-$(date -u +%Y%m%dT%H%M%SZ)" --disk-only --atomic

A snapshot meglétét a labhost01-ről futó virsh nem tudja ellenőrizni, mert a hypervisor API a lab-mgmt hálózati zónájában van. Az ellenőrzés a lab-mgmt konzolon:

# target: lab-mgmt; user: lab-admin; privilege: libvirt group
virsh snapshot-list labhost01

12.5.5 Hibák és ellenpróbák

Tünet: a drift diff minden sorban eltérést mutat, mert a teljes report byte-egyezőségét várjuk.
Ok: a report tartalmaz időbélyeget, a localectl status kiírhat futásfüggő értékeket, a DNS TTL is változik.
Hipotézis: a drift ellenőrzéshez csak a stabil mezőket szabad hasonlítani, mint az OS/kernel, packages, hostname, timezone, DNS resolver és a failed servicek.
Javítás: szűrt diff készítése, például:

# target: labhost01; user: lab-admin; UID: 1000
diff -u <(grep -v '^generated:' baseline.txt) <(grep -v '^generated:' current.txt)

Ez még mindig tartalmazhatja a localectl status változó részeit, ezért a reportot érdemes show típusú parancsokkal stabilizálni.

Tünet: a baseline report resolvectl query hibát mutat, de a DNS szerver konfiguráció helyes.
Ok: a lab hálózati policy vagy a DNS szerver nem elérhető; a laborban a documentation címek mögött valós kifelé útvonal nem garantált.
Ellenőrzés: ip route és resolvectl dns külön vizsgálata; a query hibája nem feltétlenül host-configurációs drift.

Tünet: a snapshot neve látszólag létezik, de visszaállítás után a host nem a baseline állapotot mutatja.
Ok: a snapshot készítése előtt a host fájlrendszerét nem szinkronizálta a lab, vagy a snapshot csak a diszket, nem a memória állapotot rögzíti.
Ellenőrzés: a baseline report és a snapshot időbélyegének egyezése, valamint a sync futtatása a snapshot előtt.

12.5.6 Feladatok

12.5.6.1 1. feladat – Baseline komponensek értelmezése

Futtassa a fenti baseline scriptet a labhost01-en. A kimenetből készítsen táblázatot, amelyben minden szakaszhoz hozzárendeli a megfigyelt értéket és a hozzá tartozó lab targetet. Írja meg, melyik szakasz hiánya milyen üzemeltetési hibát takar (például a failed services szakasz hiánya rejtett szolgáltatáshibát jelezhet).

12.5.6.2 2. feladat – Baseline report, rebuild jegyzet és snapshot

Hozza létre a labhost01 baseline reportot a scripttel. Ellenőrizze, hogy nem tartalmaz secret markert. Írja meg a rebuild jegyzetet, és készítsen lab snapshotot a lab management konzolon. A postcondition: a baseline report SHA-256 értéke ismert, a rebuild jegyzet tartalmazza a config source hivatkozásokat, és a snapshot listában szerepel a labhost01 baseline bejegyzés.

12.5.6.3 3. feladat – Drift diagnosztika és visszaállítás

Módosítsa átmenetileg a labhost01 DNS resolver beállítását egy nem létező labcímre, például 192.0.2.99. Generáljon új reportot, és a stabil mezők szűrt diffje alapján azonosítsa a driftet. Állítsa vissza az eredeti resolver értéket 192.0.2.53-ra, majd bizonyítsa a visszaállást egy új report generálásával és összehasonlításával.

A módosító parancsnál explicit rollback:

# target: labhost01; user: lab-admin; UID: 1000; sudo szükséges
sudo resolvectl dns enp1s0 192.0.2.99
# rollback:
sudo resolvectl dns enp1s0 192.0.2.53

Az interface neve a labhost01 baseline report network szakaszából olvasandó; ha a labor eltér, a tényleges név a mérvadó.

12.5.7 Megoldások

12.5.7.1 1. megoldás

A baseline report szakaszai és a hozzájuk tartozó lab targetek:

Szakasz Lab target Hiány következménye
OS/kernel labhost01 OS image nem reprodukálható kernelhiba
packages labhost01 dpkg nem ismert a telepített csomagverzió
disk labdisks nem azonosítható a kapacitás és a diszk modell
memory labhost01 RAM nem detektálható memóriahiány
network enp1s0, 192.0.2.15 nem diagnosztizálható a hálózati elérés
time/locale/dns labhost01 systemd nem garantált az idő, locale és névfeloldás
access lab-admin, UID 1000 nem ellenőrizhető a bejelentkezés és sudo

A megoldás indoklása: a baseline report egy eszköz, amely a lab targeteket összeköti a megfigyelhető állapottal. A szakaszok hiánya megnehezíti a d004 szerinti hipotézisvezérelt diagnosztikát.

12.5.7.2 2. megoldás

A script lefut, a report elérhető az /home/lab-admin/lab-baseline/ könyvtárban. A secret marker ellenőrzés no-secret-marker üzenetet ad. A rebuild jegyzet tartalmazza a base image, config source és restore lépéseket. A lab snapshot a lab-mgmt konzolon a baseline- előtagú névvel szerepel. Az elfogadás postconditionje: a sha256sum kimenet rögzítve van a rebuild jegyzetben, és a snapshot listája visszaadja a bejegyzést. Ha a snapshot készítése nem lehetséges, akkor ezt az ellenőrzési hiányokban fel kell tüntetni; a lab továbbra is futhat, de a rollback gyorsabb útja elveszik.

12.5.7.3 3. megoldás

A drift detektálása a stabil mezők szűrt diffjével:

# target: labhost01; user: lab-admin; UID: 1000
diff -u <(grep '192.0.2.53' baseline.txt) <(grep '192.0.2.53' current.txt)

A módosítás után a resolvectl dns kimenete 192.0.2.99-at mutat, a baseline report 192.0.2.53-at. A szűrt diff egy sorban mutatja az eltérést. A rollback után egy új report már 192.0.2.53-at tartalmaz, a diff üres. A postcondition: a futó resolver ismét megegyezik a baseline-val, és a labhost01 belső névfeloldása működik.

12.5.8 Rövid összefoglaló

A golden host és a baseline labor célja, hogy a labhost01 állapota visszakereshető és reprodukálható legyen. A baseline report az OS/kernel, csomagok, disk, memória, hálózat, hozzáférés, time/locale/DNS, és systemd failed state stabil jellemzőit gyűjti össze. A smoke test gyorsan jelzi, ha valamelyik alapszolgáltatás nem működik. A drift a megfigyelt és a baseline állapot közti eltérés, amelyet szűrt diff és szándékolt változás osztályozás kezel. A rebuild jegyzet és a lab snapshot biztosítja, hogy a későbbi labok tiszta kiindulópontból induljanak. A report titokmentességét ellenőrizni kell.

Továbbhasznált definíciók: baseline, golden host, smoke test, drift.
