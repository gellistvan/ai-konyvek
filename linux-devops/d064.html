13.4 Admin script: idempotencia, hiba és locking

13.4.1 Motiváció, definíció és előfeltételek

Egy üzemeltetési változtatás nem egy egyszeri parancs, hanem kis működtetési szerződés: ugyanaz a futás ugyanazt a kívánt állapotot (desired state) adja, konkurens futás ne írjon egymás fölé, hiba esetén maradjon auditnyom és visszaút. A szenior C++ tudás itt is használható: a resource lifetime fegyelmet, a determinisztikus destruktort és a tranzakciós gondolkodást a shellben részben trap, mktemp, mv és flock pótolja. A shell azonban nem C++: a hibák nem kivételek, hanem exit code-ok és processzhatárok.

Definíciók:

  • Idempotens admin script: ismételt futtatás ugyanazt a postconditiont adja; a már elért állapotot nem módosítja újra.
  • Atomic rename: ugyanazon fájlrendszeren belüli rename()-alapú mv; a cél név alatt vagy a régi, vagy az új inode látszik, részleges tartalom nem.
  • Advisory flock lock: a kernel a nyitott file descriptorhoz kötött lockot tárol; a processz kilépésekor az FD záródik, a lock automatikusan felszabadul.

Előfeltételek: d063 shell parsing, quoting és streammodell; d005 runbook és változtatási szerződés. Labhost: labhost1, Ubuntu Server 24.04 LTS, felhasználó labuser, emelt jog sudo-val.

13.4.2 Shell hiba- és folyamatmodell admin scripthez

13.4.2.1 set -euo pipefail és kivételek

A set -e fail-fast alapot ad: ha egy egyszerű parancs nonzero exit kóddal tér vissza, a script leáll. A set -u undefined változót, a set -o pipefail a pipelineban a jobb szélső nemnulla exitet is hibának tekinti.

A set -e azonban nem mindenhol lép: if, while, until feltételben, &&/|| bal oldalán, ! negációval, illetve bizonyos subshell-helyzetekben nem állítja meg a scriptet. Ezért például az if diff -q "$a" "$b" >/dev/null; then ... kifejezésben a diff 1-es visszatérési értéke elvárt jelzés, nem hibaüzenet. A megbízható admin script ezért nem kizárólag a set -e-re támaszkodik, hanem explicit if ! parancs; then ...; fi blokkokat használ.

13.4.2.2 Explicit error path, trap, mktemp és atomic rename

A die() függvény üzenetet ír stderrre, majd exit 1-gyel kilép. A trap cleanup EXIT C++-analógiával a determinisztikus destruktor szerepét tölti be: a script lefutása után, hiba esetén is takarít. Nem véd a SIGKILL ellen, mert az a processzt azonnal megszakítja.

A kritikus fájlfrissítéshez a mktemp a cél könyvtárban hoz létre egyedi nevű ideiglenes fájlt. A tartalom kiírása után a chmod, majd az mv -f atomi csere. Ha a /tmp külön fájlrendszer, a mktemp -p /tmp után a mv átmásolás + unlink, nem atomi; ezért a példában a temp a cél /etc/sysctl.d alá kerül.

13.4.2.3 Instance locking flock

A kritikus frissítést konkurens futtatás ellen flock védi. Az exec 9>"$LOCK" megnyitja a lock fájlt, a flock -n 9 nem blokkoló lockot próbál szerezni. Ha egy másik példány már tartja, a script hibaüzenettel kilép. A lock nem a fájl tartalmától függ, hanem a kernelben tárolt nyitott FD-től, ezért a processz elhalásakor nem marad dead lock.

A lock fájl elérési útja /run/lock/${PROG}.lock; ezt csak root írhatja, ezért a need_root ellenőrzés a lock előtt fut.

13.4.2.4 Privilege boundary és sudo

A script maga soha nem hív sudo-t, és nem ismétli magát emelt joggal. A hívó explicit módon sudo /home/labuser/bin/lab-tune --dry-run parancsot használ. A script elején a need_root az EUID-ot ellenőrzi, és ha nem root, kilép. A lock, a célfájl és a sysctl alkalmazás így azonos, root trust osztályba tartozik.

13.4.2.5 Dry-run, diff, rollback és audit trail

A --dry-run ugyanazt a desired fájlt előállítja, de nem ír célfájlt, nem futtat sysctl-t, csak diff -u-val mutatja a különbséget. A tényleges futás készít egy backupot, majd a logger parancsot használ audit sorként. A log tartalmazza a régi és új sha256sum-ot, a backup nevét és a célt. A rollback a backupból állítja vissza a célfájlt, majd újra alkalmazza a sysctl beállításokat.

13.4.3 Kidolgozott példa: lab-tune sysctl admin script

A példa a vm.swappiness=10 és a net.ipv4.ip_forward=0 persistent beállítást írja a /etc/sysctl.d/99-lab-tune.conf fájlba a labhost1 rendszeren. A config-state a fájl, a runtime-state a sysctl -n vm.swappiness és a sysctl -n net.ipv4.ip_forward. A cél nem egy sablon; a script csak ezt a saját 99-lab-tune célfájlját kezeli, a labban más sysctl.d fájlok nem módosulnak.

A script elérési útja: /home/labuser/bin/lab-tune. Telepítés után chmod 0755; futtatás sudo-val.

#!/usr/bin/env bash
set -euo pipefail

PROG="${0##*/}"
TARGET="/etc/sysctl.d/99-lab-tune.conf"
LOCK="/run/lock/${PROG}.lock"
AUDIT_TAG="lab-tune"
mode="${1:-apply}"
TMP_FILE=

cleanup() {
    [[ -n ${TMP_FILE:-} && -f $TMP_FILE ]] && rm -f "$TMP_FILE"
}
trap cleanup EXIT

usage() {
    cat <<'EOF'
Usage:
  sudo lab-tune [--dry-run]
  sudo lab-tune --rollback BACKUP_FILE
EOF
    exit 2
}
die() { echo "$PROG: $*" >&2; exit 1; }
log() { logger -t "$AUDIT_TAG" -p local1.info -- "$1"; }

need_root() {
    [[ $EUID -eq 0 ]] || die "run as root with sudo"
}

acquire_lock() {
    exec 9>"$LOCK"
    flock -n 9 || die "another instance holds $LOCK"
}

make_desired() {
    local f="$1"
    cat >"$f" <<'EOF'
# Managed by lab-tune. Do not edit manually.
vm.swappiness=10
net.ipv4.ip_forward=0
EOF
    chmod 0644 "$f"
}

apply_sysctl() {
    local backup="$1"
    if ! /sbin/sysctl --system >/dev/null; then
        echo "$PROG: config written, but sysctl --system failed" >&2
        echo "Rollback with: sudo $PROG --rollback $backup" >&2
        return 1
    fi
}

replace_from_backup() {
    local backup="$1"
    local tmp
    tmp=$(mktemp -p /etc/sysctl.d .99-lab-tune.tmp.XXXXXXXXXX) || die "mktemp"
    cp -p "$backup" "$tmp"
    mv -f "$tmp" "$TARGET"
}

rollback() {
    local backup="$1"
    [[ -f "$backup" ]] || die "backup file does not exist: $backup"
    if diff -q "$TARGET" "$backup" >/dev/null; then
        echo "No change: target already matches backup"
        exit 0
    fi
    replace_from_backup "$backup"
    apply_sysctl "$backup"
    log "rollback applied from $backup"
    echo "Rollback complete from $backup"
}

main() {
    need_root
    acquire_lock
    case "$mode" in
        --dry-run)
            local tmp
            tmp=$(mktemp -p /etc/sysctl.d .99-lab-tune.tmp.XXXXXXXXXX) || die "mktemp"
            TMP_FILE="$tmp"
            make_desired "$tmp"
            if [[ ! -f "$TARGET" ]]; then
                echo "DRY-RUN: $TARGET would be created:"
                cat "$tmp"
            elif diff -q "$TARGET" "$tmp" >/dev/null; then
                echo "OK: $TARGET already matches desired state"
            else
                echo "DRY-RUN: $TARGET would be changed:"
                diff -u "$TARGET" "$tmp" || true
            fi
            exit 0
            ;;
        --rollback)
            [[ $# -lt 2 ]] && usage
            rollback "$2"
            exit 0
            ;;
        "")
            ;;
        *)
            usage
            ;;
    esac

    local tmp backup
    tmp=$(mktemp -p /etc/sysctl.d .99-lab-tune.tmp.XXXXXXXXXX) || die "mktemp"
    TMP_FILE="$tmp"
    backup=$(mktemp -p /etc/sysctl.d .99-lab-tune.conf.bak.XXXXXXXXXX) || die "mktemp"
    make_desired "$tmp"

    if [[ -f "$TARGET" ]] && diff -q "$TARGET" "$tmp" >/dev/null; then
        echo "OK: $TARGET already matches desired state"
        exit 0
    fi

    if [[ -f "$TARGET" ]]; then
        cp -p "$TARGET" "$backup"
    else
        : >"$backup"
        chmod 0644 "$backup"
    fi

    old_sum=$(sha256sum "$backup" | cut -d' ' -f1)
    new_sum=$(sha256sum "$tmp" | cut -d' ' -f1)

    if [[ -L "$TARGET" ]]; then die "refusing to replace symlink $TARGET"; fi
    mv -f "$tmp" "$TARGET"
    TMP_FILE=
    apply_sysctl "$backup"
    echo "Applied. Backup: $backup"
    log "applied $TARGET old=$old_sum new=$new_sum backup=$backup"
}

main "$@"

A futtatási lépések a labhost1 hoston:

# 1. Dry-run
sudo /home/labuser/bin/lab-tune --dry-run
# Várható kimenet, ha a célfájl még nem létezik:
# DRY-RUN: /etc/sysctl.d/99-lab-tune.conf would be created:
# # Managed by lab-tune. Do not edit manually.
# vm.swappiness=10
# net.ipv4.ip_forward=0

# 2. Alkalmazás
sudo /home/labuser/bin/lab-tune
# Várható kimenet: Applied. Backup: /etc/sysctl.d/.99-lab-tune.conf.bak.ZZ...

# Ellenőrzés
sysctl -n vm.swappiness
# Várt: 10

# 3. Idempotencia ellenőrzés
sudo /home/labuser/bin/lab-tune
# Várható kimenet: OK: /etc/sysctl.d/99-lab-tune.conf already matches desired state

# 4. Rollback a kiírt backup névvel
sudo /home/labuser/bin/lab-tune --rollback /etc/sysctl.d/.99-lab-tune.conf.bak.ZZ...
# Várható kimenet: Rollback complete from ...
sysctl -n vm.swappiness
# Várt: az eredeti alapérték, például 60

Ha a kiinduló alapérték nem 60, akkor a rollback utáni érték a backupban tárolt, üres fájl esetén a kernel default marad. A postcondition így a fájl és a runtime-state egyezése a backup tartalmával.

13.4.4 Hibák és ellenpróbák

A set -e nem áll le if feltételben. Ha a felhasználó önállóan ír diff -q "$TARGET" "$tmp" parancsot, a script leáll, ha a fájlok eltérnek. Ellenpróba: a --dry-run ágban a diff -u hívás után || true kell, mert a különbség elvárt, nem hiba.

A trap túl széles köre. Ha a trap a backup fájlt is törli a kilépéskor, akkor a rollback elveszik. Tünet: az Applied. kiírás után a backup nem létezik. Hipotézis: a cleanup minden tempet töröl. Javítás: a cleanup csak a TMP_FILE-t kezelje, a backupot soha ne.

A temp és a cél eltérő fájlrendszeren. Ha a temp a /tmp-ben készül, az mv nem atomi. Tünet: a célfájl rövid ideig hiányos olvasható másolás lehet. Javítás: a mktemp -p a cél könyvtárat használja.

A lock nem blokkoló ellenőrzése. A flock -n hibásan konfigurált esetben azonnal meghiúsul. A tipikus hibaüzenet: another instance holds /run/lock/lab-tune.lock. Ennél ellenőrizni kell, hogy a másik processz valóban fut-e még, vagy csak egy régi FD maradt nyitva. A kernel lock nem marad dead lock, ha a processz megszűnik; a fájl tartalma nem a lock forrása.

A sysctl alkalmazás hibája. Ha a config fájlba kerül egy hibás sor, például vm.swappiness=not_a_number, akkor a sysctl --system kiírja a hibát, és a script leáll. A fájl már új, a runtime régi. Ilyenkor a kiírt rollback parancs a backupból visszaállítja a konzisztens állapotot. A script ezt a --dry-run-nal nem fogja meg, mert a dry-run csak a configot hasonlítja össze; a sysctl --system futtatása a tényleges validáció.

13.4.5 Feladatok

  1. Magyarázó: A lab-tune --dry-run ága diff -u "$TARGET" "$tmp" || true-t használ. Magyarázd el, miért van itt szükség az explicit || true-ra a set -e mellett, és mutass egy egyszerű parancssort, ahol enélkül a script leállna.

  2. Adminisztrációs/konfigurációs: Készítsd el a lab-limits scriptet a /etc/security/limits.d/99-lab-nproc.conf fájlhoz a következő desired tartalommal:

    # Managed by lab-limits.
* soft nproc 4096
* hard nproc 8192

    A script legyen idempotens, készítsen backupot, használjon flockot, mktemp-et és atomic rename-et. A lock fájl neve /run/lock/lab-limits.lock, a scripté /home/labuser/bin/lab-limits.

  3. Diagnosztikai/failure/recovery: Indítsd el a lab-tune-ot kétszer párhuzamosan ugyanazon a hoston. Figyeld meg a második hibaüzenetét. Ezután írd a TARGET-ba a vm.swappiness=not_a_number sort, futtasd a sudo /sbin/sysctl --system-et, és állítsd helyre a mentett backupból a lab-tune --rollback paranccsal. Ellenőrizd a fájl tartalmát és a runtime értéket is.

13.4.6 Megoldások

  1. A diff akkor tér vissza 1-essel, ha a fájlok különböznek. A --dry-run esetén ez elvárt állapot, nem valódi hiba. A set -e az ilyen nonzero exitet hibaként kezelné, és a script leállna. Az explicit || true ezt a visszatérési értéket 0-ra normalizálja. Példa: diff -u /etc/hostname /etc/hostname.old eltérő fájlokkal set -e alatt a scriptet megszakítja, ha nincs kezelés.

    Postcondition: a --dry-run eltérő fájlok esetén is befejeződik 0 exit kóddal, és kiírja a különbséget.

  2. A lab-limits script a lab-tune mintát követi. A TARGET="/etc/security/limits.d/99-lab-nproc.conf", a desired tartalmat a make_desired írja, a backup mktemp -p /etc/security/limits.d .99-lab-nproc.conf.bak.XXXXXXXXXX, a lock /run/lock/lab-limits.lock. A futtatás:

    sudo /home/labuser/bin/lab-limits --dry-run
sudo /home/labuser/bin/lab-limits
sudo /home/labuser/bin/lab-limits

    Postcondition: a 99-lab-nproc.conf a desired tartalmat tartalmazza; a második futtatás OK üzenetet ad; a backup létezik; a lock felszabadult.

  3. A párhuzamos futásnál az első példány lockot szerez, a második flock -n hibaüzenettel kilép: lab-tune: another instance holds /run/lock/lab-tune.lock. A hibás sysctl bejegyzésnél a fájl új tartalmat kap, a sysctl --system stderrre hibát ír, és a script exit 1-gyel leáll. A rollback:

    sudo /home/labuser/bin/lab-tune --rollback /etc/sysctl.d/.99-lab-tune.conf.bak.ZZ...
sysctl -n vm.swappiness
grep 'vm.swappiness' /etc/sysctl.d/99-lab-tune.conf

    Postcondition: a célfájl tartalma a backupéval egyezik, a sysctl -n vm.swappiness a korábbi értéket adja, a második lab-tune futás ismét OK-t ír ki.

13.4.7 Rövid összefoglaló

Az admin script kis változtatási szerződés: idempotens, hibakezelt, concret futástól védett, visszaállítható elegendő. A set -euo pipefail fail-fast alapot ad, de a feltételben szereplő parancsok kivételek; explicit if és die kell. A trap cleanup takarít, a mktemp + mv atomi cserét ad, az flock processzhez kötött lockot biztosít. A sudo-t a hívó adja, a script root ellenőrzést végez. A dry-run, backup, rollback és logger audit költsége kicsi, de a recovery képesség alapja.

Definíciók:

  • Idempotens admin script: ismételt futás ugyanazt a postconditiont adja, újabb módosítás nélkül.
  • Atomic rename: ugyanazon fájlrendszeren belüli mv; a cél név alatt vagy régi, vagy új tartalom látszik.
  • Advisory flock lock: a kernel a nyitott FD-hez kötött lockot tartja; processz halálakor felszabadul.

13.4.8 Források és ellenőrzési hiányok

  • GNU Bash Reference Manual – shell parsing, set, trap, paraméterek; nem ellenőrzött aktuális verzióspecifikus viselkedés.
  • Ubuntu Server documentation – Ubuntu Server 24.04 LTS sysctl, sudo, logger csomagviselkedés; a példa futtatása előtt ellenőrizendő.
  • man7 Linux man-pages – flock, mktemp, mv, sysctl, logger man oldalak; a példában használt util-linux és procps pontos kiadása ellenőrizendő.

Ellenőrzési hiányok: a sysctl --system hibás sorral adott visszatérési viselkedése, az Ubuntu 24.04 /run/lock permission modellje, a flock használata NFS-en kívüli lokális lockfájllal. A példa futás nélküli illusztratív kimenet.
