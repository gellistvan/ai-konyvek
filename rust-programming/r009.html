4.3 Mintaillesztés: match, if let, let else és a minták

4.3.1 Motiváció

A C++17 switch utasítása csak egész típusokon működik; enumok esetén is csak annyit tud, hogy a felsorolt értékekhez ugrik. Ha egy enum class-szal dolgozunk, a fordító legfeljebb figyelmeztet, ha egy új értéket kihagytunk, de nem tud típusos destrukturálást, kimerítőség-ellenőrzést vagy bonyolult feltételeket. A std::variant és a std::visit már közelebb visz a célhoz, de a látogató sablonok és a generikus lambda körülményesek, és a C++17 kódban a hibaüzenetek gyakran sablonmélységbe vezetnek.

A Rust match kifejezése éppen azt a hiányt pótolja, amit egy C++-fejlesztő a switch-ben és a std::visitben keres: típusos, kimerítő, értékekre, mintákra és feltételekre egyaránt illeszthető, és kifejezésként használható. A fordító fordítási időben észleli, ha egy enum új variánsa után elfelejtettünk egy ágat frissíteni – ez a refaktorálás egyik legerősebb eszköze.

4.3.2 Fogalmak és szabályok

Definíció. A mintaillesztés (pattern matching) olyan szerkezet, amely egy értéket egy mintával (pattern) vet össze, és sikeres illeszkedés esetén a minta változóihoz kötött értékekkel végrehajt egy kódágat. A Rust match kifejezés minden ága minta => kifejezés alakú.

Definíció. A match kimerítő (exhaustive), ha a célérték típusának minden lehetséges értékéhez tartozik legalább egy illeszkedő minta. Enumoknál a fordító ezt ellenőrzi, és ha hiányzik egy variáns, hibát ad.

Szabály. A match kifejezés minden ága ugyanarra a típusra értékelődik ki. A minták (és szükség esetén a guardok) sorrendben kerülnek vizsgálatra, és az első illeszkedő ág hajtódik végre; az ágtörzsek közül csak a kiválasztott fut. A közös típus koercióval is kialakulhat, nem feltétlenül azonos már kezdetben.

Szabály. A _ minta bármely értékre illeszkedik, de nem köt értéket. A _ használata „mindent elnyelő” ágat ad, amely kimerítővé teszi a match-et; ezt azonban megfontoltan kell használni, mert elrejtheti az új variáns kezelését.

Definíció. A guard egy if feltétel a minta után, amely tovább szűkíti az illeszkedést: Some(x) if x > 0 => .... Guard csak akkor fut le, ha a minta már illeszkedett, és ha a guard hamis, a következő ág próbálkozik.

Definíció. A @ binding lehetővé teszi, hogy egy részmintához tartozó teljes értéket elnevezzük: pair @ (x, y) => ... vagy Some(n @ 1..=5) => ....

Definíció. A refutable minta olyan, amely nem feltétlenül illeszkedik (pl. Some(x)), az irrefutable minta mindig illeszkedik (pl. x, _, (a, b)). A let utasítás csak irrefutable mintát fogadhat el; a let else ezt a korlátot oldja fel azzal, hogy ha a minta nem illeszkedik, az else ág fut le.

4.3.3 C++ és Rust összevetés

Vegyünk egy C++17 példát, ahol egy std::variant-ot kell feldolgoznunk látogatóval:

#include <variant>
#include <string>
#include <iostream>

using Value = std::variant<int, std::string>;

struct Printer {
    void operator()(int i) const { std::cout << "int: " << i << '\n'; }
    void operator()(const std::string& s) const { std::cout << "string: " << s << '\n'; }
};

int main() {
    Value v = 42;
    std::visit(Printer{}, v);
}

Rustban ugyanez match-csel:

enum Value {
    Int(i32),
    String(String),
}

fn main() {
    let v = Value::Int(42);
    match v {
        Value::Int(i) => println!("int: {i}"),
        Value::String(s) => println!("string: {s}"),
    }
}

A különbség: - A Rust match kifejezés, visszatérési értéke van; a C++ std::visit is képes értéket visszaadni (az eredményt a látogató adja, és minden ágnak azonos visszatérési típusúnak kell lennie, mint a match ágainak), a különbség a szintaxisban és a mintákban van. - A Rust enum variánsai közvetlenül tartalmazzák az értékeket, a minta pedig egyszerre bontja ki azokat; a C++ std::variant alternatíváit az indexek vagy a std::get kezeli, ami hiba esetén futásidejű kivételt dobhat. - Ha a Rust enumhoz új variánst veszünk fel, a match fordítási hibát ad, amíg nincs kezelve; a C++ std::visit a látogató minden alternatíváját lefedi, és ha egy overload hiányzik, a fordítás többnyire olvashatatlan, de fordítási hibával áll meg. A switch + std::get_if alapú kézi megközelítésnél viszont nincs nyelvi kimerítőség-ellenőrzés, csak külső eszköz (például -Wswitch-enum figyelmeztetés vagy statikus analízis) jelezheti a hiányzó ágat.

4.3.4 Kidolgozott példa: kimerítőség-ellenőrzés

Tekintsük a következő hibás Rust kódot, amely nem kezeli az összes variánst:

enum Color {
    Red,
    Green,
    Blue,
}

fn describe(c: Color) -> &'static str {
    match c {
        Color::Red => "piros",
        Color::Green => "zöld",
    }
}

Ez a változat szándékosan nem fordul le. A fordító hibaüzenetének lényege E0004 (nem kimerítő minta):

error[E0004]: non-exhaustive patterns: `Color::Blue` not covered
 --> src/main.rs:8:11
  |
8 |     match c {
  |           ^ pattern `Color::Blue` not covered

A javítás: egészítsük ki a hiányzó ággal, vagy használjunk _ ágat, ha tényleg minden más érték ugyanúgy kezelendő. Itt természetesebb a teljes felsorolás:

match c {
    Color::Red => "piros",
    Color::Green => "zöld",
    Color::Blue => "kék",
}

A kimerítőség-ellenőrzés a refaktorálás során válik igazán értékessé: ha később felveszünk egy Color::Yellow variánst, a fordító azonnal megmutatja az összes olyan match helyet, ahol frissíteni kell a logikát. Ez a C++ switch-ben csak jó esetben, figyelmeztetéssel működik.

4.3.5 Minták fajtái

A match ágak mintái sokfélék lehetnek:

  • Literálminta: 1, "hello", true.
  • Tartományminta: 1..=5 (zárt), 'a'..='z'.
  • Tuple és struct destrukturálás: (x, y), Point { x, y }.
  • Enum variáns destrukturálás: Some(x), Ok(v), Err(e).
  • Alminták kombinálása: Some((x, y)).
  • @ binding: n @ 1..=5 – az n a teljes értéket köti, miközben a tartományra is illeszkedik.
  • Guard: Some(n) if n % 2 == 0 => ....

Példa guard és @ binding használatára:

fn classify(n: i32) -> String {
    match n {
        n @ 0..=9 => format!("egyjegyű: {n}"),
        n if n < 0 => format!("negatív: {n}"),
        n => format!("nagy: {n}"),
    }
}

Itt az első ág a n @ 0..=9 mintával egyszerre köti a teljes értéket és ellenőrzi a tartományt; a második ág guardot használ; a harmadik minden maradékot elkap.

4.3.6 if let, while let, let else

A match gyakran akkor is szükséges, ha csak egyetlen minta érdekel. Az if let kényelmes szintaktikai cukor, amely egyetlen refutable mintát ellenőriz:

let opt: Option<i32> = Some(5);
if let Some(x) = opt {
    println!("van érték: {x}");
} else {
    println!("nincs");
}

A while let hasonlóan működik, amíg a minta illeszkedik; tipikusan iterátoroknál használjuk:

let mut iter = vec![1, 2, 3].into_iter();
while let Some(x) = iter.next() {
    println!("{x}");
}

A let else lehetővé teszi, hogy refutable mintát használjunk egy let-ben, és ha nem illeszkedik, az else ág (amely nem térhet vissza normálisan, pl. return, break, panic!) fusson le:

let Some(config) = load_config() else {
    eprintln!("nincs konfiguráció");
    return;
};
// config itt már a kicsomagolt érték

4.3.7 Referencia-minták és binding-módok (előzetes)

Amikor a match egy referencia mögötti értéket vizsgál, a kötés alapértelmezés szerint referencia marad, nem másolódik. Például:

let opt = Some(String::from("hello"));
match &opt {
    Some(s) => println!("{s}"), // s típusa &String
    None => {}
}

Itt opt típusa Option<String>, de a match &opt-ra illeszkedik, ezért az s kötés &String típusú. Ha a belső értéket mozgatni akarnánk, a match opt kellene, de akkor az opt elveszne. A ref kulcsszóval explicitté tehetjük, hogy referenciát kössünk; a & a mintában pedig referenciát vár. Ez a téma a Borrowing fejezetben mélyül el; itt elég annyi, hogy a binding-módok határozzák meg, hogy a minta által kötött változó milyen módon (érték, &, &mut) kapja meg az értéket.

4.3.8 Labor: az rkv parancsfeldolgozója match-csel

Munkakönyvtár: ~/rust-labor/rkv/

Ebben a laborban az Az enum mint összeg-típus és az Option a null helyett alfejezetben létrehozott Command enumhoz (rkv-core/src/command.rs) parancsértelmezőt írunk, és az rkv-cli-t átállítjuk a protokoll szerinti parancsokra. Új Command típust nem hozunk létre: a protokollnak egyetlen parancstípusa van. A kiinduló állapot az enum mint összeg-típus és az Option a null helyett ellenőrzési pontja.

A protokoll nyelvtana. Az értelmező ugyanazt az előírást követi, mint a könyv összes későbbi parsere (a Saját hibatípusok: enum-hibák, thiserror, anyhow és az Az rkv hálózati szerver: TCP, protokoll, kecses leállás alfejezeté):

  • egy sor egy parancs, a sorvég \n; a parancsszó és az argumentumok között pontosan egy szóköz áll;
  • a kulcs (és a LIST prefixe) nem üres, és nem tartalmaz szóközt, más whitespace-t vagy vezérlőkaraktert;
  • GET <kulcs> és DEL <kulcs>: pontosan egy argumentum; a többletargumentum hiba;
  • SET <kulcs> <érték>: az érték a kulcs utáni szóköztől a sor végéig tart, tehát tartalmazhat szóközt; üres nem lehet, és nem tartalmazhat sortörést (\n, \r);
  • LIST vagy LIST <prefix>.

Szóköz és whitespace: közös táblázat. A parancsszó és a kulcs között pontosan egy ASCII szóköz az elválasztó; az érték a kulcs utáni első szóköz után kezdődik, ezért egy szóközzel kezdődő érték érvényes, nem elválasztóhiba (SET k x → érték: " x"). A futtatott viselkedés (Command::from_str):

Bemenet Eredmény
SET k x Set("k", "x")
SET k x (két szóköz) Set("k", " x"): az érték vezető szóközzel kezdődik
SET k x\ty Set("k", "x\ty"): a tab az értékben megengedett
GET a\tb, GET a\u{a0}b (NBSP) hiba: a kulcsban whitespace és vezérlőkarakter tilos (a Unicode-whitespace is)
GET a (két szóköz) hiba: többletargumentum / üres kulcs
LIST List(None); LIST (üres prefix) és LIST \u{a0} hiba
SET k / SET x hiba: üres érték / üres kulcs
SET k v\n, GET a\nb, GET a\r hiba: sortörés az értelmezőnek átadott sorban

A hálózati szerver a keretezéskor már levágja a sorvégi \n-t és a megelőző \r-t (CRLF), így a nc-ből jövő \r\n sor is érvényes; az értelmező maga a sorvég karaktereket tartalmazó sort hibának veszi.

Ezen a tartományon a Command::to_line és az értelmező egymás inverzei: parse_command(&cmd.to_line()) == Ok(cmd). Ami kívül esik rajta (szóközös kulcs, sortöréses érték, többletargumentum), azt az értelmező hibával utasítja el, nem csonkolja csendben.

Kódblokk — fájl: rkv-cli/src/main.rs · művelet: teljes csere · ellenőrzés: cargo build -p rkv-cli → hibátlan fordítás

use rkv_core::Store;
use rkv_core::command::Command;

/// Egy kulcs (vagy prefix) ellenőrzése a protokoll nyelvtana szerint.
fn parse_key(s: &str) -> Result<String, String> {
    if s.is_empty() || s.chars().any(|c| c.is_whitespace() || c.is_control()) {
        Err(format!("invalid key: {s:?}"))
    } else {
        Ok(s.to_string())
    }
}

/// A protokoll egy sorát `Command`-dá alakítja.
fn parse_command(line: &str) -> Result<Command, String> {
    let (verb, rest) = match line.split_once(' ') {
        Some((verb, rest)) => (verb, Some(rest)),
        None => (line, None),
    };
    match (verb, rest) {
        ("GET", Some(key)) => parse_key(key).map(Command::Get),
        ("DEL", Some(key)) => parse_key(key).map(Command::Delete),
        ("SET", Some(rest)) => match rest.split_once(' ') {
            Some((_, "")) => Err("SET requires a non-empty value".to_string()),
            Some((_, value)) if value.contains(['\n', '\r']) => {
                Err("SET value must not contain a line break".to_string())
            }
            Some((key, value)) => parse_key(key).map(|k| Command::Set(k, value.to_string())),
            None => Err("SET requires a key and a value".to_string()),
        },
        ("LIST", None) => Ok(Command::List(None)),
        ("LIST", Some(prefix)) => parse_key(prefix).map(|p| Command::List(Some(p))),
        ("GET" | "DEL", None) => Err(format!("{verb} requires a key")),
        ("SET", None) => Err("SET requires a key and a value".to_string()),
        ("", _) => Err("empty line".to_string()),
        (other, _) => Err(format!("unknown command: {other}")),
    }
}

/// Végrehajtja a parancsot a tárolón, és visszaadja a protokoll szerinti választ.
fn execute(store: &mut Store, command: Command) -> String {
    match command {
        Command::Get(key) => match store.get(&key) {
            Some(bytes) => match String::from_utf8(bytes.clone()) {
                Ok(text) => format!("VALUE {key} {text}"),
                Err(_) => format!("ERR value of {key} is not valid UTF-8"),
            },
            None => "NOTFOUND".to_string(),
        },
        Command::Set(key, value) => {
            store.set(key, value.into_bytes());
            "OK".to_string()
        }
        Command::Delete(key) => match store.delete(&key) {
            Some(_) => "OK".to_string(),
            None => "NOTFOUND".to_string(),
        },
        Command::List(prefix) => {
            let mut keys = store.keys();
            keys.retain(|k| match &prefix {
                Some(p) => k.starts_with(p.as_str()),
                None => true,
            });
            keys.sort();
            let mut out = String::new();
            for key in keys {
                if let Some(bytes) = store.get(&key) {
                    out.push_str(&format!("VALUE {key} {}\n", String::from_utf8_lossy(bytes)));
                }
            }
            out.push_str("OK");
            out
        }
    }
}

fn main() {
    // A parancssori argumentumokat egy protokollsorrá fűzzük össze:
    // `rkv-cli SET name "Alice Smith"` -> "SET name Alice Smith".
    let line = std::env::args().skip(1).collect::<Vec<_>>().join(" ");
    let mut store = Store::new();
    match parse_command(&line) {
        Ok(command) => println!("{}", execute(&mut store, command)),
        Err(e) => {
            eprintln!("ERR {e}");
            std::process::exit(1);
        }
    }
}

#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn round_trip_on_supported_domain() {
        let commands = [
            Command::Get("k".into()),
            Command::Set("k".into(), "hello world".into()),
            Command::Delete("k".into()),
            Command::List(None),
            Command::List(Some("app".into())),
        ];
        for cmd in commands {
            assert_eq!(parse_command(&cmd.to_line()), Ok(cmd));
        }
    }

    #[test]
    fn nothing_is_dropped_silently() {
        assert!(parse_command("GET k extra").is_err());
        assert!(parse_command("SET k").is_err());
        assert!(parse_command("SET k ").is_err());
        assert!(parse_command("SET k a\nb").is_err());
        assert!(parse_command("LIST a b").is_err());
        assert_eq!(
            parse_command("SET k hello world"),
            Ok(Command::Set("k".into(), "hello world".into()))
        );
    }
}

A match (verb, rest) egy tuple-ra illeszt: a minta egyszerre vizsgálja a parancsszót és azt, hogy van-e argumentum. Az ("GET" | "DEL", None) ág a vagy-mintát, a Some((_, "")) ág a beágyazott literálmintát (üres érték), a Some((_, value)) if value.contains(...) ág pedig a guardot mutatja. (Az üres értékre is írhatnánk if value.is_empty() guardot, de a clippy redundant_guard lintje jogosan javasolja helyette a literálmintát.) A kimerítőséget a fordító ellenőrzi: az utolsó (other, _) ág minden más esetet lefed. A parse_key(key).map(Command::Get) a Result sikeres ágát alakítja át; a ? operátort csak a Result, a ? operátor és a panic helye alfejezet vezeti be.

4.3.9 Tipikus hibák és átállási csapdák

  1. Túl korai _ ág. A _ kényelmes, de ha új variánst veszünk fel, a fordító nem figyelmeztet, mert a _ mindent elnyel. Inkább soroljuk fel a tényleges variánsokat, és csak akkor használjunk _-t, ha valóban minden más értékre ugyanaz a viselkedés.

  2. if let túlhasználata. Az if let elveszíti a kimerítőségi ellenőrzést. Ha egy enum több variánsát kell kezelni, a match a megfelelő eszköz; az if let csak akkor indokolt, ha tényleg csak egy ág érdekel, a többi pedig figyelmen kívül hagyandó.

  3. Guard logika erőltetése. A guard if feltétel, nem minta. Ha a feltétel a minta részeként kifejezhető (pl. tartományminta), akkor azt használjuk: 1..=5 jobb, mint n if n >= 1 && n <= 5. A guard akkor hasznos, ha a feltétel nem minta (pl. x % 2 == 0).

  4. Binding-módok félreértése. Amikor match &opt-ot írunk, a minta Some(s) a s-t &String-ként köti, nem String-ként. Ha a mozgatás szándékos, akkor match opt kell; ha a kölcsönzés szándékos referencia nélkül, akkor a ref vagy ref mut használható. Ez a hibás kód gyakran cannot move out of borrowed content hibaüzenethez vezet, amit a Borrowing fejezet tárgyal részletesen.

4.3.10 Feladatok

4.3.10.1 (a) Fogalmi kérdés: lefordul-e és miért?

Az alábbi kód szándékosan hibás:

enum Status {
    Pending,
    Running,
    Done,
}

fn describe(s: Status) -> &'static str {
    match s {
        Status::Pending => "várakozik",
        Status::Running => "fut",
    }
}

Mi a hiba, és hogyan javítható? Mondja ki a kimerítőségi szabályt.

4.3.10.2 (b) C++-kód átírása idiomatikus Rustra

Írd át a következő C++17 std::variant-os kódot Rustra match-csel, enumnal és destrukturálással:

#include <iostream>
#include <string>
#include <type_traits>
#include <variant>

using Result = std::variant<int, std::string>;

int main() {
    Result r = 42;
    std::visit([](auto const& v) {
        if constexpr (std::is_same_v<std::decay_t<decltype(v)>, int>) {
            std::cout << "szám: " << v << '\n';
        } else {
            std::cout << "szöveg: " << v << '\n';
        }
    }, r);
}

4.3.10.3 (c) Implementációs feladat az rkv-ban

Bővítsd a parse_command függvényt egy PING paranccsal, amely visszaad egy Command::Ping variánst. Ehhez módosítsd a Command enumot is. A PING parancsnak nincs argumentuma. Teszteld a cargo run -p rkv-cli -- "PING" parancsot.

4.3.10.4 (d) Hibajavítás, refaktorálás

Az alábbi kód helyes és minden esetet kezel (a Some-ágban az if/else, a külső else a None-t), tehát ez nem hibajavítás, hanem olvashatósági refaktorálás. Írd át egyetlen match-csel, guarddal; opcionálisan készíts egy külön, let else-t használó változatot is, és vesd össze a kettőt:

fn process(opt: Option<i32>) {
    if let Some(x) = opt {
        if x > 0 {
            println!("pozitív: {x}");
        } else {
            println!("nem pozitív: {x}");
        }
    } else {
        println!("nincs érték");
    }
}

A cél: ugyanaz a kimenet Some(5), Some(-1) és None bemenetre.

4.3.11 Megoldások

4.3.11.1 (a)

A hiba: a match nem kimerítő, mert a Status::Done variáns nincs lefedve. A javítás:

match s {
    Status::Pending => "várakozik",
    Status::Running => "fut",
    Status::Done => "kész",
}

A kimerítőségi szabály: minden enum-variánsnak rendelkeznie kell legalább egy illeszkedő mintával, különben a fordító E0004 hibát ad.

4.3.11.2 (b)

Rust megfelelő:

enum Result {
    Number(i32),
    Text(String),
}

fn main() {
    let r = Result::Number(42);
    match r {
        Result::Number(n) => println!("szám: {n}"),
        Result::Text(s) => println!("szöveg: {s}"),
    }
}

A C++ if constexpr helyett a match enum variánsokra illeszkedik, és a destrukturálás automatikus.

4.3.11.3 (c)

A bővítés a meglévő rkv-core/src/command.rs Command enumját módosítja; új típust nem hozunk létre. A feladat egy kísérleti bővítés: a könyv kanonikus Command enumja a továbbiakban is négy variánsú marad (lásd lent).

Kódblokk — fájl: rkv-core/src/command.rs · művelet: módosításrészlet: új variáns és új to_line ág · ellenőrzés: cargo build -p rkv-core

#[derive(Debug, Clone, PartialEq, Eq)]
pub enum Command {
    Get(String),
    Set(String, String),
    Delete(String),
    List(Option<String>),
    Ping,
}

// a to_line match-jébe:
            Command::Ping => "PING".to_string(),

Ha most cargo build --workspace-t futtatunk, a fordító az rkv-cli execute függvényében E0004-es hibát ad (non-exhaustive patterns: Command::Ping not covered): a kimerítőség-ellenőrzés pontosan megmutatja, hol kell az új variánst kezelni. A teljes, módosított parse_command (csak a két új ág tér el a laborbeli változattól) és az execute új ága:

Kódblokk — fájl: rkv-cli/src/main.rs · művelet: a parse_command cseréje és egy új ág az execute match-ében · ellenőrzés: cargo run -p rkv-cli -- PING → PONG

fn parse_command(line: &str) -> Result<Command, String> {
    let (verb, rest) = match line.split_once(' ') {
        Some((verb, rest)) => (verb, Some(rest)),
        None => (line, None),
    };
    match (verb, rest) {
        ("GET", Some(key)) => parse_key(key).map(Command::Get),
        ("DEL", Some(key)) => parse_key(key).map(Command::Delete),
        ("SET", Some(rest)) => match rest.split_once(' ') {
            Some((_, "")) => Err("SET requires a non-empty value".to_string()),
            Some((_, value)) if value.contains(['\n', '\r']) => {
                Err("SET value must not contain a line break".to_string())
            }
            Some((key, value)) => parse_key(key).map(|k| Command::Set(k, value.to_string())),
            None => Err("SET requires a key and a value".to_string()),
        },
        ("LIST", None) => Ok(Command::List(None)),
        ("LIST", Some(prefix)) => parse_key(prefix).map(|p| Command::List(Some(p))),
        ("PING", None) => Ok(Command::Ping),
        ("PING", Some(_)) => Err("PING takes no arguments".to_string()),
        ("GET" | "DEL", None) => Err(format!("{verb} requires a key")),
        ("SET", None) => Err("SET requires a key and a value".to_string()),
        ("", _) => Err("empty line".to_string()),
        (other, _) => Err(format!("unknown command: {other}")),
    }
}

// az execute match-jébe:
        Command::Ping => "PONG".to_string(),

Futtassuk:

cargo run -p rkv-cli -- PING

Várt kimenet:

PONG

A round-trip tesztbe a Command::Ping is felvehető. Fontos: a könyv kanonikus protokollja a négy parancsot (GET, SET, DEL, LIST) tartalmazza, a további laborok erre épülnek. Ha a Ping-et a saját projektedben megtartod, minden későbbi match-be (például a szerver execute függvényébe) fel kell venned az ágát; a fordító mindegyik helyet megmutatja. Ha a könyv kódját változtatás nélkül szeretnéd követni, a feladat után állítsd vissza a két fájlt.

4.3.11.4 (d)

Refaktorált változat:

fn process(opt: Option<i32>) {
    match opt {
        Some(x) if x > 0 => println!("pozitív: {x}"),
        Some(x) => println!("nem pozitív: {x}"),
        None => println!("nincs érték"),
    }
}

A match mindhárom esetet egy helyen, kimerítően mutatja. Az opcionális let else változat a „korai kilépés” stílus, és akkor a legértékesebb, ha az x értékére a függvény további részében is szükség van:

fn process_let_else(opt: Option<i32>) {
    let Some(x) = opt else {
        println!("nincs érték");
        return;
    };
    if x > 0 {
        println!("pozitív: {x}");
    } else {
        println!("nem pozitív: {x}");
    }
}

A három változat (az eredeti, a match és a let else) ellenőrzötten azonos kimenetet ad: pozitív: 5, nem pozitív: -1, nincs érték. Itt a match elegendő és tömörebb; a let else hosszabb függvényben csökkenti a behúzást.

4.3.12 Rövid összefoglaló

Ebben az alfejezetben tanulmányoztuk a Rust match kifejezést, amely a C++ switch-nél és std::visit-nél kifejezőbb, kimerítő és típusos. A minták lehetnek literálok, tartományok, destrukturáló tuple/struct/enum minták, @ bindingek és guardok. Az if let, while let és let else a gyakori egyágú esetek kényelmes formái. A kimerítőség-ellenőrzés a refaktorálás során garantálja, hogy új enum-variáns felvételekor minden match frissüljön. Továbbvitt eredmények: a protokoll nyelvtana, a parse_command és az execute függvény (rkv-cli/src/main.rs) a rkv-core/src/command.rs Command enumjára építve, valamint a kimerítő match elve, amelyet a Result és a ? operátor, a trait objektumok és a haladó típusrendszeri minták használnak tovább.
