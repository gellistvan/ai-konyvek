5.2 Függőségek, feature-ök, verziózás és workspace-ek

5.2.1 Motiváció

Egy C++-projektben a külső függőség többnyire három dologból áll: include-útvonalak, linker-kapcsolók és platformfüggő binárisok. A vcpkg, Conan vagy a CMake FetchContent megoldja a letöltést, de a build-rendszer továbbra is a te felelősséged marad: melyik fejléc, melyik könyvtárfájl, melyik ABI-verzió kerüljön a parancssorba. Az is gyakori, hogy ugyanannak a könyvtárnak két verziója él a gépen, és a hibás find_package csendben a rosszat választja.

A Rust ezt a problémát a Cargo manifestben rendezi: a Cargo.toml deklarálja a függőséget, a verziómegkötést, a fordítási lehetőségeket (feature-ök) és a Cargo gondoskodik a letöltésről, a tranzitív függőségek feloldásáról és a linkelésről. A cél nem az, hogy mindent „varázslatosan” kezeljen, hanem hogy a függőségi fa reprodukálható és ellenőrizhető legyen.

5.2.2 Fogalmak és szabályok

Definíció. A Cargo-manifest (Cargo.toml) a crate leíró állománya; a [dependencies] szekció a normál, a [dev-dependencies] a tesztekhez és példákhoz, a [build-dependencies] a build scripthez szükséges függőségeket sorolja fel.

Definíció. A szemantikus verziózás (semver) MAJOR.MINOR.PATCH alakú. A Cargo alapértelmezett verziómegkötése a caret (^), ami a bal szélső nem nulla komponenst tartja meg: ^1.2.3 jelentése >=1.2.3, <2.0.0, ^0.2.3 jelentése >=0.2.3, <0.3.0. A Cargo-ban a jel nélküli 1.2.3 nem pontos rögzítés: ugyanaz, mint a ^1.2.3, tehát >=1.2.3, <2.0.0. Pontosan egy kiadást az egyenlőségjeles =1.2.3 enged meg. A * bármely verziót elfogad – ezt kerüld, mert nem reprodukálható buildhez vezet. A manifest követelménye és a Cargo.lock két különböző dolog: a manifest a megengedett tartományt adja meg, a lockfájl pedig azt a konkrét verziót rögzíti, amelyet a feloldás ebből a tartományból kiválasztott (például ^1.2.3 mellett 1.4.0-t). A reprodukálható buildet a commitolt Cargo.lock adja, nem az = megkötés; az =-t csak indokolt esetben, például egy ismert hibás kiadás kizárására használjuk.

Definíció. A feature opcionális, additív fordítási lehetőség; a crate-ek [features] szekcióban hivatkozhatnak más feature-ökre vagy opcionális függőségekre. Egy opcionális függőség akkor válik elérhetővé, ha optional = true jelölést kap, és egy feature bekapcsolja. Egy crate default feature-je azoknak a feature-öknek a listája, amelyek akkor is bekapcsolnak, ha a függőség deklarálásakor semmit sem kérünk (például a std). A default-features = false ezt a listát nem veszi figyelembe, ilyenkor csak az explicit features = [...] felsoroltak kerülnek be — a saját függőségi deklarációnkra nézve. A Cargo azonban a gráfban a feature-ket egyesíti (feature unification): ha egy másik függő ugyanahhoz a crate-hez további feature-t, akár a default-ot vagy a std-et is kéri, az bekerül; a no_std kompatibilitás tehát egyetlen default-features = false beállításból nem következik. Az explicit feature tehát additív kérés (a clap derive feature-je nem része a clap default készletének, ezért kérni kell); a default-features = false pedig kivonás (az alapértelmezett készlet nélkül indulunk).

Szabály. A Cargo.lock a feloldott függőségek pontos verzióit tárolja. A Cargo FAQ jelenlegi ajánlása szerint minden projekt lockfájlját érdemes verziókezelésbe tenni (alkalmazásnál és könyvtárnál egyaránt), mert így a saját fejlesztői és CI-build reprodukálható. Egy közzétett könyvtár lockfájlját a fogyasztó nem használja: ő a saját gráfját oldja fel. Az rkv workspace egyetlen, a gyökérben lévő Cargo.lock-ot használ.

Szabály. A függőségi higiénia része a fa és a biztonsági állapot ellenőrzése: cargo tree a megszűnt/duplikált verziókat, cargo audit az ismert sebezhetőségeket, cargo deny a licenceket és a nemkívánatos függőségeket mutatja. Ez utóbbi kettő külön telepítendő eszköz.

5.2.3 C++ és Rust összevetés

C++-ban egy CLI-argumentum feldolgozása gyakran kézi argc/argv-járás vagy getopt; a függőséget a build-rendszer külön kezeli:

// C++: CMake FetchContent + getopt (rövidített vázlat)
#include <getopt.h>
#include <string>
#include <vector>

int main(int argc, char** argv) {
    std::string key, value;
    int opt;
    while ((opt = getopt(argc, argv, "k:v:")) != -1) {
        if (opt == 'k') key = optarg;
        else if (opt == 'v') value = optarg;
    }
    // ellenőrzés, hibaüzenet, súgó kézzel...
}

A megfelelő Rust-kód a clap derive API-jával:

use clap::{Parser, Subcommand};

#[derive(Parser)]
#[command(name = "rkv-cli", version, about = "rkv parancssori kliens")]
struct Cli {
    #[command(subcommand)]
    command: Command,
}

#[derive(Subcommand)]
enum Command {
    /// Kulcs lekérdezése
    Get { key: String },
    /// Kulcs–érték beállítása
    Set { key: String, value: String },
    /// Kulcs törlése
    Del { key: String },
    /// Kulcsok listázása opcionális prefixszel
    List { prefix: Option<String> },
}

fn main() {
    let cli = Cli::parse();
    match cli.command {
        Command::Get { key } => println!("GET {}", key),
        Command::Set { key, value } => println!("SET {} {}", key, value),
        Command::Del { key } => println!("DEL {}", key),
        Command::List { prefix } => match prefix {
            Some(p) => println!("LIST {}", p),
            None => println!("LIST"),
        },
    }
}

A különbség: a Rust-verzió a Cargo.toml egyetlen bejegyzéséből húzza be a clap-ot, a fordítás során a Cargo feloldja a tranzitív függőségeket, a #[derive] makró pedig a típusból generálja a parancssori elemzőt, a hibaüzeneteket és a súgót. Nincs külön include-útvonal, nincs linker-flag, nincs platformfüggő .lib/.so kézi kezelés.

5.2.4.3 3. lépés – A CLI típus implementálása

A clap saját Command-szerű enumot vár a részparancsokhoz. Hogy ne ütközzön az rkv_core::Command-dal, a clap-os enum neve CliCommand. A clap a parancssor szerkezetét ellenőrzi (melyik részparancs, hány argumentum); a kulcsok és értékek tartalmát továbbra is a protokoll nyelvtana dönti el, ezért a felépített parancsot a meglévő parse_command-dal visszaellenőrizzük. Így a nyelvtan egyetlen helyen él.

Kódblokk — fájl: rkv-cli/src/main.rs · művelet: beillesztés és csere: a use sorok és a main cseréje, a parse_key, parse_command, execute függvény és a tesztmodul változatlan · ellenőrzés: cargo test -p rkv-cli → 2 sikeres teszt

use clap::{Parser, Subcommand};
use rkv_core::{Command, Store};

/// rkv parancssori kliens
#[derive(Parser)]
#[command(name = "rkv-cli", version, about)]
struct Cli {
    #[command(subcommand)]
    command: CliCommand,
}

#[derive(Subcommand)]
enum CliCommand {
    /// Kulcs lekérdezése
    Get { key: String },
    /// Kulcs–érték beállítása
    Set { key: String, value: String },
    /// Kulcs törlése
    Del { key: String },
    /// Kulcs–érték párok listázása opcionális prefixszel
    List { prefix: Option<String> },
}

// ... parse_key, parse_command és execute változatlanul (r009) ...

fn main() {
    let cli = Cli::parse();
    let command = match cli.command {
        CliCommand::Get { key } => Command::Get(key),
        CliCommand::Set { key, value } => Command::Set(key, value),
        CliCommand::Del { key } => Command::Delete(key),
        CliCommand::List { prefix } => Command::List(prefix),
    };
    // A protokoll nyelvtana szerinti ellenőrzés: ugyanaz a parser dönt,
    // mint a protokollsorok esetén.
    let command = match parse_command(&command.to_line()) {
        Ok(command) => command,
        Err(e) => {
            eprintln!("ERR {e}");
            std::process::exit(1);
        }
    };
    let mut store = Store::new();
    println!("{}", execute(&mut store, command));
}

A #[command(version, about)] automatikusan hozzáadja a --version és --help kapcsolókat; az about szövegét a Cli feletti /// komment adja, a részparancsok súgóját pedig a variánsok feletti /// kommentek. A mezők (key, value, prefix) attribútum nélkül pozicionális argumentumok: get foo, nem get --key foo. Név szerinti kapcsolóhoz a mezőre #[arg(long)] kellene.

5.2.4.5 5. lépés – Biztonsági és licenc-ellenőrzés

A cargo audit és a cargo deny nem része a Rust disztribúciónak. A könyv a cargo-deny 0.20.2-es kiadásával dolgozott; a verziót rögzítve telepítjük:

cargo install cargo-deny --version 0.20.2 --locked
cargo deny --version   # cargo-deny 0.20.2

Minden workspace-tagra (az rkv-core, rkv-cli, és a később létrehozott rkv-server, rkv-ffi, rkv-cxx, rkv-derive manifestjére is) érvényes: ahol egy későbbi lépés teljes Cargo.toml-cserét ír elő, és a blokk a license és publish = false sorokat nem tartalmazza, a [package] táblában ezeket meg kell tartani vagy vissza kell adni, különben a cargo deny check licenses elbukik.

A cargo deny licencet kér minden crate-től, ezért a saját workspace-tagjainknak is kell license mező, és publish = false jelzi, hogy nem kerülnek a crates.io-ra (különben a path-függőségeket “wildcard”-nak minősítené). A tagok Cargo.toml-jának [package] táblájába vegyük fel:

A rétegábra a működő rendszer függőségi viszonyait mutatja:

Továbbvitt eredmény. Ez a Cli típus és a CliCommand enum a rkv-cli/src/main.rs fájlban a clap-alapú parancssori felület alapja. A Hibakezelés: saját hibatípusok alfejezetben a Command feldolgozás hibatípusra köt majd rá, a Záróprojekt: az rkv teljes rendszerként alfejezetben a CLI lokális Store/FileStore klienseként marad; a hálózati szerverhez az nc és a C++-kliens csatlakozik, saját Rust TCP-kliens nem készül.

5.2.5 Tipikus hibák és átállási csapdák

  1. Wildcard verziómegkötés. A clap = "*" azt mondja a Cargo-nak, hogy bármely verzió megfelel. Egy féléves projektben már nem reprodukálható a build, mert az új kiadás API-t törhet. Mindig adj meg legalább főverziós caret-megkötést, és a Cargo.lock-ot commitold.
  2. A default-features = false félreértése no_std környezetben. Sok crate default feature-je a std-et is bekapcsolja, ami no_std célra (például thumbv7em-none-eabihf) fordítási hibát okoz. A serde jó példa: a std-et a default készlet tartalmazza, a derive viszont explicit feature. Ellenőrzött viselkedés: serde = { version = "1", default-features = false, features = ["derive"] } lefordul a no_std célra, a serde = { version = "1", features = ["derive"] } (az alapértelmezett készlettel) viszont E0463: can't find crate for std hibával áll meg. Fontos, hogy a default-features = false önmagában nem “kapcsolja ki a std-et általában”, csak azokat a feature-öket hagyja ki, amelyeket az adott crate a default listájában felsorol; a clap derive feature-je például soha nem volt a default része, ezért mindig explicit kell (features = ["derive"]).
  3. A cargo update félreértése. Az cargo update az összes függőséget frissíti a megengedett tartományon belül; ha csak egy crate-et akarsz, a cargo update -p <crate> a pontos eszköz. A Cargo.lock törlése nem „megjavítja”, hanem megszünteti a reprodukálhatóságot.

5.2.6.1 (a) Fogalmi kérdés

Adott a Cargo.toml részlet: foo = "0.3.8". Mely verziókat engedélyezi a Cargo? (Válaszd ki a helyeset, és indokold.)

5.2.6.2 (b) C++-kód átírása

Írd át a következő C++-részletet idiomatikus Rustra clap derive API-val. A program egyetlen --count N opciót vár, alapértelmezett értéke 1, és annyiszor írja ki a hello szót.

#include <cstdlib>
#include <iostream>
#include <string>

int main(int argc, char** argv) {
    int count = 1;
    for (int i = 1; i < argc; ++i) {
        std::string arg = argv[i];
        if (arg == "--count" && i + 1 < argc) {
            count = std::atoi(argv[++i]);
        }
    }
    for (int i = 0; i < count; ++i) std::cout << "hello\n";
}

5.2.6.3 (c) Implementációs feladat az rkv-ban

Bővítsd a rkv-cli/src/main.rs Cli típusát egy --verbose kapcsolóval, amely -v rövid alakkal is elérhető, és ha be van kapcsolva, a program a main elején írja ki: debug: verbose mód bekapcsolva. A kapcsolót úgy add hozzá, hogy az minden alkalmazott parancsnál elérhető legyen (globális opció).

5.2.7 Megoldások

5.2.7.1 (a)

A helyes válasz: 2. A 0.3.8 caret-megkötésben a bal szélső nem nulla komponens a 0 utáni 3, tehát >=0.3.8, <0.4.0.

5.2.7.2 (b)

use clap::Parser;

#[derive(Parser)]
struct Cli {
    /// Ismétlések száma
    #[arg(short, long, default_value_t = 1)]
    count: u32,
}

fn main() {
    let cli = Cli::parse();
    for _ in 0..cli.count {
        println!("hello");
    }
}

A default_value_t használata a u32 típus miatt biztonságos; a #[arg(short, long)] a -c és --count kapcsolókat generálja. A for _ in 0..cli.count a Rust tartományalapú iterációja.

5.2.7.3 (c)

A Cli típus kiegészítve:

use clap::{Parser, Subcommand};

#[derive(Parser)]
#[command(name = "rkv-cli", version, about = "rkv parancssori kliens")]
struct Cli {
    /// Verbose kiírás
    #[arg(short, long, global = true)]
    verbose: bool,

    #[command(subcommand)]
    command: Command,
}

#[derive(Subcommand)]
enum Command {
    Get { key: String },
    Set { key: String, value: String },
    Del { key: String },
    List { prefix: Option<String> },
}

fn main() {
    let cli = Cli::parse();
    if cli.verbose {
        println!("debug: verbose mód bekapcsolva");
    }
    match cli.command {
        Command::Get { key } => println!("GET {}", key),
        Command::Set { key, value } => println!("SET {} {}", key, value),
        Command::Del { key } => println!("DEL {}", key),
        Command::List { prefix } => match prefix {
            Some(p) => println!("LIST {}", p),
            None => println!("LIST"),
        },
    }
}

A global = true azt jelenti, hogy a kapcsolót nemcsak a főparancs után, hanem az alkalmazott parancs után is megadhatod (rkv-cli get --verbose key).

5.2.7.4 (d)

A features mezőnek lista típusúnak kell lennie, nem stringnek. A hibás sor:

features = "derive"

Helyesen:

features = ["derive"]

5.2.8 Rövid összefoglaló

A Cargo manifestben a [dependencies] szekció deklarálja a külső crate-eket, a caret (^) az alapértelmezett semver-megkötés. A feature-ök opcionális, additív fordítási lehetőségek; a default-features = false letiltja az alapértelmezett készletet. A Cargo.lock commitolandó a saját build reprodukálhatósága miatt (a fogyasztók feloldását egy könyvtár lockfájlja nem befolyásolja). A cargo tree, cargo audit és cargo deny a függőségi fa, a sebezhetőségek és a licencek ellenőrzését szolgálják. A laborban a rkv-cli crate-hez vettünk fel clap-ot (version = "4", features = ["derive"]), és létrehoztuk a Cli típust és a Command enumot a rkv-cli/src/main.rs fájlban. Ez a Továbbvitt eredmény a Hibakezelés: saját hibatípusok és a Záróprojekt: az rkv teljes rendszerként alfejezetekben használatos.

5.2.9 Források és ellenőrzési hiányok

  • A Cargo dokumentációja: https://doc.rust-lang.org/cargo/ – a verziómegkötések, feature-ök és Cargo.lock pontos szabályai.
  • A Rust referencia: https://doc.rust-lang.org/reference/ – a nyelvi szintaxis ellenőrzése.
  • A clap derive API pontos formátuma és a #[arg] attribútumok a docs.rs-en ellenőrizendők.
  • A cargo audit és a cargo deny parancskészlete verziófüggő; a bemutatott hívások a telepítés utáni --help kimenetében is megtalálhatók.
